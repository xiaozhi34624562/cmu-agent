## 1. 演讲的论证骨架

## 2. 对投研最重要的转变：以需要更新的判断组织工作

假设研究员问：“A 公司财报不错，原有投资逻辑是否需要调整？”

这个问题包含事实核实、原因解释、持续性判断和原有观点更新。搜索“业绩向好”“利润增长”无法自动完成这些任务。系统必须先明确原有判断、它依赖的假设、当前材料可能改变的部分，再决定检索什么。

建议将投研任务分成四层：

| 层次 | 示例 | 验收重点 |
|---|---|---|
| 事实查询 | 本期扣非归母净利润是多少？ | 数值、期间、单位、口径、来源 |
| 解释分析 | 利润增量来自哪里？ | 对账、证据、替代解释 |
| 前瞻研究 | 改善能否持续？ | 假设、机制、领先指标、反证 |
| 决策支持 | 原有判断应如何调整？ | 与既有观点和预期比较、条件与边界 |

任务不必层层升级。明确事实查询可以直接结束；只有问题需要解释和判断时，才进入较长研究流程。MADQA 等文档问答基准也不能直接验证预测能力或投资收益。

## 3. 一条完整案例：从财报变化到观点更新

以下公司、期间和数值全部为虚构示例。以制造业公司演示，不代表所有金融研究任务。

### 3.1 先把原观点变成可检验假设

原观点可能是：“高毛利产品占比上升将带动盈利修复，但需求持续性尚不确定。”

需要拆成可分别更新的假设：

- H1：产品结构向高毛利业务迁移。
- H2：改善来自可持续经营，而非主要依赖一次性项目。
- H3：需求能持续，订单及交付情况提供支持。
- H4：经营改善尚未被已有盈利预测或市场预期充分反映。

H1 与 H2 都成立也不自动证明 H3、H4。系统应更新具体假设，不宜把整套投资逻辑压缩成一个乐观/悲观标签。

### 3.2 建立研究计划，但允许发现新问题后修改

| 子问题 | 最低必要证据 | 依赖关系 |
|---|---|---|
| 财务变化是否成立？ | 同口径财务报表、附注、历史数值 | 先统一实体、期间、口径 |
| 利润增长由什么构成？ | 扣非对账、非经常性项目明细 | 依赖前一项 |
| 毛利率为什么变化？ | 分产品收入成本、价格销量、成本与会计说明 | 先确认总体变化 |
| 经营改善能否持续？ | 订单、交付、客户、库存及行业证据 | 可先探索，结论依赖归因 |
| 是否改变原观点？ | 原备忘录及其假设、当时预测与价格信息 | 最后综合 |

假设初步发现利润主要由资产处置推动，后续就应追查处置收益及预测处理方式。如果出现应收款快速上升，则可能需要追加回款与收入确认问题。这种变化要记录为研究计划的修订，而非无限扩展搜索。

### 3.3 用同口径数据先校正直觉

假设两期数据均已按同一合并口径核验，金额单位为亿元；非经常性损益均为税后归母口径。

| 指标 | 上年同期 | 本期 | 变化 |
|---|---:|---:|---:|
| 营业收入 | 100 | 110 | +10% |
| 毛利率 | 20% | 23% | +3 个百分点 |
| 毛利润 | 20 | 25.3 | +5.3 |
| 归母净利润 | 10 | 14 | +40% |
| 扣非归母净利润 | 8 | 9 | +12.5% |
| 非经常性损益 | 2 | 5 | +3 |
| 经营现金流净额 | 12 | 7 | -5 |

在这个简化例子里：归母净利润增量 4 = 扣非归母增量 1 + 非经常性损益增量 3。也就是说，75% 的归母利润增量来自非经常性损益增量。它是算术构成，不是对全部经营原因的因果识别。

毛利润增加 5.3 可以采用一种固定顺序分解：

- 收入规模变化项：(110−100)×20% = 2。
- 毛利率变化项：110×(23%−20%) = 3.3。

这仍然不能识别“销量提升贡献多少”或“产品结构贡献多少”：收入还包含价格、销量、结构等因素，总体毛利率也可能受成本、汇率或会计变化影响。必须继续取证。

现金流下降构成待解释的不一致，不足以单独证明盈利恶化或财务造假。季节性、备货、账期及付款时点都可能是解释，需要逐项验证。

### 3.4 区分事实、他人陈述、解释和假设

| 内容 | 应记录为什么 | 常见越界 |
|---|---|---|
| 财报列示毛利率 23% | 披露事实，附口径与来源 | 自动归因于竞争力提升 |
| 管理层称高端产品需求强劲 | 管理层陈述 | 直接当成订单已经兑现 |
| 某券商预测下一年利润增长 | 外部预测，附发布日期与假设 | 当成未来实际结果 |
| 产品结构改善可能解释毛利率提升 | 研究推断 | 写成已证实原因 |
| 新订单有望支撑未来两个季度 | 待验证假设 | 无条件外推全年增长 |

检索结果可能证明“某人说过这个观点”，却不足以证明观点描述的现实已成立。引用真实存在，和引用足以支持结论，是两项检查。

### 3.5 对竞争解释做定向研究

对毛利率上升，至少比较产品结构、涨价、原材料下降、产能利用率和口径变化等候选解释。每个解释应写明支持证据、反对证据、还缺的证据。

例如，验证“高毛利产品占比上升”需要业务结构与分部盈利证据；只找到全公司毛利率上升，不足以闭环。如果五篇研报都引用同一次业绩会，它们可能只有一个共同信息源，不能算五份独立验证。多个 agent 认同同一说法，也不自动构成独立证据。

### 3.6 形成有条件的观点更新

在上述有限证据下，合理输出可以是：

> 本期毛利率和扣非归母净利润改善，支持盈利修复正在发生；归母净利润的高增速主要由非经常性损益增量贡献，不宜直接外推。现有资料尚不足以确认产品结构是主要原因，经营现金流下降也需要解释。因此，可提高对“当期盈利改善”的确信，但暂不提高对“改善持续性”的确信；待分产品盈利、订单兑现与回款证据补齐后，再评估原有预测。

若要进一步判断价格吸引力，还需要当时可得的价格、预测、情景和预期信息。经营改善不自动等于预期差扩大。

## 4. 研究分工：先定义交付物，再决定是否增加 agent

建议主研究 agent 管理研究问题、假设、证据缺口、依赖和预算；子任务负责有明确边界的问题；程序负责计算与校验；最终综合保留分歧和未解条件。

单个 agent 也可以按照这个过程工作。只有发现独立方向太多、工作上下文相互干扰或并行有实际价值时，再增加子 agent。

Anthropic 的多智能体研究实践强调目标、输出格式、工具与来源和任务边界；也明确指出，强依赖、必须大量共享上下文的工作不一定适合多智能体。参见 [How we built our multi-agent research system](https://www.anthropic.com/engineering/multi-agent-research-system)。

建议研究备忘录至少包含：

| 字段 | 内容 |
|---|---|
| 研究任务 | 本任务必须回答什么 |
| 范围 | 实体、期间、资料截止时间、口径 |
| 直接回答 | 已解决、部分解决或仍不可判断 |
| 核验事实 | 事实标识、来源、页码或区域 |
| 推断 | 根据哪些事实，依赖什么假设 |
| 反证与分歧 | 哪些材料不支持当前解释 |
| 缺口 | 还缺什么，为什么重要 |
| 下一步与停止原因 | 继续取证的价值，或为何停止 |

备忘录不能成为原始证据的唯一副本。综合者应能按引用重新打开原页、读取事实、检查计算。需要的是可核验的研究产出，不是模型内部思维过程。

委派示例：“截至 T 时点，核实 A 公司本期归母净利润增量的构成；使用税后归母口径；列出对账公式与来源；核实非经常性项目的性质；不要据此推断需求持续性；缺失明细时明确保留缺口。”这比“你是资深财务专家，分析一下公司”更易验收。

## 5. 工具设计：让下一步研究动作可执行

工具应暴露适合研究的能力，不必为每个能力建设独立服务。

| 能力 | 适合的问题 | 必须保留的信息 |
|---|---|---|
| 精确查找 | 证券代码、特定公告、具体术语 | 命中位置、文档身份 |
| 语义或混合检索 | 哪些材料解释利润率变化？ | 匹配理由、来源、时间、读取入口 |
| 页面及区域读取 | 表格、图例、脚注具体是什么？ | 原页、单位、表头、相邻上下文 |
| 结构化指标查询 | 明确实体、期间、口径的数据 | 数值、版本、单位、原始出处 |
| 计算校验 | 增长率、桥接、对账、情景分析 | 输入事实、公式、结果和异常 |

全文检索、语义检索与视觉阅读各有适用任务。金融专名、代码、具体数字常需要精确检索；同义表达和隐含主题需要语义匹配；图表与布局需要原页。不要只因更换嵌入模型，就假设缺失表头、单位或权限过滤会自动解决。

保留原始文件、页面图像、提取文本和结构化事实之间的连接。页面是核验入口，结构化事实支撑计算，研究备忘录记录解释与缺口。

工具设计应通过实际任务观察：若 agent 反复丢失表头，就修改返回内容；若经常搜索错误年份，就让时间过滤成为明确输入。Anthropic 的 [Writing effective tools for AI agents](https://www.anthropic.com/engineering/writing-tools-for-agents) 支持按工作设计工具、提供高信号返回、用真实评测验证的方向；具体金融接口是本文建议。

## 6. 金融场景的知识组织：让事实能够跨时间复用

事实记录建议包含实体、指标、数值、单位、报告期、合并/分部口径、实际/预测属性、披露时间、数据版本与证据位置。原页页序号和文件印刷页码最好分别保存。

时间还要分清“业务属于哪个期间”“公众何时可知”“系统何时获取”。研究 T 时点的判断时，不得混入 T 之后公布的更正数或预测。新版本可以用于今天的研究，但历史回放应保留当时可得版本。

来源质量需要按主张判断：财报用于确认正式披露指标，业绩会用于确认管理层表述，券商报告用于了解分析与预测，行业数据用于外部比较。不存在一个能代替所有问题判断的简单来源排名。

建议持久化三类对象：证据原件与定位、核验事实与计算、研究假设与变更记录。最终写作重新读取关键事实，而不是依赖多轮摘要记忆。相关背景见 Anthropic [Effective context engineering for AI agents](https://www.anthropic.com/engineering/effective-context-engineering-for-ai-agents)；它讨论按需取回、外部笔记和压缩边界，未提供本文这套金融事实结构。

## 7. 实验数字应怎样读

BrowseComp-Plus 用固定语料和证据标注改善可复现性，帮助区分检索与回答环节；它仍是有明确答案的研究问答，不是完整投研。见 [BrowseComp-Plus 原论文](https://arxiv.org/abs/2508.06600)。

MADQA 全量含 2,250 题，train/dev/test 为 1,550/200/500，基于 800 份 PDF、18,619 页。它分别考察答案、证据归属和搜索投入；原论文的错误分析也表明，找到正确页面后仍可能理解错误。见 [MADQA 原论文](https://arxiv.org/html/2603.12180v1)。

演讲口述的 BrowseComp-Plus 90.2% 与减少约 20% 工具调用，属于演讲报告结果；调用更少不自动意味着总费用同比例下降。MADQA 口述 88.9%、提升 3.5 个百分点和人类 oracle 99.4%，算出的差距缩小为 3.5/(99.4−88.9)=33.3%，与口述约 40% 不完全一致。未取得完整对应实验配置，不能给出强因果归因。见 [主办方逐字稿](https://ai.engineer/talks/O84lhGc1OOI-if-we-want-them-do-knowledge-work)。

Mixedbread 的 [Closing the Oracle Gap](https://www.mixedbread.com/blog/closing-gap) 是另一份实验报告：MADQA 的 Gemini 3 Pro 单次检索为 88.2%，Button 基于 Gemini 3.1 Pro 的系统为 91.7%。模型与系统不同，不能把这两行改写成演讲同一系统的受控消融，也不能用当前榜单替换演讲当时的数据。

99.4% 是“人类＋正确证据”成绩，不是同一个模型的上界。即便两个系统总体同分，也不能推出它们错误相同或推理能力相等。

## 8. 用自己的评测决定先改哪里

建议固定模型、任务、资料截止时间、输出要求与评分标准，逐级给证据：

| 对照 | 给系统什么 | 主要帮助诊断 |
|---|---|---|
| 正常模式 | 原始问题和工具 | 端到端表现 |
| 正确文档 | 人工核准的充分文档集合 | 文档发现问题 |
| 正确页面 | 人工核准的充分页面集合 | 文档内导航问题 |
| 核准事实 | 带口径的事实表及必要文字 | 阅读、抽取、结构与计算问题 |

这是一种诊断，不是严格的误差因果分解；证据变少也改变了上下文负担，人工证据可能不充分。若给足事实仍出现无依据归因，就不能继续只调检索器。

将检索和工作组织做成两个独立实验因素：现有/改进检索 × 单 agent/拆题备忘录流程。既比较同预算质量，也比较达到同等质量的总成本。多 agent 是否更好必须用自己的任务证明。

建议把答案评价拆成：数字及口径、证据支持、关键问题覆盖、冲突处理、不确定性表达、截止时间遵守、人工复核时间。重要错误单独记录，不能让大量普通陈述的高分冲淡一个关键利润数字错误。

事实题可以设明确答案；开放研究更适合专家评分准则，包括必须考虑的解释、禁止跳跃的结论与合理的保留意见。不要强迫所有合格研究产生同一投资观点；也不要用事后涨跌替代对当时证据质量的评价。

每次追加搜索应明确准备消除的缺口及可能改变的判断。关键证据齐全可以停止；有明确新线索则继续；重复搜索无新证据、来源不可得或预算耗尽，应交付未解决项。“未找到反证”与“已经排除风险”要保持不同状态。

## 9. 建议的最小落地顺序

1. 选“新公告是否影响已有研究假设”作为一个完整闭环，明确交付格式和资料范围。
2. 用二三十个历史案例建立初始诊断集，覆盖更正、缺失、冲突、一次性因素和不改变原观点的情况；这个规模用于发现问题，不足以证明全面可靠。
3. 先让单 agent 交付事实记录和带引用的备忘录，并通过程序计算与原页核验。
4. 根据失败定位改善工具；只有可独立并行的研究分支需要时再增加子 agent。
5. 让研究员盲评结果，记录判断是否可用以及核验所需时间；留下每次观点变化对应的证据和假设。

这一方案的价值目标是：研究员能迅速看清已经确认的事实、需要修改的具体假设、仍未消除的不确定性，以及下一份最有价值的证据。
