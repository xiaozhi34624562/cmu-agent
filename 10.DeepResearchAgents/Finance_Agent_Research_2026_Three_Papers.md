## 阅读说明与核心发现

本文研究以下三项工作：

1. **FutureX-Pro: Extending Future Prediction to High-Value Vertical Domains**，重点分析金融子集 FutureX-Finance，以及与金融检索相关的 FutureX-Search。
2. **MBABench: Evaluating LLM Agents on End-to-End Spreadsheet Tasks in Finance**，早期版本名为 WorkstreamBench。
3. **Can Language Models Learn to Forecast Stock Prices**，其预测环境名为 BETA，训练后的模型名为 AURA-4B。论文名、基准名和模型名不能混用。

三篇分别研究“预测未来数值”“交付可修改的金融工作簿”“用历史反馈训练预测策略”。它们拓宽了 FinSearchComp 的研究视角，但不是同一团队按统一协议完成的一组连续实验。FutureX-Pro 与 FinSearchComp 有多位共同作者；MBABench 通过 Hongseok Namkoong 延续哥伦比亚商学院一侧的研究；AURA 论文通过共同作者 Jiashuo Liu 连接合作网络，主要署名机构来自 Princeton、InclusionAI、Harvard 与 Stanford。作者关系依据论文作者列表与机构标注，不据此推断人员转岗、组织归属或项目内部继承关系。[FutureX-Pro 作者与贡献](https://arxiv.org/html/2601.12259v1#S9) · [MBABench 作者信息](https://arxiv.org/html/2605.22664v5) · [AURA 作者信息](https://arxiv.org/html/2609.36914v1)

**原文发现、本文分析和工程建议严格分开。**凡称“作者报告”，指论文中的任务、机制或实验；“本文分析”指对实验设计与证据边界的推导；“工程建议”指尚未在本仓库或用户系统中验证的方案。教学数字会单独标明，不当作论文实测。

本次核查得到五项最重要的结论：

- **预测与检索的验收逻辑不同。**FutureX-Finance 把任务推进到尚未发生的结果，但价格相对误差得分本身不能证明方向预测或交易收益；需要简单价格延续等基线才能判断新增信息价值。原文 §2 与本文对指标的分析见后文。
- **最终数字正确，并不足以验收专业交付物。**MBABench 同时检查结果、公式与格式，强调可审阅和可修改性。其最高综合分是加权质量分，不能读成整项工作成功率。原文 §3—6、图 2。
- **后训练改善了特定预测基准上的成绩。**AURA 的提升主要关联预测幅度，而非大幅改善方向准确率；工具调用变化是描述性证据，尚未通过受控消融证明每类工具的因果贡献。原文 §4—5、附录 A、D。
- **数据构建与评分策略会改变我们看到的能力。**AURA 的任务接受过程使用已实现结果，并且 398 道测试题中只对 240 道计分。它回答的是特定筛选分布上的问题，不能直接外推到任意市场机会。原文 §2.2—2.3、附录 A。
- **公开源码不自动等于论文结果可原样复现。**MBABench 的论文裁判与公开仓库默认配置存在差异；FutureX 通用评测代码不等于 FutureX-Pro 金融实验的独立复现包；AURA 的公开材料仍需按实际可访问范围判断。实现证据与未验证事项见各篇复现小节。

## 2. FutureX-Pro：从金融信息获取走向未来预测

### 2.1 身份、版本与原团队关系

- 论文完整标题为 *FutureX-Pro: Extending Future Prediction to High-Value Vertical Domains*。arXiv 当前记录仅 v1，首发 2026-01-18；不能把 2026 年发布误写成 2026 年实验，金融图 2 的数据来自 10 月 24 日至 11 月 28 日。结合 2026-01 首发及论文其余例子的 2025 年时间，研究期应理解为 **2025 年 10—11 月**；图注本身未打印年份，需要保留此边界。[元信息](https://arxiv.org/abs/2601.12259)、[PDF，p.4 Fig.2](https://arxiv.org/pdf/2601.12259v1)。
- 这是一个**评测框架报告**，包含 Finance、Retail、PublicHealth、NaturalDisaster 四个垂直预测领域，以及 FutureX-Search 检索任务；它不提出一个金融模型，也没有 SFT / RL 训练实验。[§1、§8，pp.1–2、17–18](https://arxiv.org/html/2601.12259v1#S1)。
- §9 将 Jiashuo Liu、Siyuan Chen、Zaiyuan Wang、Zhiyuan Zeng 列为项目负责人；Finance 核心贡献者包括 Jiacheng Guo、**Liang Hu**、Lingyue Yin、Suozhi Huang、Wenxin Hao、Yang Yang、Zerui Cheng、Zixin Yao。作者来自 ByteDance Seed、Princeton、Georgia Tech、Stanford、HKUST；§9 说明未特别注明者均来自 ByteDance Seed。[§9，p.19](https://arxiv.org/html/2601.12259v1#S9)。
- FinSearchComp 作者与此文有明显交集，包含 Liang Hu、Jiashuo Liu、Zaiyuan Wang、Zhiyuan Zeng、Wenhao Huang，以及 Tianci He、Yali Liao、Mingren Yin、Zhenwei Zhu、Ge Zhang、Xiang Gao、Kaiyuan Zhang、Zhoufutu Wen。**这是作者重叠支持的研究延续，不是原来的字节—哥伦比亚完整团队原班续作。** FutureX-Pro 的作者单位和 §9 没有 Columbia / Hongseok Namkoong。[FinSearchComp 原作者记录](https://arxiv.org/abs/2509.13160)、[FutureX-Pro §9](https://arxiv.org/html/2601.12259v1#S9)。

### 2.2 核心问题：金融信息查得到，未来价格也预测得准吗？

FinSearchComp 评估最新或历史客观事实的检索、抽取和计算。FutureX-Finance 则把目标换成**尚未实现的股票市场指标**，以真正未来事件降低标准答案被模型提前记忆的风险。作者把这定位为初级分析师所需的基础预测能力；这并非对完整投研报告、基本面尽调或交易策略的全面验收。[§1–2，pp.1–4](https://arxiv.org/html/2601.12259v1#S2)。

从 Agent 角度，工作变成：识别实体与指标 → 搜集当时可得的行情、新闻与披露 → 综合信息 → 输出数值 → 事件实现后取真实结果评分。**后半段的预测难度与前半段的检索难度必须区分**；找到更多事实并不能保证价格预测误差更小。这是本报告的任务分解，不是论文提出的新架构。

### 2.3 FutureX-Finance 的数据与任务

#### 2.3.1 150 个实体是股票覆盖数量，不是题目数

美股 100 家，选自 NASDAQ-100 与 S&P 500，上市市场为 NASDAQ / NYSE；A 股 50 家，覆盖 SSE / SZSE。美股示例为 NVDA、MSFT、VRTX；A 股示例为贵州茅台与宁德时代。Fig.1 显示美股样本更偏科技和通信服务，中国样本的工业、材料和日常消费权重更明显。[§2.1、Fig.1，p.3](https://arxiv.org/html/2601.12259v1#S2.SS1)。

这是一组重要公司的精选样本，不能称为全市场随机代表样本。论文未在金融章节给出每类总题数、每个交易日的抽样数量、完整股票清单、预测提前量分布、去重规则或按市场细分的成绩。[§2.1–2.3，pp.3–5](https://arxiv.org/pdf/2601.12259v1)。

#### 2.3.2 三种任务

| 类别 | 输出目标 | 论文示例的要点 | 注意事项 |
|---|---|---|---|
| Type 1：Spot Prediction | 某目标交易日、某指标的确切数值 | TSLA 某日收盘价 | 主要示例是价格级别，并非收益方向 |
| Type 2：Window Extremum Prediction | 未来 N 个交易日内，某指标的最大值 | 中国移动未来 5 个交易日的最高价 | 不能改写成概率区间预测；图例 Range 不代表输出完整区间分布 |
| Type 3：Directional Momentum Prediction | 未来窗口中的价格变化指标 | NVDA 未来 3 个交易日最高正向变化 | 文中没有充分说明变化是金额还是百分比、参考价格和聚合边界 |

来源：[§2.1，pp.3–4](https://arxiv.org/html/2601.12259v1#S2.SS1)。

**重要勘误：定义了三类任务，金融结果图只展示 Type 1 和 Type 2。** v1 中找不到 Type 3 的成绩；不能写成“三类任务均经过结果验证”。[Fig.2、§2.3，pp.4–5](https://arxiv.org/html/2601.12259v1#S2.SS3)。

论文的 Spot 示例给 TSLA 的日期为 2025-12-25，但本节没有说明如何将示例日期映射为有效交易日。这提醒复现者核对交易日历，不能仅照模板生成题目。[§2.1，p.3](https://arxiv.org/pdf/2601.12259v1)。

### 2.4 评分式：严格相对误差，不是金融 alpha

作者采用：

$$
S=\max\left(0, 1-20\frac{|\hat y-y|}{|y|}\right).
$$

误差 1% 得 0.8；误差 2.5% 得 0.5；误差达到 5% 得 0。图 2 的纵轴将均分画在百分制上，**46.37 是平均得分，不是方向准确率，也不是有 46.37% 的题完全预测正确**。[§2.2、Eq.(1)、Fig.2，p.4](https://arxiv.org/html/2601.12259v1#S2.SS2)。

作者称严格容差能反映真实市场洞见。本报告对这一解释保留边界：

1. **价格级别接近不等于预测了可交易的变化。** 假设当前价为 100，下一日真实价格为 101，仅预测“仍为 100”也会得约 0.802。这是本报告的虚构计算示例；它说明 last-price 的朴素基线可能在低波动短期样本上取得较高成绩。
2. **没有 last-price / 随机游走 / 常规时间序列基线，无法确认模型相对于“价格不变”的增量预测能力。** v1 金融部分只展示 8 个 LLM 配置，不含这些基线。[§2.3、Fig.2，pp.4–5](https://arxiv.org/pdf/2601.12259v1)。
3. **误差被截断后的平均分不能反推出平均相对误差。** 超过 5% 的不同程度错误都得零分，尾部损失被压平。这是评分式直接推导。
4. 如果 Type 3 的真实变化是零或很接近零，分母 \(|y|\) 会未定义或非常敏感；v1 金融章节没有说明这种情况如何处理。负值虽然以绝对值归一化，但指标口径仍需明确。[Eq.(1)](https://arxiv.org/html/2601.12259v1#S2.SS2)。
5. 本文没有交易回测、手续费、滑点、风险调整收益或资金容量结果，因此不能从评分得出真实交易收益。这是根据报告实验范围作出的边界判断。

| 配置 | Type 1 平均分（百分制） | Type 2 平均分（百分制） |
|---|---:|---:|
| GPT-5-high | 46.37 | 正文未给精确值 |
| Grok-4 | 41.25 | 正文未给精确值 |
| Hunyuan | 25.85 | 15.29 |

另外五个配置的分数只以 Fig.2 柱形图呈现，不在本报告中制造精确数值。Type3 在 v1 未报告实验成绩。

作者的结论：GPT-5-high / Grok-4 领先；大多数模型多日极值低于单点预测；没有模型平均分超过 50。Hunyuan 是其下降示例。正文又称 DeepSeek-V3.2 相对稳定，但图中它的两类分数仍有差距，Grok-4-fast 的两柱更接近。[§2.3](https://arxiv.org/html/2601.12259v1#S2.SS3)。

本报告分析：

- “多日极值更难”是总体观察，不是每个配置都成立：Gemini-2.5-pro、Qwen3-Max 的 Type2 高于 Type1。
- 没有误差条、置信区间、重复运行结果和按市场结果，难以判断相邻排名差是否稳定。
- 金融章节未披露足以核查统一工具权限、预算与完整版本的细节，不能把整个系统差距直接归因于基础模型能力。
- 低分至少反映该评分协议下结果有限，不能单凭绝对分数证明模型缺乏市场知识，更不能证明市场不可预测。

### 2.6 FutureX-Search：把已实现的事件改成检索题

#### 2.6.1 为什么加这一部分？

未来预测得差，有可能是取数失败，也有可能是预测失败。作者把已结束预测任务改写成历史查询，称其为检索控制实验，以检查答案确实存在时 Agent 能不能找到。[§6，pp.14–16](https://arxiv.org/html/2601.12259v1#S6)。

它**不是仅金融题集**；来源是 FutureX / FutureX-Pro 已结束的事件档案。FinSearchComp 的联系在于历史检索与实体解析，但不能把 FutureX-Search 全部称为金融研究任务。[§1、§6.1](https://arxiv.org/html/2601.12259v1#S6.SS1)。

#### 2.6.2 构造过程

1. 用原预测阶段 23 个基线模型的结果筛选：至少 19 个答对的过易题删除；至多 3 个答对的过难题删除，保留中间难度。
2. 将未来时改成过去时，得到标准搜索题 **N=100**。
3. 对子集 **N=39** 加入基于 Wikipedia 的实体描述掩码，造成额外实体解析和多跳搜索负担。

来源：[§6.1，pp.14–15](https://arxiv.org/html/2601.12259v1#S6.SS1)。

本报告分析：以**原预测表现**筛题，不等于独立证实历史检索难度；可预测性和可检索性是不同属性。模型驱动的筛选也改变题目分布，不能代表未经筛选的全部金融问题。

#### 2.6.3 三个层次

| 层次 | 查询结构 | 日元汇率例子的任务 |
|---|---|---|
| L1 直接检索 | 实体明确 | 2025-09-04，人民币兑 100 日元的中间价是多少？ |
| L2 显式实体解析 | 实体换成描述，同时明确要求先识别实体 | 先回答“是哪种货币”，再查询汇率 |
| L3 隐式多跳 | 只有描述，不提醒识别步骤 | Agent 必须自行确定货币，再查询汇率 |

L1 / L3 单题 0/1；L2 的实体子问占 0.4、数据子问占 0.6；作者同时提到 EM 和 F1（因部分模型拒答）。v1 未完整解释 F1 分母及拒答处理细节，也未充分说明 Fig.9 中 L1 是全部 100 道，还是配对的 39 道标准问题。[§6.2–6.3，pp.15–16](https://arxiv.org/html/2601.12259v1#S6.SS2)。

#### 2.6.4 主要结果及解释边界

内部 Agent 框架配搜索工具，测试 GPT-5.1-high、GPT-5-high、Claude-Opus-4.1、Claude-Sonnet-4.5、Grok-4、Gemini-3-pro、DeepSeek-V3.1、DeepSeek-V3.2、Kimi-K2-thinking、GLM-4.6。[§6.4、Fig.9，p.16](https://arxiv.org/html/2601.12259v1#S6.SS4)。

正文给出的精确比较：

- GPT-5.1-high：L1 **71.8%** → L3 **43.6%**，降低 28.2 个百分点。
- Grok-4：L1、L3 均 **53.8%**。
- 最难 L3 最好约 **54%**，由 Grok-4、Claude-Sonnet-4.5、GPT-5-high 并列。

来源：[§6.4、Fig.9，p.16](https://arxiv.org/html/2601.12259v1#S6.SS4)。

作者把 Grok 的稳定解释为架构重视深度语义匹配。本报告认为这是**作者假说**：无机制实验、无受控消融，不能单靠排行榜推出内部架构的因果解释。L2 也不是纯准确率，因为有 0.4/0.6 的部分给分，因此三个柱形不能不加说明地当成完全同质的成功率。

更稳健的工程启发是：**先识别要找的实体与字段，再写查询**。这是本报告建议；无需假设哪个模型具有某种不可见架构。

### 2.7 “不可能污染”主张应怎样解释？

作者沿用 FutureX 的实时流程，强调结果发生之前完成预测，标准答案尚未存在，可以防止已发生答案进入训练数据或搜索结果；构建细节转引原 FutureX §3.2。[§1，p.2](https://arxiv.org/html/2601.12259v1#S1)、[原 FutureX](https://arxiv.org/abs/2508.11987)。

本报告分析的适用条件：

- 防污染依赖真实提交时间早于结果实现、工具内容也只取提交前可得信息，并保留可审计日志。v1 的金融章节没有给出逐题时间戳和完整工具日志，不能把口号当成所有配置都被独立审计的证明。
- 未来题不会让历史来源、题目模板、历史价格、分析师预测“消失”；这些可以是合法输入。排除未来标准答案泄露，与排除所有历史知识复用是两回事。
- **FutureX-Search 的答案已经公开**，所以它不享有相同的“尚未存在标准答案”保证。
- 事件结束后用今天的网页重跑历史金融预测，可能查到已实现结果，不能称为原始实时评测复现；需要时间锁定数据或档案。

#### 2.8.1 发现公开代码，但评分协议不一致

当前官方组织提供 [Futurex-Eval](https://github.com/Futurex-ai/Futurex-Eval)。2026-10-05 检查的 main commit 是 **2626f7a297cd87c73a45408e23af8d838f5b60e5（2026-08-24）**。[固定 commit](https://github.com/Futurex-ai/Futurex-Eval/tree/2626f7a297cd87c73a45408e23af8d838f5b60e5)。

README 写明这是原 **FutureX** 通用评测脚本：L1/L2 用集合 F1，L3/L4 用 LLM judge 处理数字、字符串和排序；不能据此声称是 FutureX-Pro 全套复现包。[README](https://github.com/Futurex-ai/Futurex-Eval/blob/2626f7a297cd87c73a45408e23af8d838f5b60e5/README.md#L1-L9)。

关键实现：

```python
# Futurex-Eval 的通用数值评分（不是 FutureX-Pro 金融线性式）
return max(0, 1 - ((model_prediction - real_answer) / std) ** 2)
```

来源：[llm_judge_level_34.py L234–L235](https://github.com/Futurex-ai/Futurex-Eval/blob/2626f7a297cd87c73a45408e23af8d838f5b60e5/llm_judge_level_34.py#L234)。`std` 对数字答案自动设为 `0.05 * gt`，`gt == 0` 时为 0.01。[eval.py L247–L252](https://github.com/Futurex-ai/Futurex-Eval/blob/2626f7a297cd87c73a45408e23af8d838f5b60e5/eval.py#L247)。

因此，同样 1% 相对误差，代码二次式可得 0.96，而论文金融线性式得 0.8。**直接调用该公开函数无法忠实重现金融图 2 的评分定义。** 若复现，须明确实现 Eq.(1)，确认数据与版本匹配，并保留对零真实值的约定。

FutureX-Pro 并非只研究股票。Retail 使用 Temu 的 240 个商品，交叉设置“只给过去页面快照 / 加入历史销量”与“单点 / Top-3 概率 / 完整分布”输出；PublicHealth 使用美国和中国 CDC 的报告；NaturalDisaster 使用 NOAA、USGS、中国气象部门与英国 Met Office 等官方来源。报告试图观察一般搜索与推理能力能否适应专业信息环境。[§3—5，PDF 第 5—14 页](https://arxiv.org/pdf/2601.12259v1#page=5)

其中 Retail 的历史信息输入对照很有启发：应检查结果改善来自模型还是输入信息增加。另一方面，其概率输出的评分是各候选数值匹配分按模型概率加权的期望值。**本文分析：这不是对概率校准的直接检验。**对固定真实值，期望得分对预测概率呈线性关系；仅观察该得分提高，不能证明预测分布与真实事件频率匹配。若关心校准，还需独立检验可靠性或使用适当概率评分规则。[§3.3—3.4，PDF 第 7—9 页](https://arxiv.org/pdf/2601.12259v1#page=7)

公共卫生与自然灾害部分使用数值误差与集合匹配规则，但这些成绩不能转移成金融预测能力的证据。不同任务的单位、标签、波动尺度与评分不同，本报告不把各领域排名归纳成统一的金融能力结论。

## 3. MBABench：可交付、可修改的金融工作簿

### 3.1 版本、作者与研究定位

本文使用 **arXiv:2605.22664v5，2026 年 8 月 19 日，41 页**。首次公开时间是 **2026 年 5 月 21 日**；v1 名为 *WorkstreamBench*，v5 名为 *MBABench: Evaluating LLM Agents on End-to-End Spreadsheet Tasks in Finance*，两者属于同一 arXiv 工作的版本演进，不是两篇论文。截至研究日期 2026-10-05，arXiv 显示的最新版本为 v5。[arXiv 版本记录](https://arxiv.org/abs/2605.22664) · [v1](https://arxiv.org/abs/2605.22664v1)

主要作者来自 Columbia Business School，Julian Poeltl 来自 Reutlingen University。与 FinSearchComp 的明确共同作者是 **Hongseok Namkoong**；这说明哥伦比亚一侧的研究联系，不足以把本作称为字节 Seed 原班团队的续作。[MBABench v5，PDF 第 1 页](https://arxiv.org/pdf/2605.22664v5#page=1) · [FinSearchComp 作者名单](https://arxiv.org/abs/2509.13160)

**作者要解决的问题**：金融工作中的 Excel 会被经理、客户和其他分析师检查、调整假设、继续使用。只生成一个正确最终数字，不代表生成了一份专业人员可以接手的模型。MBABench 因此评价完整工作簿的正确性、公式质量和呈现质量。本作主要贡献是**评测基准、质量 taxonomy 与裁判验证**，没有提出新的金融预测模型，也没有训练一个专属金融 Agent。[§1–3，PDF 第 1–4 页](https://arxiv.org/pdf/2605.22664v5#page=1)

### 3.2 任务究竟要求 Agent 做什么？

典型任务是 ModelOff 2015 的 **Bread and Butter**：给定虚构公司 Macrohard 的收购情境与建模假设，构建互相关联的利润表、资产负债表和现金流量表，计算十年期内部收益率 IRR。这是论文引用的竞赛案例，虚构公司本身属于原任务设定，不是本文添加的教学例子。[§2，PDF 第 3–4 页](https://arxiv.org/pdf/2605.22664v5#page=3)

输入因来源不同，可以是案例 PDF、原始 Excel 数据、部分完成的起始工作簿；输出是完整 Excel 文件。工作簿必须支持假设修改，留下可以追踪的中间计算。把 Python 算出的数字全部粘贴进 Excel，即使当前数字正确，也可能在 Formula 维度失败。[§2、§5，PDF 第 3–4、7 页](https://arxiv.org/pdf/2605.22664v5#page=3)

任务来源是 Financial Modeling World Cup（FMWC）、ModelOff 和 Wall Street Prep（WSP）。根据图 4 的分组计数，任务合计 **206**：FMWC 136、ModelOff 40、WSP 30；附录 D.1.5 也明确用“Across 206 tasks”描述 API 分析。[§4、图 4，PDF 第 5 页；附录 D.1.5，第 35–36 页](https://arxiv.org/pdf/2605.22664v5#page=5)

| 难度等级 | 任务数 | 大致含义 |
|---|---:|---|
| 1：Very Easy | 27 | 很小的直接计算 |
| 2：Easy | 56 | 数步相连的计算，不需要深入金融知识 |
| 3：Medium | 88 | 多项假设和相连计算组成的标准案例 |
| 4：Medium-Hard | 28 | 跨多个互相关联部分，通常需要有经验的建模者 |
| 5：Hard | 7 | 高度互相关联、较长工作量的案例 |
| 6：Very Hard | 0 | 分类体系存在该档，实际数据没有覆盖 |

以上数量来自图 4 的柱状标注；难度体系见附录 B.1–B.6。难度不是模型耗时的简单函数：作者分别评 Scope、General Modeling、Finance Knowledge、Excel Implementation，权重为 **1/3、1/3、1/6、1/6**，加权后四舍五入到整数。[图 4，PDF 第 5 页](https://arxiv.org/pdf/2605.22664v5#page=5) · [附录 B，PDF 第 16–20 页](https://arxiv.org/pdf/2605.22664v5#page=16)

**数据边界**：WSP 任务常是局部财务操作，并非每道题都从零建造整个模型；作者使用写在起始工作簿内的指令，而非逐字保留其原始课程指令。FMWC 只收录传统金融案例，排除棋盘、竞赛等 freestyle 题。ModelOff 参考答案来自参赛者，而非竞赛组织者。因此，“端到端”描述的是交付与验收方向，不能理解为 206 道题都有同等规模或同等官方答案可靠性。[附录 F，PDF 第 40 页](https://arxiv.org/pdf/2605.22664v5#page=40)

表 1 显示参考工作簿的规模远大于 SpreadsheetBench：平均 **58,300 个单元格、43,391 次函数调用、4.8 个 sheet**，中位数分别为 **2,600、933、4**。作者由此报告平均单元格数约 33 倍、中位数函数调用数约 93 倍。平均与中位数落差很大，说明规模分布不均，不能把平均值当成每题的典型工作量。[表 1，PDF 第 5 页](https://arxiv.org/pdf/2605.22664v5#page=5)

### 3.3 验收体系：数字正确之外，还检查模型是否可维护

一级评分权重为 **Accuracy 50%、Formula 35%、Format 15%**。各子维度使用 pass/fail，按权重汇总到 0–100 的 composite score。因此 **82.9 分不是“82.9% 的题全部成功”**，也不是收益、预测准确率或专家接受率。[§3–4、图 2，PDF 第 3–6 页](https://arxiv.org/pdf/2605.22664v5#page=3)

| 一级维度 | 子维度及论文内权重 |
|---|---|
| Accuracy（50%） | Final Calculations 35%；Starting Values 25%；Task Completed 25%；Sign Consistency 15% |
| Formula（35%） | Logic Readability & Size、Handle Edge Cases、Avoid Hardcoding、Range Hygiene、Using Absolute References，各 20% |
| Format（15%） | Workbook & Sheet Structure 20%；Number Notation 20%；Readability、Color Standards、Information Alignment、Style Consistency、Borders & Shading、Output Presentation，各 10% |

论文图 2 列出上述权重；作者明确承认权重带有主观性，读者可以按用途重加权。[图 2、§4，PDF 第 3、6 页](https://arxiv.org/pdf/2605.22664v5#page=3)

金融公式的一些具体要求：将常量输入与计算分开，适当使用 `$` 绝对引用，避免多段逻辑挤进难审计的单个巨型公式，正确处理动态范围与错误值。Format 也涉及 sheet 结构和单位、数值记号，而不是只检查是否“好看”。[附录 A，PDF 第 13–16 页](https://arxiv.org/pdf/2605.22664v5#page=13)

### 3.4 裁判是否可靠？

正文使用 **Gemini-2.5-pro** 作为 LLM judge。裁判接收 rubric、参考答案与 Agent 工作簿的结构化表示，逐项输出 JSON pass/fail；失败时解释所在位置、原因和预期修正。它既评数值，也评公式及结构，因此可以识别“数值碰巧正确、逻辑其实错误”。[§4–5，PDF 第 6–7 页](https://arxiv.org/pdf/2605.22664v5#page=6)

作者进行了两种验证：向参考文件人工注入特定错误；人工复核真实 Agent 产物。真实产物共 **408 项专家标注**，报告 accuracy **0.92**、balanced accuracy **0.88**、F1 **0.85**。2 名 MBA 与 3 名金融专业人士在 rubric 迭代、扰动设计和标注上投入 **700+ 小时**。这里的 408 是判项标注，不能当成独立完整任务数。[§5、表 2–3，PDF 第 5–8 页](https://arxiv.org/pdf/2605.22664v5#page=5)

超过 **2M 字符**的超大工作簿使用 agentic judge：按需检索 sheet、范围、公式和格式，再记录局部证据。221 项 agentic judge 标注的 accuracy/balanced accuracy/F1 为 **0.90/0.89/0.87**；187 项非 agentic 标注为 **0.94/0.83/0.79**。两组数据不同，不是同一数据集上裁判架构优劣的严格消融。[附录 E.2，PDF 第 39 页](https://arxiv.org/pdf/2605.22664v5#page=39)

裁判仍会误判：合成扰动中漏掉部分绝对引用及色彩错误；真实工作簿中存在 false positive 和 false negative。它的价值是扩展质量检查，不能理解为对金融工作簿正确性的形式化证明。[表 2–4，PDF 第 5、8、39 页](https://arxiv.org/pdf/2605.22664v5#page=5)

### 3.5 系统与实验设置

作者比较三种运行面：**API** 使用统一自建 Excel CLI Agent；**GUI** 使用厂商网页／Excel 插件；**CODE** 使用 Codex 和 Claude Code。图 2 实际显示 **18 个结果条目：9 API、7 GUI、2 CODE**；摘要称“over 18 agents”。附录另说明 OLMo Think 因无法输出合法结构化调用而被排除，但没有解释摘要计数与图表之间的对应关系。为避免猜测，报告采用“18 个报告结果的系统配置”，并保留计数措辞差异。[图 2、附录 C，PDF 第 3、25–30 页](https://arxiv.org/pdf/2605.22664v5#page=3)

API harness 最多 **15 轮**，经 MCP 暴露 **19 个工具**，覆盖文件、sheet、读写单元格、分析、格式与公式验证；每次公式／数值写入后用 LibreOffice 重算。默认 fresh_context_mode 每轮重新载入文件，最近三轮历史保留在上下文。CODE 在仅允许厂商 API 网络出口的 Docker 中运行，阻断普通网页访问以减少公共竞赛答案泄漏；Codex 使用 GPT-5.6 Sol/xhigh，Claude Code 使用 Fable 5/max。[附录 C.1–C.5，PDF 第 25–30 页](https://arxiv.org/pdf/2605.22664v5#page=25)

每题处理上限 **120 分钟**；文件最大 **25 MB**，有一项 Data-King 因文件限制排除。pipeline 错误可重试至多 10 次，Agent 错误可重试至多 3 次，作者报告产物收集成功率超过 99%。这个成功率说明成功收集了输出，不意味着 99% 专业任务完成；重试也意味着不能把分数直接当作单次调用可靠性。[附录 D.3–D.4，PDF 第 37–38 页](https://arxiv.org/pdf/2605.22664v5#page=37)

### 3.7 失败模式：金融知识之外，基础设施也会成为瓶颈

1. **静态数值取代动态公式**：模拟任务跨 1,000+ 行，外部计算后填入硬编码数值，当前结果正确，但假设变化后失效且难审计。
2. **范围错位**：过去十二个月 EBITDA 的四季度窗口偏移，季度值相近导致最终数字偶然正确；纯数值核验会漏掉。
3. **建模质量与呈现不完整**：遗漏场景、单位标签、颜色标准、核验行，或关键 sheet 留空。
4. **大上下文与状态失忆**：静态数据 300K+ tokens，fresh_context_mode 反复发送完整文件，作者观察到 4–5 倍重写开销。
5. **工具吞吐瓶颈**：单单元格写入及重算造成大量调用；一次复杂任务 Opus 需 3,138 个工具调用，1,400+ 公式时重算偶尔超过 90 秒 MCP 超时。
6. **Excel 特性兼容**：循环引用和迭代求解在某些 Python／LibreOffice 工作流里失败；一个案例出现 1,044 个 `#VALUE!`，共 1,782 公式。

前两项见 §5，第 7 页；其余见附录 D.1–D.2，第 31–36 页。以上是作者观察，不应推广为所有相关工具版本永久无法处理这些功能。[§5](https://arxiv.org/pdf/2605.22664v5#page=7) · [附录 D](https://arxiv.org/pdf/2605.22664v5#page=31)

### 3.9 与 FinSearchComp 的连接，以及工程推导

**论文直接支持**：金融任务需要同时检查正确数据、计算逻辑、公式可修改性与专业呈现；harness、状态管理和工具吞吐的差异与端到端质量明显相关；较难任务仍有较大改进空间。

**本文推导**：FinSearchComp 更像检查“能否自己找到并核验金融事实”，MBABench 更像检查“能否把已给出的情境和假设转成可交接的分析资产”。构建投研 Agent 时，两者可以作为不同阶段的验收依据：前端记录来源、时点和口径；后端输出可追溯公式、情景参数、核验 sheet。不能把两篇的分数混合为一个能力排行榜。

**工程建议，未由论文直接验证**：在自建系统中优先检查批量公式写入、增量状态、Excel 兼容性、公式与数值双重验证、修改假设后的重算检查，再决定是否训练模型。论文没有通过受控实验得出“改 harness 一定优于微调”的普遍结论。

## 4. BETA 与 AURA-4B：用结果反馈训练价量预测策略

### 4.1 作者关系与研究问题

**原文事实。** 论文作者包括 Jiacheng Guo、Suozhi Huang、Shuzhen Li、Yunlong Gao、Zerui Cheng、Jason Ge、Shushu Liang、Zihao Li、Hao Lu、Ming Yin、Shilong Liu、Jiashuo Liu、Xu Kuang、Mengdi Wang。标注机构包括 Princeton University、InclusionAI、Harvard University 与 Stanford University；Jiashuo Liu 在这篇首页没有标注机构上标，因此不能依据前作替他补当前机构。[本论文首页，PDF p.1](https://arxiv.org/pdf/2609.36914v1#page=1)

Jiashuo Liu 是 FinSearchComp 的 Core Contributor。FinSearchComp v1 的贡献列表还说明，未明确标机构的贡献者来自 ByteDance Seed。因此可以确认它是**原作者参与的延伸合作**，不能称其为 FinSearchComp 原班团队的正式续作。[FinSearchComp §7，PDF p.16](https://arxiv.org/pdf/2509.13160v1#page=16)

**研究问题。** 数学题有相对清晰的答案验证，股票未来收益既有噪声，也无法从终局分数直接判断哪一次查询产生了价值。作者研究：能否把工具调查与最终数值预测作为一条完整策略，通过 SFT 和 PPO 后训练改善它？这篇研究的是**价量信息约束下的收益预测**，不是开放网页新闻检索、财报阅读或综合投资报告生成。[§1，PDF pp.2–3](https://arxiv.org/html/2609.36914v1#S1)

### 4.2 沙箱允许模型看到什么

**原文事实。** 环境覆盖 499 只美国股票，底层为经过拆股调整的正常交易时段一分钟行情，较粗 K 线与派生指标从中计算。模型在决策日收盘后行动，只能查询该日及以前的观察；反复调用是在查看同一历史状态的不同视角，而不是获得新的未来信息。[§2.1、表1，PDF pp.3–4](https://arxiv.org/html/2609.36914v1#S2.SS1)

九个检索工具和一个终止动作如下。[附录B、表6，PDF pp.15–16](https://arxiv.org/html/2609.36914v1#A2)

| 工具 | 返回的信息 |
|---|---|
| `get_kline` | 一分钟至一个月分辨率的 OHLCV |
| `get_quote` | 当日价格、VWAP、缺口、收益、量比、52 周价格区间 |
| `get_market_kline` | 市场或行业 K 线、市场宽度统计 |
| `get_indicator` | 可指定参数的技术指标序列 |
| `list_indicators` | 可用指标及默认参数 |
| `get_ranking` | 横截面指标排名及目标股票的位置 |
| `list_symbols` | 决策日之前已上市的股票集合 |
| `get_symbol_info` | 行业与首次上市日期 |
| `get_relative` | 相对收益、beta、相关性、残差收益 |
| `submit_prediction` | 提交目标期限的对数收益，结束 episode |

指标包括均线、RSI、MACD、ATR、OBV、VWAP、已实现波动率等 20 种。系统提示明确排除新闻和基本面。所谓“market context”在这里主要指市场/行业数值背景，不是新闻背景。[附录B，PDF pp.15–16](https://arxiv.org/pdf/2609.36914v1#page=15)

### 4.3 BETA 如何构建：两个必须保留的选择条件

#### 4.3.1 时间隔离

| 属性 | 训练 | 测试 |
|---|---:|---:|
| 任务数量 | 3,807 | 398 |
| 不同股票数量 | 489 | 224 |
| 决策日范围 | 2011-02 至 2023-12 | 2024-02 至 2026-03 |
| 最终评分任务 | 不适用 | 240 |

不仅训练决策日在测试之前，**最后一个训练标签的实现日 2023-12-29，也早于首个测试决策日 2024-02-01**。这避免长预测期限的训练标签越过测试开始日期。[§2.3、表2，PDF pp.4–5](https://arxiv.org/html/2609.36914v1#S2.SS3)

#### 4.3.2 按实际结果筛选任务

**原文事实。** AI 先使用决策时观察形成候选判断，再检查已实现结果，保留方向一致且满足 outcome-quality 条件的案例；这个过程用于训练和测试。训练 4,859 个候选保留 3,807 个，测试 607 个候选保留 398 个，并按股票、日期、期限去重，限制单股票覆盖。[§2.3、附录A，PDF pp.4、15](https://arxiv.org/html/2609.36914v1#A1)

作者明确称之为 **outcome-selected collection**，不是市场机会的随机样本。难度由构建者标注，评测模型看不到难度和构建理由。最终评分子集含 easy 65、medium 107、hard 68。[附录A，PDF p.15](https://arxiv.org/pdf/2609.36914v1#page=15)

**推导。** 时间隔离和选择偏差是两回事：前者防止工具或训练标签直接越过时间边界；后者会让测试分布偏向“事后证明某种事前判断成立”的案例。BETA 支持在这套选定分布内比较后训练的收益，尚不能回答从所有股票日期随机抽样时表现如何。

#### 4.3.3 再筛掉小幅实际变化

**原文事实。** 每个期限用测试标签计算总体标准差 `sigma_H`，只评分实际对数收益满足 `|y| >= 0.5 sigma_H` 的任务；398 个任务中剩 240 个。非有限预测或标签也由 scorer 排除。工具行为统计仍主要使用全部 398 个任务。[§2.2、附录A，PDF pp.4、15；表5，p.10](https://arxiv.org/html/2609.36914v1#S2.SS2)

**推导。** 评分进一步聚焦事后变化较大的案例。现实决策时无法预知某个股票日期是否会通过这个筛选。报告分数不是全部 398 个任务的准确率，也不是无条件金融预测准确率；失败预测是否被排除还需按模型核验，原文没有详列每模型缺失预测数量。

### 4.4 预测目标和评分

模型得到股票、决策日、交易日期限和当天 VWAP，提交：

$$
y = \log(\mathrm{VWAP}_{t+H}/\mathrm{VWAP}_t),\qquad H\in\{1,2,5,10,21,42,63,126\}.
$$

对数收益预测 `p` 对应价格 `VWAP_t exp(p)`。这不是涨跌分类，也不是收盘价预测。[§2.2，公式1，PDF pp.3–4](https://arxiv.org/html/2609.36914v1#S2.SS2)

单题奖励为：

$$
s(p,y)=\mathbb{1}[\operatorname{sign}(p)=\operatorname{sign}(y)]\frac{2\min(|p|,|y|)}{|p|+|y|+10^{-9}}.
$$

预测方向错或预测为零得零分；方向正确时，幅度越接近实际值分数越高。平均分 `S`、方向准确率 `D`、**仅在方向正确样本上**的幅度一致性 `M` 均用 0–100 标度，满足 `S = D M / 100`。`M` 不是概率校准指标。[§2.2 公式2–3、附录A，PDF pp.4、15](https://arxiv.org/html/2609.36914v1#A1)

**教学推导，非论文例题。** 若实际对数收益是 +0.04，预测 +0.02 或 +0.08，幅度部分均约 2/3；预测 -0.04 得零。可见它衡量相对幅度匹配，而非预测概率、绝对美元误差或投资组合收益。

### 4.5 训练方法：teacher 使用了历史答案

**原文事实。** 3,807 个训练任务产生 3,631 条可用示范。GPT-5.4 在 teacher-only context 里得到已实现训练收益及任务标注，再基于决策时数值信息生成多轮分析与工具轨迹。给学生的样本将 teacher context 替换为普通求解提示，保留分析和工具轨迹，最后的数值 target 改为真实收益。作者强调：这是**以结果为条件的示范**，不是 teacher 在不知道结果时独立做出的预测。[§3.1–3.2，PDF pp.6–7](https://arxiv.org/html/2609.36914v1#S3.SS2)

| 阶段 | 原文设置 |
|---|---|
| SFT | Qwen3-4B 全参数；2 epochs；学习率 1e-5；global batch 32；只对 assistant token 计算损失，包括分析、工具调用及预测；观察 token 仅提供上下文 |
| PPO | SFT 策略生成自身轨迹；终局奖励等于上述单题分数；KL 约束参考 SFT；不奖励多工具调用或长分析；50 iterations，每批 64 任务、每任务1条 sampled episode，约3,200 episodes；学习率1e-6，clip0.2，KL系数1e-3 |
| 计算 | SFT 和 PPO 都使用8张 H200；原文未给总 GPU-hours、训练成本和单题时延 |

来源：[§3.2–3.3，PDF p.7](https://arxiv.org/html/2609.36914v1#S3.SS3)。

**推导。** 已知答案的 teacher 可以生成便于解释正确结果的轨迹，但是否具有事前预测价值需要额外验证。不能把其解释自然地视为实际市场因果关系；也不能据此声称测试时学生看到了未来答案，论文的泄漏隔离规则与 teacher 的训练期答案监督应分开理解。

#### 4.6.4 较晚测试区间

### 4.7 模型到底学会了什么：证据与因果边界

方向准确率62.9→65.4，幅度一致性33.3→66.2；对称代数分解把约94%的总分增益归到幅度项。由于每个模型方向正确的样本集合不同，这不是在同一子集上识别出来的幅度能力因果贡献。[§5.1、图3、附录A，PDF pp.9、15](https://arxiv.org/html/2609.36914v1#S5.SS1)

| 行为 | Base | SFT | AURA |
|---|---:|---:|---:|
| 调用数中位数（含最终提交） | 5 | 18 | 16 |
| 不同检索工具数中位数 | 4 | 7 | 6 |
| 排名/市场行业查询占比 | 16.2% | 31.4% | 38.0% |
| 绝对预测中位数 | 0.0120 | 0.0312 | 0.0420 |
| 评分题中正预测比例 | 80.4% | 47.9% | 58.8% |

前四行主要用398题，最后一行用240题。占比对所有任务的调用混合计数，统计`get_ranking`和`get_market_kline`；distinct tools排除提交。[§5.2、表5，PDF pp.9–10](https://arxiv.org/html/2609.36914v1#S5.SS2)

SFT 扩大调查范围，PPO 调整查询组合，而非继续增加调用数。作者明确表示这些是描述性比较；要识别具体工具贡献，需要受控工具访问对比。论文未报告无工具/固定工具集消融，也没有隔离“更大输出幅度”与“更好调查”各自的贡献。

附录D提供一个特别重要的诊断：把gpt-5.6-sol所有预测乘以正数3.65，方向完全不变，分数能33.52→52.97。但系数是使用测试预测与实际标签事后拟合的，作者明示是**样本内oracle诊断**，不是独立训练出来的基线。[附录D，PDF pp.16–17](https://arxiv.org/html/2609.36914v1#A4)

**推导。** 该诊断说明分数对输出尺度敏感；不能把52.97当成可部署模型成绩。后续实验可以在独立验证集拟合尺度后锁定测试，并加入固定调查轨迹/工具组消融，帮助分离幅度适配与工具调查的实际收益。

### 4.8 交易与可复现性边界

**全文核验结果。** v1 报告收益点预测及工具轨迹，不报告交易执行、组合构建、资金曲线、换手率、手续费滑点、Sharpe、最大回撤或真实交易盈利。决策在当日收盘后，但预测收益的分母是当天日内VWAP；这个已发生的均价并不自动等于收盘后可实现的买入价格。因此不能直接把它转换成可交易收益。[§2.2、§4及附录B，PDF pp.3–4、7–9、16](https://arxiv.org/html/2609.36914v1#S2.SS2)

**可复现性。** 本次核验 arXiv v1 PDF、HTML、版本页，没有作者给出的 BETA 数据下载、AURA-4B checkpoint、训练代码或项目仓库链接。精确措辞应是“本次未找到作者公开链接”，不是断言作者永远不会公开。已有公开信息包括工具名、普通求解提示、训练主要超参数及聚合结果；未详列数据供应商、teacher完整提示、任务接受阶段 outcome-quality 检查的具体阈值、具体GBM/动量参数、推理采样设置、预算及失败处理、逐任务结果、种子重复，限制独立复现。另有同名 Aura-4B 模型，但其模型系谱不是Qwen3-4B，不能误作本论文发布物。

**工程建议，非论文实验结论。** 复用这套训练思路前，至少补做：（1）无需未来标签筛选的固定股票日期集合；（2）全398题与240题分开报告；（3）独立验证集数值尺度校准；（4）工具访问消融和时间预算；（5）种子重复、时间/股票聚类bootstrap；（6）下一个可交易时点执行价格、成本及组合回测；（7）未来发布后再收集的前向预测日志。它们用于检验本论文尚未建立的真实市场适用性。

## 5. 跨论文研究：我们真正学到了什么？

本节是本文的综合分析。三篇论文没有执行下述跨系统对照实验，也没有共同验证一套投研架构。

### 5.1 把金融 Agent 的目标拆成三个可以独立验收的对象

**事实对象**需要记录实体、字段、时间、单位、口径与来源。**预测对象**需要记录决策时点、可用信息、目标、期限、输出与事后结果。**工作簿对象**需要记录输入、公式依赖、输出、格式与修改后的行为。这三种对象的错误不能只用“回答不准确”统称。

FinSearchComp 已让我们看到“找到正确来源却抽错字段”的问题；FutureX 提醒我们，正确事实不会自动产生准确预测；MBABench 表明，正确答案也不会自动产生可维护的交付物；AURA 则表明训练收益可能集中于评分函数的一部分。工程上应分别保留错误证据，再判断需要改善取数、推断、训练还是交付。[FinSearchComp §4](https://arxiv.org/html/2509.13160v1#S4) · [FutureX-Pro §2](https://arxiv.org/html/2601.12259v1#S2) · [MBABench §3](https://arxiv.org/html/2605.22664v5#S3) · [AURA §5](https://arxiv.org/html/2609.36914v1#S5)

### 5.2 评分函数会改变“表现好”的含义

下面的数字是**本文构造的教学示例，非论文实验或真实行情**。

假设当前价格为 100，未来价格为 101。始终预测“未来仍为 100”的策略，在 FutureX-Finance 的价格相对误差规则下得到：

$$
S=\max\left(0,1-20\frac{|100-101|}{101}\right)\approx0.802.
$$

这说明，即使没有预测出涨幅，也可能获得较高的价格级别匹配分。它不证明 FutureX 的实际模型只在机械延续价格，而是解释为什么“有严格容差”仍需配套朴素基线。是否击败该基线，要在同一实际题集上检验。

若换成 AURA 的收益评分，预测零收益直接得 0 分；若实际对数收益为 0.01、预测为 0.03，方向正确，但幅度项约为：

$$
\frac{2\min(0.01,0.03)}{0.01+0.03}=0.5.
$$

同样一个策略，在不同目标和损失下可能得到完全不同的评价。另一方面，AURA 排除了不少小幅变动题，并按实际结果筛选任务，不能据此说它比 FutureX 更公平。两者是在不同分布上测不同能力。公式依据：[FutureX-Pro §2.2](https://arxiv.org/html/2601.12259v1#S2.SS2)、[AURA §2.2、附录 A](https://arxiv.org/html/2609.36914v1#S2.SS2)。

### 5.3 “没有未来工具数据”不等于排除了所有信息泄漏

本文建议区分三层检查：

| 层次 | 要检查什么 | 对三篇研究的含义 |
|---|---|---|
| 工具层 | 查询是否严格截断在决策时点；后续修订、复权和派生特征是否使用未来信息 | AURA 明确限制沙箱观察时点；具体数据处理仍需源码和数据验证 |
| 参数层 | 模型训练语料是否可能包含历史测试事件 | 实时 FutureX 减少未知结果提前进入参数的风险；历史沙箱限制不自动清除模型记忆 |
| 构建层 | 出题、筛选、标签阈值、调参是否依赖测试结果 | AURA 明示 outcome-selected；测试集缩放只能作诊断；MBABench 来源公开时也需考虑参考解记忆 |

这是研究设计检查框架，不是指控某篇存在已证实的数据泄漏。实时预测的优势是答案在预测时尚未实现；但仍需要预测提交时间、标签产生时间和可访问来源等审计记录，才能把设计主张转化为可复查的运行证据。

### 5.4 同一模型的行为变化与因果解释要分开

AURA 的 Base→SFT→PPO 比较是三篇中最直接的同一骨干训练证据；它支持“在该环境和题集上，训练带来了成绩增量”。但工具调用多样性、查询构成和成绩一起变化，不足以单独证明“更多查询造成了提升”。MBABench 中同模型使用不同 harness 的结果支持编排值得研究，但产品配置和预算并非总能完全控制。FutureX 的产品成绩主要是端到端观察，没有把检索与预测策略逐项隔离。[AURA §3—5](https://arxiv.org/html/2609.36914v1#S3) · [MBABench §4、§6、附录 C—D](https://arxiv.org/html/2605.22664v5#S4) · [FutureX-Pro §2.3](https://arxiv.org/html/2601.12259v1#S2.SS3)

对于实际投研系统，不能由这三篇直接得到“优先训练”或“优先改工具”的无条件结论。应先用本地失败任务定位错误，再做单变量实验。

## 6. 面向金融投研工程的实验建议

以下是**本文提出的工程实验，尚未执行**。目的在于把论文启发转化为可检验问题，避免只照搬排行榜或构建一个无法诊断的完整系统。

### 6.1 实验一：信息获取是否仍是主要瓶颈？

固定任务、模型、时间截止点与预算，对比正常取数和人工核验后的证据注入。注入应包含明确字段与口径，不提前给最终判断。分别记录取数正确率、信息覆盖、计算正确率、推断质量与总成本。

若正确证据注入大幅改善结果，优先改善数据源、解析与字段核验；若证据已经正确仍然失败，再检查计算依赖、条件核验或模型行为。这个实验延续 FinSearchComp 对信息获取的诊断意义，但不是上述三篇已共同做过的实验。

### 6.2 实验二：预测是否优于简单基线？

固定决策时点和预测期限，在未经结果筛选的时间滚动样本上比较：价格不变、历史中位数、动量规则、现有量化模型、通用 LLM、领域后训练 LLM。价格预测和收益预测分开评价。

至少报告每个期限的误差、方向、幅度、样本数，以及按股票和时间分组的不确定性。如果要评价经济价值，另外定义持仓、换手、交易费用、滑点、风险暴露及可执行约束；预测评分不能代替这些项目。

AURA 的优势是提供了多种量化参考；FutureX 的开放问题是缺少相应金融基线。两个实验体系值得结合，但不能直接把它们已有分数拼成对照。

### 6.3 实验三：训练收益来自策略，还是输出尺度？

比较 Base、仅在独立验证集校准输出尺度的 Base、SFT、SFT+PPO。校准参数只在训练/验证期拟合，再固定到测试期；禁止使用测试标签挑系数。对每个检查点做等工具预算、等最大步数比较，并加入单类工具禁用或固定证据实验。

这个设计同时回答两个问题：AURA 所提示的幅度改善能否通过更低成本校准获得；工具策略的改变是否真正提供了额外信息。它比“调用次数变多，所以研究更深入”更容易检验。

### 6.4 实验四：交付物是否经得住修改？

借鉴 MBABench 的三个维度，增加确定性的变更测试：改变增长率或融资成本，检查所有关联输出是否重算；扩大时间范围，检查公式是否自动覆盖；制造零分母或缺失输入，检查是否返回正确的业务状态；检查关键平衡关系与来源可追溯性。

采用“程序核验 + 语义裁判 + 专家抽查”的组合。裁判要给出具体工作表和单元格位置；程序核验负责可确定的公式执行与依赖检查；专家处理有合理多解的建模选择。该组合是本文建议，不能称为 MBABench 已验证的完整生产方案。

### 6.5 建议保留的最小研究记录

| 记录 | 至少包含 |
|---|---|
| 任务定义 | 对象、目标、期间、单位、截止时点、允许来源、验收标准 |
| 证据记录 | 原始值、字段、来源、来源版本、可获得时间、抽取位置 |
| 计算记录 | 输入身份、公式、单位转换、执行结果、异常与复算状态 |
| 预测记录 | 决策时点、目标期限、允许信息、提交值、标签时点与评分 |
| 工作簿记录 | 输入与假设区域、公式依赖、输出、变更测试、裁判定位 |
| 实验记录 | 模型版本、harness、工具、预算、随机种子、题集、评分器版本 |

这套记录可以把事实、计算、预测和交付质量的责任分开，也便于复查论文结果与本地实验之间的差异。它是本文提出的实现约定，不是三篇共享的协议。

## 7. 阅读顺序与尚未解决的问题

如果目标是建设研究员助手，先读 **MBABench §2—6 与附录 A**，把“什么算可用交付物”定义清楚；再读 **FutureX-Pro §2 和 §6**，区分检索与预测；最后读 **AURA §2—5、附录 A、D、E**，考察可学习的行为与训练数据边界。这个顺序是本文的学习建议。

仍需后续实验回答的问题包括：

1. 对未经结果筛选的新市场样本，AURA 的幅度提升是否保持？
2. 校准输出尺度后，SFT/PPO 还增加多少收益，是否值得训练成本？
3. 在相同预算与数据源下，改工具、改 harness 和改参数各贡献多少？
4. MBABench 裁判能否稳定接受不同但合理的建模结构，能否检查修改后的行为？
5. 开放金融检索、价量预测与专业工作簿构建组合后，是否真正减少研究员返工？

三篇论文分别提供了研究对象、评价标准和训练证据，还没有提供一套已验证的端到端金融投研解决方案。
