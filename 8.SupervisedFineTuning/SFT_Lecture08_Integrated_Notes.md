## 1. SFT 在 Agent 系统里负责什么？

### 1.1 三种改进位置，不是三个互相替代的产品

讲义第 4 页比较了上下文、外部材料与模型权重。可以把它们理解为三种不同的经验存放位置。[S00，第 4 页](#src-s00)

| 改进位置 | 实际操作 | 优势 | 代价与限制 |
|---|---|---|---|
| 当前上下文 | 加规则、示例、历史过程 | 修改快，具体信息直接可见 | 每次需要读取，占用上下文，噪声也会进入 |
| 外部 Skills、Memory、知识材料 | 整理成可加载、可检索的经验 | 可检查、可修改、可迁移 | 需要组织、检索、选择和维护 |
| 模型权重 | 用训练改变条件输出分布 | 后续调用可以直接体现行为变化 | 更新慢，难以检查，绑定具体模型 |

**教学示例。** 希望 Coding Agent 修改代码后运行测试，有三种做法：在提示词中要求验证；提供一个包含验证流程的 Skill；使用“修改—测试—修复—再测试”的高质量轨迹做 SFT。前两种是在运行时提供依据，第三种是在改变模型更容易采取的行为。

**工程建议：把行为习惯交给模型，把硬性约束交给程序。** 可以训练模型主动测试，但“测试失败不得自动合并”应该由执行系统保证。SFT 改变概率，不等于建立不可绕过的权限或验收机制。

### 1.2 “SFT 只学格式”是一种过度简化

讲义第 5 页列出的学习内容包括：生成当前 harness 能执行的工具调用；在长对话中继续推进；等待真实工具反馈，而不是自己写出工具结果。与此同时，示范中的冗余解释、重复命令和单一解题习惯也可能被学进去。[S00，第 5 页](#src-s00)

因此，不宜把 SFT 理解为“只能学输出格式，不能改变其他能力”。它更新参数，学习到什么取决于起始模型、示范内容、监督目标和优化过程。相反，也不能把“可以学习”理解为“适合把所有事实写进权重”。

**工程建议。** 对变化频繁、必须精确核验的事实，保留外部数据源；对稳定、重复、可以通过示范学习的工作方式，考虑 SFT。例如，与其让模型背诵某张报表中的数字，不如训练它在比较指标前核对区间，在缺少依据时重新读取文件，在证据不足时停止补写。

这是职责划分建议，不是“SFT 不能学知识”的理论结论。

### 1.3 SFT、蒸馏、LoRA、RL 分别在描述什么？

| 概念 | 描述的维度 | 不应混淆的地方 |
|---|---|---|
| SFT | 用示范目标进行监督优化 | 不等于某一种参数更新方式 |
| 蒸馏 | 行为或知识由教师传给学生 | 可以通过 SFT 完成，也可以采用其他目标 |
| LoRA | 以低秩增量参数化权重更新 | 可以用来做 SFT；不是 SFT 的同义词 |
| RL | 根据策略执行后的反馈改进策略 | 不只存在一种奖励形式，也不一定必须先做 SFT |

R1 报告中的小模型蒸馏，就是使用约 80 万条生成数据进行 SFT，学生没有再进行额外 RL。这是“蒸馏通过 SFT 实现”的具体例子。[S02，附录 F，第 60–61 页](#src-s02)

LLaMA-Factory 也将 SFT、偏好训练等目标，与 full-tuning、freeze-tuning、LoRA、QLoRA 等更新方式分开列出。[S19，Features](#src-s19)

## 2. 从轨迹到条件行为策略：模型真正学的是什么？

### 2.1 长推理文本，不等于长程环境交互

把 DeepSeek-R1 与 SWE-Gym 并排看，会发现“轨迹”这个词包含两类不同对象。

R1 所提供版本的 Table 5 统计了约 **804,745 条样本，平均约 1.0 轮、5,355.3 个 token**。作者明确指出，大多数样本是单轮交互，这可能限制多轮对话能力。[S02，附录 B.3.3，第 27 页](#src-s02)

SWE-Gym 用于 OpenHands 训练的 **491 条成功轨迹，平均约 19 轮、19,000 个 token**，其中有真实命令、文件编辑和环境观察。[S08，§4.2，第 5 页](#src-s08)

```text
长推理文本：问题 → 推理文本 → 答案

交互轨迹：问题 → 动作 → 环境反馈 → 新动作 → 新反馈 → 最终交付
```

模型在第一类任务里主要继续生成自己的文本；在第二类任务里还必须响应一个不受自己控制的外部结果。它预期编辑成功，工具却返回“没有找到目标字符串”，下一步就必须改变，而不是沿原计划写总结。

**解释。** 长思维链扩展了内部计算的表达空间；交互轨迹还要训练模型接受外部证据、更新判断和调整行动。二者相关，但不能互相替代。

### 2.2 Harness 是学习条件的一部分

这里把 **harness** 译为 Agent 运行框架：包括 system prompt、工具定义、调用解析器、执行环境、上下文管理和停止规则。SWE-Gym 用 scaffold 描述相关的工具与提示策略，并比较 OpenHands 与 MoatlessTools 两种工作方式。[S08，§4.1，第 5 页](#src-s08)

同一个“编辑文件”动作，在一个系统里可能是替换整个文件，在另一个系统里则要求提供旧字符串进行精确替换。模型不仅需要理解目的，还要知道当前系统允许怎样执行。

因此，不能仅用“模型知道如何修复代码”解释一切。还要问：它是否会使用当前工具，是否能根据当前观察格式做判断，是否能在当前上下文策略下保留必要信息？

### 2.3 用策略表示“当前应该做什么”

将第 $k$ 步前的可见历史记为 $h_k$，下一步动作记为 $a_k$，模型策略记为：

$$
\pi_\theta(a_k\mid h_k)
$$

动作可以是执行命令、读取文件、提出澄清问题、输出结论或结束任务。这是对讲义轨迹训练的数学解释。

一条完整轨迹提供了多个条件决策：

```text
看到任务描述 → 检查相关文件
看到测试失败 → 定位原因
看到编辑失败 → 重新读取当前文件
看到局部测试通过 → 判断是否需要回归测试
看到验收完成 → 给出有依据的总结并结束
```

### 2.4 动作拆成 token，就得到 SFT 目标

轨迹经过 chat template 和 tokenizer 后变成序列 $x_{i,1:T_i}$。在讲义的 assistant-only 配方中，对选定的 assistant token 计算负对数似然。将讲义的求和形式写成有效目标 token 平均形式：

$$
\mathcal L_{\mathrm{SFT}}
=
-\frac{\sum_i\sum_{t=2}^{T_i}m_{i,t}\log p_\theta(x_{i,t}\mid x_{i,<t})}
{\sum_i\sum_{t=2}^{T_i}m_{i,t}}
$$

其中 $m_{i,t}\in\{0,1\}$ 是监督开关。$m=1$ 表示该 token 是预测目标；$m=0$ 表示不计算该位置的直接预测损失。分母必须非零。[S00，第 11–13 页](#src-s00)

直白地说，每个被监督的位置都在问：“看到前面的内容后，老师写下这个 token 的概率应该有多高？”

**关键边界：提高示范行为的概率，不等于直接最大化任务成功率。** 如果成功轨迹中有十次无效搜索，且这些搜索都被监督，普通 SFT 就会给它们模仿信号。结果标签不会自动替你完成过程级信用分配。

### 2.5 Teacher forcing 不等于偷看未来

训练时，模型根据记录好的前缀预测后续 token。因果注意力仍然限制它不能看到未来答案；问题在于，前缀始终来自记录，而不是模型自由执行后产生的新历史。

这让训练可以在固定轨迹上组织计算，但也带来后文要讨论的分布错配：学生一旦选择不同动作，就可能遇到训练数据里没有的观察。[S00，第 42 页](#src-s00)

## 3. Mask、推理与停止行为：监督范围就是行为设计

### 3.1 Loss mask 与 attention mask 是两件事

| 轨迹部分 | 是否作为有效输入被看到 | assistant-only 基线是否计算直接 loss |
|---|---:|---:|
| system 指令 | 是 | 否 |
| user 请求 | 是 | 否 |
| 工具返回内容 | 是 | 否 |
| assistant 工具调用 | 是 | 是 |
| assistant 的目标回答 | 是 | 是 |
| 应由模型生成的结束标记 | 是 | 是 |
| padding | 不应作为有效内容参与 | 否 |

讲义明确将工具观察定义为条件上下文，而不是默认的预测目标。[S00，第 12 页](#src-s00)

**实现解释。** 常见做法是保留完整 `input_ids`，将不参与监督的位置在 `labels` 中设为 `-100`。不能为了“不训练工具返回”，就把工具返回的 attention mask 也置零，否则模型连决定下一步所需的信息都看不到了。

“没有直接预测损失”也不等于“完全没有学习信号”。后续 assistant 输出仍然依赖前面的工具观察，相关梯度可以影响模型如何表示和利用这些输入。

### 3.2 标签位移：只做一次

因果语言模型用当前位置输出预测下一个 token。概念上是：

```python
logits[:, :-1]  # 预测下一 token 的分布
labels[:, 1:]   # 对应的目标 token
```

**工程建议。** 先确认你调用的模型或训练框架是否已经处理位移。使用内置 causal language modeling loss 时，不要再不加检查地手动移一次。训练曲线能下降，并不意味着标签语义正确。

### 3.3 “只训练 assistant”不等于“只训练最后一轮”

如果前面十九轮包含搜索、编辑、验证，最后一轮只是“已完成”，只监督最后一轮主要是在学习如何根据给定历史写结束说明，而不是如何产生前面的工作过程。

讲义附录明确区分：TRL 的 `assistant_only_loss=True` 用于选择 assistant 内容；LLaMA-Factory 的 `mask_history: true` 对应只训练最后一轮。两者不是同一个开关。[S00，第 49 页](#src-s00)

但最后一轮监督也可能是有意的数据设计。Nemotron 的多轮聊天数据会让早期 assistant 回答包含非最佳候选，只训练最后一个高质量回答，以提高面对不完美历史时的当前轮质量。[S03，§3.1.1，Chat，第 18 页](#src-s03)

**先确定前面的回答是否值得模仿，再决定 mask。不要反过来让框架默认值决定数据语义。**

### 3.4 停止 token 不是装饰，而是控制行为

讲义第 15 页强调：在它展示的模板中，assistant 角色头由推理端提供，而模型自己生成的结束标记必须放进监督范围。[S00，第 15 页](#src-s00)

需要区分三种事件：结束当前消息、把控制权交给工具、结束整个任务。不同模型可能通过通道、消息结构和特殊标记共同表达这些语义，不应假定所有模板都使用同样的三个 token。

特别是，Kimi K3 附录 F 描述的是 `think`、`response`、`tools` 等通道，以及 `[end_of_msg]` 停止标记。讲义对控制事件的教学概括，不应被扩写为“K3 定义了三个不同的停止 token”。[S01，附录 F，第 46–47 页](#src-s01)

**工程建议。** 模型不停止、调用工具后自己编结果、明明做完却继续输出时，先检查结束标记的渲染、监督、解析与生成停止配置。角色头是否需要被监督，也应依据推理端实际提供的前缀，而不是套用“永远不训练 header”的口号。

### 3.5 推理是否保留，与是否监督，是两个独立开关

讲义第 16 页区分：推理可以留在上下文中，却不计算直接 loss；也可以既作为输入，又要求模型模仿生成。[S00，第 16 页](#src-s00)

| 设计 | 模型学什么 | 主要风险 |
|---|---|---|
| 保留并监督推理 | 生成推理及其后的动作 | 冗余推理可能占据大量监督信号 |
| 保留但不监督推理 | 给定推理后产生动作 | 部署时可能缺少教师提供的额外信息 |
| 删除推理后监督动作 | 更直接的状态到动作映射 | 删除后可能失去解释动作所必需的信息 |

**推导。** 将教师推理 mask 掉，不能消除学生对它的依赖。训练时如果关键参数只在教师推理中出现，部署时却没有这段内容，模型仍然面对输入条件变化。Mask 控制“直接学什么”，不控制“依赖了什么”。

### 3.6 Nemotron 的截断推理：不要把预算结束教成自然结束

Nemotron 为推理预算控制构造了一部分样本：推理在随机预算处截断，最终回答保持不变，并将人工截断处的 `</think>` 从 SFT loss 中排除。[S03，§3.1.1，第 16 页](#src-s03)

这里排除的是人工结束标记，不是整段推理。可以将其目的理解为：不要让模型直接把“系统预算用尽”模仿成“此时已经自然完成思考”。这是对设计的解释，不是仅凭这个规则就能保证模型学会最优预算分配。

**本章小结：监督范围既决定模仿哪些行为，也可能决定模型如何交接控制权、面对不完美历史以及使用中间推理。**

## 4. IM、WIT 与 BalanceSFT 联读：谁在分配训练信号？

这三篇论文不是相同方法的不同名字。IM 改变输入与输出的监督范围；WIT 改变两者的相对权重；BalanceSFT 进一步改变 assistant 内部推理与动作的权重，并调整困难数据。

### 4.1 Instruction Modelling：把输入建模作为辅助目标

常规 instruction tuning 主要优化：

$$
\mathcal L_{\mathrm{IT}}=-\log p_\theta(C\mid I)
$$

$I$ 是 instruction，$C$ 是 completion。IM 对两部分都计算损失，但排除固定 prompt template token。忽略模板细节，可解释为：

$$
\mathcal L_{\mathrm{IM}}
=-\log p_\theta(I)-\log p_\theta(C\mid I)
$$

它没有放弃回答监督，而是在回答目标旁加入输入语言建模目标。[S11，§3，第 4 页](#src-s11)

为什么这可能有帮助？论文发现，收益与两个条件关系较强：训练样本较少；输入很长而回答较短。作者提出的解释是，额外的语言建模信号能够缓解对少量输出模式的过拟合。[S11，§4.2，第 6 页](#src-s11)

#### 关键实验：更低训练 loss 不一定更好

IM 第 7 页 Figure 3 对比以下结果。为保持可比，两个模型在这些测量中都只计算回答部分的 loss。

| 测量对象 | 常规 IT | IM |
|---|---:|---:|
| LIMA 训练样本上的回答 loss | 1.37 | 1.45 |
| Tulu 新样本上的回答 loss | 1.32 | 1.17 |

IM 对训练数据拟合稍弱，却在新数据上更好。作者将其作为缓解过拟合的证据。[S11，§4.3、Figure 3，第 6–7 页](#src-s11)

**工程含义。** 如果训练集越来越好，独立任务越来越差，问题可能不是训练不够，而是监督过度集中在有限的输出形式上。监控训练 loss 不能代替验证集或任务评测。

**适用边界。** IM 作者并未将方法定位为替代所有 instruction tuning 的统一默认方案。长工具日志、网页噪声和多轮 Agent 的数据结构，与论文重点验证的小样本指令任务不同。不能从该结果直接推出“所有工具观察都应该计算 loss”。

### 4.2 WIT：输入与回答不必只能选 0 或 1

WIT 将 prompt、response 分别赋予权重 $\lambda_p,\lambda_r$。设 $S_p,S_r$ 为两部分负对数似然之和，$N_p,N_r$ 为 token 数，可将其公式简写为：

$$
\mathcal L_{\mathrm{WIT}}
=
\frac{\lambda_p S_p+\lambda_r S_r}
{\mathbf1(\lambda_p\ne0)N_p+\mathbf1(\lambda_r\ne0)N_r}
$$

**分母是非零权重 token 的数量，不是 token 权重之和。** 当 $(\lambda_p,\lambda_r)=(0,1)$ 时，回到常规的回答监督目标。[S12，§2，第 3 页](#src-s12)

WIT 在不同模型、数据集和权重配置下进行了 525 次 SFT 实验，并继续进行了 525 次 DPO 实验，用于研究收益是否能传递到后续偏好训练。[S12，第 2–3 页](#src-s12)

最值得学习的结论不是某个固定权重，而是：**不同下游行为可能偏好不同的监督分配。** 论文汇总中，IFEval 对应的平均最优回答权重约为 0.43，AlpacaEval 约为 0.64；最佳值随模型、训练集与评测任务变化。[S12，§4.1、Table 2，第 6 页](#src-s12)

这提示，严格遵守指令约束与生成丰富流畅的回答，未必对应同一个最优训练配置。但这些数值是实验统计，不是可以直接复制到任意 Agent 的推荐值。

#### 从 WIT 公式推导：监督组成与尺度同时改变

**教学示例。** 一条样本包含 1,000 个 prompt token、100 个 response token。只训练 response 时，分母是 100；当 prompt 权重从 0 改为很小的正数，分母变成 1,100。

因此，这次修改既加入了输入监督，也改变了回答项的绝对尺度。将公式替换成除以 $\sum_t w_t$ 的另一种 weighted loss，并不属于原样复现。

**工程建议。** 同时记录 loss 的分段组成、归一化方式和梯度统计。不能把性能变化全部归因于“模型更加重视输入”。损失整体缩放对优化的影响还与优化器、裁剪、数值精度等有关，也不宜简单等同于线性改变学习率。

### 4.3 BalanceSFT：长解释可能遮住短动作

BalanceSFT 分析的一组函数调用数据中，推理段平均 **350.74 个 token**，函数调用平均 **31.07 个 token**。[S10，§3.2、Table 1，第 3 页](#src-s10)

为了直观说明，以下用标准 token 交叉熵的分段均值表示普通 SFT：

$$
\mathcal L_{\mathrm{SFT}}
=
\frac{N_t}{N_t+N_f}\mathcal L_{\mathrm{think}}
+
\frac{N_f}{N_t+N_f}\mathcal L_{\mathrm{call}}
$$

$N_t$ 是推理 token 数，$N_f$ 是调用 token 数。长推理天然获得更多损失项权重，但真正决定工具能否正确执行的，可能只是一个函数名、路径或数值参数。

**注意：损失项数量占比，不等于实际梯度影响占比。** 不同 token 的误差、梯度和参数路径不同。不能说“九成推理 token 就消耗了九成学习能力”。

SSB 将两段分别归一化，再使用可学习系数组合：

$$
\mathcal L_{\mathrm{SSB}}
=
\alpha\mathcal L_{\mathrm{think}}
+(1-\alpha)\mathcal L_{\mathrm{call}},\qquad \alpha\in[0,1]
$$

它不取消推理，而是不让文本长度完全决定两类监督的相对地位。[S10，§3.2，第 3 页](#src-s10)

#### 消融实验：loss 与数据各自贡献多少？

| Qwen2.5-Coder-7B-Instruct 的训练设置 | 单轮函数调用准确率 | 多轮函数调用准确率 |
|---|---:|---:|
| 普通 SFT | 81.73% | 38.25% |
| 加入 SSB | 82.20% | 41.62% |
| 加入 HDR 困难数据重采样 | 83.85% | 43.12% |
| SSB 与 HDR 同时使用 | 84.00% | 47.00% |

这些结果来自同一篇论文的组件比较。38.25% 到 47.00% 是 **8.75 个百分点**，并非全由 SSB 产生；HDR 有独立贡献。[S10，Table 5，第 7 页](#src-s10)

#### 可学习权重不等于自动获得任务级信用分配

**公式推导。** 固定模型参数时：

$$
\frac{\partial\mathcal L}{\partial\alpha}
=
\mathcal L_{\mathrm{think}}-\mathcal L_{\mathrm{call}}
$$

这个导数没有直接包含任务成功率。因此，SSB 是在特定实验中有效的监督设计，不是“只要让权重可学习，就自动得到业务最优平衡”的定理。实现时还需核对系数约束与实际训练方式。

### 4.4 三篇论文的统一框架

| 方法 | 修改位置 | 主要证据 | 不支持直接推出的结论 |
|---|---|---|---|
| IM | 指令与回答的监督范围 | 小数据、长输入短输出下的泛化改善 | 所有 Agent 应对所有观察计算 loss |
| WIT | prompt 与 response 的权重 | 不同任务偏好不同配置，收益可影响后续 DPO | 存在跨模型、跨任务统一最优权重 |
| BalanceSFT | 推理与调用的分段权重；困难数据 | SSB 与 HDR 均有增益 | 所有提升都来自 loss；更长推理一定有害 |

讲义第 19 页把 Agent 场景的 mask 实验作为值得研究的问题。这应理解为讲义的研究观察，而不是未经全面检索就断言整个领域不存在相关研究。对于本课提供的 IM/WIT 证据，确实不能自动外推到所有长轨迹 Agent。[S00，第 19 页](#src-s00)

**实践顺序：先建立语义正确的 assistant-only 基线，再针对明确瓶颈改变某一个监督维度。** 同时改变 prompt loss、推理权重、困难数据和训练预算，会让结果难以解释。

## 5. 数据生产：先有可验证环境，再谈高质量轨迹

### 5.1 SWE-Gym：最终 patch 不是完整的 Agent 训练数据

SWE-Gym 包含 **2,438 个任务、11 个 Python 仓库**，为任务提供执行环境与测试；这些仓库与 SWE-Bench 的仓库分开。其 Lite 子集有 230 个任务，Raw 集合则包含更广泛但未配齐执行环境的问题。[S08，§3，第 3 页](#src-s08)

只有问题与最终 patch，你知道“结果是什么”，却不知道“Agent 如何从初始状态得到结果”。要产生交互监督，还需要初始代码版本、依赖、工具调用、真实观察和可复现验收。

```text
任务规范 + 环境初始状态
          ↓
教师或学生执行动作
          ↓
环境产生真实观察
          ↓
继续行动与验证
          ↓
验收结果 + 完整轨迹
```

**工程解释。** Agent 的环境不仅是测试设施，也是数据生产设施。没有可信的状态转移，“测试通过”可能只是模型写出来的一句话。

### 5.2 少量高质量轨迹可以有效，但不存在通用最低条数

SWE-Gym 的 491 条成功轨迹，将其 32B Qwen2.5-Coder-Instruct 在 OpenHands 设置下的 SWE-Bench Verified 解决率从 **7.0% 提高到 20.6%**，Lite 从 **3.0% 提高到 15.3%**。[S08，§4.2、Table 3，第 5–6 页](#src-s08)

该结果说明，当基础模型已有相关能力、轨迹覆盖目标工作方式时，有限数据也可能产生明显收益。它不意味着“所有 Agent 都只需约 500 条数据”。一条 19 轮的真实轨迹，也不是一条简短问答。

### 5.3 Kimi K2：从工具规格开始构造数据

Kimi K2 的合成管线有三个阶段：工具规格生成、Agent 与任务生成、交互轨迹生成。真实环境难以大规模建立，因此它结合真实工具与合成工具。[S06，§3.1.1，第 9 页](#src-s06)

其工具库包含 3,000 多个真实 MCP 工具和 20,000 多个合成工具规格。随后通过不同 system prompt、工具组合形成 Agent 配置，为每个配置生成任务与 rubric。Rubric 包括成功条件、预期工具使用模式和检查点。[S06，第 10 页](#src-s06)

```text
领域与工具规格
→ Agent 配置
→ 任务及验收标准
→ 用户模拟 + 有状态工具模拟
→ 多轮轨迹
→ 质量判定与筛选
→ SFT
```

工具模拟器维护状态，并引入部分失败和边界情况；针对代码与软件工程等需要高真实性的任务，再加入真实执行沙箱与测试。[S06，第 11 页](#src-s06)

**工程建议：用模拟扩大覆盖，用真实执行校验关键语义。** 可以模拟工具组合、不同用户表达与错误类型，但能由代码检查的计算、文件修改和测试结果，尽量实际检查。模拟器自己声称“成功”，不是独立证据。

### 5.4 OpenThoughts-Agent：用学生的收益评价数据工厂

OpenThoughts-Agent 不仅提出一套数据管线，还做了上百次消融，研究任务来源、混合、增强、任务过滤、教师和轨迹过滤。小规模实验使用约 10,000 条轨迹、Qwen3-8B 全参数 SFT、32,768 上下文、7 个 epoch、全局 batch 96、余弦学习率；一次包含上述 7 个 epoch 的完整 10k 轨迹微调实验，约消耗 160 GH200 GPU-hours。[S07，§3，第 4 页](#src-s07)

这些数字是论文实验设置，不是小团队的默认配方。值得复用的是研究方法：**在相对可控的规模上比较数据策略，固定多数变量，再将有效选择扩展到更大训练。**

它使用三个核心 benchmark 的阶段内标准化成绩综合排名，并将其他任务保留到数据管线选择结束后评测。这比只追逐某一个 benchmark 更能检查泛化。[S07，第 4–5 页](#src-s07)

### 5.5 最强教师不一定是最好的老师

OpenThoughts-Agent 的教师消融如下。这里记录的是**使用相应教师轨迹训练后的学生表现**，不是教师自身得分。

| 教师 | 学生在 SWE-bench Verified-100 | 学生在 OT-TBLite | 学生在 Terminal-Bench 2.0 |
|---|---:|---:|---:|
| GLM 4.7（量化） | 28.00% | 17.86% | 8.61% |
| Kimi K2.5 | 33.33% | 14.19% | 8.24% |
| GLM 5 | 33.00% | 14.30% | 7.50% |
| GPT-5.3-Codex | 21.67% | 10.42% | 3.75% |

论文将 GPT-5.3-Codex 描述为比较对象中自身 benchmark 能力最强的模型，但在该蒸馏设置中并未产生最强学生。[S07，Table 6，第 7 页](#src-s07)

这不矛盾。教师评测问“它自己能不能完成任务”；蒸馏评测问“它留下的示范能不能让这个学生学会”。可能涉及策略复杂度、解释充分性、学生能力匹配和任务覆盖，但该表没有逐一证明这些机制。

**工程建议。** 在相同任务与相近生成预算下，用候选教师各生成一小批数据，训练相同学生后比较。教师排行榜可以用于初筛，学生收益才是数据选择的最终依据。

### 5.6 不要把“更复杂的任务描述”自动当作更好的数据

OpenThoughts-Agent 比较加约束、提高难度、合并任务、加入提示等增强策略。在其小规模消融中，没有一种可靠优于不增强的原始描述；但在更大规模且原始表达覆盖不足时，特定描述改写又产生收益。两组实验对应不同问题，不能选其中一组宣称“增强一定有效”或“一定没用”。[S07，§3.3、Table 4、第 6 页；§4、第 8 页](#src-s07)

BalanceSFT 的自然 CoT 与规定策略 CoT 比较也应谨慎解读：两组生成方式涉及不同教师，不能把差异完全归因于“自然推理风格”。[S10，§4.2，第 5 页](#src-s10)

## 6. 轨迹筛选、恢复数据与多样性：成功不代表全部值得学

### 6.1 拒绝采样会改变任务分布

**推导。** 设原始任务分布为 $q(x)$，教师通过验收的概率为 $p_{\mathrm{pass}}(x)$。如果每个任务采样相同次数、只保留成功轨迹，那么保留数据中的任务分布近似为：

$$
q_{\mathrm{kept}}(x)
\propto q(x)\,p_{\mathrm{pass}}(x)
$$

教学例子：两类任务原本各占一半，成功率分别为 90% 和 10%。过滤后，成功样本大约变成 9∶1。数据都成功了，但任务覆盖已经偏向容易部分。

SWE-Gym 在受约束工作流的迭代训练中观察到这种容易任务偏置，并用每任务保留上限控制。在它的实验中，上限 2 是较好的折中。[S08，§4.3，第 6 页](#src-s08)

**工程建议。** 同时记录独立任务数、每任务轨迹数和各难度桶的保留率。只有“成功样本总数”，无法说明数据覆盖是否改善。

### 6.2 Nemotron：成功轨迹仍然需要过程检查

Nemotron 对软件工程轨迹检查有效提交、无收敛的编辑—测试循环、长期探索但少有修改、畸形工具调用、最终 patch 的调试残留，以及修改后从未测试等问题。它还按自己的任务设置过滤部分 git 操作。[S03，§3.1.1，第 17 页](#src-s03)

这些不是所有项目通用的禁令。例如，某些真实任务本来就需要合法的远程仓库操作。应当复用“按任务语义检查过程”的方法，而不是不加区分地复制整张过滤列表。

### 6.3 失败观察、错误动作与无效循环不能混为一谈

| 轨迹片段 | 含义 | 建议处理 |
|---|---|---|
| 运行复现测试，得到失败结果 | 有效诊断 | 通常保留该动作与观察 |
| 误改文件，检查后发现问题并纠正 | 有价值的恢复状态 | 保留因果历史，重点监督有效恢复 |
| 重复同一命令且没有新增信息 | 无效循环 | 考虑过滤或重新生成 |
| 看似成功，但修改后没有验收 | 缺乏可靠结果证据 | 不仅凭最终文字认定为优质轨迹 |

这是工程判断框架，不是三篇论文使用的统一标注标准。

一个重要技巧是：保留错误动作及其后果作为上下文，对明确不希望模仿的错误动作关闭直接 loss，监督后面的纠正行为。但这只是“不奖励模仿错误”，不是显式惩罚错误。

更重要的是，**不能删掉某个会改变环境的动作，却保留它造成的后续观察。** 那样的轨迹不再因果一致。若要精简，最好重放整理后的动作序列，确认观察仍然成立。

### 6.4 HDR：困难任务池保存的是待解决问题，不是错误答案

BalanceSFT 首先通过基础质量检查与答案检查，将数据划分为合格训练样本和困难任务。当前模型对困难任务重新生成候选，经过多评审质量门控，将新合格样本用于训练，未解决任务继续保留。[S10，§3.3，第 4 页](#src-s10)

```text
基础质量合格 + 答案正确 → 冷启动数据
基础质量合格 + 答案不正确 → 困难任务池
                                     ↓
                       当前模型重新生成与验证
                                     ↓
                         新合格数据 → 下一轮训练
```

每任务上限防止容易任务过度代表；HDR 尝试让欠缺的困难任务产生合格示范。两者是互补的数据分布控制方式。

### 6.5 长轨迹与短轨迹，为什么不同论文结论不同？

| 材料 | 观察 | 必须保留的条件 |
|---|---|---|
| OpenThoughts-Agent | 至少五轮的过滤优于它比较的 timeout/subagent 过滤 | 在其多轮 Agent 数据中；匹配 token 预算后收益仍存在 |
| SWE-Gym / MoatlessTools | 每任务限额内偏好较少响应轮数 | 动作空间受约束、链条较短的工作流 |
| MAI 自蒸馏 | 随机采样优于最短轨迹等偏置策略 | 为后续 RL 保留行为与策略多样性的设置 |

来源分别为 [S07，§3.6，第 7 页](#src-s07)、[S08，§4.3，第 6 页](#src-s08)、[S04，§3.1.4，第 36 页](#src-s04)。

这些实验不能被简单归并为同一条普遍规律。轮数只是代理指标：太短可能缺少多轮决策，太长也可能是低效重复；只选择短路径还可能损失探索多样性。

**工程建议。** 除了长度，记录有意义的动作、验证、恢复和重复次数。对你的任务，先抽查“短而好”“长而好”“长而差”的实例，再设计过滤规则。

### 6.6 多样性至少有四种，不能都用数据行数表示

**任务多样性**：真正不同的问题。  
**表达多样性**：同一问题的不同表述。  
**状态与路径多样性**：同一任务从不同中间状态、通过不同路径完成。  
**运行协议多样性**：工具定义、提示、观察与上下文管理方式不同。

这是对前述资料的组织性解释，四类不一定相互独立。

OpenThoughts-Agent 在 31.6K 到 100K 规模间反复采样相同描述时，部分成绩趋于平缓。其有效扩展之一，是对同样的 **997 个 Tezos 底层问题**改写描述，将可用表面形式由约 902 扩展到超过 21K，并结合新的采样权重。没有引入新的底层问题。[S07，§4，第 7–8 页](#src-s07)

因此，直接得到的证据是“该设置中表达覆盖与配套采样有价值”，不能全部归因为“新增独立任务”。从 Top-4 扩到 Top-16 来源还使其大规模实验退化，也不能说来源越多越好。[S07，Table 8，第 8 页](#src-s07)

SWE-Gym 则在最多 491 条轨迹的范围内仍看到采样扩展收益。这与更大规模实验的饱和并不直接冲突，但也不支持任意规模下重复采样都有效。[S08，§5.2，第 8 页](#src-s08)

**切分要求。** 同一底层任务的改写、不同教师轨迹和重复采样必须共享父任务标识，避免训练集和测试集只是同一道题的不同说法。

<a id="chapter-7"></a>
## 7. ADP、harness 与 XTML：把数据管线理解成一套编译流程

### 7.1 三个层次解决三个不同问题

| 层次 | 核心问题 | 示例 |
|---|---|---|
| 交互语义 | 实际发生了什么动作与观察？ | 调用某函数，得到一次失败结果 |
| Harness 适配 | 当前运行框架如何执行、表示这件事？ | 工具名称、参数模式、文件操作语义 |
| 模型序列化 | 模型最终看到什么 token？ | 角色边界、工具通道、特殊 token、换行 |

ADP 位于第一层到第二层之间；Kimi K3 的 XTML 主要规定第三层的消息结构；TRL、Axolotl 等再将这些结构转成训练 mask。把三者都叫“统一格式”，会掩盖它们不同的职责。

### 7.2 ADP：先统一动作和观察，而不是直接统一 prompt

ADP 使用 `Trajectory` 表示轨迹，包含 id、动作/观察内容序列和可扩展的 details。动作分为 API Action、Code Action、Message Action，观察包括文本和网页观察。API 调用的 description 是可选解释，不是所有动作必须具有的字段。[S09，§3.2，第 4–5 页](#src-s09)

| 类型 | 保留的信息 |
|---|---|
| API Action | 函数名称、参数、可选动作说明 |
| Code Action | 编程语言、执行代码、可选说明 |
| Message Action | 对用户的解释、澄清、回答 |
| Text Observation | 用户或环境来源、文本内容 |
| Web Observation | HTML、可访问性树、URL、视口与可选截图等 |

ADP 论文的转换流程是：Raw → ADP → 特定 Agent 的 SFT 格式，再做质量检查。特定 Agent 的转换负责工具动作空间、system prompt、上下文管理和观察表达。[S09，§3.3，第 5 页](#src-s09)

```text
原始日志
  ↓ 输入转换器
ADP 等统一语义表示
  ↓ 目标 harness 转换器
目标工具与对话格式
  ↓ chat template
文本与特殊 token
  ↓ tokenizer + 监督范围映射
input_ids / labels / mask
  ↓ collator 与 packing
真正进入训练的 batch
```

这像编译器：原始数据是多种源语言，统一表示是中间表示，harness 和模型模板是不同后端。若有 $D$ 种数据与 $A$ 种框架，可以将逐对适配的 $D\times A$ 类工作组织为 $D+A$ 类转换器。[S09，Figure 2，第 6 页](#src-s09)

### 7.3 格式可转换，不等于语义已对齐

**教学示例。** `edit_file` 可能覆盖整个文件，`str_replace` 可能只做精确替换。将名字替换一下，不能保证动作仍然等价。只有 HTML 的轨迹也不能凭空恢复当时的真实截图。

**工程建议。** 在中间表示中保留父任务 id、环境版本、工具 schema 版本、上下文管理策略、教师版本和质量标签，便于重放和追踪。将最终成功标签、隐藏测试答案等元信息留在训练控制侧，不应无意写入模型可见 prompt。

ADP 的质量检查中“多数工具调用配有英文 thought”及其阈值，是那份训练配方的选择，不是协议规定所有工具 Agent 必须生成英文推理。[S09，§3.3，第 5 页](#src-s09)

### 7.4 ADP 的迁移结果：有用，但不要忽略预算

| 对应实验 | 单域数据 | ADP 综合数据 |
|---|---:|---:|
| Qwen3-8B / SWE-bench，SWE-smith only 对比 | 11.0% | 16.6% |
| Qwen2.5-7B-Instruct / WebArena | 16.0% | 20.1% |
| Qwen3-8B / AgentBench OS | 21.5% | 25.7% |

每一行是在该 benchmark 对应的相同模型与 harness 下比较数据混合；不表示三行使用相同模型。论文支持综合数据在这些设置中有效，但表格不构成“固定总训练量后，仅多样性这一因素”的纯因果证明。[S09，Table 6，第 9 页](#src-s09)

**工程建议。** 比较配方时同时报告任务数、轨迹数、总 token、受监督 token、训练步数与算力预算。否则很难区分覆盖更广与训练更多的作用。

### 7.5 XTML：协议本身也在影响学习难度

Kimi K3 的 XTML 围绕可扩展性、较低格式学习代价和解析/约束解码友好性设计。结构使用 `[open]`、`[sep]`、`[close]`，生成停止使用 `[end_of_msg]`。[S01，附录 F，第 46 页](#src-s01)

第 46 页 Figure 16 将消息内部拆为 `think`、`response`、`tools` 通道，并通过索引关联并行工具调用与结果。它不是在普通字符串外面随便加几个标签，而是在规定模型与运行系统共享的交互语言。[S01，Figure 16，第 46 页](#src-s01)

其中三个设计特别有工程价值。

**配置的作用范围影响位置。** 全局工具声明与努力级别放在历史前；单次 `tool_choice`、`response_format` 放在历史后；动态工具通过新增声明插入会话。这样单次选项变化不必重写整个历史前缀。[S01，第 46–47 页](#src-s01)

**工具参数带类型。** 字符串可以使用原始文本，代码不必总被转义成 JSON 字符串；其他 JSON 类型紧凑序列化。工具结果通过 tool/index 与调用对应。[S01，第 47 页](#src-s01)

**历史推理有一致规则。** Thinking 模式保留历史 think 通道，即使为空也保持结构；instruct 模式使用 response 与 tools 通道。推理保留方式本身就是训练—部署协议的一部分。[S01，第 47 页](#src-s01)

**综合解释：能由协议消除的歧义，不要全部留给模型用参数去猜。** 清晰的控制事件、参数类型和结果关联，有助于让训练目标与执行语义对应；但它们本身不保证任务推理正确。

<a id="chapter-8"></a>
## 8. 从论文目标到正确的训练输入：最危险的 bug 往往很安静

### 8.1 模型读到的不是 JSON 文件，而是最终 token

“数据里写了 `role=assistant`”并不等于训练器知道哪些部分应该学习。讲义第 13 页描述了三个步骤：模板渲染并记录 assistant 字符跨度；tokenize 将字符跨度映射为 token 位置；据此构造 mask。[S00，第 13 页](#src-s00)

因此，审核训练数据至少要看三层：原始交互记录、渲染后的文本、最终 batch 中的 `input_ids` 与 `labels`。只看第一层是不够的。

### 8.2 一个模板处理可能抹掉整段蒸馏目标

上传的 TRL 模板文档记录了 DeepSeek-R1-Distill 的训练修补：移除对 assistant 内容按 `</think>` 切分的处理，避免推理部分被静默丢掉，并增加 assistant 监督标记。[S17，DeepSeek-R1-Distill training template](#src-s17)

你以为自己在训练：

```text
问题 → 推理过程 → 最终回答
```

实际输入可能已经变成：

```text
问题 → 最终回答
```

这是监督任务改变，不是无关紧要的排版差异。判断训练成功，不能只凭原始数据文件中“存在推理”。

### 8.3 特殊 token 不能重复添加

Transformers 文档提醒：chat template 通常已包含所需特殊 token。先 `apply_chat_template(tokenize=False)`，再单独 tokenize 时，应避免又自动添加一遍 BOS/EOS；文档建议这类场景使用 `add_special_tokens=False`。[S14，Chat templates](#src-s14)

**工程建议。** 对固定对话保存渲染快照和 token 快照，尤其覆盖空内容、工具调用、多轮消息、推理开关、结束标记与特殊字符。字符串看起来接近，不代表 token 序列相同。

### 8.4 Prefix-preserving：追加消息后，旧历史不应意外变化

讲义第 39 页展示的失败模式是：追加工具消息触发模板中的条件逻辑，导致前面的 assistant 内容重新渲染，旧前缀发生变化。TRL 文档也专门讨论工具交互中的 prefix-preserving 要求。[S00，第 39 页](#src-s00)；[S17，Training chat templates](#src-s17)

需要比较的是模型实际看到的 token，而不是两个 Jinja 文件是否逐字相同。训练模板可以添加不输出字符的 generation 标记，而不改变序列化后的内容。

**工程建议。** 用同一条轨迹分别模拟训练渲染与在线逐轮渲染。追加工具返回后，检查本应保持的历史前缀是否一致。存在有意的上下文压缩或历史改写时，应单独测试该策略，而不是误将一切变化视为 bug。

### 8.5 框架开关对照：相似名字不代表相同语义

| 位置 | 控制项 | 所提供材料中的含义 |
|---|---|---|
| Transformers | `return_assistant_tokens_mask=True` | 请求 assistant 生成 token 的 mask，需要模板支持 generation 标记 |
| TRL | `assistant_only_loss=True` | 对 conversational 数据选择 assistant 输出 |
| TRL | `completion_only_loss` | 对 prompt-completion 数据选择 completion；与角色选择是不同维度 |
| Axolotl | `roles_to_train` | 选择参与监督的角色 |
| Axolotl | `train_on_eos`、逐消息/片段 train 控制 | 控制结束标记与特定内容的监督 |
| LLaMA-Factory | `train_on_prompt`、`mask_history` | 控制 prompt 与历史回合的监督；讲义列出 `mask_history: true` 为最后一轮 |

对应 [S15，apply_chat_template](#src-s15)、[S16，SFTTrainer](#src-s16)、[S18，Conversation](#src-s18)、[S00，第 49 页](#src-s00)。以上是所提供文档的接口语义，安装版本是否一致需要在本地核对。

Boolean mask 只回答“是否训练这个位置”，不自动实现 WIT 或 SSB 的连续加权。即使框架有 `weight` 字段，也要核对其取值与语义，不能从名称推断它支持任意实数权重。

### 8.6 数据存储类型与模型输入类型也要区分

Axolotl 文档提醒：当不同工具的同名参数使用不同数据类型时，数据集底层类型推断可能遇到转换问题；其文档给出了以 JSON 字符串存储的处理建议。[S18，Tool calling](#src-s18)

**工程解释。** 存储时用字符串避免列类型冲突，与模板渲染时需要 dict 或特定结构，是两个阶段的要求。应在转换层明确解析，不要因为存储格式改变就把“字符串形式的 JSON”重复转义两次送进模型。

### 8.7 训练前必须通过的五类检查

| 检查 | 主要断言 | 能防止什么问题 |
|---|---|---|
| 渲染检查 | 工具参数、推理段、控制标记没有丢失或重复 | 数据语义与模型输入不一致 |
| Mask 检查 | 目标动作被监督，观察按设计忽略 | 训练了错误部分，或根本没有有效目标 |
| 前缀检查 | 逐轮追加不意外改写历史 | 训练与在线输入漂移 |
| Batch 检查 | padding、位移、packing 后 labels 正确 | collator 覆盖标签、跨边界监督错误 |
| 重放检查 | 动作可执行，观察与前因相符 | 不可执行轨迹、拼接后的因果断裂 |

这些是工程建议，附录 A 提供可直接用于预处理检查的纯文本示例。它不会替你验证工具语义，更不会替代真实任务评测。

## 9. 优化、长序列与训练配方：不能只抄学习率

### 9.1 LoRA 与全参数训练：更新范围和监督目标是两条轴

**背景解释。** 常见 LoRA 参数化为：

$$
W'=W+\frac{\alpha}{r}BA
$$

其中 $W\in\mathbb R^{d_{out}\times d_{in}}$ 保持冻结，低秩增量的参数量约为 $r(d_{in}+d_{out})$，而非整个矩阵的参数量。这是前面讲解中的参数化背景，不是 Lecture-08 对 LoRA 的专项实验结论。

减少可训练参数能够减少相应梯度和优化器状态需求，但不意味着长序列前向、激活与必要的反向计算成本消失。全参数 SFT、LoRA-SFT、QLoRA-SFT 在相同数据上出现不同表现时，不能只把原因归给数据；更新空间与数值条件也变了。S19 将这些训练方式分别列出。[S19，Features](#src-s19)

**工程建议。** 先用资源允许的更新方式建立可靠基线，再单独比较参数化方式。不要把“使用了 LoRA”当作已经设计好了 SFT。

### 9.2 工具观察不算 loss，也依然需要处理

一条轨迹含 30,000 个观察 token、1,000 个 assistant token，并不等于只计算 1,000 个 token。模型需要利用观察来预测动作。

**建议指标：**

$$
\text{监督密度}=
\frac{\text{参与直接 loss 的有效 token 数}}
{\text{有效输入 token 数}}
$$

监督密度低不一定不好：观察可能不可省略。但只看输入吞吐量，可能看不出大量重复日志占用了计算。建议同时统计输入 token/s、目标 token/s、任务覆盖、成功率与成本。

这些是对讲义“观察作为条件上下文”的工程推导，不是用一个比率取代任务评测。

### 9.3 长度分布决定训练成本，也可能决定学到什么

长轨迹常常把最终验证、错误恢复或提交动作放在末尾。简单右截断可能丢掉这些目标；左截断则可能丢掉原始约束、工具定义或关键证据。

**工程建议。** 超长样本可以采取几种明确策略：保留完整的较短轨迹；提高训练长度；构造带充分状态信息的决策窗口；或者按照部署时实际采用的上下文压缩方式生成训练数据。不能仅因为“截断后还能计算 loss”，就认为训练目标没有改变。

尤其要防止训练时给予学生全量历史，部署时却经过多次压缩；这会同时改变模型能够利用的证据与记忆条件。MAI 报告过较短轨迹自蒸馏造成长上下文能力遗忘，并通过混入 mid-training 数据缓解。[S04，§3.1.4，第 36 页](#src-s04)

### 9.4 Packing：完整性、混合与隔离分别检查

Nemotron 的 best-fit packing 轮流读取不同来源，维护固定规模的未完成 pack，将新对话放进最适合的剩余空间；不拆分、不截断完整对话；同一 pack 避免重复 prompt，最后再打乱 pack。[S03，§3.1.2，第 19–20 页](#src-s03)

这既减少 padding，也防止每段训练连续看到单一数据源。但必须区分：

**完整对话打包**：保护轨迹语义。  
**充分混合来源**：管理优化过程中的局部分布。  
**跨样本注意力隔离**：决定一条样本能否看到另一条样本。

原文该段 packing 描述没有完整交代注意力隔离实现。不能从“完整对话”推断“严格隔离”。

**实现解释。** EOS 本身不建立注意力屏障，重置 position IDs 也不必然实现隔离。如果希望 pack 内样本独立，必须核对分段注意力或变长序列边界的具体实现，并避免在独立段起点形成错误的跨段预测目标。LLaMA-Factory 资料专门列出 `neat_packing` 对应的 contamination-free packed training，也说明 packing 是需要读语义的配置。[S19，Changelog](#src-s19)

### 9.5 梯度累积：平均方式会改变训练目标

**推导。** 两个 micro-batch 分别有 100 和 10,000 个目标 token。先对每个 micro-batch 求平均，再把两个平均值平均，会让前一个 micro-batch 的单个 token 获得更高相对权重。

希望实现全局目标 token 平均时，逻辑上应对应：

$$
\mathcal L_{step}
=
\frac{\sum_b\mathrm{loss\_sum}_b}
{\sum_b\mathrm{valid\_target\_count}_b}
$$

这并不是说 token 平均永远优于样本平均。按样本、按回合、按 segment、按 token 平均，可以对应不同研究目标。关键是让实现与目标一致。

**工程建议。** 检查分布式归约、梯度累积与训练框架内置归一化，避免额外多除一次或少除一次。不要在未理解框架行为时凭经验补系数。

### 9.6 样本比例、token 比例与实际能力不是同一件事

MAI 第 49 页的混合配方如下：

| 能力 | 样本占比 | token 占比 |
|---|---:|---:|
| STEM 与 Coding | 56% | 89% |
| Agent 能力 | 11% | 9% |
| 通用帮助性与安全 | 33% | 2% |

作者明确指出，该配方中长 STEM/coding 轨迹占据多数 token，并未在实践中损害帮助性与安全能力。[S04，Table 10、§3.5，第 49 页](#src-s04)

在统一 token 平均的简化条件下，某领域的损失项份额受采样比例、平均受监督长度、token 权重共同影响：

$$
\text{某领域损失项份额}
\propto
\text{采样比例}\times\text{平均目标长度}\times\text{目标权重}
$$

这是目标组成分析，不是实际梯度范数或模型能力的等式。MAI 与 BalanceSFT 联读后，正确结论不是“长度失衡必然失败”，而是“必须检查长度如何改变监督，再用任务表现判断是否需要调整”。

### 9.7 阅读真实配方：讲义给概览，论文给阶段细节

| 实验/阶段 | 序列长度 | 全局 batch | 学习率与目的 |
|---|---|---:|---|
| OpenThoughts-Agent 数据消融 | 32,768 | 96 | $4\times10^{-5}$，余弦，7 个 epoch；比较数据选择 |
| Nemotron SFT Stage 1 | packed 294,912 | 64 | 峰值 $1.5\times10^{-5}$，最低 $10^{-6}$ |
| Nemotron SFT Stage 2 | packed 515,000 | 64 | 峰值 $10^{-5}$，最低 $2\times10^{-6}$；加入更长数据 |
| MAI self-distillation | packed 128K | 2,048 | $1.7\times10^{-5}\rightarrow5.2\times10^{-6}$，2% warmup |
| K2 Horizon SFT | 512K，三个阶段 | 模型卡该表未列 | 最后阶段在高质量子集上衰减学习率 |

来源：[S07，§3，第 4 页](#src-s07)；[S03，§3.1，第 15 页](#src-s03)；[S04，§3.1.5，第 36 页](#src-s04)；[S05，Training Overview](#src-s05)。

**细节说明。** 讲义第 36 页用一行概括 Nemotron 的学习率；其报告分别给出了两个阶段的不同取值，上表按报告分开列出，而不是把概览当成两个阶段完全相同。不同论文中的 batch 单位和 packing 方式也不同，不能直接比较为相同数量的原始对话。

Nemotron 的 SFT 还保留了 MTP 辅助目标，使用两个共享权重的 MTP 层和每 token 0.1 的辅助损失系数。这提醒我们：讲义中的基本交叉熵是主线，不代表所有工业训练配方都只有这一个损失项。[S03，§3.1，第 15 页](#src-s03)

### 9.8 MoE 与部署精度：结构和数值条件不能忽略

MAI 报告窄领域训练可能造成专家选择不均衡：自蒸馏阶段采用较大的负载均衡系数 $10^{-2}$，RL 阶段采用 $10^{-5}$，自蒸馏使用 0.15 dropout。作者将其与专家均衡、分布熵和后续 RL 稳定性联系起来。[S04，§3.1.5，第 37 页](#src-s04)

Kimi K3 则从 SFT 阶段起使用部署相关量化感知训练：专家权重 MXFP4、相关激活 MXFP8，其他指定组件维持较高精度；后续 RL 的 rollout 和训练保持相同量化方案。[S01，§4.1.4，第 14 页](#src-s01)

**工程含义。** 对 MoE，应监控路由负载和辅助目标；对量化部署，应在最终部署精度下评测。不能把 dense 模型上某组 SFT 超参数原样当成所有结构的默认值，也不能把 QLoRA 与上述量化感知训练当作同一种方法。

## 10. 离线模仿为什么不等于实际成功？

### 10.1 模型学的是示范分布，运行时却会创造自己的分布

训练时前缀来自示范，部署时前缀来自模型自己的动作与环境反应。用分布表示：

$$
\text{训练主要覆盖： }h\sim d_{\mathrm{demo}}
\qquad
\text{运行需要面对： }h\sim d_{\pi_\theta}
$$

讲义第 42 页给出同一前缀后的分岔：教师编辑 A，测试通过；学生编辑 B，测试失败，此后进入示范没有覆盖的状态。[S00，第 42 页](#src-s00)

**教学示例。** 老师直接定位正确文件，学生先修改了相似名称的另一个文件。再给学生十条老师从头一次成功的轨迹，未必能教会它如何处理此时的错误状态。需要的是这个状态下的诊断与恢复行为。

所以，低 teacher-forced loss 说明“沿着记录好的历史，更能预测老师”，不等于“自由运行时能处理所有偏离”。

### 10.2 一个理论边界：错误可能沿任务链条放大

**来自 DAgger 原论文的补充阅读，不是上传 HTML 摘要本身包含的公式。** 在单步代价有界、模仿损失上界控制动作错误的条件下，论文 Theorem 2.1 给出：

$$
J(\pi)\le J(\pi^*)+T^2\epsilon
$$

其中 $\epsilon$ 在专家状态分布上测量。Theorem 2.2 改为在自身状态分布上控制错误，并以 $u$ 约束一次偏离后再跟随专家的额外代价，得到 $J(\pi)\le J(\pi^*)+uT\epsilon$；$u$ 本身仍可能随 $T$ 增长。[S13-PDF，§2](#src-s13-pdf)

**解释与边界。** 这些式子说明，只在专家走过的路径上保证小错误，不足以保证长任务闭环表现；不是每个 Agent 必然按平方速度退化，也不是普通神经网络 SFT 自动满足理论条件。工程上更重要的问题是：第一次偏离后是否还有可学习、可执行的恢复路径。

### 10.3 DAgger：让专家标注学生实际访问的状态

DAgger 迭代运行当前策略，收集其访问状态，请专家提供这些状态下的动作，聚合数据后训练下一版策略；采集时也可以混合专家与学生策略。[S13-PDF，Algorithm 3.1](#src-s13-pdf)

上传的摘要页强调，策略影响未来观察，打破普通独立同分布监督学习的假设；其理论依赖相应的在线学习与归约条件。[S13，Abstract](#src-s13)

**迁移到 LLM Agent 的工程建议：**

```text
学生在受控环境执行
→ 保存真实偏离点的可见上下文与环境快照
→ 专家从这个状态接手
→ 验证下一步动作或恢复轨迹
→ 聚合为新的监督数据
→ 重新训练并闭环评测
```

这与让教师“重新独立做一次原任务”不同，也与只保留学生成功任务不同。核心不是泛泛地增加数据，而是补上学生真正会遇到的状态。

### 10.4 SWE-Gym 的负面结果：成功样本回流不保证进步

SWE-Gym 在 OpenHands 设置中，用已微调的 32B 学生采样 868 条成功轨迹，与原来的 491 条教师轨迹混合训练，SWE-Bench Lite 解决率却从 **15.3% 降至 8.7%**。[S08，§4.2，第 5–6 页](#src-s08)

而在受约束的 MoatlessTools 中，迭代拒绝采样微调带来有限收益：7B 从 7.0% 到 10.0%，32B 从 19.0% 到 19.7% 后基本停止增长。[S08，§4.3，第 6 页](#src-s08)

不能从中推出“自训练无效”或“工作流永远优于自由 Agent”。它说明初始策略、harness、任务链条和筛选方法都会影响结果。只回流已经成功的样本，可能强化原有偏好，并未覆盖最需要学习的失败状态。

### 10.5 自训练、HDR、DAgger、MOPD 必须分清

| 方法 | 数据位置 | 学习信号 | 不能误称为什么 |
|---|---|---|---|
| 成功轨迹自训练 | 学生完成原任务的记录 | 模仿通过验收的轨迹 | 不等于专家纠正失败状态 |
| HDR | 学生重新尝试困难任务 | 模仿新生成且合格的输出 | 不等于反复训练错误答案 |
| DAgger | 当前策略实际访问的状态 | 专家给出的动作标签 | 不等于只采集专家从头成功轨迹 |
| MOPD | 学生生成的前缀与输出 | 多个教师的概率级指导 | 不等于普通教师文本 SFT |

Nemotron 的 MOPD 在学生诱导状态上匹配对应领域教师；其理想 on-policy 表述使用学生到教师的 reverse KL，提供密集 token 级信号。[S03，§3.3.1，第 20–21 页](#src-s03)

Kimi K3 的具体信号包含教师与学生 token 对数概率比，使用 stop-gradient 和裁剪。为了建立直觉，可以简写为：

$$
r_t\sim
\log\pi_{\mathrm{teacher}}(y_t\mid h_t)
-
\log\pi_{\mathrm{student}}(y_t\mid h_t)
$$

这只是解释性简式，不替代原文的完整算法。[S01，§4.1.3，第 13–14 页](#src-s01)

两者与 DAgger 的联系在于关注学生遇到的状态；区别在于标签与优化方式不同。只有教师文本输出时，可以做示范蒸馏或专家纠正后的 SFT；复现概率级蒸馏则需要相应概率计算和训练基础设施。

<a id="chapter-11"></a>
## 11. 如何评测真正的能力提升？

### 11.1 二十条样本过拟合：是管线检查，不是能力证明

讲义建议先确认模型能拟合二十条样本，再在目标 harness 里执行可验收任务。[S00，第 43 页](#src-s00)

小样本拟合主要检查 labels、参数更新、模板和优化过程是否工作；独立任务评测才检查泛化。两者不能互相替代。小样本 loss 降得很低，也不意味着模型学会了未见任务。

### 11.2 评测至少分四层

| 层次 | 需要回答的问题 | 典型观测 |
|---|---|---|
| 协议 | 输出能否被系统理解？ | 调用解析、参数类型、结果关联、正确停止 |
| 行为 | 是否有效推进并响应观察？ | 验证行为、失败恢复、重复操作、提前终止 |
| 结果 | 最终工作是否完成？ | 测试通过、结构化结果校验、交付物验收 |
| 成本与回归 | 提升付出什么代价，其他能力是否受损？ | token、耗时、调用数、非目标任务表现 |

这是工程评测框架。SWE-Gym 同时报告解决率、空 patch、卡循环和轮数，说明单一结果分数不足以解释行为变化。其 32B Verified 设置中，解决率提升的同时平均轮数也增加，部分过程指标没有同步改善。[S08，Table 3，第 6 页](#src-s08)

因此，“更高成功率”既可能来自更合理的策略，也可能部分来自更长尝试。要结合预算解释。

### 11.3 能产生正确候选，与能选出正确候选，是两种能力

SWE-Gym 用成功/失败轨迹训练结果验证器。验证器读取任务与轨迹，预测 `<YES>` 或 `<NO>`，再用于候选排序。[S08，§5.1.1，第 7 页](#src-s08)

| 指标 | 含义 |
|---|---|
| Pass@1 | 单次运行是否成功 |
| Pass@k | $k$ 个候选中是否至少有一个成功；这里是候选发现能力 |
| Best@k | 验证器从 $k$ 个候选中选出的那个是否成功 |

该实验在 SWE-Bench Verified 上，单次为 **20.6%**；采样 16 次时，**Pass@16 为 42.8%**，但 **Best@16 为 32.0%**。差距反映了验证器选择能力的不足。[S08，Figure 3，第 7 页](#src-s08)

**工程解释。** Pass@k 高而 Best@k 低，说明不只是 actor 需要改进，verifier 也是瓶颈。Best@16 包含多次采样和选择计算，不能当作单次 Agent 成绩去比较。

### 11.4 一个跨论文实验假设：先在 verifier 上测试 IM

SWE-Gym verifier 的形态是长轨迹输入、短判断输出，比长输出 Agent 更接近 IM 重点研究的长输入短输出设置。

**待验证假设。** 在相同 verifier 数据与训练预算下，比较只训练判断 token，与加入部分输入建模目标，观察独立任务的判断质量、校准和 Best@k。该建议来自两份材料的联系，不是它们已经完成的实验，也不意味着对噪声很大的整段轨迹计算 loss 必然有益。

### 11.5 切分方式必须匹配泛化声明

同一任务的所有采样、改写和教师版本应保持在同一侧。声称泛化到新仓库，就需要仓库层面的独立切分；声称泛化到新工具，就需要相应工具或 schema 测试。[S00，第 43 页](#src-s00)

**工程建议。** 固定环境初始状态、工具集合、上下文策略、最大执行步数、超时、采样参数和重试方式。将开发集用于配方选择，将最终测试集用于独立验收；不要反复根据最终测试集改数据后仍把它当未见评测。

OpenThoughts-Agent 的部分综合表按模型在原始 harness 与 Terminus-2 中的更高成绩报告。它与固定单一 harness 的消融表不是同一种比较口径。[S07，Table 1，第 3 页](#src-s07)

### 11.6 未专项训练的能力也需要回归

讲义第 45 页提醒：训练一种能力会移动其他能力，即使你没有测量。[S00，第 45 页](#src-s00)

MAI 的实际例子是：自蒸馏要防止长上下文行为遗忘；最终轻量 RL 还保留少量 STEM/coding 数据和较长训练上下文，以避免复杂推理缓慢退化。[S04，§3.1.4、§3.5，第 36、49 页](#src-s04)

**工程建议。** 目标能力以外，至少保留一组通用指令遵循、长输入信息使用、正常停止和基础任务回归。不能将“没有测到退化”表述为“没有退化”。

## 12. SFT 与 RL 的完整生命周期：冷启动不是唯一位置

### 12.1 讲义的线性图，是教学总览而非单一模型的完整时间线

讲义第 6 页用不同模型的数据规模说明 pre-training、mid-training、SFT、RL 的关系；其中包含 Nemotron 与 K2 Horizon 的数字。不能把这张图读成某一个模型真实、完整、严格线性的训练日志。[S00，第 6 页](#src-s00)

第 8 页把 SFT 的 token 级目标与每 rollout 一个奖励并排，这是对相关 Agent 设置的教学简化；并不是所有 RL 都只能使用终局标量奖励。

### 12.2 R1：SFT 既冷启动，也重新组织已有能力

R1-Zero 从基础模型直接进行 RL，没有先做 SFT。R1 则加入几千条冷启动示范，再进行 RL、拒绝采样与 SFT，然后继续后续 RL。[S02，第 2、6 页](#src-s02)

第二次 SFT 数据大致包含 60 万条推理和 20 万条非推理样本。前者通过候选生成与验证筛选；后者包含写作、事实问答、翻译和部分软件工程任务。[S02，附录 B.3.3，第 26 页](#src-s02)

因此，SFT 在该流程中不仅教输出结构，也承担组织与混合能力的作用。R1-Zero 同时说明“所有 RL 必须先 SFT”不是普遍规律。

### 12.3 Kimi K3 与 Nemotron：基础策略、领域专家与多教师整合

Kimi K3 的报告将后训练分为 SFT、领域/推理努力级别的 RL 专家、MOPD。其三类广义领域与三个努力级别组合成九个专家，再进行整合。[S01，§4.1，第 12–14 页](#src-s01)

Nemotron 同样先建立 SFT 与统一 RLVR 的学生，再用十余个领域教师提供密集指导，并进行多轮教师—学生迭代。[S03，§3.3，第 20–21 页](#src-s03)

这些流程不能被概括成“所有教师轨迹混在一起做一次普通 SFT”。其中有学生 rollout、教师评分、异步更新和专门的蒸馏目标。

### 12.4 MAI：自蒸馏是在新的起点上保留行为成果

MAI 的自蒸馏收集 RL 运行中的轨迹，对一个 **mid-trained checkpoint** 做 SFT，再将结果作为继续 RL 的起点。不是在原 RL 权重上简单追加几步监督训练。[S04，§3.1.4，第 34 页](#src-s04)

它用于迁移聊天格式、迁移到新的基础 checkpoint、过滤奖励投机样本，并在训练故障后保留已有进展。作者指出，某些数值问题可能在性能明显崩溃前很久就进入参数，因此回滚到看似正常的 checkpoint 未必足够。[S04，第 34–35 页](#src-s04)

**工程解释。** 权重保存了模型当前的内部状态；经过验证的轨迹则保存了一部分可迁移行为。二者是不同资产。保留高质量轨迹，有时能够在换底座或重新建立训练状态时继续利用过去的工作。

MAI 的自蒸馏消融还报告：百万量级轨迹在其设置中已足以较好传递能力；更大数据量收益递减且可能限制后续探索；多个较强后期 checkpoint 的轨迹比只用最终 checkpoint 更有利于恢复后的 RL；固定 token 预算时，prompt 多样性比每 prompt 更多轨迹有价值。[S04，第 35–36 页](#src-s04)

作者也观察到包含部分最终答案错误的轨迹与仅成功轨迹表现相近，但最终仍使用成功轨迹，因为成功数据足够。这是该设置的观察，不能变成“错误答案都可以直接作为 SFT 目标”的建议。

### 12.5 K2 Horizon：SFT 也可以出现在 RL 专家合并之后

这里的 K2 Horizon 是 **IFM/K2-Horizon-375B-A23B**，不是 Kimi K2。上传模型卡的时间线是：从 mid-training checkpoint 训练五个 RL 专家，合并后再进行三阶段 SFT。[S05，Training Overview](#src-s05)

| 阶段 | 训练步数 | 阶段训练 token | 序列长度 | 目的 |
|---|---:|---:|---:|---|
| SFT Phase 1 | 2,400 | 81B | 512K | 从合并 RL checkpoint 扩展领域覆盖 |
| SFT Phase 2 | 6,000 | 201B | 512K | 以接近的数据混合继续训练 |
| SFT Phase 3 | 1,500 | 50B | 512K | 高质量子集与学习率衰减 |

三阶段相加为 332B token；模型卡没有报告完整 RL 步数与 token，所以不能据此计算包含 RL 的完整训练预算。[S05，Training Overview](#src-s05)

这份材料说明，不能仅凭“SFT”这个标签就推断它是冷启动、训练很少，或者只负责格式。

### 12.6 独立部署最好的 SFT，不一定是后续 RL 最好的起点

OpenThoughts-Agent 的 Table 11 在 8B、Terminus-2 与三个核心 benchmark 下报告：

| 设置 | SWE-bench Verified-100 | OT-TBLite | Terminal-Bench 2.0 | 原始平均 |
|---|---:|---:|---:|---:|
| Qwen3-8B | 5.3% | 1.3% | 1.5% | 2.7% |
| 直接进行该组 Agent RL | 1.0% | 7.8% | 1.9% | 3.6% |
| ColdSFT | 23.7% | 14.8% | 6.7% | 15.1% |
| 10K 数据的 SFT | 24.3% | 15.6% | 7.9% | 15.9% |
| ColdSFT + RL | 35.7% | 16.0% | 13.5% | 21.7% |

表中结果支持“为 RL 选择适当起点”的重要性。[S07，Table 11，第 11 页](#src-s07)

**证据边界。** 表里没有完整列出所有更强 SFT checkpoint 接上相同 RL 的对照；因此不能只凭它证明“越早停 SFT 越好”。MAI 关于保留分布多样性的观察也有其具体条件。正确做法是保存多个候选，在相同 RL 任务与预算下继续训练，再比较终点。

独立部署关心当前成功率、成本、稳定性；作为 RL 起点还关心输出分布、可探索策略与后续可提升性。两种目的应采用不同的 checkpoint 选择标准。

### 12.7 一张生命周期对照表

| 材料 | SFT 的关键角色 | 对工程理解的贡献 |
|---|---|---|
| R1 | 冷启动；混合与整理已有推理/非推理能力；小模型蒸馏 | SFT 与 RL 可以多次交替 |
| Kimi K2 | 通过大量工具交互示范建立能力 | 数据工厂与验证体系很重要 |
| OpenThoughts-Agent | 数据配方研究；为 Agent RL 建立起点 | 需要用消融选择数据与起点 |
| MAI | 自蒸馏、换底座、恢复、能力整合 | 轨迹可作为独立于旧权重的行为资产 |
| K2 Horizon | RL 专家合并后的领域覆盖训练 | SFT 不一定在 RL 前 |
| Kimi K3 / Nemotron | 基础策略与后续多教师体系中的组成部分 | 不能把完整后训练都叫普通 SFT |

这张表是前述原文流程的归纳，不意味着任何单一团队都需要复现全部阶段。

<a id="chapter-13"></a>
## 13. 一轮可执行的工程实验：从行为缺陷出发，而不是从训练命令出发

本章是对前面材料的工程整合。所列步骤与建议不是某篇论文原样公布的统一配方。

### 13.1 先写清楚要修复什么行为

不要以“把模型微调得更聪明”为目标。可以选择：工具参数错误；执行失败后重复原命令；部分证据到手就提前结束；修改后不验证；长任务后半段不再重新读取来源；最终总结与实际执行不一致。

| 可观察缺陷 | 首先排查 | 更有针对性的数据 |
|---|---|---|
| 工具 JSON 经常不能解析 | 模板、schema、停止与解析规则 | 当前协议下的正确调用示范 |
| 参数类型或对象经常错 | 输入是否明确、短动作是否受充分监督 | 相似工具对比、参数边界、澄清示范 |
| 报错后不断重复 | 观察是否保留、恢复状态是否覆盖 | 真实错误状态下的有效下一步 |
| 不验证就结束 | 验收动作是否在目标中、是否被截断 | 包含完整验证与提交的轨迹 |
| 长任务后半段丢失证据 | 上下文策略、引用与重新读取行为 | 与部署上下文一致的查证和恢复过程 |
| 回答说完成但环境没完成 | 验收是否只看最终文字 | 外部可核验结果的轨迹与负例评测 |

训练可能修复行为倾向，但接口或执行器缺陷应优先在系统层解决。

### 13.2 固定最小可复现实验单元

一次实验至少固定：基础模型版本、tokenizer 与模板、工具 schema、harness、环境初始状态、任务家族切分、上下文管理、执行预算和验收方法。

将同一任务的原始表达、改写、不同教师版本归到相同父任务。把最终测试任务从数据生成、示范筛选和 checkpoint 选择中隔离。

对小团队，首先选择一个可在受控环境中重复运行、能外部验收的窄任务，不必一开始复现全面多域后训练。

### 13.3 数据管线与评测管线先于正式训练

```text
任务登记与分组切分
→ 教师生成或人工示范
→ 环境执行和验收
→ 语义标准化
→ 结果与过程质量检查
→ harness 适配
→ 模板、token 与 mask 检查
→ 二十条样本管线测试
→ 小规模独立任务闭环评测
→ 再扩大数据与训练预算
```

保留原始轨迹，不要只保留最终渲染文本。将过滤原因、环境错误、超时与模型错误分别记录；生成环境失败不应自动算成模型任务失败或困难样本。

### 13.4 用单变量实验回答一个问题

| 实验 | 尽量只改变什么 | 目标 |
|---|---|---|
| E0：固定基线 | 不更新权重 | 建立真实失败分类 |
| E1：标准 SFT | 高质量完整轨迹、明确 assistant 监督 | 判断示范是否改善目标行为 |
| E2：过程筛选 | 去掉无效循环和不合格过程 | 检查成功轨迹中的坏习惯影响 |
| E3：恢复数据 | 加入学生实际失败状态与纠正行为 | 检查偏离后的继续执行能力 |
| E4：监督分配 | 固定数据，改变分段目标或权重 | 检查短动作监督是否不足 |
| E5：覆盖扩展 | 匹配预算，增加任务/表达/状态覆盖 | 检查重复数据瓶颈 |
| E6：后续 RL 起点 | 多个 SFT 候选接相同 RL 预算 | 选择适合继续学习的 checkpoint |

每轮记录样本数、独立父任务数、输入与目标 token、更新步数、训练资源、闭环成功率、成本和回归结果。无法完全匹配预算时应如实列出差异，而不是将所有收益归给方法。

### 13.5 用现象诊断，不要只反复加数据

| 现象 | 优先检查 | 不宜立即得出的结论 |
|---|---|---|
| 小样本 loss 不降 | labels、全 mask、参数冻结、优化器、位移 | 模型不够大 |
| loss 很低但调用仍错 | 是否监督了工具参数、协议一致性 | 再训练几个 epoch 一定好 |
| 离线很好、上线明显差 | 模板、上下文裁剪、历史推理、工具版本 | 模型随机不稳定 |
| 首次错误后迅速失控 | 学生状态覆盖、恢复数据、环境可恢复性 | 只增加完美教师答案 |
| 总成绩升，目标调用反而退化 | 分段损失、任务配比、长度份额 | loss 下降代表所有能力改善 |
| 数据越多成绩越差 | 每任务重复、来源质量、过拟合、预算变化 | SFT 天生不能扩展 |
| SFT 好但接 RL 不提升 | 起点分布、任务难度、奖励与运行协议 | SFT checkpoint 越强一定越适合 RL |

这些是排查路径，不是对具体故障的确定诊断。

### 13.6 发布制品不能只有权重

建议将一次训练制品组织为以下可追踪集合。目录仅表示建议的结构，不假装已经为你的项目创建这些文件：

```text
experiment/
├── model_manifest.json       # 基础模型、更新方式、精度与版本
├── data_manifest.json        # 数据来源、父任务、过滤与切分信息
├── template/                 # tokenizer、chat template、生成标记约定
├── harness/                  # 工具 schema、提示、上下文与停止规则
├── train_config/             # loss、packing、优化器与训练参数
├── evaluation/               # 任务集合、预算、验收与回归结果
└── checkpoints/              # 候选 checkpoint 或 adapter
```

若没有这些信息，下一次仅更换模板或上下文策略，就可能改变行为，而你无法判断是模型变化还是运行条件变化。

<a id="chapter-14"></a>
## 14. 综合洞见与常见误区

### 14.1 三个层次必须同时成立

**监督目标正确。** 数据、mask、归一化和权重共同决定模型得到什么模仿信号。

**执行契约正确。** 工具语义、模板、上下文与停止条件共同决定模型学到的行为能否被执行。

**闭环表现正确。** 模型不仅要沿老师路径预测，还必须面对自身动作造成的新状态。

任何一层缺失，都可能产生“训练成功，产品失败”。这是对全套材料的综合解释。

### 14.2 六条需要带进实践的认识

**第一，数据清洗也是目标设计。** 删除一种轨迹、限制每任务样本数、改变推理 mask，都会改变模型应该模仿的分布，而不仅是让数据更整洁。

**第二，老师强不等于示范适合学生。** 教师选择要以学生收益验证；同样，教师输出更长、更像人类思考，也不自动代表更有教学价值。

**第三，长度与重要性不是同一个量。** 长段落获得更多 token 监督，短工具调用却可能决定任务能否执行。是否需要重加权应通过消融判断。

**第四，格式层不是研究之外的杂务。** 推理被模板删除、结束 token 被 mask、工具参数被重复转义，都会把原本的研究问题变成另一个问题。

**第五，有价值的新数据常来自学生的真实失败位置。** 完美轨迹教起步，恢复轨迹教偏离后怎么办；两者应根据目标一起设计。

**第六，SFT 是模型迭代中的方法，不是固定阶段标签。** 它可以冷启动、蒸馏、迁移、整合，也可以作为 RL 之后的覆盖训练；是否有效取决于具体目标与条件。

### 14.3 常见误区对照

| 误区 | 更准确的理解 |
|---|---|
| SFT 只学格式 | 更新参数会影响多种行为；实际学到什么取决于信号 |
| 蒸馏和 SFT 是两种互斥方法 | 蒸馏可以通过 SFT 实现 |
| 不计算 prompt loss，模型就不理解输入 | 条件输入仍影响目标输出，仍可通过后续损失学习 |
| assistant-only 就是只训练最后一轮 | 角色选择与回合选择是不同维度 |
| 最终成功意味着所有中间动作都值得模仿 | 无效循环与坏习惯也可能伴随成功 |
| 删除失败动作就能得到干净轨迹 | 可能破坏后续观察的因果一致性 |
| 最长或最短的轨迹必然更好 | 不同实验条件下，长度只是不同质量属性的代理 |
| 综合数据提升证明多样性单独有效 | 还需排除总数据量、预算与配比变化 |
| `packing=True` 自动保证样本独立 | 完整性、混合与注意力隔离需要分别检查 |
| SFT 的最优 checkpoint 一定是 RL 的最佳起点 | 当前成绩与后续可提升性是不同目标 |
| Pass@16 可以当成单次模型能力 | 它包含额外采样预算，Best@16 还包含选择能力 |
| 回流成功样本就是可靠自进化 | SWE-Gym 提供了具体反例，必须闭环验证 |

### 14.4 对来源保持严谨的五个边界

**讲义概览不等于每份报告的完整配方。** 工业报告的阶段细节、辅助目标和真实时序需要保留；本文明确标出了 Nemotron 阶段学习率与 Horizon 时序等区别。

**结果不自动给出机制。** 教师消融说明“谁教出的学生好”，并未单独证明是风格、长度还是策略复杂度造成。

**局部消融不自动成为通则。** 五轮过滤、每任务上限 2、百万级自蒸馏数据与某个最优权重，都依赖对应设置。

**理论不自动适用于任意实现。** DAgger 的界带有假设；把某个恢复数据循环搬进神经网络训练，不意味着理论保证自动成立。

**没有实验的联系应写成假设。** 例如将 IM 用于长输入短判断的 verifier，是值得检验的组合思路，而不是已被这些论文证实的结果。

**最后一句话：掌握 SFT，不是会启动一次训练，而是能解释为什么监督这些行为、为什么保留这些状态，以及为什么相信模型在真实运行时会因此更可靠。**

## 附录 A：纯文本 SFT 预处理与监督检查代码

### A.1 使用范围

下面代码将前面讨论的监督约定落实为一条纯文本样本的编码与检查。接口依据所提供的 Transformers `apply_chat_template` 文档。它不是完整训练脚本，也没有自动实现 WIT、SSB 或多模态处理。[S15，apply_chat_template](#src-s15)

使用前需要将 tokenizer 配置成与模型匹配、支持 generation mask 的**训练模板**。直接调用 tokenizer，并不意味着训练器初始化时的模板修补已经发生。过长样本会显式报错，不静默截断；具体压缩或切窗策略应在上游确定。

### A.2 编码函数与监督片段检查

```python
from typing import Any

def encode_sft_example(
    tokenizer: Any,
    messages: list[dict[str, Any]],
    *,
    max_tokens: int,
    tools: list[dict[str, Any]] | None = None,
) -> dict[str, list[int]]:
    """编码一条无 padding 的纯文本对话，保留完整历史，只监督 assistant。

    前提：tokenizer 已配置正确的训练模板，能够返回 assistant_masks。
    不负责模型加载、模板修补、多模态输入、packing 或训练器内部位移。
    """
    if not messages:
        raise ValueError("messages 不能为空。")
    if not isinstance(max_tokens, int) or max_tokens < 2:
        raise ValueError("max_tokens 必须是至少为 2 的整数。")

    template_args: dict[str, Any] = {
        "tokenize": True,
        "add_generation_prompt": False,
        "return_dict": True,
        "return_assistant_tokens_mask": True,
        "truncation": False,
        "padding": False,
    }
    if tools is not None:
        template_args["tools"] = tools

    encoded = tokenizer.apply_chat_template(messages, **template_args)
    if "input_ids" not in encoded:
        raise ValueError("tokenizer 没有返回 input_ids。")

    input_ids = list(encoded["input_ids"])
    mask_raw = encoded.get("assistant_masks")
    if mask_raw is None:
        raise ValueError("没有 assistant_masks，请检查训练模板的 generation 标记。")
    assistant_mask = list(mask_raw)

    if any(not isinstance(token_id, int) for token_id in input_ids):
        raise ValueError("预期一条样本的一维整数 input_ids，不接受 batch 或张量。")
    if len(input_ids) != len(assistant_mask):
        raise ValueError("assistant_masks 与 input_ids 长度不一致。")
    if any(value not in (0, 1) for value in assistant_mask):
        raise ValueError("assistant_masks 必须只包含 0 和 1。")
    if len(input_ids) < 2:
        raise ValueError("序列太短，无法构造有效的下一 token 目标。")
    if len(input_ids) > max_tokens:
        raise ValueError(
            f"样本长度 {len(input_ids)} 超过上限 {max_tokens}；"
            "请在上游明确处理，不要静默截断。"
        )
    if not any(assistant_mask[1:]):
        raise ValueError("没有可用于下一 token 预测的有效 assistant 目标。")

    # labels 在这里与 input_ids 同位置对齐，不提前做 causal shift。
    labels = [
        token_id if selected else -100
        for token_id, selected in zip(input_ids, assistant_mask)
    ]
    labels[0] = -100  # 第一位置没有本序列内部的前一位置可预测它。

    return {
        "input_ids": input_ids,
        "attention_mask": [1] * len(input_ids),
        "labels": labels,
    }

def supervised_spans(
    tokenizer: Any,
    sample: dict[str, list[int]],
) -> list[tuple[int, int, str]]:
    """返回连续监督片段：[起始位置, 结束位置)，便于人工检查。"""
    input_ids = sample["input_ids"]
    labels = sample["labels"]
    if len(input_ids) != len(labels):
        raise ValueError("input_ids 与 labels 长度不一致。")

    spans: list[tuple[int, int, str]] = []
    start: int | None = None
    for position in range(len(labels) + 1):
        selected = position < len(labels) and labels[position] != -100
        if selected and start is None:
            start = position
        elif not selected and start is not None:
            text = tokenizer.decode(
                input_ids[start:position],
                skip_special_tokens=False,
            )
            spans.append((start, position, text))
            start = None
    return spans
```

检查时对每个片段使用 `repr(text)` 输出，保留换行与特殊符号。需要人工核对：工具名、参数、完整回答、应生成的停止标记是否出现；用户和工具观察是否被误选；历史各轮是否符合数据设计。

这些函数只能验证结构与展示结果，**不能证明语义 mask 正确**。一个错误模板同样可能返回长度正确的全 0/1 列表。

### A.3 Collator 之后仍需复查

上游 labels 正确，不代表进入模型的 batch 正确。建议再次检查：

| 项目 | 验收要求 |
|---|---|
| Padding | padding 位置不产生目标损失，也不作为有效内容被关注 |
| Causal shift | 由模型或自定义 loss 处理一次，不重复位移 |
| Packing | 原始片段监督保持，独立段边界按设计处理 |
| 归一化 | 按 token、样本或 segment 的目标与实验定义一致 |
| 有效目标数 | 不出现全忽略样本或全忽略 batch |
| 停止行为 | 模型应生成的结束标记没有被遗漏 |
| 多模态 | 实际项目存在图像等输入时，不得只返回文本字段 |

### A.4 先做模拟测试，再用真实 tokenizer 检查

最小单元测试应覆盖：正常对话；缺少 mask；mask 长度错误；非二值 mask；超长样本；只有首位置被监督；完全没有监督目标；多段 assistant 目标的展示。

模拟测试只能检查程序分支。真实 tokenizer 的字符—token 边界、特殊 token、工具序列化和 generation mask，仍需使用目标模型的真实模板测试。本文代码未执行模型微调，也没有声称已经验证某个模型的训练效果。

## 附录 B：术语与符号速查

| 术语 | 本文中的含义 | 关键区别 |
|---|---|---|
| SFT | 对选定示范目标进行监督优化 | 不等于单一数据格式或参数更新方法 |
| Trajectory | 一次任务中的消息、动作与观察记录 | 不一定只是长思维链文本 |
| Policy / $\pi_\theta$ | 给定历史选择后续行为的条件分布 | 行为包含工具调用、沟通和停止 |
| $h_k$ | 第 $k$ 步前可见历史 | 与环境完整状态不必相同 |
| $a_k$ | 下一步动作 | 可由多个 token 表达 |
| Harness / scaffold | 运行框架、工具与提示等约定 | 与模型权重共同影响表现 |
| Teacher forcing | 使用记录好的前缀进行下一 token 监督 | 不等于自由执行，也不等于看未来 |
| Loss mask | 哪些位置计算直接预测损失 | 不决定哪些输入对模型可见 |
| Attention mask | 哪些位置之间允许信息交互 | 不等于监督范围 |
| Labels | 训练目标 token；忽略位置常用 `-100` | 需要核对位移与 padding |
| IM | 对指令与回答建模，排除固定模板 token | 重点研究小数据等条件的泛化 |
| WIT | 对 prompt 与 response 分别加权 | 原文按非零权重 token 数归一化 |
| SSB | 分别归一化推理与调用，再以系数组合 | 是 BalanceSFT 的一个组件 |
| HDR | 对困难任务重新生成并验证训练数据 | 是 BalanceSFT 的另一个组件 |
| Rejection sampling | 生成候选，再按质量或成功条件保留 | 可能偏向容易通过的任务 |
| ADP | 动作与观察的统一中间表示 | 不等于某个模型的 chat template |
| XTML | Kimi K3 的结构化消息序列化设计 | 结构、通道、选项与停止共同表达协议 |
| Packing | 将多个样本放进更长输入序列 | 是否隔离注意力是另一个问题 |
| On-policy | 数据由当前或接近当前策略产生 | 具体系统可能有异步带来的版本滞后 |
| DAgger | 聚合当前策略状态上的专家动作标签 | 不等于成功轨迹自训练 |
| MOPD | 多教师在学生生成状态上的蒸馏 | 不是普通离线教师文本 SFT |
| Pass@k | 多个候选里是否有成功解 | 衡量发现能力而非选择能力 |
| Best@k | 排序后选出的候选是否成功 | 同时依赖验证器 |
| Checkpoint | 某一训练阶段的参数快照 | 最终成绩好不一定最适合继续 RL |

本表为正文术语的汇总，具体证据与适用范围见相应章节。

## 附录 C：关键实验速查——结论必须带着条件读

## 附录 E：自测问题与参考答案

### E.1 为什么工具观察不计算 loss，模型仍然可以学习使用工具结果？

观察仍在输入上下文中，后续 assistant 动作以其为条件。忽略观察位置的直接预测损失，不等于遮蔽输入，也不等于切断后续输出对这些输入的依赖。应区分 loss mask 和 attention mask。

### E.2 为什么只用最终成功的轨迹，仍可能把模型训差？

成功不代表过程无坏习惯；成功筛选会偏向容易任务；重复采样可能降低有效覆盖；学生成功样本也未必包含其最需要学习的失败状态。SWE-Gym 的具体负面实验说明不能假设回流一定单调改善。

### E.3 为什么不能说 BalanceSFT 的全部收益来自新 loss？

它包含 SSB 与 HDR。Table 5 显示两者各有贡献；只比较完整方法与普通 SFT，无法把数据改进产生的收益全部归给损失函数。

### E.4 IM 与 WIT 是否证明所有 Agent 都应训练 prompt？

没有。它们在各自指令数据与模型设置中给出证据，尤其 IM 强调低资源与长输入短输出条件。长工具观察、网页噪声和多轮执行需要另外验证。

### E.5 删除历史错误动作，然后保留后面的成功观察，有什么问题？

可能破坏因果一致性。后续文件或环境已经发生变化，但保留下来的历史无法解释该状态。精简后需要重新执行验证，或在保留历史的情况下调整监督范围。

### E.6 为什么最强教师不一定产生最强学生？

教师独立完成任务的能力，与示范对特定学生的可学习性不是同一指标。论文消融证明了这种差异，但具体机制还需要控制策略、风格、覆盖等因素来检验。

### E.7 为什么 packing、EOS 与注意力隔离不能画等号？

Packing 是放置样本的方法，EOS 是序列符号；跨样本是否能互相注意由实际注意力与序列边界实现决定。完整打包不自动意味着独立计算。

### E.8 Pass@k 与 Best@k 差距大，意味着什么？

模型已经能产生更多成功候选，但验证器未能可靠选中它们。需要分别诊断生成与选择能力，并把额外采样预算计入比较。

### E.9 为什么 SFT 的最佳独立成绩不必对应最好的 RL 起点？

当前模仿质量与后续探索空间是不同目标。配方可能在提高当前表现的同时过度集中输出分布。需要让不同 SFT 候选接上相同 RL 条件后再比较，而不是仅看 SFT 排名。

### E.10 如何判断自己真的理解了这节课？

能够拿到一条轨迹，明确说出哪些信息是条件、哪些行为是目标、哪些片段不应模仿；能解释数据筛选如何改变分布；能检查渲染、mask 与 batch；能用目标 harness 验证自由执行；并且对论文结果的适用范围作出准确判断。

---

**全篇归纳：SFT 是有选择地模仿经验。数据决定模型看见哪些状态，表示决定它如何看见，监督决定它模仿哪些行为，运行与评测决定这些行为是否真正有用。**
