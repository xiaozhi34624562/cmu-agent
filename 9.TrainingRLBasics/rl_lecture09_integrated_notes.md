# 面向 LLM 工程师的强化学习
## Lecture 09 与六份参考资料贯通讲义：从 SFT、ReST 到 REINFORCE、GRPO 与 DrGRPO

> 核心问题：当我们不能为每一步提供唯一的标准答案，只能评价一次尝试的结果时，怎样让模型通过尝试改进自己的行为？
>
> 阅读主线：**任务目标 → 交互轨迹 → 探索与筛选 → 奖励到梯度 → 优势估计 → 更新约束 → 归一化偏差 → 训练系统与独立评测。**

本文合并、重组前面几轮课程讲解，以 Daniel Fried 的 Lecture 09《RL Foundations for Agents: From SFT to policy gradients》为骨架，将 ReST、ReST-EM、Williams 的 REINFORCE、Sean Welleck 的 RL Fundamentals、DeepSeekMath 和 DrGRPO 放进同一条问题链路，而不是分别做论文摘要。

**材料范围。**讨论以所提供的 PDF 版本为准，不涉及最新训练框架接口或当前模型排名。Lecture 09 刻意省略的概率比率、clipping 和 reference-model 项，使用参考材料补充；异步 RL、通用离策略学习、DPO 的完整理论不是本讲的主要内容。

**内容标识。**“原文结论”指材料报告的定义、方法或实验；“推导说明”指基于材料公式、在明确假设下进一步展开的解释；“工程建议”指由这些机制得到的实现与实验设计建议，不冒充论文已验证的生产方案。不同论文的实验不能被视为同一受控实验，也不将它们的结果强行归结为一个普遍结论。

**引用方式。**正文使用可独立阅读的材料简称、章节和 PDF 页码，例如 `[DSM，§4.1.1，PDF p.13]`。页码均从 PDF 第一页算起；Williams 论文的 PDF 页码与期刊页码不同。文末给出材料全名、对应文件和回读索引。

## 0. 课程地图：七份材料分别解决什么问题

### 0.1 不是七段知识，而是一条逐步解决困难的链路

Lecture 09 从 SFT 的三个错位出发，将交互表示为轨迹，先介绍成功轨迹上的自训练，再推导策略梯度，最后讨论 baseline、组相对优势、GRPO 和 DrGRPO。其第 44 页将方法统一为“对采取过的动作计算梯度，再用不同权重决定怎样更新”。[L09，PDF pp.2–44]

### 0.2 全文反复使用的三个层次

**任务层：我们希望什么发生？**例如找到数字、代码通过任务测试、生成得到人类认可的翻译。

**估计层：怎样从有限尝试中形成学习信号？**例如成功样本过滤、回报、baseline、组中心化、价值预测。

**优化与系统层：怎样把信号变成可控的参数更新？**例如动作 token 的 log probability、mask、概率比率、clipping、损失聚合、数据刷新。

很多混乱来自跨层替换概念：把“reward model”当作“critic”，把“GRPO”当作“规则奖励”，把“输出更长”当作“任务能力更强”，或者把“loss 正常下降”当作“训练过程正确”。后文会逐一拆开。

### 0.3 统一符号，避免公式之间换了对象

| 符号 | 含义 |
|---|---|
| $x$ | 任务实例，例如一道题或一个代码任务 |
| $o_t$ | Agent 在时刻 $t$ 得到的观察 |
| $h_t$ | Agent 实际用于决策的历史或上下文 |
| $a_t$ | 第 $t$ 个动作，可是一条工具调用，也可采用 token 粒度 |
| $\pi_\theta(a_t\mid h_t)$ | 参数为 $\theta$ 的策略 |
| $\tau$ | 一次完整交互轨迹 |
| $r_{t+1}$ | 采取 $a_t$ 之后获得的奖励 |
| $R(\tau)$ | 整条轨迹的总回报 |
| $U_t$ | 从动作 $a_t$ 之后开始的未来回报，即 reward-to-go |
| $y_{1:T}$ | 单次文本回答的 token 序列 |
| $B$ | 一个批次中的任务数量 |
| $G$ | 每道题的采样回答或轨迹数量 |
| $T_i$ | 第 $i$ 条回答的实际动作 token 数 |
| $C$ | 所有回答共用的固定归一化常数，例如统一生成预算 |
| $\pi_{\mathrm{old}}$ | 产生当前批次样本的旧策略 |
| $\pi_{\mathrm{ref}}$ | KL 正则使用的参考策略 |
| $V_\phi$ | 学习出来的价值函数，也称 critic |
| $\hat A$ | 从有限样本或价值模型估计出的优势 |

为便于串讲，主体采用有限回合、未折扣回报，即 $\gamma=1$。介绍 FUND 中的 TD、GAE 时会注明折扣扩展。全文将“希望最大化的目标”记作 $J$，将送入最小化优化器的损失记作 $\mathcal L$；部分原文的命名与时间下标不同，本文只统一记号，不将不同目标视为相同目标。

## 1. 为什么有了 SFT，还需要 RL

**对应：L09 PDF pp.2–7；FUND PDF pp.2–12。**

### 1.1 同一道任务，可以有不止一种正确行为

Lecture 09 的 Number Search 设定如下：隐藏数字在 1～16 之间，Agent 有四次猜测机会。猜错后，环境告诉它“更大”或“更小”；只有找到数字，最终奖励才为 1。本次隐藏数字是 11。[L09，PDF p.2]

| 轨迹 | 交互过程的动作部分 | 结果 |
|---|---|---|
| $\tau_1$ | 8 → 12 → 10 → 11 | 成功，$R=1$ |
| $\tau_2$ | 4 → 8 → 12 → 11 | 成功，$R=1$ |
| $\tau_3$ | 16 → 8 → 9 → 10 | 次数耗尽，$R=0$ |
| $\tau_4$ | 1 → 2 → 3 → 4 | 次数耗尽，$R=0$ |

如果拿第一条轨迹做 SFT，训练目标是：

$$
\mathcal L_{\mathrm{SFT}}
=
-\sum_t\log\pi_\theta(a_t^*\mid h_t).
$$

它会在对应历史下，提高示范动作出现的概率。例如，最初提高“猜 8”的概率，收到“更大”之后提高“猜 12”的概率。[L09，PDF p.3]

问题在于，第二条路径虽然与示范不同，也可以成功。我们最终关心的不是“与第一条轨迹逐步一致”，而是“成功完成任务”。

### 1.2 三个错位分别是什么

**任务错位：模仿某个输出，不完全等于满足任务标准。**

代码字符串不同，不代表功能不同；检索路径不同，不代表证据不充分。讲义也提醒，不能把所有非示范动作都等同对待：收到“比 12 小”之后再猜 13，与采取另一条有效路径，不是同一种偏离。[L09，PDF p.4；FUND，PDF p.4]

**数据错位：真实数据里有失败，但直接模仿失败不合适。**

我们可能拥有大量带有错误的代码、无效工具调用和失败尝试。普通示范学习需要筛选目标；反馈学习希望利用结果，区分应该强化和应该减少的行为。[L09，PDF p.5；FUND，PDF p.5]

**暴露偏差：训练时的历史，与模型运行时制造的历史不一致。**

SFT 往往在给定示范前缀上预测下一步。运行时模型会产生自己的前缀，包括错误。它可能进入示范没有覆盖的状态。让当前模型在训练时生成轨迹，可以让学习过程接触这些状态。[L09，PDF pp.6–7；FUND，PDF pp.6–7]

**推导说明。**这不是说 SFT 不能学习多解、纠错或恢复；你完全可以提供这样的示范。也不是说一旦 on-policy 采样，模型就必然学会恢复。更准确的表述是：反馈学习改变了目标和数据产生方式，为学习这些行为提供了机会，收益仍取决于探索、评价与优化。

### 1.3 SFT 与 RL 的根本差别，写在期望的分布里

SFT 的典型目标是：

$$
\mathcal L_{\mathrm{SFT}}
=
-\mathbb E_{(x,y^*)\sim D}
\log\pi_\theta(y^*\mid x).
$$

任务级 RL 目标是：

$$
J(\theta)
=
\mathbb E_{x\sim D}
\mathbb E_{\tau\sim p_\theta(\cdot\mid x)}
[R(\tau)].
$$

前者对固定目标数据做拟合；后者关心当前策略产生的结果。二元成功奖励下，后者就是平均成功概率。[FUND，PDF p.3；L09，PDF p.13]

### 1.4 RL 不等于某一种损失函数

FUND 将 RL 同时称为一类问题、一类求解方法和一个研究领域，并区分策略、价值和环境模型等路线。本讲集中讨论策略梯度及相关自训练方法，并不是整个 RL 课程。[FUND，PDF pp.14、25]

因此，判断一个训练流程，必须分开看：

| 整体循环 | 局部更新 |
|---|---|
| 谁生成数据、如何探索、用什么反馈、多久重新采样 | 用交叉熵还是策略代理损失、哪些 token 求导、权重如何计算 |

**用交叉熵更新参数，并不意味着整体流程没有反馈学习；用了名为 GRPO 的 loss，也不意味着探索与评价就自动正确。**这正是理解 ReST 的起点。

## 2. 把学习对象定义清楚：策略、历史、轨迹与回报

**对应：L09 PDF pp.8–13；FUND PDF pp.19–26。**

### 2.1 策略就是给定上下文的动作分布

$$
\pi_\theta(a_t\mid h_t)
$$

回答的是：“在模型实际看到的上下文里，各个动作应该以多大概率被选择？”对语言模型来说，最细的动作可以是下一个 token；对 Agent，可以把一条完整工具调用看成较高层动作，再拆成 token 概率。[L09，PDF pp.9、21；FUND，PDF p.24]

例如：

```text
较高层动作：search("目标公司的最新公告")
底层动作：构成这条调用的逐个 token
```

采用整段回答作为一个宏观动作，或者采用逐 token 的序列决策，是不同粒度的建模。FUND 在 RLVR 预告中使用了一步 MDP 的说法，在基础建模时则使用 token MDP。[FUND，PDF pp.24、46]

**推导说明。**未经 clipping 的整段对数概率可以拆成 token 对数概率之和；但“对整段概率比做 clipping”与“分别对每个 token 的概率比做 clipping”一般不同。不能因为底层来自同一个语言模型，就把两种代理目标视为等价。

### 2.2 环境状态、观察、Agent 使用的信息不是一回事

Number Search 的真实数字属于环境内部状态。模型看不到 11，只能看到自己猜过什么以及环境给出的反馈。

$$
h_t=(o_0,a_0,o_1,\ldots,o_t).
$$

FUND 更明确地区分环境私有状态、可见观察和 Agent 用来选择动作的信息表示。[L09，PDF p.10；FUND，PDF p.23]

**工程建议。**对长任务 Agent，必须记录每一步实际使用的上下文。完整日志里有某个数字，不代表模型在决策时也看到了这个数字；它可能已经被压缩、截断，或者没有被加载。将事后完整日志直接回放训练，可能改变 $\pi_\theta(a_t\mid h_t)$ 中的条件。

### 2.3 一次交互就是一条轨迹

$$
\tau=(o_0,a_0,r_1,o_1,\ldots,a_{H-1},r_H,o_H).
$$

这里用 $H$ 表示环境动作数，避免与文本 token 数 $T$ 混淆。

总回报是：

$$
R(\tau)=\sum_{t=0}^{H-1}r_{t+1}.
$$

Number Search 的奖励只有最后成功时才出现，所以成功轨迹总回报为 1，失败为 0。[L09，PDF p.11]

把讲义中策略与环境两部分展开，轨迹概率可写成：

$$
p_\theta(\tau\mid x)
=
p(o_0\mid x)
\prod_{t=0}^{H-1}
\pi_\theta(a_t\mid h_t)
P(o_{t+1},r_{t+1}\mid h_t,a_t,x).
$$

这个完整写法显式保留初始观察分布和环境转移项；它们就是讲义图中与策略概率相乘的部分。[L09，PDF p.12]

### 2.4 优化的不是一条轨迹，而是轨迹分布

讲义第 13 页给出四条轨迹的概率：

$$
p(\tau_1,\tau_2,\tau_3,\tau_4)
=(0.30,0.20,0.25,0.25).
$$

期望回报为：

$$
0.30\times1+0.20\times1+0.25\times0+0.25\times0=0.50.
$$

我们希望把更多概率分配给成功行为，而不需要强迫所有成功行为都变成同一条路径。[L09，PDF p.13]

**贯穿全讲的直觉：RL 不是给某个已生成答案“加分存档”，而是利用这次结果改变以后生成行为的概率。**

## 3. ReST：用探索和筛选构造更好的训练数据

**对应：L09 PDF pp.14–16；REST §3–4。**

### 3.1 最简单的反馈学习循环

先让模型尝试，再保留成功结果，最后做监督训练：

```text
当前模型 → 多次生成 → 外部评价 → 过滤低质量样本 → 监督训练 → 新模型
```

在 Number Search 中，只保留 $\tau_1$、$\tau_2$：

$$
\mathcal L_{\mathrm{ReST}}
=
-\sum_{i:R(\tau_i)=1}
\sum_t\log\pi_\theta(a_{i,t}\mid h_{i,t}).
$$

这就是 Lecture 09 展示的简化形式。[L09，PDF pp.15–16]

### 3.2 学习自己的数据，为什么不是在原地踏步

原模型成功率为 0.5，但筛选后的数据不再是原模型的完整分布。对于前面的四条轨迹，保留成功并重新归一化后：

$$
q(\tau_1,\tau_2,\tau_3,\tau_4)
=(0.60,0.40,0,0).
$$

**推导说明。**这个例子忽略了有限采样误差，并假设我们可以直接谈论四条轨迹的分布。它说明有效的“老师”不是原模型自己，而是：

$$
\boxed{\text{原模型}+\text{探索}+\text{外部选择}}
$$

EM 论文将这种结构与 Expert Iteration 联系起来：先用策略与搜索构成更好的专家分布，再把专家行为蒸馏回模型。该论文实际采用温度采样与反馈过滤，而不是完整树搜索。[EM，§4，PDF p.5]

### 3.3 原始 ReST 的重点，是 Grow 和 Improve 不必同频

REST 将整个过程划分为两个循环：外层 Grow 更新数据，内层 Improve 在固定数据上多次训练。[REST，§1、§3，PDF pp.2–4]

```text
Grow：当前模型生成一批候选，并统一评分
  → Improve 1：过滤、训练
  → Improve 2：提高过滤阈值、继续训练
  → Improve 3：再次过滤、继续训练
  → 下一轮 Grow：让更新后的模型生成新数据
```

**原文结论。**因为生成数据昂贵，一次 Grow 后多次 Improve 可以摊薄生成成本。原论文的 Improve 允许普通 NLL，也允许其他离线 RL 损失；它不是只有一种固定的训练器。[REST，PDF pp.2、4]

原论文还将生成数据与原始数据混合，并在连续 Improve 时降低学习率，以应对筛选后数据越来越小等问题。[REST，PDF pp.3–4]

### 3.4 奖励可以通过“数据入口”发挥作用

REST 在机器翻译实验中比较了多种 Improve 损失，普通行为克隆 BC/NLL 在所比较配置的奖励模型得分上表现较好。虽然 BC 本身没有奖励权重，奖励已经通过过滤决定哪些样本可以训练。[REST，§4，PDF p.7，Fig.5]

这带来一个重要工程认识：**优化反馈学习系统，不一定先从复杂 loss 开始。选择什么数据、保留多少数据、什么时候刷新数据，本身就能改变学习效果。**

但这不是“简单交叉熵普遍优于 RL 损失”的证据。上述结论来自特定翻译任务、评分器和实验配置。

### 3.5 筛选成功样本有边界

过滤阈值越高，数据集可能越小、越缺乏多样性，模型容易过拟合。REST 特别提醒：在具有随机动态的环境里，按单次高回报筛选，可能偏向结果方差较大的行为；其论文的语言生成与翻译分析使用确定性的环境设定。[REST，§3，PDF p.4]

**工程建议。**代码测试、外部工具和网页交互中，要区分策略好坏与偶然成功。服务超时、外部数据变化和测试随机性，都可能使“这一条成功了”不能直接等同“这种策略可靠”。在环境随机性明显时，应设计重复验证或更加稳定的评价，而不是无条件复制成功轨迹。

## 4. ReST-EM：先改进分布，再把分布学进模型

**对应：L09 的 Expert Iteration 段落；EM §3–5。**

### 4.1 从经验流程到概率解释

EM 论文引入一个二元最优性变量 $O$。$O=1$ 表示输出符合高质量条件。一般情况下：

$$
P(O=1\mid x,y)\propto f(R(x,y)),
$$

其中 $f$ 是非负、单调不减的函数。在二元成功奖励下，可以直接令：

$$
P(O=1\mid x,y)=R(x,y).
$$

论文希望提高观察到 $O=1$ 的对数似然。[EM，§3，PDF p.3]

### 4.2 E-step：如果已经知道成功，哪些回答应该被学习

固定任务 $x$，给定旧模型，成功条件下的输出分布为：

$$
q(y\mid x)
=
\frac{\pi_{\mathrm{old}}(y\mid x)R(x,y)}{Z(x)},
\qquad
Z(x)=\mathbb E_{y\sim\pi_{\mathrm{old}}}[R(x,y)].
$$

要求 $Z(x)>0$。二元奖励下，$Z(x)$ 就是旧模型的成功概率。

这个分布保留了旧模型对不同成功解法的相对倾向，将失败解法的权重置零，再归一化。采样后过滤，就是对这一目标分布的近似构造。[EM，§3，PDF pp.3–4]

### 4.3 M-step：训练模型接近成功条件分布

$$
\theta_{\mathrm{new}}
=
\arg\min_\theta
D_{\mathrm{KL}}\big(q(\cdot\mid x)\|\pi_\theta(\cdot\mid x)\big).
$$

当 $q$ 固定时，等价于最大化：

$$
\mathbb E_{y\sim q}[\log\pi_\theta(y\mid x)].
$$

也就是用好的样本进行最大似然学习。[EM，§3，PDF p.4]

**直观总结：E-step 决定“值得学的行为分布”，M-step 决定“怎样让模型表达这个分布”。**

### 4.4 为什么可以用 EM：变分下界提供了连接

引入分布 $q$ 后，由 Jensen 不等式：

$$
\log P_\theta(O=1\mid x)
\geq
\mathbb E_q[\log P(O=1\mid x,y)]
-
D_{\mathrm{KL}}(q\|\pi_\theta).
$$

E-step 优化 $q$，M-step 优化 $\theta$。在原文的理想优化条件下，两步交替不会降低这个下界。[EM，§3，PDF p.4，Eq.2]

**适用条件。**实际系统中，我们只有有限样本、近似优化、有限模型容量，还可能用新的初始化重新训练。因此，理论中的下界性质不能直接翻译成“每轮真实测试成绩一定上升”。原论文自身也观察到部分任务继续迭代后测试成绩回落。[EM，§5.1，PDF pp.8–9]

### 4.5 推导补充：奖励加权为什么构造了更好的目标分布

对于固定问题、确定性的非负输出奖励，若 $Z=\mathbb E_\pi[R]>0$ 且二阶矩有限，令 $q\propto\pi R$，则：

$$
\mathbb E_q[R]
=
\frac{\mathbb E_\pi[R^2]}{\mathbb E_\pi[R]}
=
\mathbb E_\pi[R]
+
\frac{\operatorname{Var}_\pi(R)}{\mathbb E_\pi[R]}.
$$

因此，这个理想目标分布的平均奖励不低于旧分布。二元奖励下，它只包含成功输出。

**这是基于奖励加权公式的推导，不是额外实验，也不是现实神经网络训练的单调改进保证。**它不能直接推广成“我们能任意控制随机环境中的整条成功轨迹分布”；REST 对随机环境过滤的警告仍然成立。

### 4.6 一个影响实现的细节：每题归一化，与全局样本聚合并不相同

EM 论文 Eq.3 写出的实际奖励加权目标是：

$$
H(\theta;\theta_k)
=
\mathbb E_{x\sim D}
\mathbb E_{y\sim\pi_{\theta_k}}
[R(x,y)\log\pi_\theta(y\mid x)].
$$

而将每道题的条件分布 $q(y\mid x)$ 归一化后，再按相同任务权重拟合，会出现每题的 $1/Z(x)$ 因子。[EM，§3，PDF p.4，Eq.3]

**推导说明。**对固定一道题，$Z(x)$ 只是常数；但多道题共享参数时，各题的常数不同，会改变题目权重。$\mathbb E_x[Z_\theta(x)]$ 与 $\mathbb E_x[\log Z_\theta(x)]$ 也不是同一个多任务目标。本讲保留论文的 Eq.3，同时明确区分它与逐题规范化解释，不把它们无条件当作相同的全局优化问题。

这件事将在 DrGRPO 中再次出现：**归一化与数据聚合，都在规定哪些任务更重要。**

### 4.7 ReST-EM 与 ReST 的关键实现差异

| 设计 | 原始 ReST | ReST-EM 的论文实验 |
|---|---|---|
| 反馈 | 翻译任务中的学习型连续评分 | 数学、代码任务中的二元验证 |
| 数据组织 | 生成数据与原始数据混合 | 不混入人工输出 |
| 一轮内部 | 可多次提高过滤阈值并 Improve | 二元奖励下不同中间阈值等效 |
| 下一轮生成 | 用改进后的模型 | 用改进后的模型 |
| 下一轮训练起点 | 延续上一轮策略 | 重新从原始基础模型微调 |

这些区别来自两篇论文的方法说明，而不是对所有“自训练”方法的定义。[REST，§3；EM，§3，PDF p.5]

ReST-EM 的 APPS 消融显示，重新从基础模型训练与延续上一轮的任务内表现接近，但前者对 HumanEval 的迁移较好。[EM，§5.3，PDF p.11，Fig.7]

**工程理解：数据生成器持续改进，与学习器参数持续继承，是两个独立选择。**

### 4.8 人工答案与模型答案：实验控制了什么，没有控制什么

ReST-EM 先观察到模型生成数据的效果优于人工示范，但二者可能包含不同数量的解法。为控制这个因素，作者选出约 5,000 道模型已经能生成正确解的题，比较每题一条人工解法与每题一条随机选出的模型正确解法。在这个子集上，模型生成数据仍然表现更好。[EM，§5.3，PDF pp.10–11，Fig.6]

作者提出“模型生成解法更贴近模型已有分布”作为可能解释；这是解释性假设，而不是已经排除其他原因的定论。实验也只覆盖特定模型、任务和可解题目子集。[EM，PDF p.10]

对工程更稳妥的启发是：**训练数据既要正确，也要可学习。经过外部验证、当前模型能够表达的解法，可以成为有价值的训练材料。**

## 5. REINFORCE：不可微的奖励怎样变成梯度

**对应：L09 PDF pp.17–24；W92 §4、§5、§7；FUND PDF pp.28–31。**

### 5.1 不对测试结果求导，而对产生行为的概率求导

考虑代码任务：

```text
模型参数 → token 分布 → 采样代码 → 执行测试 → 得到通过/失败
```

采样是离散的，外部测试通常不可微。RL 不要求计算“测试是否通过对某个字符的导数”。它需要估计参数变化怎样影响高回报代码的出现概率。[L09，PDF p.18]

固定任务，写出：

$$
J(\theta)=\sum_\tau p_\theta(\tau)R(\tau).
$$

假设奖励、环境没有对参数 $\theta$ 的直接依赖，且可以交换求导与求和：

$$
\begin{aligned}
\nabla_\theta J
&=\sum_\tau R(\tau)\nabla_\theta p_\theta(\tau)\\
&=\sum_\tau p_\theta(\tau)R(\tau)
\nabla_\theta\log p_\theta(\tau)\\
&=\mathbb E_{\tau\sim p_\theta}
[R(\tau)\nabla_\theta\log p_\theta(\tau)].
\end{aligned}
$$

这就是 score-function 梯度估计。L09 与 FUND 都通过 $\nabla p=p\nabla\log p$ 来推导它。[L09，PDF p.19；FUND，PDF p.29]

### 5.2 为什么不需要知道环境转移概率

对轨迹概率取对数：

$$
\log p_\theta(\tau\mid x)
=
\log p(o_0\mid x)
+\sum_t\log\pi_\theta(a_t\mid h_t)
+\sum_t\log P(o_{t+1},r_{t+1}\mid h_t,a_t,x).
$$

环境项不直接依赖模型参数，因此：

$$
\nabla_\theta\log p_\theta(\tau\mid x)
=
\sum_t\nabla_\theta\log\pi_\theta(a_t\mid h_t).
$$

于是单条轨迹给出的梯度估计为：

$$
\hat g
=
R(\tau)\sum_t\nabla_\theta\log\pi_\theta(a_t\mid h_t).
$$

帽子表示有限采样估计，不是精确梯度。我们仍然需要环境提供反馈，但不需要显式学习或求导环境转移函数。[L09，PDF pp.20–21；FUND，附录，PDF pp.48–50]

### 5.3 Williams 原论文：一次结果怎样分配到模型参数

原始 REINFORCE 定义不是只有一个无 baseline 的特例，而是：

$$
\Delta w_{ij}=\alpha_{ij}(r-b_{ij})e_{ij},
\qquad
e_{ij}=\frac{\partial\log g}{\partial w_{ij}}.
$$

$e_{ij}$ 被称为 characteristic eligibility，刻画参数对当前随机输出概率的影响；$r-b$ 则表示结果相对基准的好坏。[W92，§4，PDF p.6]

可以把它理解成：

$$
\underbrace{\text{这次结果值得强化多少}}_{r-b}
\times
\underbrace{\text{哪些参数使这次行为发生}}_{\nabla\log\pi}.
$$

原论文要求 baseline 在给定输入和参数后与当前随机输出条件独立。统一学习率时，期望更新等于学习率乘以期望奖励的梯度；更一般的非负参数级学习率条件下，论文给出期望更新与目标梯度夹角的性质。[W92，§4，PDF p.6，Theorem 1]

**重要边界。**保证期望方向，不等于每条轨迹的更新都改善模型，也不等于任意步长、任意函数逼近条件下都会收敛。W92 的 §8.1 专门指出，前面的分析并不自动给出收敛保证。[W92，PDF pp.15–16]

### 5.4 最后仍然使用反向传播

构造最小化损失：

$$
\mathcal L_{\mathrm{PG}}
=
-R(\tau)\sum_t\log\pi_\theta(a_t\mid h_t).
$$

然后照常反向传播。W92 的 §7 将随机输出处的统计梯度与确定性网络内部的链式求导连接起来。[W92，PDF pp.12–13]

所以，“不能直接穿过采样与环境求导”不等于“RL 不使用 backpropagation”。

### 5.5 LLM 的计算形式：teacher forcing、mask 和权重

一条工具调用由多个 token 构成时：

$$
\log\pi_\theta(a_t\mid h_t)
=
\sum_k\log\pi_\theta(u_{t,k}\mid h_t,u_{t,<k}).
$$

因此，在 rollout 完成后，可以回放真实前缀，计算已生成 token 的 log probability。计算方式与 SFT 相似，但前缀和目标来自模型自己的尝试，权重来自结果。[L09，PDF pp.21–23]

$$
\mathcal L_{\mathrm{PG}}
=
-R(\tau)\sum_km_k\log\pi_\theta(u_k\mid u_{<k}).
$$

$m_k=1$ 表示策略实际采样的 token，包括模型采样的结束标记；$m_k=0$ 表示用户输入、工具观察或其他模型没有选择的上下文。[L09，PDF p.22]

工具结果被 mask 掉损失，不代表模型不能利用它。它仍然影响后续动作，只是不把“预测工具结果”作为该策略更新的训练目标。

### 5.6 为什么二元 REINFORCE 看起来像 ReST

当 $R\in\{0,1\}$、不使用 baseline：

$$
-R_i\log\pi_\theta(\tau_i)
=
\begin{cases}
-\log\pi_\theta(\tau_i),&R_i=1,\\
0,&R_i=0.
\end{cases}
$$

于是，它与成功轨迹上的监督学习具有相同的局部计算形式。L09 第 24 页明确强调了这种联系，同时保留批量更新与数据聚合等区别。[L09，PDF p.24]

### 5.7 与 ReST-EM 的更精确连接：在更新起点，共享一个梯度

固定旧策略 $\pi_{\theta_k}$，使用 EM Eq.3 形式：

$$
H(\theta;\theta_k)
=
\mathbb E_{x\sim D,y\sim\pi_{\theta_k}}
[R(x,y)\log\pi_\theta(y\mid x)].
$$

在 $\theta=\theta_k$ 时：

$$
\left.\nabla_\theta H(\theta;\theta_k)\right|_{\theta=\theta_k}
=
\left.\nabla_\theta J(\theta)\right|_{\theta=\theta_k}.
$$

**推导说明。**这个相等针对论文式的原始奖励加权、相同任务权重、当前策略采样的理想期望；不能忽略前文讨论的每题归一化、有限筛选与其他损失项。

当继续在旧数据上更新多步后，$\theta\ne\theta_k$，它就不再是当前策略原始 on-policy 梯度的同一估计。EM 论文将“固定旧策略生成数据、解耦采样与优化”作为其关键特点。[EM，§3，PDF p.4]

**这条连接把两篇论文串起来了：ReST-EM 可以看成一次较充分的分布拟合；on-policy 策略梯度则不断以当前策略的尝试重新估计改进方向。**

## 6. Baseline 与 advantage：利用失败，降低梯度噪声

**对应：L09 PDF pp.25–34；W92 §4、§8.3；FUND PDF pp.38–40。**

### 6.1 奖励的绝对大小，不等于这次表现的学习价值

一次得到 0.6 分，到底好不好？如果同样的任务平时只能得到 0.2，它很好；如果平时得到 0.9，它就不理想。我们希望比较：

$$
\text{实际结果}-\text{在当前条件下通常能做到的结果}.
$$

这就是 baseline 与 advantage 的出发点。无 baseline 的二元奖励 REINFORCE 对失败样本直接给出零权重；减去合适的基准后，失败也可以提供减少相应行为的信号。[L09，PDF pp.26–28]

### 6.2 V、Q、A 的区别

$$
V^\pi(h)=\mathbb E_\pi[\text{未来回报}\mid h]
$$

表示已经处于历史 $h$ 时，接下来按当前策略行动，预计能得到多少回报。

$$
Q^\pi(h,a)=\mathbb E_\pi[\text{未来回报}\mid h,\text{先采取 }a]
$$

表示第一步指定为 $a$，之后按当前策略行动的预期回报。

$$
A^\pi(h,a)=Q^\pi(h,a)-V^\pi(h).
$$

优势评价的是“相对当前策略平均水平好多少”，不是某个动作永远正确或错误。[L09，PDF p.27]

讲义用“候选数字只剩 9、10、11，还有两次机会”说明：猜中间的 10 可以得到更有用的反馈，通常比猜边缘的数字更有利。具体优势数值仍取决于候选数字的分布与后续策略，不能脱离这些条件给出固定的好坏幅度。

### 6.3 为什么减掉 baseline，不会改变期望梯度

在给定历史后，baseline $b(h)$ 不依赖当前采样动作，则：

$$
\begin{aligned}
\mathbb E_{a\sim\pi_\theta}
[b(h)\nabla_\theta\log\pi_\theta(a\mid h)]
&=b(h)\sum_a\pi_\theta(a\mid h)
\nabla_\theta\log\pi_\theta(a\mid h)\\
&=b(h)\sum_a\nabla_\theta\pi_\theta(a\mid h)\\
&=b(h)\nabla_\theta1\\
&=0.
\end{aligned}
$$

因此，减掉 baseline 后的梯度估计与原估计具有相同的期望。[L09，PDF p.29]

这里有两个条件不能混淆：

| 条件 | 含义 |
|---|---|
| 自动求导上固定 baseline | 在 actor loss 中不通过 baseline 反向传播 |
| 统计上不依赖当前动作 | 保证上述期望为零的条件 |

`detach()` 只能处理第一件事，不能自动保证第二件事。W92 的原始定义强调的是条件独立。[W92，§4，PDF p.6]

### 6.4 把讲义的二选一例子算透

设只有一个参数：

$$
p(A)=\sigma(\theta)=0.25,\qquad p(B)=0.75.
$$

动作 A 的奖励是 1，动作 B 的奖励是 0。其 log probability 对参数的导数为：

$$
\nabla_\theta\log p(A)=1-p=0.75,
\qquad
\nabla_\theta\log p(B)=-p=-0.25.
$$

| 采样结果 | 概率 | 无 baseline 的梯度 | $b=0.5$ 的梯度 |
|---|---:|---:|---:|
| A，奖励 1 | 0.25 | $1\times0.75=0.75$ | $(1-0.5)\times0.75=0.375$ |
| B，奖励 0 | 0.75 | $0\times(-0.25)=0$ | $(0-0.5)\times(-0.25)=0.125$ |

采到失败动作 B 时，带 baseline 的梯度仍然推动 $\theta$ 上升，从而提高 A 的概率、降低 B 的概率。[L09，PDF pp.30–31]

两个估计的平均值相同：

$$
0.25\times0.75+0.75\times0=0.1875,
$$

$$
0.25\times0.375+0.75\times0.125=0.1875.
$$

但是，梯度标准差从约 0.325 降到约 0.108。讲义的采样展示正是要说明：**相同的期望方向，可以有很不一样的噪声。**[L09，PDF pp.32–33]

### 6.5 更深一层：最小方差 baseline 不一定是平均奖励

FUND 推荐预期未来回报作为一个自然的 baseline。W92 的 §8.3 则提醒，若以最小化权重更新方差为目标，最优 baseline 一般不是简单平均奖励。[FUND，PDF p.39；W92，PDF p.17]

**推导说明。**固定历史 $h$，记：

$$
s=\nabla_\theta\log\pi_\theta(a\mid h).
$$

在上述独立性条件下，梯度均值不随 $b$ 改变。最小化梯度估计的总方差，可以转化为最小化：

$$
\mathbb E[(R-b)^2\|s\|^2].
$$

对 $b$ 求导，得到：

$$
b^*=
\frac{\mathbb E[R\|s\|^2]}{\mathbb E[\|s\|^2]}.
$$

这个式子不仅看奖励，也看不同动作对应的参数梯度有多大。它针对这里的固定历史、单项梯度方差问题，不是完整长轨迹所有协方差问题的通用最优解。

在上面的二选一例子里，$b=0.75$ 时，两种采样结果的梯度都恰好是 0.1875，方差为零；而平均奖励只有 0.25。这是一个特殊的教学例子，不是实际 LLM 应设置的 baseline 常数。

**工程意义：baseline 的目的，是更高效地使用已有反馈，而不是形式上把奖励减一个均值。**训练一个复杂 baseline 的收益，也应与其估计误差和计算成本一起评估。

### 6.6 方差降低，不等于精确找到了错误位置

如果代码前面十步都正确，最后一行写错导致失败，那么给整条轨迹同一个负优势，仍然没有准确识别最后一行的责任。

Lecture 09 明确指出，共享整条轨迹优势的 baseline 方法可以减少噪声，却没有解决细粒度信用分配。[L09，PDF p.34]

这引出下一节：我们需要区分“结果有没有超过预期”和“究竟是哪一步改变了结果”。

## 7. 信用分配：从终局奖励到 reward-to-go、critic 与 GAE

**对应：L09 PDF pp.34–35；FUND PDF pp.37–43；DSM §4.1.3。**

### 7.1 Reward-to-go：动作只对未来奖励负责

定义：

$$
U_t=\sum_{k=t}^{H-1}r_{k+1}.
$$

原始总回报包含采取 $a_t$ 之前已经发生的奖励。那些奖励不受当前动作影响，用它们给当前动作加权只增加噪声。使用未来回报可以去掉这部分无关信息，而不增加相应的策略梯度偏差。[L09，PDF p.35；FUND，附录，PDF p.50]

只有终局奖励时，每一步的 $U_t$ 仍然相同。因此，reward-to-go 不会自动为最终答错的一长段推理定位错误。

### 7.2 折扣：它也在规定什么样的成功更重要

FUND 引入折扣未来回报：

$$
U_t^{(\gamma)}
=
\sum_{k=t}^{H-1}\gamma^{k-t}r_{k+1},
\qquad 0<\gamma\leq1.
$$

远期奖励被赋予较低权重。[FUND，PDF p.37]

**推导说明。**引入折扣不是无条件保持原“最终成功率”目标不变的数值技巧。主体采用 $\gamma=1$，以避免把更快得到奖励与最终能否成功混成同一标准。要采用折扣目标，应同时明确目标函数与梯度的时间加权约定，不能仅随手在代码中给回报乘一个系数。

### 7.3 Critic 与 reward model 是不同的模型

| 组件 | 它在问什么 | 典型输入 |
|---|---|---|
| Reward model / verifier | 已经生成的回答或步骤得多少分 | 完整回答或完成的步骤 |
| Value model / critic | 从当前状态出发，按当前策略继续，预计得多少分 | 当前前缀或历史 |

Reward model 定义或近似评价标准；critic 预测当前策略的未来回报，用于优势估计。策略变化时，critic 的预测目标也会变化。[L09，PDF p.28；DSM，§4.1.1，PDF p.13]

把 critic 理解成“第二个给答案打分的模型”是不准确的。

### 7.4 TD 残差：一步行动是否改善了未来预期

统一到本文的时间下标：

$$
\delta_t
=
r_{t+1}+\gamma V_\phi(h_{t+1})-V_\phi(h_t).
$$

意思是：眼前得到的奖励，加上新状态的未来价值，是否高于旧状态的预期。若整道题最后才评分，训练出来的 critic 仍可能对不同前缀给出不同预测，因此每一步获得不同信号。[FUND，PDF p.40]

但预测可能不准，尤其当策略持续变化、前缀分布很广、终局反馈又很稀疏时。DSM 正是基于这些计算与预测困难，提出用组内分数替代额外价值模型。[DSM，PDF p.13]

### 7.5 GAE：混合不同跨度的 TD 信息

$$
\hat A_t^{\mathrm{GAE}}
=
\sum_{l=0}^{H-t-1}(\gamma\lambda)^l\delta_{t+l}.
$$

FUND 使用 $\alpha$ 表示这里的 $\lambda$；本文采用后者以免与学习率混淆。[FUND，PDF p.40]

当 $\lambda=0$ 时，只使用一步 TD；当 $\lambda=1$ 时，完整回合求和会展开为折扣未来回报减去当前价值，前提是终点价值为零。取中间值，是在反馈跨度与价值预测误差之间做取舍。

**边界。**TD/GAE 使信号具有位置差异，但不等于已经完成严格的因果责任识别。它们仍依赖奖励定义、采样与价值估计质量。

### 7.6 DeepSeekMath 的过程监督，走的是另一条路

DSM 不只讨论终局评分，还讨论在推理步骤结束时给出过程奖励。论文对步骤分数进行归一化，再用后续步骤的归一化奖励之和构成 token 的优势。在其比较实验中，过程监督版本优于结果监督版本。[DSM，§4.1.3，PDF p.14；§5.2.1，PDF pp.19–20，Fig.5]

这与训练 critic 的区别是：

**critic 试图预测原目标下将来的回报；过程奖励直接为中间行为规定评价。**

**工程建议。**奖励“有用的检索结果”与奖励“调用过检索”，奖励“检查发现了真实错误”与奖励“写出检查话术”，不是同一个目标。密集奖励可能增加可学习信号，也可能让模型更有效地优化错误代理指标。过程监督的结果应当由独立任务评测验证。

## 8. GRPO：用同一道题的多次尝试代替价值模型

**对应：L09 PDF pp.36–38、42；DSM §4.1.1–4.1.2；DR 附录 A。**

### 8.1 组相对优势的计算

对于同一个任务 $x$，采样 $G$ 个回答，得到奖励 $R_1,\ldots,R_G$：

$$
\bar R=\frac1G\sum_{i=1}^GR_i,
\qquad
\hat A_i=\frac{R_i-\bar R}{\sigma_R}.
$$

原始结果监督 GRPO 将同一回答的这个优势赋给所有生成 token。[DSM，§4.1.2，PDF p.14]

| 奖励组 | 组均值 | 优势，按讲义标准差计算 |
|---|---:|---|
| $[1,1,0,0]$ | 0.50 | $[1,1,-1,-1]$ |
| $[1,0,0,0]$ | 0.25 | 约 $[1.73,-0.58,-0.58,-0.58]$ |
| $[1,1,1,0]$ | 0.75 | 约 $[0.58,0.58,0.58,-1.73]$ |

每道题分别计算自己的均值和标准差，而不是把不同题目奖励混在一个组里。[L09，PDF pp.37–38]

**实现说明。**讲义数值对应按组内总体标准差计算的示例；代码库的标准差修正约定可能不同。实现必须明确分母约定和零方差处理，不能默认不同实现的数值完全一致。

### 8.2 组相对到底相对什么

它比较的是“同一个任务下，当前策略的不同尝试”，不是给所有题目设一个统一及格线。对于只成功一条的组，成功样本相对其他尝试更突出；对于只失败一条的组，失败样本更突出。[L09，PDF p.38]

但是，组均值仍然是题目级基准，不是每个 token 前缀的准确 $V^\pi(h_t)$。GRPO 减少了 critic 的训练需求，没有神奇地解决 token 级信用分配。

### 8.3 为什么 DeepSeekMath 要去掉 critic

论文指出，LLM PPO 中额外价值模型可能与策略模型规模相近，产生显存和计算开销；而多数奖励只出现在回答末尾，学习准确的逐 token 价值也有难度。因此，GRPO 用组内分数估计基准。[DSM，§4.1.1，PDF p.13，Fig.4]

论文还认为，组内相对计算适合奖励模型通常基于同题回答比较进行训练的特性。[DSM，PDF p.13]

**工程推论。**GRPO 是用多次采样换取不训练价值模型。它不是“没有 baseline”，也不是“没有探索成本”。长工具链 Agent 的多次 rollout 可能很贵，必须比较完整的生成、环境、评分与训练成本。

### 8.4 GRPO 与 PPO 并非全套互斥

要分开两个设计问题：

| 问题 | 选择示例 |
|---|---|
| 优势从哪里来 | learned critic、Monte Carlo 回报、同题组内比较 |
| 更新幅度如何约束 | 原始策略梯度、概率比率、PPO 式 clipping、KL |

GRPO 使用组优势，但仍保留 PPO 式概率比率与 clipping。Lecture 09 第 38 页为了讲清权重而省略这些项，第 42 页明确把它们留给更高级内容。DSM 则给出完整形式。[L09，PDF pp.38、42；DSM，PDF pp.13–14]

### 8.5 组均值包含自己：与 leave-one-out 的关系

baseline 无偏性要求不能依赖正在评价的当前采样动作，但组均值包含当前样本自己的奖励。

定义排除自身的 baseline：

$$
b_{-i}=\frac1{G-1}\sum_{j\ne i}R_j.
$$

则：

$$
R_i-b_{-i}
=
\frac G{G-1}(R_i-\bar R).
$$

DR 附录 A 明确给出这一关系，将中心化优势与 REINFORCE Leave-One-Out 联系起来。[DR，附录 A，PDF pp.13–14]

**推导说明。**同题条件独立采样、使用当前策略、没有标准差归一化与 clipping 时，组均值版本的期望策略梯度是：

$$
\mathbb E[\hat g_{\mathrm{group}}]
=
\frac{G-1}{G}\nabla J.
$$

固定 $G$ 时是统一尺度变化，不是不同任务的相对方向加权。它与每道题使用不同 $1/\sigma_R$ 的情况不同。实际优化器、梯度裁剪和多步更新可能进一步影响数值过程，因此不能把这个代数关系夸大成任意训练设置下完全相同的动态。

### 8.6 GRPO 不等于 RLVR

GRPO 描述的是一种优势估计与策略优化方式；RLVR 描述奖励来源可以由规则或验证器计算。DSM 的相关训练使用奖励模型，DR 的相关实验使用最终答案验证器。[DSM，§4.2，PDF p.15；DR，§3.2，PDF p.7]

所以，“不需要 critic”“不需要 reward model”“不需要 reference model”是三件不同的事。它们能否省略，分别取决于优势、奖励与正则的设计。

## 9. 完整的 GRPO：旧策略、概率比率、clipping 与 KL

**对应：L09 第 38、40 页明确省略的部分；FUND PDF p.41；DSM §4.1。**

### 9.1 旧策略解决“数据是谁生成的”这个问题

假设一批回答由 $\pi_{\mathrm{old}}$ 生成，而当前正在优化的是 $\pi_\theta$。对于已采样 token：

$$
\rho_{i,t}(\theta)
=
\frac{\pi_\theta(y_{i,t}\mid h_{i,t})}
{\pi_{\mathrm{old}}(y_{i,t}\mid h_{i,t})}
=
\exp(\log p_{\mathrm{new}}-\log p_{\mathrm{old}}).
$$

它表示当前策略相对采样时的策略，对这个已发生动作的概率改变了多少。[DSM，PDF pp.11、13]

在初次更新前，$\rho=1$，但其对当前参数的导数不为零。不能把概率比直接替换成不带计算图的常数 1。

### 9.2 Clipping 是代理目标里的限制，不是任意参数变化的硬边界

$$
S_{i,t}
=
\min\left(
\rho_{i,t}\hat A_i,
\operatorname{clip}(\rho_{i,t},1-\epsilon,1+\epsilon)\hat A_i
\right).
$$

正优势动作的概率已经被提高很多时，不再继续给予同样的增加动机；负优势动作的概率已经被压低很多时，也不再无限鼓励继续压低。[FUND，PDF p.41；DSM，PDF p.13]

以 $\epsilon=0.2$ 为例：

| 情况 | 未截断项 | 截断项 | 取最小后的含义 |
|---|---:|---:|---|
| $\hat A=1,\rho=1.5$ | 1.5 | 1.2 | 正向强化在该方向上饱和 |
| $\hat A=-1,\rho=0.5$ | -0.5 | -0.8 | 继续压低坏动作不再增加收益 |
| $\hat A=-1,\rho=1.5$ | -1.5 | -1.2 | 把坏动作提高太多仍受到惩罚 |

**推导说明。**clipping 不是将所有策略概率变化严格锁在 $[1-\epsilon,1+\epsilon]$ 内。模型共享参数，一个 token 的更新会影响其他 token；代理目标饱和也不等于全模型状态被硬约束。

另外，token 级概率比与 clipping 不是对任意陈旧完整轨迹分布的精确修复。前缀分布本身也由旧策略产生，因此不能把“有 ratio”理解成“旧数据可以无限复用而不产生近似问题”。

### 9.3 Old policy 与 reference policy 的区别

| 角色 | 回答的问题 | 变化节奏 |
|---|---|---|
| 当前 policy | 现在怎样选择动作 | 每次训练更新 |
| old policy | 这一批数据是怎样采出来的 | 对当前采样批次固定 |
| reference policy | 不希望离哪一个策略太远 | 在指定训练阶段作为正则锚点 |
| reward model / verifier | 结果得多少分 | 规则固定或在外层重新训练 |
| critic，若使用 | 当前前缀未来预计得多少分 | 跟随策略训练 |

这是一张概念角色表，不意味着实现必须同时保留五份完整模型；例如 old policy 的作用有时可以由可靠保存的采样 log probability 表达。DSM 的算法与结构图展示了不同角色的分工。[DSM，PDF pp.13–15，Fig.4、Algorithm 1]

### 9.4 KL 在这里是锚点，而不是另一个任务分数

DSM 的原始 GRPO 目标可概括为：

$$
J_{\mathrm{GRPO}}
=
\mathbb E\left[
\frac1G\sum_{i=1}^G\frac1{T_i}
\sum_{t=1}^{T_i}
\big(S_{i,t}-\beta K_{i,t}\big)
\right].
$$

论文将 KL 直接加入策略目标，避免先混入奖励再计算组优势。[DSM，§4.1.1，PDF p.13，Eq.3]

这里还要和 EM 中的 KL 分开：

$$
D_{\mathrm{KL}}(q_{\mathrm{good}}\|\pi_\theta)
\quad\text{用于拟合更好的目标分布；}
$$

$$
D_{\mathrm{KL}}(\pi_\theta\|\pi_{\mathrm{ref}})
\quad\text{用于限制偏离参考策略。}
$$

**同样是 KL，方向、优化对象和作用不同。**前者将模型拉向一个改进分布，后者为策略变化设置约束。[EM，§3；DSM，§4.1.1]

### 9.5 KL 样本估计项的边界

DSM 使用的样本项为：

$$
K_{i,t}
=
\frac{\pi_{\mathrm{ref}}}{\pi_\theta}
-\log\frac{\pi_{\mathrm{ref}}}{\pi_\theta}-1,
$$

各概率在同一前缀、同一个已采样 token 上求值。[DSM，PDF p.14，Eq.4]

**推导说明。**这个表达式在正概率下非负；比值为 1 时为零。对固定前缀，如果 token 来自当前 $\pi_\theta$ 且满足支持集条件，其期望等于相应的 KL。若数据来自旧策略并已进行多次更新，不能无条件沿用“当前策略采样下”的无偏说法。

另外，样本值对某个统计量无偏，与把固定样本上的表达式直接求导就获得该统计量完整无偏梯度，不是同一个命题。本讲只解释原文的样本项和角色，不把整个有限采样、多步 clipping 训练称为完全无偏。

### 9.6 两篇论文的具体配置，不是可直接照搬的超参数答案

| 项目 | DeepSeekMath 的 RL 设置 | DrGRPO 论文设置 |
|---|---|---|
| 奖励 | 学习型奖励模型 | 规则验证最终答案 |
| 每题输出数 | 64 | 8 |
| 生成上限 | 1,024 token | 3,000 token |
| 策略学习率 | $10^{-6}$ | $10^{-6}$ |
| KL 系数 | 0.04 | 0 |
| 更新描述 | 每轮 exploration 后单次策略更新 | inner proximal update epoch 为 1 |

数据来自论文各自的方法与配置说明。[DSM，§4.2，PDF p.15；DR，附录 G，PDF p.19]

**注意单位。**“一次策略更新”与“一轮 proximal epoch”不应自动理解为相同数量的 optimizer step；epoch 还可能包含多个微批次。两篇论文的模型、任务和反馈不同，表格只用于理解设计，不用于断言某一组超参数更好。

## 10. DrGRPO：两个分母怎样改变模型行为

**对应：L09 PDF pp.39–40；DR §3.1–3.2、附录 A/C。**

### 10.1 为什么必须认真看 `sum`、`mean` 和 mask 的分母

原始 GRPO 的有效权重不仅包含 $R_i-\bar R$，还包含：

$$
\frac1{\sigma_R}\times\frac1{T_i}.
$$

前者可能随任务变化，后者随回答变化。DR 认为，这两项会改变问题与回答的相对权重，而不只是改善数值尺度。[DR，PDF p.6，Fig.4]

### 10.2 回答长度偏差：长错误回答的 token 被较弱地压低

假设两条错误回答的优势都为 -1：

| 回答 | token 数量 | 每个 token 的系数 |
|---|---:|---:|
| 短错误回答 | 100 | $-1/100=-0.01$ |
| 长错误回答 | 1,000 | $-1/1000=-0.001$ |

长错误回答每个 token 的负向权重更小。对正优势而言，短正确回答每个 token 的正向权重更大。论文据此分析长度偏好，并在实验中观察到原始 GRPO 的错误回答持续变长。[DR，§3.1，PDF pp.6–8]

**边界。**这里说的是有效 token 权重与优化倾向，不是“任意长回答的总梯度一定较小”。参数共享、梯度方向和其他损失项仍然影响整体更新；也不能据此认定所有长推理都无效。

### 10.3 为什么长度分母会破坏前面的 baseline 抵消

**推导说明。**普通 baseline 使用：

$$
\mathbb E[b\nabla\log p_\theta(y)]=0.
$$

但引入依赖回答的长度后：

$$
\mathbb E\left[\frac b{T(y)}\nabla\log p_\theta(y)\right]
$$

一般不再为零，因为 $T(y)$ 是模型行为的函数。

因此，回答长度平均不是无条件保持原始期望回报梯度不变的常数缩放。这个推导连接了 W92 的 baseline 条件与 DR 的长度分析。[W92，§4；DR，§3.1、附录 A]

### 10.4 题目难度偏差：标准差归一化隐式改变题目权重

原始 GRPO 在每一道题内进行：

$$
\hat A_i=\frac{R_i-\bar R}{\sigma_R}.
$$

某题所有回答都被乘以 $1/\sigma_R$。对于二元反馈，几乎全对或几乎全错、但仍有差异的组，标准差较小，可能获得更强的缩放。DR 将其称为题目级难度偏差。[DR，PDF p.6]

完全全对或全错时，中心化结果为零，需要专门处理零标准差。不能把它误读成“标准差越接近零，所有组的有效学习信号就越大”。

**重要理解：标准化不是永远错误，而是它可能定义了另一个任务加权。是否需要这种加权，应当是有意识的设计。**

### 10.5 DrGRPO 怎样修改

优势改成：

$$
\hat A_i^{\mathrm{Dr}}=R_i-\bar R.
$$

回答聚合改成统一常数：

$$
\frac1C\sum_{t=1}^{T_i}(\cdots).
$$

其中 $C$ 对所有回答相同，论文用统一生成预算实现。保留概率比率和 clipping 后：

$$
J_{\mathrm{DrGRPO}}
=
\mathbb E\left[
\frac1{GC}\sum_{i=1}^G\sum_{t=1}^{T_i}
\min\left(
\rho_{i,t}\hat A_i^{\mathrm{Dr}},
\operatorname{clip}(\rho_{i,t},1-\epsilon,1+\epsilon)\hat A_i^{\mathrm{Dr}}
\right)
\right].
$$

这里写的是 DR 所讨论的无 KL 任务代理目标；其全文采用 $\beta=0$。[DR，§3，PDF p.5；§3.2，PDF pp.6–7；L09，PDF pp.39–40]

**“去偏”的范围。**它针对上述标准差与长度归一化相对于指定目标造成的偏差；不能进一步声称有限样本、多步 clipping、奖励误差等其他因素都消失了。组均值与 leave-one-out 的比例关系，也仍需放在相应假设下理解。

### 10.6 实验为什么有说服力：不只比较两个名字，还拆开两个改动

DR 主实验使用 Qwen2.5-1.5B 基础模型、R1 模板和最终答案验证，比较 GRPO 与 DrGRPO。其 Fig.5 将训练奖励、总输出长度、正确回答长度、错误回答长度和评测得分分开展示。[DR，§3.2，PDF p.7]

附录 C 的 Fig.8 又分别比较：原始 GRPO、只移除长度归一化、只移除标准差归一化、同时移除二者。移除长度项的版本更短，使长度变化与具体设计的关系更加清楚。Fig.9 报告三个独立运行的均值与波动，支持该设置中的 token 效率与表现改善。[DR，附录 C，PDF p.15]

**解释边界。**这些结果支持论文所研究模型与任务上的效果，不是所有任务上 DrGRPO 必然最佳的证明。更重要的可迁移方法，是用消融隔离变量，而不是把所有变化都归功于算法名字。

### 10.7 与 ReST-EM 串起来：数据选择也在做题目加权

若一道题单次成功率为 $p_x$，每题生成 $G$ 次，则成功样本数量的期望为：

$$
\mathbb E[N_{\mathrm{success}}(x)]=Gp_x.
$$

把全部成功样本直接混合训练，简单题通常贡献更多数据。EM 为此限制每题最多保留 10 条成功解法。[EM，PDF pp.7–8]

| 设计 | 它改变什么 |
|---|---|
| 保留所有成功样本 | 各题进入训练集的频次 |
| 每题归一化成功样本 | 各题的总权重 |
| 每题除以奖励标准差 | 各题更新幅度 |
| 每条回答除以自身长度 | 各回答中每个 token 的权重 |
| 固定常数 $C$ | 统一梯度尺度，不使用回答自己的长度作分母 |

**统一结论：从数据筛选到 loss reduction，都必须追问“谁因此变得更重要”。**

### 10.8 不要混淆三种平均

**工程推导。**设 token 代理项为 $\ell_{i,t}$：

$$
\text{逐回答平均：}\quad
\frac1N\sum_i\frac1{T_i}\sum_t\ell_{i,t};
$$

$$
\text{全批 token 平均：}\quad
\frac{\sum_i\sum_t\ell_{i,t}}{\sum_iT_i};
$$

$$
\text{固定预算平均：}\quad
\frac1{NC}\sum_i\sum_t\ell_{i,t}.
$$

第一种在同一批次内按回答长度改变 token 相对权重。第二种在当前批次内是统一标量，但分母随批次构成变化，跨批次仍影响尺度和随机权重。第三种使用预先定义的固定尺度。

它们不能被一概说成同一种长度偏差，也不能在梯度累积和多设备同步时随意替换。DR 对实现与公式不一致的讨论，是理解这些区别的入口；这里的三式对比是基于聚合定义的展开。[DR，PDF pp.6–7，Listing 1]

## 11. RL 为什么有时学不动：退化组、初始模型与模板

**对应：L09 PDF p.41；DR §2、§3.3–3.4；EM §5；DSM 的训练前置阶段。**

### 11.1 有数据，不一定有任务梯度

对于组相对方法：

$$
[0,0,0,0]\longrightarrow[0,0,0,0],
$$

$$
[1,1,1,1]\longrightarrow[0,0,0,0].
$$

奖励相同，减均值后优势全部为零。前者可能意味着题目太难，后者可能意味着题目太容易。[L09，PDF p.41]

这里的“零梯度”指组优势产生的任务梯度。若存在 KL、熵或其他辅助项，整体训练仍可能产生更新。

**工程推论。**训练步数、rollout 数和总 token 数，并不等于有效任务学习信号的数量。排查训练不提升时，要先看有多少组真正产生了奖励差异。

### 11.2 有效比较组的概率

**推导说明。**假设一道题每次尝试独立，成功概率都是 $p$，组大小为 $G$，则：

$$
P(\text{同时出现成功与失败})
=
1-p^G-(1-p)^G.
$$

取 $G=8$：

| 单次成功率 $p$ | 产生有效比较组的概率 |
|---:|---:|
| 1% | 约 7.7% |
| 10% | 约 57.0% |
| 50% | 约 99.2% |
| 90% | 约 57.0% |
| 99% | 约 7.7% |

这不是论文实验表，而是独立采样假设下的计算。真实输出存在相关性、任务难度变化或不同终止机制时，实际比例可能不同。

它说明：单纯增加训练步数，未必能解决几乎采不到成功行为的问题。可以改变题目难度、探索方式、示范数据或反馈信息量；这些也是讲义提出的方向。[L09，PDF p.41]

**边界。**一批全失败说明这一批缺少相应信号，不证明模型永远不能学会这道题。其他题目上的学习、改进采样和新的反馈，都可能改变之后的成功概率。

### 11.3 为什么不能照搬“只训练最难题”

组相对学习需要一定的差异性；成功样本自训练需要能采到值得保留的输出。过难题可能只有失败，过易题又可能几乎没有新的比较信息。

EM 将题目按基础模型成功率分组，观察到所有难度组都有改善，其中中等与较难问题的收益较大。[EM，§5.3，PDF p.12，Fig.8]

**工程建议。**不要把理论上的某个成功率直接设为通用最优课程阈值。应按真实任务统计有效组比例、样本质量、覆盖和单位成本收益，同时保留业务必须处理的容易题与困难题，避免训练分布偏离部署。

### 11.4 DrGRPO 不只讲 loss：模板先决定初始策略是什么

DR 比较基础模型在 R1、Qwen-Math 和不加模板下的行为。部分模型需要合适模板，才能从续写问题转为回答问题；Qwen2.5 系列在所研究场景中表现出不加模板也能回答的特点。[DR，§2.1，PDF p.3]

其 Table 1 对 Qwen2.5-Math-7B 的实验采用贪心解码与 3,000 token 预算，MATH500 得分分别为：

| 模板 | MATH500 |
|---|---:|
| R1 模板 | 0.0 |
| Qwen 模板 | 50.6 |
| 不使用模板 | 69.0 |

这是论文报告的特定版本、任务与设置，不是对所有模板和所有模型的建议；同一表中其他基准也没有表现出完全相同的排序。[DR，§2.2，PDF p.4，Table 1]

**工程认识：一条从很低分迅速上升的 RL 曲线，可能同时包含“学到更好的策略”和“恢复被不匹配模板压低的已有能力”。**

作者关于问答拼接预训练的解释被明确写为假设，本讲也不将其当作已证实的预训练细节。[DR，PDF p.4]

### 11.5 基础模型的能力，是 RL 的起点而不是背景噪声

DSM 在 RL 之前，已经完成领域继续预训练，以及 CoT、PoT、工具推理形式的监督微调；SFT 数据有 776K 条。其报告的 RL 增量，是 GSM8K 从 82.9% 到 88.2%，MATH 从 46.8% 到 51.7%。不能把整个模型的成绩全部归因于 GRPO。[DSM，PDF pp.2、10]

DR 则比较 Llama-3.2-3B 及其数学继续预训练版本，发现后续 RL 在更有数学知识的初始化上效果更强。论文称之为提高 RL ceiling；这里应理解为其训练设置与预算下观察到的水平，而不是已经证明了模型的理论能力上限。[DR，§3.4，PDF p.9]

**连接两篇论文：预训练、SFT、模板、任务分布与采样设置，共同构成 RL 的探索起点。算法名字不能替代对这个起点的测量。**

### 11.6 自我反思文字，也可能在 RL 之前就存在

DR 在多个基础模型，包括其测试的 DeepSeek-V3-Base 中观察到反思行为。附录也指出，单纯找“wait”“recheck”等关键词会误判，LLM 评价器同样可能误判。[DR，§2.3，PDF p.4；附录 D，PDF pp.15–16]

因此，“出现某种行为”“该行为出现更频繁”“该行为在合适时候被使用”“该行为提高任务成功率”是不同的问题。不能把一个反思句式的出现，当成 RL 新创造推理能力的充分证据。

## 12. 从论文到训练系统：数据、参数、奖励的不同更新节奏

**对应：REST 的双循环；EM 的迭代、重置和迁移实验；DSM 的 iterative GRPO。**

### 12.1 数据更多，与数据更新，并不是一回事

EM 比较了一次生成三倍数据、只训练一轮，与多轮重新采样的区别。MATH 实验中，前者达到 40.3%，而第二、第三轮版本约为 41% 和 41.9%。这支持在该设置中重新采样的价值，但不是无限增加轮次的保证。[EM，§5.3，PDF p.10]

DSM 也比较 RFT 与 Online RFT：二者都学习正确回答，但后者使用更新中的策略生成数据。在其 1.3B 实验中，Online RFT 后期表现更好。[DSM，§5.2.1，PDF pp.19–20，Fig.5]

两组证据共同提示：**训练材料应当跟上当前策略的行为分布，而不只是一次性扩大旧模型生成的数据集。**

但 REST 的设计同时提醒，采样可能昂贵，因此数据新鲜度与复用效率要一起考虑。不能从“重新采样有价值”直接推成“每个微小更新都必须重新采样”。[REST，PDF pp.2、4]

### 12.2 不要把非受控比较误读成单一因素因果结论

DSM 的 Online RFT 使用正确性规则，而 GRPO 相关实验还使用了学习型奖励模型；过程监督版本又改变了反馈粒度。其 Table 10 清楚列出了数据来源和奖励类型的差别。[DSM，PDF pp.19–20]

因此，观察到 GRPO 优于 Online RFT，不能把全部差距严格归因于“它使用负优势”。数据、奖励、归一化和优化共同组成实验配置。

**工程方法：提出具体解释后，用一次只改变一个关键因素的消融去验证，而不是根据最终曲线给算法贴一个整体原因标签。**

### 12.3 数据更新，不等于必须继承上一轮全部参数状态

EM 用新模型生成下一轮数据，却在 Improve 时重新从基础模型微调。其 APPS 与 HumanEval 对比说明，在该实验中这有助于保持迁移表现。[EM，§3，PDF p.5；§5.3，PDF p.11]

这形成两个独立控制量：

```text
生成器：上一轮更好的策略 → 下一轮更好的探索数据
学习器：上一轮策略继续训练，或回到基础模型重新吸收新数据
```

**适用边界。**重置并不是 EM 理论或 RL 的普遍要求，也不一定适合所有任务。它是该论文为减少任务特定漂移采用并验证的一项训练选择。

### 12.4 奖励模型也会过时

REST 的人评结果与奖励模型得分排序并不一致。作者分析，策略远离原行为分布时，奖励模型可能更难准确评价，持续训练会对评分器过拟合。[REST，PDF pp.8–9，Fig.7]

DSM 把“评价器也要跟上策略”落到 iterative GRPO 中：根据新策略输出更新奖励训练集，继续训练 reward model，并混入 10% 历史数据回放；随后使用当前策略作为新的 reference，进入下一阶段。[DSM，§4.1.4，PDF p.15]

### 12.5 三个循环必须分别设计

| 循环 | 更新对象 | 它要解决的问题 |
|---|---|---|
| 参数更新循环 | 当前策略参数 | 消化当前批次反馈 |
| 数据刷新循环 | 新回答、工具轨迹与结果 | 保持数据与策略的相关性 |
| 评价器/阶段更新循环 | 奖励模型、阶段性 reference | 保持评价有效，管理策略漂移 |

旧策略快照、reference 锚点、重置基础模型和更新奖励模型，分别属于这些不同控制点，不能混用。[REST，§3；EM，§3；DSM，Algorithm 1、§4.1.4]

### 12.6 Rule-based verifier 减少一类误差，但不消除评价风险

DR 的训练使用规则验证器并去掉 KL；DSM 使用学习型评分器与 KL。这是两篇论文的具体配置选择。[DR，PDF pp.5、7、19；DSM，PDF pp.13–15]

**工程建议。**规则验证器仍然只能检查被编码进去的条件。以下等价关系都不成立：

| 表面检查通过 | 不等于 |
|---|---|
| SQL 能执行 | 业务口径正确 |
| 代码通过已有测试 | 覆盖所有真实需求 |
| 引用来源存在 | 引用确实支持结论 |
| 最终数字正确 | 推理和证据链正确 |
| 用户点击采纳 | 内容已经客观核实 |

EM 讨论提供正确答案再生成理由的做法时，就观察到最终答案正确、推理却错误的假阳性。[EM，§4，PDF p.6]

所以，训练反馈与独立验收最好分开：训练反馈决定怎么更新；验收体系检查模型是否真正满足任务，包括评分器没覆盖到的错误。

### 12.7 多目标不能靠随手加权掩盖

**工程建议。**在实际 Agent 中，你可能同时关心成功、证据、成本与格式。不要未经验收就把它们拼成一个任意加权分数，让“格式好看”补偿“任务错误”。可以先明确必须满足的成功条件，再将成本、冗余和其他质量维度作为次级指标观察；确需加入奖励时，必须验证这些项是否诱导了绕过主任务的行为。

这是从奖励代理风险得到的设计建议，不是这些论文已验证的一套业务奖励公式。

## 13. 怎样判断 RL 到底提升了什么

**对应：DSM §5.2.2；EM §5.1–5.4；DR 的基础模型、长度与反思分析。**

### 13.1 不能只用一个平均准确率回答能力问题

单次正确率提高，可能来自更多正确路径、已有正确路径概率提高、输出格式变得可解析、停止行为更合适，或者更高推理预算。区分这些解释，需要不同测量，而不是只看一个最终得分。

DSM 的 Fig.7 比较了 Maj@K 和 Pass@K。作者观察到多数投票改善，而较大采样数下的 Pass@K 没有相应提升，并提出“使正确回答更容易被采到或占优”的解释。[DSM，§5.2.2，PDF p.21]

EM 则在它的设置中报告，所测各个 K 下 Pass@K 都提高，多数投票也改善。[EM，§5.2，PDF pp.9–10]

**这两项观察可以同时成立。**它们不是相同模型、数据、奖励和训练设置下的受控对照，不能强行推出“RL 永远只重排已有答案”，也不能仅凭 Pass@K 的变化证明普遍的新能力创造。

### 13.2 四种指标回答四种问题

| 指标 | 主要问题 | 容易忽略的边界 |
|---|---|---|
| 单次成功率 | 一次调用是否更可靠 | 贪心与采样成功率需要分开报告 |
| Pass@K | K 次尝试中是否至少有一次正确 | 不意味着系统能识别正确候选 |
| 多数投票或实际选择器成功率 | 候选中出现正确答案后，能否选中 | 选择机制本身可能有偏差 |
| 跨任务、领域外、错误恢复表现 | 行为是否可迁移 | 训练题目与评测题目的关联需控制 |

Pass@K 与多数投票的定义来自 EM；REST 的 Best-of-N 则是由评分器排序候选，与多数投票不同。[EM，PDF p.9；REST，PDF p.8]

**工程建议。**把候选生成能力与最终选择能力分别测试。数学标准答案或私有测试可以在离线评估时判断是否存在正确候选，但部署中的真实选择器未必拥有这种判定能力。

### 13.3 比较时必须同时控制推理预算

DR 附录比较基准时，区分部分模型的 3K 与 8K 生成预算。更长预算可能影响性能，因此不能将不同预算结果无条件归为训练算法的收益。[DR，附录 B，PDF p.14]

建议同时报告每任务的尝试次数、生成 token、工具执行次数和耗时。在固定预算下比较成功率，再另行画出更大预算带来的收益。

### 13.4 长度增长不等于有效思考增长

DR 将正确回答和错误回答的长度分开测量，发现优化偏差可能使错误回答变得更冗长，即使训练奖励提升已经放缓。[DR，PDF pp.7–8，Fig.5]

因此，更长回答至少有三种可能解释：确实需要更多有效推理；模型更愿意尝试和检查；错误路径被较弱惩罚后变长。只看平均长度无法区分它们。

**工程建议。**除了平均长度，还应分别观察成功/失败长度、重复率、截断率，以及额外 token 是否带来更高成功率。判断“是否更会思考”，应回到任务效果与预算，而不是反思词数量。

### 13.5 训练集提升不等于迁移提升

EM 在 APPS 上观察到继续迭代后，训练性能继续提高，但测试与 HumanEval 迁移回落；作者将小训练题目集上的过拟合作为可能解释。[EM，§5.1，PDF pp.8–9]

这意味着早停不能只看训练奖励。至少需要独立的任务内验证集与一个相关但未训练的迁移集。论文中的回归现象并不否定自训练，而是提醒数据轮次与参数漂移需要验收。

### 13.6 “新能力”的讨论，应该保留证据层次

可以将观察分为三层：

**可直接测量的事实。**例如在明确模板、预算和测试集上成功率提高，或错误回答缩短。

**机制解释。**例如更好的数据刷新、归一化改变了梯度权重、模板恢复了已有表现。

**更强的能力论断。**例如模型形成新的可迁移策略，或者拓宽了此前难以探索的解法空间。

第三层需要比第一层更强的实验，不能仅凭一条训练曲线完成归因。DSM、EM 和 DR 的组合价值，正在于让我们同时关注效果、机制与解释边界。

## 14. 工程落地：数据契约、损失实现、监控与排错

本章是基于前述公式与论文实验的**工程建议**。这些材料没有直接提供完整的生产级 Agent 训练平台，因此这里不将建议描述为已复现的端到端实验。

### 14.1 先判断该解决的是学习问题，还是接口和数据问题

开始 RL 前，至少需要回答三个问题：当前策略有没有机会探索到更好的行为，评价机制是否足够可靠，采样和验证成本是否可承受。

如果模型已经能正确完成任务，主要失败来自上下文遗漏、格式解析或工具异常，那么先修复这些环节，往往比把错误全部交给奖励学习更直接。DR 的模板实验就是“初始接口会显著改变被测策略”的具体证据。[DR，§2.1–2.2]

对于固定格式行为，示范学习可以是清晰基线；对于多条有效路径、难以提供逐步示范、结果可验证的任务，可以比较 ReST 式数据循环与策略优化。不是先选一个算法名字，再寻找适配它的问题。

### 14.2 一条 rollout 应是一份可重建的决策记录

建议至少保留以下字段类别。

| 字段类别 | 内容 | 对应的数学或系统作用 |
|---|---|---|
| 任务身份 | task_id、group_id、数据版本、环境版本 | 保证同组确实是同一任务 |
| 策略身份 | 模型权重版本、模板、采样参数 | 确定行为分布 |
| 实际上下文 | 每次决策输入、截断/压缩结果 | 重建 $h_t$ |
| 行为 | token IDs、动作、action mask、停止标记 | 重建被优化的选择 |
| 采样概率 | 对应策略定义下的 old log probability | 计算概率比率 |
| 环境反馈 | 工具结果、测试结果、错误类型 | 区分策略错误与环境错误 |
| 终止 | 成功结束、模型结束、预算耗尽、工具失败 | 正确解释回合结尾 |
| 评价 | 奖励分项、总奖励、评价器版本 | 知道模型实际在优化什么 |

对于上下文会变化的多轮 Agent，单一拼接文本未必能够恢复每次模型调用。可以按决策保存输入快照或可重建的事件记录，而不是只保存最终回答。

### 14.3 把“概率对齐”当作训练前置条件

采样温度、top-p、top-k、提示模板、特殊 token 和截断规则，都可能影响采样分布或条件上下文。需要明确策略到底定义为哪一种分布，以及 old/current log probability 分别来自什么。

**工程建议。**建立简单、明确定义的同步基线后，再引入异步采样和数据复用。不能一边用某种截断采样生成，一边使用另一个分布的概率，却不记录这种差异，并仍然声称与基础 on-policy 推导完全一致。

训练时还要核对 causal shift：计算某个 token 的概率，应该使用它之前的前缀，而不是把该 token 本身误放进预测条件。

### 14.4 Action mask 不是普通 padding mask 的同义词

padding mask 表示哪些位置有效；action mask 表示哪些有效 token 是策略实际选择的。工具结果可能是有效上下文，但不是动作目标。固定插入的 role 前缀是否属于动作，也取决于它究竟由模型生成还是由系统插入。[L09，PDF p.22]

同理，模型实际采样的 EOS/回合结束标记属于动作；由于外部预算强制停止而没有生成的 EOS，不应凭空当成模型选择。不同终止机制要在轨迹记录中区分。

### 14.5 Loss 为零，仍可能有非零学习梯度

**推导说明。**在原始 GRPO 的简化情形下，暂不考虑 KL，更新开始时 $\rho=1$，组内优势之和为零。如果每条回答内部先做 token 平均，代理目标数值可能为零。

但它的梯度包含：

$$
\sum_{i,t}\hat A_i\nabla_\theta\rho_{i,t},
$$

不同回答的概率梯度不同，所以总梯度并不必然为零。

附录的固定长度教学测试也验证了“标量 loss 为零但梯度非零”的情况。对 DrGRPO 固定分母、不同回答长度的设置，loss 初始值未必为零，不要把零值当作普遍特征。

**结论：代理 loss 数值不能单独作为能力指标。**必须结合真实任务结果、优势、策略变化与梯度检查。

### 14.6 分组与全局聚合需要显式检查

一个批次通常为 `[任务数 B, 每题采样数 G, token 数 T]`，但张量形状正确不代表内容分组正确。采样结果乱序、重试或过滤之后，应按 task/group ID 重建分组，不能盲目 reshape。

梯度累积与多设备训练中，也要保证目标分母一致。例如微批次包含不同数量的轨迹时，直接对各自 mean 再取平均，不一定等于对所有轨迹统一平均。先写出全局目标，再推导各设备、各微批次应该贡献什么。

附录给出的函数明确采用组中心化、固定 $C$、PPO clipping，不含标准差归一化、critic 或 KL。它是用于检查数学实现的 policy-loss 核心，不是完整训练器。

### 14.7 监控应该能够解释不同类型的失败

| 现象 | 优先排查 | 不能仅凭什么下结论 |
|---|---|---|
| 训练奖励长期不变 | 初始成功率、有效组比例、奖励是否正确绑定 | 学习率是否不够大 |
| 奖励提高而独立评测下降 | 奖励漏洞、过拟合、训练与评测分布 | 奖励曲线好看 |
| 长度持续增长而成功率不变 | 正确/错误长度、归一化、重复和截断 | 模型更会思考 |
| 单次更新后突然失效 | log probability 对齐、策略漂移、梯度幅度 | 随机波动 |
| 单轮任务好，多轮任务差 | 实际上下文、工具状态、恢复轨迹 | 模型参数能力不足 |
| loss 正常但任务学不会 | mask、梯度符号、group_id、奖励绑定 | 自动求导能跑通 |
| 训练集好、迁移差 | 数据覆盖、迭代轮次、参数继承方式 | RL 已经普遍提升能力 |

建议分开监控任务奖励、独立成功率、有效组比例、每题奖励分布、优势范围、ratio 分布、clip 情况、KL（若使用）、梯度范数、输出长度、停止原因与工具错误。

### 14.8 训练耗时，不只来自反向传播

串行诊断近似可以写成：

$$
T_{\mathrm{iter}}
\approx
T_{\mathrm{rollout}}+
T_{\mathrm{reward}}+
T_{\mathrm{logprob}}+
T_{\mathrm{update}}+
T_{\mathrm{sync}}.
$$

实际系统可重叠执行，这个式子只是拆分瓶颈的工具。

REST 的数据复用、DSM 的去 critic、DR 的长度效率，分别优化了这条链路中的不同部分。[REST，§3；DSM，§4.1.1；DR，§3.2]

**工程建议。**比较方案时，不只记录峰值显存或模型数量，还要记录达到同一独立评测水平所消耗的生成 token、环境执行和总时间。无效组大量增加、错误回答变长，都可能使名义吞吐上升而实际学习效率下降。

### 14.9 应用到文档数字核验 Agent：先训练可验收的子能力

下面是延伸自前面讨论的设计示例，不是论文实验。

如果任务是根据文档或数据表写分析，先把可验证行为拆开：定位数据来源、确认实体、核对时间区间、核对单位、执行计算、输出支持结论的证据。相比一开始就给整篇长文一个“质量分”，这些行为更容易建立清晰反馈。

需要区分：找到了来源但读错区间、计算正确但输入数字错误、引用存在但不支持结论、内容正确但上下文后半段丢失。它们对应不同链路错误。

训练前保留“提示/流程修复”和“正确示范”基线，再决定是否值得投入 RL。不能用强化学习替代可靠数据源、明确指标口径与独立验收。

## 15. 一套可执行的学习与实验路线

### 15.1 实验一：不用 LLM，先把 baseline 的统计意义验证清楚

复现第 6 章二选一问题，使用精确枚举计算不同 baseline 下的梯度均值与方差。

$$
p(A)=0.25,\quad R(A)=1,\quad R(B)=0.
$$

需要看到：$b=0$、$0.5$、$0.75$ 的平均梯度都为 0.1875，但方差不同。不要只调用训练循环后观察成功率，而要直接检查每个结果给出的梯度。

```python
from math import sqrt

p = 0.25
for baseline in (0.0, 0.5, 0.75):
    grad_a = (1.0 - baseline) * (1.0 - p)
    grad_b = (0.0 - baseline) * (-p)
    mean = p * grad_a + (1.0 - p) * grad_b
    variance = p * (grad_a - mean) ** 2 + (1.0 - p) * (grad_b - mean) ** 2
    print(f"b={baseline:.2f}, mean={mean:.6f}, sd={sqrt(variance):.6f}")
```

这是讲义例子的计算练习。它帮助建立一个基本判断：梯度估计的期望正确，与每次更新有多稳定，是不同的性质。

### 15.2 实验二：实现 Number Search，检查任务、轨迹与 mask

环境沿用讲义规则：数字 1～16、四次猜测、higher/lower/correct、终局二元奖励。

依次比较成功轨迹上的 SFT、无 baseline 的 REINFORCE、组中心化优势。使用相同初始策略与任务分布，并记录具体动作和反馈。

重点不是追求复杂模型，而是验证：失败何时产生梯度，奖励是否绑定到正确轨迹，错误后出现的历史是否能够被训练，模型是否利用环境反馈，而不只是记住某个固定数字。

这是教学环境，不是复杂真实任务泛化的证据。它的价值是让目标、采样与更新都可以检查。

### 15.3 实验三：比较固定数据与重新采样

选择一个可验证的小任务，建立两组训练：第一组反复训练固定初始策略产生的成功数据；第二组定期让改进后的模型生成新数据。尽量控制生成预算、训练预算与评测协议，同时记录每一轮覆盖了哪些问题。

这个实验对应 REST 的 Grow/Improve 与 EM、DSM 的数据新鲜度比较。它要回答的不是“在线一定更好”，而是当前任务中数据更新带来的收益是否抵得上采样成本。

### 15.4 实验四：把 DrGRPO 的两个改动拆开

| 实验 | 除组内标准差 | 除回答自身长度 |
|---|---|---|
| 原始 GRPO 风格 | 是 | 是 |
| 只去长度项 | 是 | 否，使用固定 $C$ |
| 只去标准差项 | 否 | 是 |
| DrGRPO 风格 | 否 | 否，使用固定 $C$ |

固定模型、模板、任务、反馈与生成预算，分别观察独立成功率、正确长度、错误长度、有效组比例和训练成本。至少使用多次独立运行，避免把随机波动当成机制。[DR，附录 C，PDF p.15]

### 15.5 实验五：把“能力提升”拆成多个可检验问题

对同一组 checkpoint，分别测单次调用、Pass@K、真实候选选择器、相关未训练任务和错误恢复场景。使用固定或明确报告的推理预算，记录变化发生在哪个环节。

如果 Pass@K 很高但选择器效果差，问题可能不只是继续训练生成模型；如果模板适配已带来大幅恢复，RL 增量应该在该基线上计算；如果奖励上升但迁移下降，应该检查反馈与数据覆盖，而不只继续加步数。

### 15.6 最终应该形成的工作习惯

遇到一个新的 RL 方法，先追问：它改变了数据来源、奖励、优势估计、样本加权、更新约束还是评测协议？然后将这个改变对应到可复现的消融与监控。

Lecture 09 的统一梯度视角与 DSM 的“数据来源—奖励函数—梯度系数”视角，可以合并成：

> **模型学到什么，取决于它遇到的任务、探索出的行为、收到的反馈，以及这些反馈被怎样加权和更新。**

真正掌握这节课，不是只会调用一个 GRPO 训练器，而是能够沿着 **任务 → 采样 → 评价 → 优势 → token 梯度 → 参数更新 → 独立评测** 找到失真发生的位置，并提出能够验证原因的实验。[L09，PDF p.44；DSM，§5.2.1，PDF pp.18–20]

## 附录 A. 公式与算法速查

### A.1 一组公式贯穿全讲

**任务目标：**

$$
J(\theta)=\mathbb E_{x,\tau\sim p_\theta}[R(\tau)].
$$

**策略梯度，未折扣、环境和奖励无直接参数依赖：**

$$
\nabla J
=
\mathbb E\left[R(\tau)\sum_t\nabla\log\pi_\theta(a_t\mid h_t)\right].
$$

**未来回报与 baseline：**

$$
\hat g=\sum_t(U_t-b(h_t))\nabla\log\pi_\theta(a_t\mid h_t).
$$

**GRPO 的结果优势：**

$$
\hat A_i=\frac{R_i-\bar R}{\sigma_R}.
$$

**DrGRPO 的结果优势：**

$$
\hat A_i^{\mathrm{Dr}}=R_i-\bar R.
$$

**当前与采样策略的 token 概率比：**

$$
\rho_{i,t}=\exp(\log p_{\mathrm{new}}-\log p_{\mathrm{old}}).
$$

**Clipped surrogate：**

$$
S_{i,t}=\min(\rho_{i,t}\hat A_i,\operatorname{clip}(\rho_{i,t},1-\epsilon,1+\epsilon)\hat A_i).
$$

**DrGRPO 风格任务损失，明确写出批次和 mask：**

$$
\mathcal L
=
-\frac1{BGC}\sum_{b=1}^{B}\sum_{i=1}^{G}\sum_t m_{b,i,t}S_{b,i,t}.
$$

最后一式是附录 B 代码实现的目标，不含 KL、critic 和标准差归一化。上述公式的来源和适用条件已在第 5–10 章逐项说明。[L09，PDF pp.19–40；DSM，§4.1；DR，§3、附录 A]

### A.2 各方法究竟改变了什么

| 方法 | 数据与反馈 | 核心更新 | 主要注意事项 |
|---|---|---|---|
| SFT | 给定示范 | 提高示范动作概率 | 示范覆盖、真实运行历史 |
| ReST | 自生成数据与质量过滤 | 固定数据上的多次 Improve，可使用 NLL 等损失 | 筛选阈值、复用成本、奖励过拟合 |
| ReST-EM | 多次采样与二元验证 | 以 EM 解释的成功数据拟合；论文每轮从基础模型训练 | 题目权重、数据平衡、轮次和迁移 |
| 无 baseline 的 REINFORCE | 当前策略轨迹与回报 | $R\nabla\log\pi$ | 方差；零奖励没有直接梯度 |
| 带 baseline 的策略梯度 | 回报减去适当基准 | $(U-b)\nabla\log\pi$ | baseline 独立性、估计质量 |
| 论文讨论的 PPO 配置 | 策略轨迹、奖励、learned critic | GAE 等优势加 clipped surrogate | critic 成本、策略漂移与更新幅度 |
| GRPO | 同题多次采样 | 组标准化优势、ratio、clipping，DSM 加 KL | 组内相关性、采样成本、退化组、归一化 |
| DrGRPO | 同题多次采样 | 组中心化、固定长度分母、ratio、clipping | “去偏”范围、奖励尺度、有限采样近似 |

这是基于所提供材料的比较，不将一个方法标签等同于所有实现细节。[REST，§3；EM，§3；W92，§4；DSM，§4；DR，§3]

### A.3 十个容易混淆的判断

| 误解 | 更准确的理解 |
|---|---|
| RL 不使用反向传播 | 不直接通过离散采样和外部环境求导；网络内部仍使用反向传播 |
| ReST 最后是 SFT，所以没有反馈学习 | 整体包含探索、评价和训练数据改进；局部更新可用 NLL |
| 原始 REINFORCE 没有 baseline | W92 的一般定义包含 baseline；零 baseline 是一个特例 |
| baseline 只要 detach 就保证无偏 | detach 与统计条件独立是两件事 |
| baseline 解决了每一步的责任 | 共享轨迹优势仍然是粗粒度信用分配 |
| PPO 必须和 GRPO 完全互斥 | 优势估计与 PPO 式更新约束是不同维度 |
| GRPO 不需要 reward model | 是否用 reward model 取决于奖励来源 |
| DrGRPO 完全消除了 RL 偏差 | 它移除特定归一化偏差，其他估计与代理目标问题仍存在 |
| 输出更长或反思更多，说明能力更强 | 需要控制模板、预算，并检查真实任务收益 |
| 训练奖励提高，说明业务效果提高 | 奖励只是评价代理，必须进行独立验收 |

### A.4 本讲没有覆盖到什么程度

FUND 与 DSM 提到 RLHF、DPO 和更多 RL 方法，但材料在本讲的主线并未完整推导 DPO、通用重要性采样、异步策略陈旧性控制或分布式 RL 系统。L09 最后一页也将 async RL、off-policy data 与 importance weighting 列为后续内容。[FUND，PDF pp.44–46；DSM，§5.2、附录 A；L09，PDF p.46]

因此，本讲对这些概念只解释必要边界，不把一个基础课程包装为所有后训练算法的完整手册。

### B.1 这段代码实现什么

输入 `logp` 已经是模型对**采样到的动作 token**给出的对数概率，不是词表 logits。输入形状为 `[B, G, T]`，奖励为 `[B, G]`。每个 G 维分组必须属于同一个任务。

代码实现组内中心化优势、PPO clipping、固定预算分母，不包含采样、模型前向、工具环境、reward model、critic、KL、梯度累积或分布式同步。它是第 10 章目标的教学实现，不是对某个生产框架接口的复刻。

其中 `max_tokens` 对应统一常数 $C$，不是当前批次最长回答，也不是每条回答的实际长度。`old_logp` 与 `rewards` 在策略更新中被视为固定量。

### B.2 验证范围

以下代码已在本次整理环境中以 CPU 运行，核心梯度检查通过。检查覆盖正负优势的梯度符号、mask、旧概率与奖励的梯度隔离、等分组、clipping 饱和、固定分母和错误形状。

这只验证策略损失的局部性质，没有运行 LLM 训练，也不代表某个真实任务的收益已被验证。代码包含便于教学的输入检查，其中 `.item()` 等同步检查不应直接当作高吞吐分布式训练的性能实现。

环境需要已经安装 PyTorch。将下面完整代码保存为一个 `.py` 文件即可运行。

```python
"""DrGRPO-style policy loss and CPU gradient checks; not a full RL trainer."""
import math
import torch


def dr_grpo_loss(
    logp: torch.Tensor,
    old_logp: torch.Tensor,
    rewards: torch.Tensor,
    action_mask: torch.Tensor,
    max_tokens: int,
    clip_eps: float = 0.2,
) -> torch.Tensor:
    """Compute a clipped policy loss with group centering and fixed denominator.

    logp, old_logp, action_mask: [B, G, T]; rewards: [B, G].
    Each G-axis contains independent rollouts for the SAME task instance.
    logp contains sampled-token log probabilities, not raw vocabulary logits.
    max_tokens is a fixed action-token budget, not this batch's longest length.
    No reward-standard-deviation normalization, critic, or KL term is included.
    """
    tensors = (logp, old_logp, rewards, action_mask)
    if not all(isinstance(x, torch.Tensor) for x in tensors):
        raise TypeError("All four inputs must be torch.Tensor instances")
    if logp.ndim != 3 or min(logp.shape) <= 0:
        raise ValueError("logp must have a nonempty [B, G, T] shape")
    if old_logp.shape != logp.shape or action_mask.shape != logp.shape:
        raise ValueError("old_logp and action_mask must match logp's shape")
    if rewards.shape != logp.shape[:2] or logp.shape[1] < 2:
        raise ValueError("rewards must have shape [B, G], with G >= 2")
    if any(x.device != logp.device for x in tensors):
        raise ValueError("All tensors must be on the same device")
    if not all(x.is_floating_point() for x in (logp, old_logp, rewards)):
        raise TypeError("Log probabilities and rewards must be floating point")
    if action_mask.dtype != torch.bool:
        raise TypeError("action_mask must be boolean")
    if isinstance(max_tokens, bool) or not isinstance(max_tokens, int) or max_tokens <= 0:
        raise ValueError("max_tokens must be a positive integer")
    if not math.isfinite(clip_eps) or not 0.0 < clip_eps < 1.0:
        raise ValueError("clip_eps must be finite and in (0, 1)")

    lengths = action_mask.sum(dim=-1)
    if torch.any(lengths == 0).item() or torch.any(lengths > max_tokens).item():
        raise ValueError("Each rollout must have 1..max_tokens action tokens")
    if not all(torch.isfinite(x).all().item() for x in (logp, old_logp, rewards)):
        raise ValueError("Inputs contain NaN or infinity")

    # Float32 loss arithmetic; gradients only flow through current-policy logp.
    current = torch.where(action_mask, logp.float(), 0.0)
    previous = torch.where(action_mask, old_logp.detach().float(), 0.0)
    r = rewards.detach().float()
    if not all(torch.isfinite(x).all().item() for x in (current, previous, r)):
        raise FloatingPointError("Float32 conversion overflow")
    advantages = r - r.mean(dim=1, keepdim=True)
    if not torch.isfinite(advantages).all().item():
        raise FloatingPointError("Advantage overflow; inspect reward scale")
    ratio = torch.exp(current - previous)
    if not torch.isfinite(ratio).all().item():
        raise FloatingPointError("Probability ratio overflow; inspect policy drift")

    a = advantages.unsqueeze(-1)
    unclipped = ratio * a
    clipped = ratio.clamp(1.0 - clip_eps, 1.0 + clip_eps) * a
    surrogate = torch.minimum(unclipped, clipped)
    per_rollout = (surrogate * action_mask).sum(dim=-1) / max_tokens
    return -per_rollout.mean()


def test_dr_grpo_core() -> None:
    # 1. At ratio=1 and equal lengths, scalar loss can be zero, yet gradient nonzero.
    logp = torch.full((1, 4, 3), -2.0, requires_grad=True)
    old = logp.detach().clone().requires_grad_(True)
    rewards = torch.tensor([[1.0, 1.0, 0.0, 0.0]], requires_grad=True)
    mask = torch.tensor([[[True, True, False]] * 4])
    loss = dr_grpo_loss(logp, old, rewards, mask, max_tokens=4)
    assert torch.isclose(loss.detach(), torch.tensor(0.0)).item()
    loss.backward()
    assert torch.all(logp.grad[0, :2, :2] < 0).item()
    assert torch.all(logp.grad[0, 2:, :2] > 0).item()
    assert torch.all(logp.grad[~mask] == 0).item()
    assert old.grad is None and rewards.grad is None

    # 2. Equal rewards produce zero TASK gradient (there is no KL loss here).
    for equal_reward in (0.0, 1.0):
        lp = torch.full((1, 2, 2), -2.0, requires_grad=True)
        r = torch.full((1, 2), equal_reward)
        m = torch.ones_like(lp, dtype=torch.bool)
        dr_grpo_loss(lp, lp.detach(), r, m, max_tokens=2).backward()
        assert torch.all(lp.grad == 0).item()

    # 3. Clipping saturates positive advantages above the upper threshold,
    #    and negative advantages below the lower threshold.
    previous = torch.full((1, 2, 1), -2.0)
    lp = (previous + torch.tensor([[[math.log(1.5)], [math.log(0.5)]]])).requires_grad_()
    r = torch.tensor([[1.0, 0.0]])
    m = torch.ones_like(lp, dtype=torch.bool)
    dr_grpo_loss(lp, previous, r, m, max_tokens=1).backward()
    assert torch.all(lp.grad == 0).item()

    # 4. Action-independent fixed denominator: unequal lengths do not change
    #    the coefficient of individual valid tokens with equal advantages.
    lp = torch.full((1, 4, 4), -2.0, requires_grad=True)
    m = torch.tensor([[[True, False, False, False],
                       [True, True, True, True],
                       [True, True, False, False],
                       [True, True, True, False]]])
    r = torch.tensor([[1.0, 1.0, 0.0, 0.0]])
    dr_grpo_loss(lp, lp.detach(), r, m, max_tokens=4).backward()
    assert torch.allclose(lp.grad[0, 0, 0], lp.grad[0, 1, 0])
    assert torch.allclose(lp.grad[0, 2, 0], lp.grad[0, 3, 0])

    # 5. Shape errors fail explicitly, rather than silently regrouping prompts.
    try:
        dr_grpo_loss(lp, lp.detach(), r[:, :2], m, max_tokens=4)
    except ValueError:
        pass
    else:
        raise AssertionError("Invalid reward shape should have raised ValueError")
    print("All DrGRPO policy-loss gradient checks passed.")


if __name__ == "__main__":
    test_dr_grpo_core()
```

### B.3 接入模型之前，再检查三件事

**概率计算是否对齐。**目标 token、前缀、位置、模板和采样策略定义必须一致。该函数不会替你验证 old log probability 是否真的来自采样时的策略。

**环境行为是否被正确区分。**模型生成的工具调用是动作，工具返回是上下文；强制截断不是模型生成的结束动作。

**全局 reduction 是否一致。**单卡函数里的 `mean()` 表示 B 与 G 维平均。将它接入梯度累积或多设备训练后，应确保整体仍实现同一个任务权重与固定分母目标。

这些是局部代码通过后仍然可能导致训练错误的系统边界。

### C.1 设计新实验时，可复用的三个问题

首先明确改变的是哪个组件；其次检查其他条件有没有同时变化；最后确认评测是否测到了你声称的机制。

例如，声称“失败样本带来收益”时，应尽可能保持奖励来源与数据新鲜度一致；声称“长度偏差被修复”时，应分开看正确和错误回答；声称“新能力出现”时，应控制初始模板，并检查多次采样覆盖和迁移。

这就是参考论文与讲义相互补充的方式：讲义给出对象和公式，实验决定哪些解释有证据、哪些仍然只是可能。

### D.3 最后保留的三条判断标准

**理论上：**我优化的目标是什么，梯度估计在什么假设下成立，哪些归一化或近似已经改变了它？

**工程上：**训练时的任务、上下文、动作、采样概率和奖励是否严格对应，分布式聚合是否仍然实现同一个目标？

**实验上：**独立任务效果是否提升，代价是多少，改进能否归因到明确组件，而不是模板、预算、评分器漏洞或随机波动？

把这三条同时落到代码与实验中，才是从“理解强化学习术语”走向“能够设计、实现和诊断 LLM 强化学习系统”。
