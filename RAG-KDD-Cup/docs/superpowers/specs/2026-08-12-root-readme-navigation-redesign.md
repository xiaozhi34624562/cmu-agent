**日期：** 2026-08-12

## 目标

将仓库根目录的 `README.md` 重构为整个研究仓库的统一入口，完整导航所有由本项目维护的研究资料。README 必须准确区分“全仓库资产”和“Meta CRAG 十篇论文专题”，并为论文、代码、技术分析、来源清单及项目设计文档提供直接入口。

## 当前问题

现有 README 满足了早期“介绍十篇 CRAG 论文”的要求，但内容比例过度偏向 CRAG 专题，没有说明全仓库的真实资产数量，也没有解释为什么 15 个 PDF 文件只对应 14 份独立内容。此外，EReL 的论文与代码入口粒度和 FinanceRAG、WattBot、CRAG 不一致，不利于读者快速定位资料。

## 资产口径与可移植边界

README 必须同时陈述两种不能互相替代的资产口径：

1. **权威主工作区物理口径**：以用户主工作区绝对路径 `/Users/wangmingzhi/qg/code/RAGKK` 为统计根，递归扫描时排除根目录第一段为 `.git` 或 `.worktrees` 的全部路径。该口径包含 15 个物理 PDF、14 个 `papers/` PDF、14 份按 SHA-256 去重的 PDF 内容、13 份 `source-manifest.md` 和 7 个保留各自 `.git` 的嵌套本地官方仓库。
2. **根 Git 可移植口径**：以 `git ls-files` 或 `git archive` 可携带的根仓库内容为准。该口径包含 14 个 PDF、13 份 `source-manifest.md` 和 0 个嵌套本地官方仓库；从同一提交创建的独立 worktree 同样只有 14 个 PDF 和 0 个嵌套仓库。

七个嵌套上游仓库被根 `.gitignore` 明确排除，因此只属于当前用户主工作区的物理状态，不属于根 Git 的自包含归档。README 不得笼统承诺新的 checkout、worktree 或 `git archive` 会包含 15 个 PDF 和 7 个本地仓库。

EReL 第一名报告的重复哈希证据只从权威主工作区核验：`EReL@MIR 2025/code/01-iLearn-MDR/report.pdf` 位于被忽略的嵌套仓库，`EReL@MIR 2025/papers/1st-iLearn-Technical-Report.pdf` 由根 Git 追踪；两者 SHA-256 均为 `06c4b8ca4751dd502b9e49132570242ea101e0cf562dece329ac78274428474c`。

## 内容规则

- “十篇论文”必须明确限定为 Meta CRAG 专题，不能代表全仓库数量。
- 15 个 PDF、14 份独立内容和 7 个本地仓库必须明确限定为权威主工作区物理口径，并由排除根 `.git` 和整个 `.worktrees` 后的文件系统与 SHA-256 核验结果支持。
- 14 个 PDF、13 份来源清单和 0 个嵌套仓库必须明确标为根 Git 可移植口径，并由 `git ls-files` 或 `git archive` 支持。
- 不得暗示新的 checkout、独立 worktree 或根 Git 归档自带 15 个 PDF 或 7 个嵌套代码仓库。
- 必须分别说明物理文件数量和去重后的独立内容数量。
- 所有本地链接均从根 README 所在位置正确解析。
- “没有官方代码”“官方代码上游不可访问”“未下载大模型或数据”必须使用不同措辞。
- 现有项目 README 继续承担详细技术分析；根 README 负责概览和导航，不大段复制下级文档。
- 不修改任何嵌套上游仓库的源文件。

## 验收条件

重构完成必须满足：

- 资产统计与最新文件系统、SHA-256 核验结果一致
- README 同时呈现权威主工作区物理口径和根 Git 可移植口径，且不混淆两者
- 统计脚本排除相对路径第一段为 `.git` 或 `.worktrees` 的路径，不把隔离 worktree 自身计入主工作区资产
- EReL 重复报告的两个文件和 SHA-256 只在权威主工作区中核验
- 5 个比赛或年度专题全部出现在快速导航中
- 14 个根 Git 追踪的 `papers/` PDF 均有直接入口；7 个嵌套仓库路径均有入口，物理存在性只在权威主工作区核验
- 10 个 CRAG 单元均直接链接技术分析、PDF、代码状态和来源清单
- EReL 技术报告的重复副本关系有明确说明
- 所有本项目维护的 Markdown 本地链接均可解析
- 不存在让读者误以为全仓库只有十篇论文的表述
- `git diff --check` 通过，且工作区没有混入无关改动

## 非目标

- 不重写各项目或单篇论文的详细 README。
- 不修改上游代码仓库的文档。
- 不额外下载模型权重、数据集、论文或代码仓库。
- 不超出来源清单已有证据声明运行复现或榜单复现。
