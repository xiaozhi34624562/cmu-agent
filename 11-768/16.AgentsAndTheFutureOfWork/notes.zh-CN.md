# AI Agents for Human Work：从基准能力到真实工作与人机协作

本课对应 CMU 11-768 在 **2026 年 10 月 27 日**的 Zora Wang 嘉宾课。官网标题是 *Agents and the Future of Work*，讲义封面是 *AI Agents for Human Work*。目录编号 16 是本地归档顺序。本文以 [62 页原讲义](2026-10-27-zora-wang.pdf)的问题链为主线，使用实际 PDF 页序，从 1 开始；资料版本和下载状态见 [SOURCES.md](SOURCES.md) 与 [REFERENCES.json](REFERENCES.json)。

学完本课，应能回答一个比“哪个 Agent 得分最高”更具体的问题：**在什么工作任务、环境和验收标准下，Agent 能以怎样的人类参与程度交付有用结果，代价和风险是什么？** 这要求同时解释能力测量、工作采样、运行环境、评价标准、协作方式和劳动市场证据。把其中一项指标直接当成另一项的答案，是本课最需要避免的错误。

本文将“讲义观点”“论文证据”和“工程推导”分开。研报审阅是贯穿的教学案例，其数据、成本和验收门槛均为构造，不是任何公司已部署系统的结果。未运行真实模型、GPU、收费 API 或论文实验；本地算例的运行记录只验证计算，不验证 Agent 能力。

## 1. 先区分六个经常被混用的量

[讲义第 2–14 页](2026-10-27-zora-wang.pdf#page=2) 一方面展示能力进步，另一方面提出它与真实工作价值的距离。理解这组对照时，应先固定每个指标的分母与条件。

**基准成功率**是在规定任务集、工具、预算和评分器下，通过标准的任务比例。它回答“在这个实验中完成了多少”，不自动回答新公司的流程。**自主完成范围**则描述在少量或没有过程中人工帮助时，系统能处理多复杂、多长的任务。成功率提高可能扩大这个范围，但不能将最大成功案例当成稳定能力。

**使用率**衡量人在多少场合使用系统。它受到可用性、授权、习惯、价格与产品入口影响；使用频繁也可能是在反复修正失败。**生产率**必须同时考虑交付质量和总投入，例如按相同质量标准完成一批任务所需的人工时间。只报告模型生成时间，漏掉审阅和返工，无法得出生产率结论。

**任务暴露**是关于某类技术可能影响任务的分类或估计，依赖研究定义；它不是实际采用率。**就业变化**是人数、招聘、工资或工时的变化，还受到需求、宏观经济、企业组织和制度的影响。技术能力与就业结果之间有多层机制，不能用一个排行榜填补这些中间环节。

因此，读任何“Agent 可以替代 X% 工作”的句子，先问：X% 的分母是任务、工时、职业、人员、工资支出，还是偏好比较次数？“可以”指专家判断、一次实验通过、稳定可交付，还是已经发生的企业采用？如果这两点说不清，结论还不能用于工程选型。

### 1.1 METR 的时间跨度到底是什么

[讲义第 3、12 页](2026-10-27-zora-wang.pdf#page=3) 引用 METR 的能力曲线。[归档论文](references/Measuring_AI_Ability_to_Complete_Long_Software_Tasks.pdf#page=1)是 arXiv:2503.14499v4，2026-07-10 版本，复用已有本地归档。

论文的 **50% task-completion time horizon** 是：Agent 达到约 50% 成功率的任务，在有相关经验的人类基线中通常需要多少完成时间。这里以人类完成时长作为任务难度代理，不是测量 Agent 自己运行多久；能力随模型发布日期变化的趋势图与按任务时长拟合的成功率曲线，其坐标轴不同。人类用两小时做完的任务，Agent 可以花十分钟、三小时或耗尽预算；这些运行成本是另外的量。

教学上，可以用 $p(t)$ 表示人类基线耗时约为 $t$ 的任务上，Agent 的成功概率；若拟合关系允许定位，则 $h_{50}$ 满足 $p(h_{50})=0.5$。这是对指标的简写，不是重新拟合原论文的算法。它依赖任务采样、人类计时、环境和统计模型；某类任务虽然耗时长，却可能高度重复，因此“时间长”并不总等于“推理更难”。

“约七个月翻倍”描述作者在其历史测量中的趋势，不是每隔七个月就保证所有职业可自动完成的规律。讲义图还包含后续模型与较长跨度估计，不能把图上后续年份的点写成早期论文原始实验。即便 $h_{50}$ 增长，50% 成功率对很多业务仍远不够；部署还要检查高可靠性门槛、失败检测、人工接管和预算。

### 1.2 使用截图和榜单为什么只能支持有限结论

讲义中的员工使用情况、Agent 排名和能力图有不同采样来源。特定机构员工的使用情况，不能代表所有美国劳动者；某一日期的模型榜单，也不能反向改写一年以前论文的成绩。合理读法是：这些例子提出“能力快速发展但真实工作仍有缺口”的问题，后续章节再分析缺口在哪里。

例如，[第 7 页](2026-10-27-zora-wang.pdf#page=7)的 RLI 截图显示后续模型的约 20% 级成绩；本地归档的 [RLI v1 摘要](references/Remote_Labor_Index_Measuring_AI_Automation_of_Remote_Work.pdf#page=1)最高是 **2.5%**。这不是相互矛盾的两个“同次实验结果”，而是不同版本和时间的证据。本文不将 21.25%、20.83% 等截图数字当作 v1 原论文结果，也不把其中任何数字解释成劳动者替代比例。

## 2. 将“做一份工作”变成能复现的任务约定

[讲义第 15–18 页](2026-10-27-zora-wang.pdf#page=15) 开始把工作拆成任务、环境和评价。一个真实任务不只有一句 prompt，还包含隐含要求、参考材料、软件、权限、交付对象和截止条件。缺少这些条件，两个 Agent 即使拿到同一句话，也未必是在做同一项实验。

工程上可将任务约定写为 $T=(I,G,E,A,B,O,Q)$：$I$ 是输入资料及版本，$G$ 是目标，$E$ 是环境，$A$ 是已授权动作，$B$ 是时间与调用预算，$O$ 是预期交付物，$Q$ 是质量标准。这个七元组是本文的教学抽象，不是讲义提出的新形式化理论。它的价值在于将“模型不行”和“任务根本没有定义完整”区分开。

贯穿案例是一项**季度经营报告审阅**：研究员提供本季、上季及上年同期报告、两份公告和指标表，希望得到数字冲突、条件遗漏与证据不足的审阅清单。完成任务不等于写出一篇流畅评论。可接受交付需要保留原文，标出问题位置，引用正确版本，说明影响，并把无法核实的结论标为待核实。

| 任务要素 | 需要事前明确的内容 | 省略后的典型失败 |
|---|---|---|
| 输入 | 公司、报告期、截止日期、文件版本、缺失页 | 将不同季度数字直接相减 |
| 目标 | 核查事实与论证，还是重写报告 | Agent 大幅润色但没有找到问题 |
| 环境 | 表格读取、PDF 页面查看、计算与文件输出能力 | 数字抽取丢掉单位或负号 |
| 权限 | 可读取哪些资料、可写哪些派生文件、是否允许外发 | 在完成正文前已经越权产生副作用 |
| 预算 | 总时长、重试上限、需要人工处理的节点 | 多次重复搜索，迟迟无法交付 |
| 交付物 | 可编辑清单、原句、证据、建议、不确定性 | 只有聊天摘要，不能逐项复核 |
| 验收 | 哪些必须程序检查，哪些必须专业判断 | 以文风替代事实和证据质量 |

任务颗粒度尤其重要。若把“负责一家公司的研究”视为一个任务，其中包含发现问题、取数、沟通、分析、解释和交付；若只测“给定表格计算一个比例”，获得的是子任务能力。拆解能让实验可执行，但拆掉所有困难条件后，不能再把子任务成功率叫作完整职业的自动化率。

状态也要随颗粒度设计。工作流应保存资料版本、任务进度、已经确认的口径、候选问题、未决冲突和人工决策，而不只是最后一段回答。持久化的依据应是可定位的证据及决策记录；模型先前说过某个数字，不会使该数字自动变成可信事实。

## 3. GDPval 与 RLI：两种真实工作评测各自回答什么

### 3.1 GDPval：经济价值任务与专家交付比较

[讲义第 19、38 页](2026-10-27-zora-wang.pdf#page=19)使用 GDPval 说明职业任务及开放交付的评价。[原论文第 1–5 页](references/GDPval_Evaluating_AI_Model_Performance_on_Real-World_Economically_Valuable_Tasks.pdf#page=1)介绍 **9 个行业、44 个职业、1,320 个任务**，公开的 gold 子集为 **220 个任务**。这些数对应不同层级，不能写成“220 个职业”或“公开了全部 1,320 个任务”。

任务由领域专家设计，要求处理真实工作形态的输入与交付物，例如表格、演示文稿和文档。行业和职业的选择考虑经济规模、薪酬与数字化任务等条件，因此比只看代码题更接近多种知识工作；但仍不是从全球所有工作中均匀随机采样。专家平均约 14 年经验描述的是构建/评估所依赖的专业背景，不代表每个任务都要求 14 年才能完成。

主要 gold 结果采用盲化的专家成对比较：评审者不知道哪份来自人或模型，按任务要求比较产物。一个模型更常被偏好，意味着在这种任务、产物和评审协议中相对表现较好；它不是二元的“所有真实约束都满足”，更不是职业已经被替代。任务过程中的沟通、实时组织知识和后续责任，未必被一个静态交付物完全覆盖。

工程启示是保留足够真实的输入和产物，并使用懂领域的人判断重要语义。对于研报审阅，应拿同一组来源和相同交付要求比较人工、Agent 与协作流程，不能让一组拿到整理好的表格，另一组从扫描 PDF 开始，再把差异全部归因于模型。

### 3.2 RLI：端到端交付能否达到专业参考水平

[讲义第 20 页](2026-10-27-zora-wang.pdf#page=20)和 [RLI v1 第 1–6 页](references/Remote_Labor_Index_Measuring_AI_Automation_of_Remote_Work.pdf#page=1)把评估推进到自由职业项目。作者招募了 358 名自由职业者，从 Upwork 的类别开始筛选，最终形成覆盖 23 个工作类别的 240 个项目，其中 **230 个用于私有量化评估，10 个用于公开定性展示**。这些不是 240 次完全相同的简短问答。

RLI 更强调端到端产物是否达到专业交付水平。[原论文第 6 页](references/Remote_Labor_Index_Measuring_AI_Automation_of_Remote_Work.pdf#page=6)将自动化率定义为：人工评审认为 AI 产物完成项目的程度至少达到专业人士参考产物水平的项目比例。这是相对参考交付物的人工评审，不是直接观察真实客户购买或企业采用。复杂项目可能要求使用图形软件、三维或多媒体工具、处理多文件并遵守具体设计要求。单个中间步骤成功、生成一个能打开的文件，均不足以证明整个项目完成。研究还对物理或强人际交互等任务有筛选边界，因此其“远程工作”不是所有劳动的同义词。

把 RLI 与 GDPval 放在一起读，能看见两种测量目标：一类通过专业偏好比较衡量交付质量，另一类强调真实项目产物相对专业参考的端到端自动化。它们的任务分布、评分、工具和版本不同，不能把分数直接相减得出“某模型在真实工作下降了多少”。

### 3.3 为自己的工作流选基准，而不是只选最高分

先找目标工作的失败条件，再选借鉴对象。若工作最终交付是开放式文档，可借鉴 GDPval 的专家标准和盲评；若需要多软件、多步骤、可直接被客户采用的产物，应借鉴 RLI 的端到端验收。若任务离不开人的判断与修订，则独立 Agent 基准只覆盖一部分，后文的协作测量更适合。

一个小型内部评估应保留任务原貌，同时划分难度：输入是否完整、是否有多文件依赖、是否存在冲突口径、是否需要视觉判断、是否必须询问人。模型版本、工具、提示、预算和评分规则都要记录。先建立相同条件下的基线，再改变一项因素；否则，所谓“新模型更强”可能只是它获得了更多重试、更完整输入或更宽松评审。

## 4. 覆盖更多基准，为什么仍可能漏掉大部分真实工作

[讲义第 21–25 页](2026-10-27-zora-wang.pdf#page=21)转向覆盖问题。补充原文 [How Well Does Agent Development Reflect Real-World Work? 第 1–6 页](references/How_Well_Does_Agent_Development_Reflect_Real-World_Work.pdf#page=1)分析 43 个基准、总池 72,342 个任务实例与美国劳动分类。注意，总池不等于对全部实例逐个作同样的深度评估：论文的覆盖采样保留 **10,288 个实例**，以减少大量相似任务带来的重复成本。

作者将任务映射到 O*NET 的职业领域和工作活动。领域回答“在哪类工作中做”，技能/活动回答“实际在做什么”：例如财务工作中既有信息提取、计算，也有与他人沟通。这种双视角避免把“能使用浏览器”误当成“覆盖了使用浏览器的所有职业”。

论文整体劳动景观包含 1,016 个职业；其中涉及计算机使用的领域子树为 743 个职业、5,806 项任务描述。它们是不同集合。映射使用 LLM，并做人工质量核查，因而仍受分类体系、任务描述完整程度、模型标注和采样规则影响。技能对应的就业与经济权重是重要性加权的估计，并不直接等于实际每天执行该技能的人数。

“覆盖率”也有多种含义。一个分类路径只要被一个简单任务命中，就可能算作覆盖，但这不代表该职业的复杂度、长尾情况和长期责任都被测过。论文报告领域和技能路径覆盖不同，反映跨职业的技能可以在较窄职业样本中重复出现；不能因此宣称已充分覆盖大量职业。

**工程推导：内部评估同时维护分布和覆盖两个视图。** 一张表记录每类真实任务的频率、人工投入和错误后果，另一张表记录评估集中有哪些任务及难度。高频但低风险的格式检查、低频但影响重大的口径冲突都要保留；后者不能因为出现少就被随机抽样完全漏掉。

若以工作量权重 $w_k$ 汇总各类通过率 $q_k$，可定义教学用指标 $Q=\sum_k w_kq_k$，其中 $w_k\ge0$、$\sum_kw_k=1$。权重必须对应事先声明的目标，例如任务频率或人工工时，不能混用。这个平均值依然会掩盖某类严重失败，因此必须同时报告分层结果和硬约束违反情况。

对于研报案例，只有大量“数字完全一致”的简单样本，模型可能靠默认无问题取得高分。需要加入币种变化、并表范围调整、负号丢失、跨期不可比和引用不支持等反例，并保留真实无问题样本，才能同时观察漏报与误报。人工构造的压力样本与自然工作分布要分开报告，不能将压力集的错误率冒充日常业务错误率。

### 4.1 人类轨迹与合成任务能补什么，不能补什么

[讲义第 21–24 页](2026-10-27-zora-wang.pdf#page=21)还比较了工作者需求、真实操作轨迹与探索生成的任务。三者提供不同信号：工作者说明想解决什么，轨迹记录实际做了什么，合成方法探索环境中能执行什么。它们都可以扩大训练资料，但不能互相代替。

讲义以 OpenCUA 说明人类操作轨迹，轨迹可包含屏幕、动作和操作序列。它有助于学习如何使用软件，但一次点击不直接揭示用户为什么这样做、放弃了什么、最终是否满意。若从轨迹反推任务，必须检查意图和成功条件，不能只因动作最终执行完成就认定实现了真实目标。

讲义中的 BAGEL、NNetNav 则代表通过环境探索、轨迹重标注等方式构造任务的思路。可复现的动作序列与可执行检查，有助于过滤不可执行或明显错误的数据；但“能够验证生成任务”不等于“生成任务代表真实工作”。若探索器偏好容易到达的页面和能自动验证的操作，训练集会围绕这些便利条件集中。

这些具体系统在本节仅按讲义介绍，没有归档或独立复读其研究全文，也不据此引用规模、胜率或训练增益。工程上可将合成压力样本与真实任务样本并用：前者定位机制弱点，后者检验目标工作分布；按来源分层报告，防止容易生成的数据挤掉真正重要但难收集的任务。

## 5. 环境不是附属配置，它会改变被测能力

[讲义第 26–32 页](2026-10-27-zora-wang.pdf#page=26)从抽象任务转到工具与运行场景。第 31 页对照 Google Docs 与 LibreOffice，第 32 页对照简化任务数据与真实财务表格，提示“任务名相同”不代表观察和动作空间相同。

GUI Agent 通过屏幕观察并点击输入，容易遇到布局变化、焦点、滚动、遮挡和视觉定位问题；程序化工具则能精确读取结构与调用接口，但可能缺少软件特有语义、排版效果或权限。GUI 并不天然更真实，API 也不天然更容易：关键是目标工作本来允许怎样操作，以及实验是否给了生产中不存在的捷径。

环境差异可以分成四层。**输入层**包括文件格式、扫描质量、隐藏工作表、公式与外部依赖；**工具层**包括软件版本、可用命令和行为；**状态层**包括登录、已有文件、网络、权限和历史修改；**组织层**包括未写明的术语、审批责任、信息更新节奏和人员协作。前三层容易被技术配置吸收，第四层通常需要人类交互和可追溯的业务知识。

研报审阅若在测试时提供人工清理好的 Markdown，而实际使用面对扫描 PDF 和复杂表格，测试主要测了分析能力，部署还增加了感知和抽取风险。合适做法是分别建立“固定正确抽取输入”的分析基线与“原文件到最终清单”的端到端评估，比较两者的差距以定位瓶颈。

迁移诊断应控制变量。保持任务和模型不变，依次替换软件、解析器、文件复杂度或权限配置；记录首个偏离正确路径的位置。若数值读取已错，再调推理提示通常治标不治本。若数据准确但输出格式不兼容，则应检查工具和产物验收。若必须询问负责人才知道业务口径，不能把等待专业判断简单算成“推理失败”。

需要持久保存的环境信息包括输入校验值、解析版本、工具版本、授权范围、任务检查点和输出位置。恢复执行时先核对这些状态是否变化；如果用户替换了报告，旧结论与旧验收记录不能自动继承。测试可使用脱敏副本和隔离目录，但必须记录与真实条件的差异，避免将方便测试的环境当成全部工作。

## 6. 评估设计先固定比较单位和归因

在进入评分细节前，应确定评价的单位是单个模型回复、一个工具动作、一个完整任务，还是人和 Agent 共同完成的一次工作会话。单位不同，成功率分母就不同。若一个任务尝试四次，只将最好一次当作普通单次成绩，会隐藏额外预算；若使用 best-of-n 或 pass@k，必须显式说明。

对于本案例，可先比较三组：独立人工、独立 Agent、人机协作。任务分配需平衡难度、人员经验与材料熟悉度；条件允许时采用随机配对或交叉设计，并防止同一人看过答案后再测另一组。产物评审隐藏作者身份；同时测质量、总耗时、人工实际投入、返工、未决项和安全事件。学习效应、疲劳、选择退出和任务顺序都可能影响结果。

如果协作组得分更高，仍需问：它是否获得更多总时间？是否用了更好的工具？是否由更有经验的人参与？这并不否定协作价值，而是决定结论能说多强。工程目标可以是“在实际资源约束下哪种流程更好”，不必强行把所有收益归因于模型；研究若要隔离某一机制，则需要相应控制与消融。

下面进一步解释评分、协作、成本和劳动影响。所有通用流程和计算式均标明为工程推导；论文里的实验结论只在相应样本和版本内使用。

### 6.1 CollabSkill：把“人的差异”作为模型的一部分

[CollabSkill 第 1–6 页](references/CollabSkill_Evaluating_Human-Agent_Collaboration_On_Real-World_Tasks.pdf#page=1)进一步解释为什么协作评价不能只取各 Agent 的会话平均分。归档为 2026-07-25 的 v2：**93 名工作者、386 次会话、165 个不同任务**，任务来自多个职业场景。人的经验、任务熟悉度、交互习惯不同，即使 Agent 没变，结果也会变。

论文以潜在技能建模一次人机合作的分数：

$$
y=s_A+s_H+\epsilon,\qquad \epsilon\sim\mathcal N(0,\beta^2).
$$

这里 $y$ 是一次会话交付物的评分，$s_A$ 和 $s_H$ 分别是 Agent 与人的潜在协作技能，$\epsilon$ 吸收观测噪声，$\beta$ 是该噪声模型的标准差。对两类技能设高斯先验，通过重复合作记录更新后验。若同一个人分别与多个 Agent 合作，就能帮助区分“这个人一直很强”与“某个 Agent 更适合合作”。论文用 $\mu_i-3\sigma_i$ 作为保守技能分数，其中 $\mu_i$ 与 $\sigma_i$ 分别是实体 $i$ 的技能后验均值与标准差，兼顾估计水平与不确定性；它是评分模型中的量，不是成功概率或职业能力的通用刻度。

这个加性模型有假设：它未必完整表达特定人与特定 Agent 的互补、任务难度、人员学习等交互。人机配对图需要足够的连接，才能利用共享参与者比较不同 Agent。使用先验和重复数据能改善估计，但不能凭这个公式宣称任何小样本排名都可靠；要检查采样、人员退出、评分噪声和对模型选择的敏感性。

论文中协作排名与独立执行排名有差异，支持“自主表现不足以概括协作表现”这一判断。它不是对当前所有同名商业产品的永久排名：实验绑定指定模型、界面和当时配置。自动 rubric 在 27 个 GDPval 任务上的核查得到 82.1% 召回率、92.2% 精确率，这是相对官方标准的规则覆盖与匹配指标，不能写成 Agent 完成任务的成功率。

本案例可以先按研究员经验和任务难度平衡分配，记录人、Agent、任务和交付版本，再比较独立与协作效果。若进一步采用技能模型，应报告模型假设和不确定性，并保留分层原始结果；不要让一个后验排名遮住“某类报告始终失败”的事实。

## 7. 开放式任务为什么仍然需要可执行检查

[讲义第 33–37 页](2026-10-27-zora-wang.pdf#page=33) 把评估放回“环境—任务—评价”的整体，并用从 GitHub issue 到数据分析、室内设计的连续谱说明：任务越开放，越难用少量规则穷尽交付质量。第 37 页展示的检查器大致能判断幻灯片存在、能否读取、是否包含指定文字，但它不能仅凭关键词出现就认定内容准确、推理有效或设计适合使用者。应把这一页理解为简单执行检查对高级语义的覆盖不足，而不是“开放任务不能使用程序检查”。

考虑一项教学任务：审阅一份公司季度经营报告，输出可供研究员修改的审阅清单。输入包括本季报告、上季及上年同期报告、两份公告和一份指标表；用户要求发现数字冲突、解释条件缺失与证据不足，并保留原文。Agent 可以给出许多不同但合理的组织方式，不存在唯一标准答案；然而，报告期、金额单位、表内加总、引用页码、原文件是否被覆盖，都能检查。开放性主要在解释是否充分、问题是否重要、修改是否忠于证据，不能借此放弃确定性的部分。

**工程推导：将交付判定分成三层，并让每层处理它有证据判断的对象。** 第一层是可执行检查，例如所有引用文件存在，页序在 PDF 范围内，指标表中可比较数值经过统一币种、单位和期间处理，审阅清单满足必填字段，原始文件校验值未变。这一层应输出逐项证据；“引用可打开”只能证明导航存在，不能证明引用支持结论。第二层是语义 rubric，即把“专业、可靠”拆成可观察标准：是否准确转述，是否保留时间和适用条件，是否提供反证，是否将工程推断标为推断。第三层是人工复核，对有重大影响的判断、评审分歧、证据缺口及不可逆动作作最终处置。

这样的分工还决定处理错误的方式。如果某指标从百分数误读为小数，继续润色段落没有意义；应回到数据抽取并重新计算依赖它的结论。如果引用页码正确、但该页只支持历史事实而非未来判断，则需修复论证而不是路径。如果模型认为所有段落都可信，但研究员指出忽略了一次口径调整，则应把问题送入评估标准与样本设计，不能只将这一次修改默默写进最终文稿。

## 8. Rubric 怎样从形容词变成可评审标准

[讲义第 38–41 页](2026-10-27-zora-wang.pdf#page=38) 依次讨论专家标准、模型生成标准、用轨迹差异演化标准、从人机交互提炼标准。这里的 rubric 是一组有判定对象、证据要求和评分锚点的评价规则，不是把需求改写成若干赞美性形容词。

以“研报结论有依据”为例，“所有结论都引用来源”过于粗糙。Agent 可以给每句话附一个不相关的页码，拿到形式分。更可靠的规则是：每条被报告为事实的核心结论，都能定位到一个具体来源版本及原文片段；该片段支持结论的主体、方向、时间和限定条件；多个来源冲突时显式记录，不能擅自选一个值。再把判分锚点写清：完全支持、部分支持但遗漏条件、不支持、资料不足无法判断。“资料不足”是一个有效评审状态，不应被迫挤成“正确”。

下面是本案例可直接讨论的评价设计，属于工程示例，不是讲义公布的评分表。

| 评价对象 | 可执行部分 | 语义或专家判断 | 失败后处理 |
|---|---|---|---|
| 数字一致性 | 统一单位后的计算、总分项关系、期间映射 | 口径变化是否允许比较 | 回查表格与附注，保留不可比状态 |
| 证据支持 | 文件版本、页码、片段存在 | 片段是否支持该主张及其条件 | 缩小主张或标记证据缺口 |
| 问题重要性 | 是否填写影响字段 | 是否改变读者理解或业务决策 | 降级普通文字建议，升级关键遗漏 |
| 修改忠实性 | 原文保留、差异可追踪 | 修改有没有加入来源未说的原因 | 撤回新增断言，另列待验证假设 |
| 安全与交付 | 权限、输出位置、禁止外发动作 | 敏感信息是否有必要出现 | 阻断交付并由负责人处置 |

评分应同时有硬约束和软质量。硬约束例如“不得未经授权覆盖原件”“关键数值必须正确”“引用正文不能与结论矛盾”，不应被漂亮表达或更多建议抵消。设第 $k$ 个硬约束的通过标记为 $h_k\in\{0,1\}$，第 $i$ 项软质量为 $q_i\in[0,1]$，权重 $w_i\ge0$ 且 $\sum_iw_i=1$。一个教学用接受条件是：

$$
\mathrm{Accept}=\mathbb{1}\!\left[\bigwedge_k h_k=1\right]\cdot\mathbb{1}\!\left[\sum_iw_iq_i\ge\tau\right]\cdot\mathbb{1}[\mathrm{required\ review\ completed}].
$$

其中 $\tau$ 是事前确定的质量门槛；最后一项表示本次任务要求的人工复核已经完成。这个式子只是帮助暴露决策结构，权重和门槛不是从讲义推导出的通用常数。若某项证据缺失，应先进入待核实状态，而不是把未知硬约束编码成通过。实务中应保留各项评分和理由，不能只留一个总分，否则无法解释得分变化来自事实质量还是文风。

模型可以起草 rubric，但生成后要做反例审查。给它一份语言流畅、数字错误的报告，看规则能否拒绝；再给它一份写法朴素、证据充分的报告，看规则是否错杀。把“长度更长”“引用更多”“语气肯定”替换掉而不改变事实，理想的事实性评分不应大幅变化。反例能证明具体标准存在漏洞，几个反例通过则不能证明标准已经完备。

## 9. LLM judge 的校准、自偏好与复核分流

**论文证据：** [GDPval 第 4–5 页](references/GDPval_Evaluating_AI_Model_Performance_on_Real-World_Economically_Valuable_Tasks.pdf#page=4) 的主要 gold 结果来自盲化的领域专家成对比较，而不是“模型按 rubric 打分就得到真实专业水平”。论文的实验自动评审器与专家的一致率为 66%，专家之间的一致率为 71%；它们是该任务与比较设置下的一致率，既不是模型任务成功率，也不是 66% 的评分可以无条件替代人工。原文 [第 8–9 页](references/GDPval_Evaluating_AI_Model_Performance_on_Real-World_Economically_Valuable_Tasks.pdf#page=8) 仍推荐专家比较，并指出自动评审器有覆盖与能力限制。

[讲义第 42 页](2026-10-27-zora-wang.pdf#page=42) 展示 rubric 评估中的自偏好：评审模型可能相对高估自己一类的输出。横轴总体准确率不错，也不代表它不会在模型排名或特定文风上产生偏差。讲义同时提醒输出随机性和视觉判断不足。这里依据讲义说明风险，没有将该图中的点估计推广成所有模型的偏差大小，也没有独立复现图中实验。

**工程推导：校准应评估错误类型，而不只比较平均分。** 先从目标工作流取一批任务，按公司、报告期、表格复杂度、问题严重性与是否存在口径调整分层。两位熟悉业务的评审者独立阅读，分歧保留并经讨论形成裁决；“人类标签”也要有版本和适用边界。随后让 judge 在看不到作者或模型身份的条件下评审同一批产物。对成对比较交换 A/B 顺序，对单件评分重复抽样，并保留原始响应，才能区别稳定偏差与随机波动。

在研报案例里，最应单独统计的是“把关键错误判为可以交付”的比例。设 $N_B$ 为人工裁决含重大问题的产物数，$N_{BA}$ 为其中被 judge 接受的数量，则

$$
\widehat{\mathrm{FAR}}=\frac{N_{BA}}{N_B},\qquad N_B>0.
$$

这是这批重大问题样本上的误接受率，分母不是全部报告数；没有重大问题样本时该指标不可估计。还应统计可交付产物被拒绝的比例、不同任务分层的差异，以及人工与模型分歧的原因。若样本小，零次漏报也不能当成真实漏报率为零；应报告样本量与不确定性。模型自己输出的“置信度 0.9”只是一个分数，除非在独立样本验证过它与正确率的关系，否则不能直接按 90% 可靠来安排无人交付。

降低自偏好可从隐藏模型身份、统一输入格式、交换比较顺序、使用独立人工裁决和跨模型评审入手，但多模型一致也不是独立证据。几个 judge 可能共享训练材料、相似偏好或同一份有缺陷的 rubric。正确做法是把“多 judge 都通过”与“原文确实支持”分开记录。涉及图表时，除文本抽取外还要提供真实页面或表格结构；抽取丢掉单位和脚注后，再强的文本 judge 也无法恢复未给它的证据。

分流规则应基于后果和可核查性：确定性核验全部通过且经过校准的低风险格式问题，可批量处理；重要结论、来源冲突和 judge 分歧送人工；原件被修改、越权外发或关键事实不受支持则直接阻断。分流节省的是有限的专家注意力，不能把“人工没有点开”重新解释成“人工默认同意”。

## 10. 训练时演化标准，评估时冻结对照

[讲义第 40–43 页](2026-10-27-zora-wang.pdf#page=40) 的演化 rubric 思路解决一个真实问题：固定奖励可能很快被模型学会，后来出现的复杂失败得不到区分。比较多条 rollout、分析人的修改和拒绝理由，可以产生新的学习信号。例如，模型已经学会给出页码，但研究员反复指出“把环比写成同比”，这一交互能提示增加“比较基期正确”的标准。此处是讲义所述研究方向，未取得的独立研究原文不被用来支持具体增益。

标准会变，并不等于一次评估可以随时改答案。工程上应隔离三个集合：训练任务与其可演化 rubric，开发集与人工校准材料，以及冻结的保留评估集。一次实验记录为 $(\theta_t,R_t,D_{\mathrm{train}},D_{\mathrm{dev}},D_{\mathrm{test}},E)$：$\theta_t$ 是被测模型或策略版本，$R_t$ 是训练时标准版本，三个 $D$ 是不同用途的数据，$E$ 是工具、权限与运行预算等环境配置。对比改进时，保留集、评审协议与预算先固定，使分数变化有可解释的分母。

从交互生成的新规则先作为候选，不直接覆盖正式规范。每条候选记录原交互、适用任务、反例、与已有规则的冲突及提出日期；人工判断这是普适缺陷、局部偏好，还是一次错误纠正。通过开发集检查后再用于下一版训练。若用户只是这次偏好短摘要，不能自动写成“所有报告不许展开”；若用户指出来源年份读错，则可能成为跨任务的数据质量规则，但仍需验证没有误伤跨年比较。

冻结评估也允许治理版本升级。例如保留集发现歧义或泄漏，可以废弃受影响项并发布新版本；但要留下原因，重新跑需要比较的模型，不能把旧模型的旧分数和新模型的新分数直接画在同一条“进步曲线”。[讲义第 44–45 页](2026-10-27-zora-wang.pdf#page=44) 对成本、漂移、污染与饱和的讨论，提示我们维护任务的新鲜度和可追溯性；它不能仅凭一张批评截图证明某个 benchmark 的所有结果都无效。

### 10.1 TAHI：从人的修改学到什么，状态更新在哪里

[讲义第 41、43 页](2026-10-27-zora-wang.pdf#page=41)中的人机交互标准演化，可以结合 [Efficient Test-Time Adaptation through Human-AI Interaction 第 2–6 页](references/Efficient_Test-Time_Adaptation_through_Human-AI_Interaction.pdf#page=2)理解。这里的 test-time adaptation 不只指在当前回答里多思考，而是随着一位用户完成多次任务，利用之前的交互调整后续 Agent。

TAHI 收集四类信号：对计划的改动、对交付文件的直接编辑、文字反馈、对 rubric 的补充或纠正。它们分别揭示流程、具体产物、解释性意见和验收标准。只读聊天文本会漏掉用户直接拖动图形、修改文件或否决自动评分所表达的知识。

论文的两条适配路径应分开理解。**上下文适配**将交互归纳为 memory 与 skills：前者保存事实和偏好，后者保存可复用的程序性工作方法，改变以后给模型的上下文。**权重适配**使用人类指导后相对更好的产物等偏好信号，经直接偏好优化（DPO）与低秩适配（LoRA）更新可训练模型，改变模型参数。前者易查看和撤回，但受检索、上下文长度和文字表达限制；后者可能形成更持久行为，但更新成本、可解释性和回滚要求不同。这些取舍是对机制的工程分析，不是论文证明一种路径普遍优于另一种。

按时间顺序，可将一轮写为“旧策略执行任务 → 人修改或补标准 → 形成交互记录 → 整理事实/技能或构造训练对 → 更新下一轮 Agent”。持久状态不只是最终文件，还包括当前 memory/skills、参数版本、反馈来源、适用范围和 rubric 版本。不能把当前任务还未出现的人类答案提前放进该任务的首次独立产物中。

**特别注意论文的评分协议。** 作者用当前任务中 Agent 首次独立生成的产物，与这一任务交互结束后的最终 rubric 对照评分；首次产物的 Agent 只学过之前任务的反馈。最终 rubric 是事后形成的测量工具，帮助捕捉最初没有写完整的人的标准。这与“整篇实验的 rubric 始终不变”不同，也与“允许 Agent 先看到当前任务最终答案再作答”不同。本文上一节建议的冻结外部保留评估，是工程上另设的公平比较手段，不应冒充论文原协议。

归档 v1 的研究覆盖 **30 名专家、600 个任务会话**，聚焦写作和视觉创作；每位参与者完成 20 个任务。不能因出现跨任务或跨用户收益，就推出可迁移到任意专业、组织和高风险领域。至少需要区分同一人的新任务、新人的相似任务和全新领域三类泛化。

对于研报案例，用户纠正“缺少合并范围说明”可能形成一条可复用检查技能；要求“这次只给三条最重要意见”更可能是当前任务偏好。归纳时必须保留证据与范围，不能把一次性偏好永久化，也不能把用户对草稿的事实错误当成可信知识直接学习。每次升级用保留任务检查已知能力是否退化，记录学习成本、人工负担和回滚点。

## 11. HAS H1–H5：先决定谁负责什么，再选择自动化程度

[讲义第 47 页](2026-10-27-zora-wang.pdf#page=47) 引入 Human Agency Scale，简称 HAS。它描述任务需要怎样的人类参与，不是给模型的智能排等级，也不是“H5 比 H1 高级”。一手论文 [WORKBank 第 4–5 页](references/Future_of_Work_with_AI_Agents_Auditing_Automation_and_Augmentation_Potential_across_the_U.S._Workforce.pdf#page=4) 的五级定义如下；右列是本章案例的工程映射，不是论文实测结论。

| 等级 | 原论文的主要含义 | 研报审阅中的一种适配方式 |
|---|---|---|
| H1 | Agent 可独立完成任务 | 在已授权的固定目录中计算校验值、检查表内加总并生成结果 |
| H2 | 少量人类输入能使表现更好 | Agent 预判后由人选择一次重点核验口径，随后完成大批格式与数值核验 |
| H3 | 人和 Agent 作为平等伙伴协作 | 研究员提出解释假设，Agent 回查证据和反证，双方共同修订审阅意见 |
| H4 | 成功完成任务需要人类输入 | 重大口径冲突或业务含义必须由负责人解释，Agent 提供材料和候选处理 |
| H5 | 持续的人类参与不可缺少 | 专家主导有价值判断的讨论与沟通，Agent 持续整理证据、记录变化 |

H3 的原始类别描述含“共同表现优于任一方单独工作”，这是尺度定义的目标含义，不能由此声称论文已经随机试验证明所有 H3 工作流都产生协同增益。要检验我们的研报流程有没有这种增益，仍需比较独立人工、独立 Agent 和人机协作，在同一批任务、预算和交付标准下分别测质量与耗时。H4 和 H5 也不能简化成“最后盖一个章”：前者有不可缺少的人类输入，后者依赖持续参与，责任与交互节奏不同。

**论文证据：** WORKBank 汇集 1,500 名工作者、104 个职业与 52 名 AI 专家的任务评估，数据收集于 2025 年 1–5 月；最终覆盖 844 个任务。论文 [第 9 页](references/Future_of_Work_with_AI_Agents_Auditing_Automation_and_Augmentation_Potential_across_the_U.S._Workforce.pdf#page=9) 的 46.1% 是任务平均自动化意愿评分超过五分量表中点 3 的任务比例。它不是 46.1% 的人愿意失业，也不是 46.1% 的任务已被实测自动完成。能力一轴来自专家判断，意愿一轴来自工作者反馈，不能合并成一个“可替代率”。

这一区分直接影响产品选择。研究员可能欢迎自动清理重复表格，却希望亲自判断经营变化原因；Agent 可能很擅长生成解释段落，却不擅长恢复扫描件里的负号。任务有能力可行性，也有人类意愿和错误后果。先自动化人们不想反复做、又能可靠检查的部分，再为需要判断和学习的部分设计协作，比按模型能生成什么就替换什么更接近讲义的问题意识。

## 12. 一个能落地的协作流程：状态、证据和交接

[讲义第 48–49 页](2026-10-27-zora-wang.pdf#page=48) 强调任务执行中的用户控制、引导，以及对不同交互模式的识别与适配。工程上的关键不是每一步都弹出确认框，而是在用户真正能改变判断、成本或行动后果的位置提供控制。

本案例可以沿以下六个步骤实施。首先建立任务约定：本次审阅覆盖哪些公司与期间，材料截止日期是什么，输出给谁，哪些动作已授权，哪些结论必须升级。把它保存为任务状态，不能只依赖几十轮之前的一条聊天消息。其次冻结输入：记录每份文件的版本、校验值、页数和解析状态，形成指标到来源片段的映射。缺页、加密或乱码进入“资料不足”，不得静默跳过后声称全量审阅。

第三步让 Agent 生成候选问题。每条至少包含原句、问题类型、证据、修改建议和不确定之处。调用工具时只给完成当前子任务所需的权限；抽取和计算可以写派生文件，但不覆盖原报告。第四步依次运行可执行检查与语义评审，把错误和分歧贴在具体问题上。第五步将需要人判断的内容成组呈现：不是泛泛问“是否继续”，而是给出冲突的两个数、各自报告期与来源，说明采用哪种处理会影响哪条结论。人员的选择成为一条有理由、适用范围与时间的决策记录。

第六步才形成交付版本，绑定输入版本、模型与工具配置、rubric 版本、检查结果、人工处置和最终文件校验值。若之后修改了影响结论的数字或证据，需要重新检查其依赖项；旧版本通过不表示新版本自动通过。要区分“候选已生成”“程序检查完成”“等待专业判断”“已完成任务要求的复核”“已交付”几个状态。这样，后台仍在运行或人工尚未处理的任务不会被前台误显示成完成。

这个流程还需要中断与恢复语义。用户暂停时，Agent 停在有保存点的位置，注明已经产生哪些文件、哪些操作尚未发生；恢复时核对资料与授权是否变化。用户若改口要求只看本季，先前关于跨季比较的任务不应继续执行。人类给出的新解释也不能悄悄改写历史来源：解释是新证据或工作假设，应与原始报告分层保存。

如何估算人机协作是否值得？不要只量 Agent 的模型延迟。记录从材料交付到审阅完成的总时长、人工实际阅读与修改时间、等待人工的时间、返工次数，以及未解决问题数量。人类在关键节点花了十分钟，可能避免几小时无效运行；反过来，如果 Agent 每个小动作都要求确认，节省的执行时间会被交互开销抵消。HAS 模式因此应按任务与阶段设定，出现重大资料冲突时可以从较自主的阶段转为强协作阶段，变化理由可见且能恢复。

## 13. 成本不能只看 token，可靠性不能只看单次通过

[讲义第 50 页](2026-10-27-zora-wang.pdf#page=50) 用大量并发 Agent 的案例和不同系统执行时长图提醒冗余问题。该页左侧关于并发数与约 50 小时的截图、右侧另一项评估的执行时间，是两个例子；不能拼起来计算某个统一实验的总 GPU 成本，也不能据此认定右图所有差异都由多 Agent 冗余造成。

**工程推导：先定义交付分母，再讨论降本。** 对一批 $M$ 次任务尝试，设 $c_m$、$c_t$、$c_s$ 分别为模型调用、工具与存储/计算的总成本，$t_h$ 为人的复核和沟通工时，$t_r$ 为额外返工工时，$w_h$ 为用于核算的每小时人工成本，$N_a$ 为按同一标准接受的交付数。则

$$
\widehat C_{\mathrm{accepted}}=
\frac{c_m+c_t+c_s+w_h(t_h+t_r)}{N_a},\qquad 0<N_a\le M.
$$

所有失败尝试的耗费都要进入分子，人工时长不能在 $t_h$ 与 $t_r$ 重复计数。这个批次平均值不是所有未来任务的价格预测；任务分布变了，分母和人工负担都会变。若 $N_a=0$，应报告“没有合格交付”与总支出，不能为了避免除零把指标填成零。

用一组纯教学数值说明：100 份候选报告共消耗 200 元模型和工具成本，人工复核 30 小时、返工 10 小时，以每小时 200 元核算，最终接受 80 份，得到每份合格交付 102.5 元。换便宜模型节省 150 元，但若增加 3 小时人工处理，合格交付数仍为 80，则变成 108.125 元。这里的价格、工时和通过数完全是假设；例子只说明模型账单下降不保证总体成本下降。

优化之前还要找到耗时在哪。将时间拆成模型执行、工具等待、队列等待、评审、人工响应与返工，记录每条子任务消耗和产物去向。两个 Agent 同时搜索相同资料、反复读取不变文件、为已确定的数值生成多次解释，都可能只扩大成本。并行的收益取决于关键路径：把独立表格核验并行化可能减少等待，把互相依赖的结论交给多个代理反复讨论则可能增加协调。可采用预算上限、共享只读证据、明确分工和停止条件，但它们需要通过任务级结果检验，而不是以 Agent 数量判断先进程度。

可靠性同样是流水线属性。设 $B$ 表示候选产物有重大错误，$V$ 表示可执行检查放行，$J$ 表示语义评审放行，$H$ 表示按任务约定完成最终复核并放行。在产物内容不被审后偷偷修改的前提下，错误被放行的概率按链式法则写成：

$$
P(B\cap V\cap J\cap H)
=P(B)P(V\mid B)P(J\mid B,V)P(H\mid B,V,J).
$$

这里没有假设各层独立。两个检查器若读同一个丢失脚注的文本抽取，错误高度相关；将它们各自的总体准确率相乘通常没有意义。没有要求人工复核的任务，可以将 $H$ 视为总成立，但不能据此声称有“人类最后把关”。对已经修过的产物，应以新版本重走相关检查，不能继续使用旧候选的概率标签和验收记录。

最后，将风险与平均质量分开。对不同严重程度 $s$ 的错误，可用 $P(\mathrm{accepted\ error}_s)L_s$ 表示一类期望损失，其中 $L_s$ 是假定后果的损失尺度；总和只能用于有合理估计的比较，并避免同一损害被重复计数。隐私泄露、未经授权外发等后果很难稳定折算成钱，应保留不可违反的约束，而不是让“平均收益为正”覆盖它们。这个模型的用途是迫使设计者说清分母、条件与后果，不能把未经测量的概率当作系统可靠性证明。

## 14. 安全评估需要看到状态变化，而不只看到回答

[讲义第 51–52 页](2026-10-27-zora-wang.pdf#page=51) 从隐私、安全和现实伤害案例转向一个限制：静态题目未必覆盖有工具、有权限和持续状态的 Agent。安全 benchmark 数量增加，不等于每个实际工作流的风险已经被覆盖。个别事故可以揭示失败路径，也不能单独估计总体事故发生率。

**工程推导：研报审阅的安全测试应从执行前状态一直观察到执行后状态。** 输入 PDF 可以包含恶意指令，外部网页可以要求上传内部表格，文件名也可能诱导错误路径。它们都只是被处理的数据，不能获得改变系统权限、隐藏问题或对外发送文件的权力。即便最终回答写着“已安全完成”，仍要检查原件是否改动、派生文件写到哪里、工具调用是否发出网络请求，以及哪些内容留在日志中。

将这个要求落到测试，至少覆盖四条路径。第一是受污染来源：在教学测试文档中插入试图改变任务的文字，检查 Agent 是否仍按用户的审阅目标处理。第二是权限边界：只允许在指定派生目录保存，尝试写入其他位置必须被工具层拒绝并留下可见记录。第三是中断恢复：在生成、检查和交付之间分别暂停，确认重试不会重复外发或错误覆盖。第四是证据缺失：故意移除一页附注，观察系统能否承认材料不足，而不是自动填充“常识”。这些是测试计划，不是本章已经运行的结果。

权限控制与语义评审的职责不能互换。给 judge 一条“不要泄露隐私”的规则，不能替代工具访问限制；把所有工具禁用也无法完成需要计算和引用的任务。较可操作的办法是只读原件、限制输出位置、把对外动作单独授权、敏感字段按用途裁剪，并为任何中途新增权限记录原因。秘密进入日志之后再从最终答案删掉，并没有撤销泄露；审查应覆盖完整数据流。

## 15. 有意义的工作与学习机会也是系统设计变量

[讲义第 53 页](2026-10-27-zora-wang.pdf#page=53) 的工作体验图提醒我们：有些容易受到 AI 影响的任务，同时提供创造、掌握和反馈的体验。图中是暴露程度与体验评分差异的关系，不能据此推导“引入 Agent 必然让所有人的工作更不快乐”。不同工作者也可能有相反偏好：一人认为整理材料是机械劳动，另一位新人正通过整理学习证据结构。因此，是否保留某一步，不能只问 Agent 能否做，还要问人的目标和成长阶段是什么。

本案例可让熟练研究员将跨表核对交给工具，把注意力放在解释、反证与沟通；也可给新人保留先独立提出三条审阅意见、再与 Agent 比较的环节。Agent 负责显示证据差异和漏掉的条件，而不是立即交付一份看似权威的完整答案。此时需要测量的不只有报告速度，还包括隔一段时间后能否独立完成相似任务、是否能解释自己接受的修改、是否越来越依赖无法核查的结论。这是工程与教学设计建议，不是讲义给出的随机对照学习效果。

[讲义第 55–60 页](2026-10-27-zora-wang.pdf#page=55) 进一步把工作任务与劳动力市场连接起来。**论文证据：** [GPTs are GPTs 第 1、7 页](references/GPTs_are_GPTs_An_Early_Look_at_the_Labor_Market_Impact_Potential_of_Large_Language_Models.pdf#page=7) 中的“约 80% 劳动力至少有 10% 的任务可能受影响”，建立在任务暴露评估与技术/配套软件假设上；其关键门槛是维持同等质量时，任务完成时间可能至少减少一半。暴露不是实际采用，不是自动化成功率，更不是 80% 岗位会消失的预测。

讲义有关早期职业就业的截图属于特定历史时期的观察。此次取得的 [Canaries 原文](references/Canaries_in_the_Coal_Mine_Six_Facts_about_the_Recent_Employment_Effects_of_Artificial_Intelligence.pdf#page=1) 已是 August 2026 版本，而讲义第 60 页图表截至 2025 年 9 月。不能把新论文的数值当作旧截图的数字补进去，也不能从就业暴露差异直接宣布某个个体失业由 AI 导致。需求变化、企业构成和宏观条件都使观察关联与因果解释不同。

[讲义第 58–61 页](2026-10-27-zora-wang.pdf#page=58) 讨论新任务、人类适应，以及“决定—执行—交付”的结构。执行时间减少后，确定正确问题、选择标准、验证证据、解释限制和承担交付责任仍可能需要投入。新任务出现是理解长期调整的机制，不保证每位被影响的劳动者都会立即得到新的岗位。第 61 页关于借助 AI 深入学习的社交媒体观点适合作为反思，不应当作证明某种学习方式普遍有效的实验。

因此，在设计业务 Agent 时，“多省下一小时”应与“这一小时原来承担什么功能”一起分析。删除重复抄录可能释放专业判断时间；完全删除新人的证据阅读可能削弱后续判断能力。较稳妥的协作设计保留人的目标设定、关键选择、纠错反馈和必要的练习机会，而不是只保留一个机械批准按钮。

### 15.1 技术可行性与自动化意愿：四个区域如何选型

[讲义第 57 页](2026-10-27-zora-wang.pdf#page=57)将技术能力判断与工作者希望自动化的程度放在两条轴上。高意愿、高能力的任务可以优先验证实际交付；高意愿、低能力的任务是研发方向；低意愿、高能力的任务要先理解人的控制、工作意义与责任要求；两者都低的任务通常优先级较低。这是任务选择框架，不是仅凭问卷就决定部署。

“能力”在 WORKBank 这里主要来自专家评估，并非每个任务都已通过真实端到端实验；“意愿”也不等于组织授权。应用时仍要检查资料、成本、可靠性和权限。研报的重复表格核验可能处于第一类，复杂经营归因可能需要研发与强协作，研究员希望亲自完成的关键判断则不能因为模型能生成文本就默认外包。

### 15.2 从任务暴露到就业变化，中间还缺哪些机制

一个职业通常是一组相互依赖的任务。自动化其中一部分，可能减少某些工时，也可能降低服务成本、扩大需求，或者增加新的检查、沟通与产品工作。企业是否采用，还取决于可靠性、成本、法规、客户要求和组织改造。因此，即使有可靠的任务暴露估计，也无法直接乘以岗位人数得到失业人数。

讲义中的新任务机制说明劳动需求可能重新分配，但没有保证这种调整立即发生、地域匹配或人人受益。早期职业人员还可能同时面临两类变化：原来承担的执行工作减少，原来通过这些工作积累经验的路径也缩短。若只保留资深人员负责“决定”和“交付”，却不设计新人学习判断的方法，短期提效可能伴随长期技能培养缺口。

观察就业数据时，至少要明确时间、年龄、行业、企业样本、暴露分类与比较组。Canaries 的后续版本扩展了数据和分析；本课对讲义旧图只作其呈现范围内的解释，不用新版数字填补旧图，也不把头条新闻当因果识别。工程师能据此提出需要跟踪的组织指标，不能仅凭相关图表替企业或个人预测必然结果。

## 16. 把案例走完：一次“数字正确但结论错误”的审阅

以下全部数据为教学构造。某报告写道：“本季营收 12 亿元，上年同期 10 亿元，同比增长 20%，证明核心业务需求显著提升。”附注又说明本季新纳入一家公司，贡献营收 2 亿元。Agent 最初只计算了 $(12-10)/10=20\%$，并因为来源页码有效而判定整句话正确。

可执行检查通过的是增长率算术、币种单位和引用位置；“核心业务需求显著提升”属于额外的因果解释，不能跟随算术结果一并通过。语义 rubric 应将这句话拆为数值事实与经营解释，要求后者有同口径、销量价格或管理层说明等证据。在现有材料中，新增合并范围已构成需要处理的替代解释。Agent 应指出论证不足，而不是自行宣布核心业务增长恰好为零：直接减去 2 亿元仍可能受内部交易抵消、业务重分类等条件影响，资料不足时没有足够依据形成完整可比口径。

协作阶段，研究员决定保留合并报表同比 20% 的事实，删除无依据的需求判断，并要求补一条“新增合并范围影响，尚不能据此判断原业务增速”。系统把这一选择记录为对当前句子的处理，不擅自生成“以后所有并购公司都不能比较增长率”的永久规则。修订后重新检查数值和证据，将原意见、修订理由与最终文本绑定。交付给用户的是一条可理解、可追踪的审阅结果，而不是只有“评分从 72 升到 91”的黑箱结论。

这个小例子也说明三类模型改进实验应分开：更好的抽取模型解决数字与单位识别；更好的 judge 解决事实与解释的区分；更好的协作流程让人员在必要位置补充业务判断。如果同时更换三个部分，最后质量上升，只能说明整套配置变好，不能把全部增益归因于某一种模型。固定其他条件逐一对照，再观察组合后的收益和新成本，才能解释改进来自哪里。

## 17. 故障诊断：从症状回到证据链

| 看到的症状 | 首先怀疑什么 | 区分原因的检查 | 修复方向与边界 |
|---|---|---|---|
| 分数很高，专家仍拒绝交付 | rubric 奖励格式而遗漏重要事实 | 用流畅但错误、朴素但正确的对照产物 | 修改标准后独立重评，不能只提高阈值 |
| 同一产物换顺序就换赢家 | 比较位置偏差或随机性 | 交换 A/B，多次运行并保留理由 | 盲化、平衡顺序与人工裁决；不保证偏差归零 |
| 多个 judge 一致漏掉单位错误 | 共用的抽取或标准有缺陷 | 对照原始页面与结构化中间表示 | 先修输入，再评模型；重复评审无法补回缺失信息 |
| 新版本开发集变好，保留集不变或变差 | 对开发反馈过拟合，或训练标准漂移 | 固定预算重跑，分任务与错误类别比较 | 缩小规则适用范围，隔离数据，不移动保留集门槛 |
| 模型费下降，总成本上升 | 人工返工、等待或失败率被忽略 | 核算全部尝试、合格交付和人工工时 | 选择总交付成本更低的配置，而非单价最低者 |
| 人只负责点同意，却很少发现错误 | 审查负担过大或证据不可见 | 看复核时间、分歧定位与抽查结果 | 减少无意义打扰，展示影响与证据，保留真实否决权 |
| 安全题通过，实际文件仍被错误发送 | 只评了回答，没有观察工具副作用 | 对比前后状态、网络动作与权限日志 | 工具层约束和有状态测试，不能仅追加一句提示 |
| 新人交付更快，却无法解释结论 | 执行外包同时移除了练习 | 无辅助迁移任务和口头证据解释 | 设计逐步减少辅助的学习任务，区分生产与训练目标 |

诊断时每次尽量改变一个机制，并保留原版本和失败样本。如果系统只更新总分而丢弃了原输入、证据片段和判分理由，后续很难知道问题出在模型、材料、工具还是评审标准。

## 18. 自测与答案

1. **为什么“原文包含这几个词”不能验证报告的专业结论？** 词语出现不保证主体、时间、方向和条件一致；它只能充当有限的形式检查，还需把结论逐项回连到支持它的证据。
2. **GDPval 的 66% 可以解释成 Agent 成功完成 66% 工作吗？** 不可以。它是实验自动评审器与专家的评审一致率；原论文 gold 的主要模型结果来自专家盲化比较，任务成功或胜率是另外的量。
3. **两个不同品牌 judge 都通过，是否可将漏报概率相乘？** 不能直接相乘。它们可能共享输入错误和评价偏好，需考察条件漏报与共同失败。品牌不同不等于统计独立。
4. **用户纠正了一次“同比/环比”，能否直接改正式 rubric 并宣布新分数进步？** 可形成候选规则，但应保留交互来源、检查适用范围，在开发材料验证；正式保留评估协议需冻结，版本升级时重新跑可比对照。
5. **H3 是否证明人机协作一定胜过独立人工？** 没有。它表达一种协作类别及目标；具体工作流的协同收益要通过同任务、同预算、同交付标准的对照验证。
6. **WORKBank 的 46.1% 是什么意思？** 是任务平均自动化意愿评分大于 3 的任务比例，不是赞成裁撤岗位的工作者比例，也不是实测可自动化比例。
7. **为何报出平均每份候选只花 2 元仍可能误导？** 它可能只计模型和工具，忽略人工与失败成本；需要把全部尝试的支出除以真正接受的交付数，并报告接受标准和任务分布。
8. **“12 亿比 10 亿增加 20%”正确，为什么整句话仍需修改？** 数值增长不自动证明核心需求提升。新增合并范围提供了替代解释；缺少可比口径和因果证据时应缩小结论，而不是凭空补一个看似精确的解释。
9. **安全评估为何必须包含状态？** 最终文字可能正常，工具已经覆盖原件或发送敏感文件；只有检查前后文件、外部动作和权限边界，才能看到这些后果。
10. **自动化是否越充分越值得部署？** 还需考虑合格交付成本、风险、工作者意愿、必要的人类判断和学习机会。把不可靠或不被需要的执行大量自动化，可能扩大负担而非创造价值。
11. **METR 的两小时时间跨度是否表示 Agent 连续运行两小时？** 不是。它对应任务的人类完成时长基线及规定成功率；Agent 实际运行时间与成本需另行记录。
12. **GDPval 的 1,320 与 220，RLI 的 240 与 230 分别是什么？** 前一组是全集与公开 gold 子集；后一组是项目总量与私有量化评估项目数，另有 10 个公开定性项目。混用会改变分母和公开范围。
13. **合成任务通过可执行验证，为什么仍可能不代表真实工作？** 验证只证明生成任务满足指定检查；任务分布、隐藏约束和人类意图可能已经被探索和过滤方式改变。
14. **CollabSkill 为什么引入人的潜在技能？** 会话产物同时受到人和 Agent 影响，共享参与者的多次配对能帮助区分贡献；加性假设、采样与评分噪声仍需检查，技能分数不是成功概率。
15. **TAHI 的最终 rubric 能否给当前任务首次生成时使用？** 原论文用最终 rubric 事后评价首次产物；首次 Agent 只能使用以前任务的学习信号。提前提供当前任务最终标准或答案会改变实验条件。
16. **“80% 劳动力有至少 10% 任务暴露”是否能换算为 80% 失业率？** 不能。它是特定等质量时间节约定义下的任务暴露估计；采用、需求、组织变化、新任务和责任约束都是中间机制。

## 19. 可运行算例与本次验证边界

[evaluation_math.py](examples/evaluation_math.py)只用 Python 标准库复算第 13、16 节的教学数字，并演示为什么不能把累计通过率当成相互独立的关卡概率。所有数值都是构造的数据，不来自真实用户或模型。

从仓库根目录运行：

```bash
python3 11-768/16.AgentsAndTheFutureOfWork/examples/evaluation_math.py
```

本次实测得到：基线每份合格交付 102.5 元；模型更便宜但人工时间增加时为 108.125 元；合并营收算术增幅为 20%。另构造 100 个已有重大错误的产物，经过三层检查后分别剩下 40、30、20 个被错误放行。条件链为 $(40/100)(30/40)(20/30)=20\%$；把三个累计比例误乘得到 2.4%，属于错误计算。这里的 20% 以重大错误产物为条件，不是全部产物中的事故发生率。

[EXECUTION.json](examples/EXECUTION.json)记录本次实际执行环境、脚本校验值、6 项检查和输出。零合格交付时拒绝计算单份成本，防止显示成零成本。这个算例验证分母与算术，不验证真实误报率、成本或协作收益。
