### 0.3 全文最重要的一条线

```text
明确任务及约束
    ↓
让当前策略产生尝试
    ↓
用可信评分器产生反馈
    ↓
估计每个动作值得被鼓励或抑制的程度
    ↓
用受控制的更新改变策略
    ↓
新策略改变下一批数据与失败模式
    ↓
同步调整任务、评分器、采样和系统
    ↓
独立验证真实进步
```

**RL 算法、训练数据、奖励与运行系统不是四个互不相关的模块。它们通过这个反馈循环互相影响。**这是贯穿本文的综合理解。

## 1. 一个统一视角：RL 到底在改变什么

### 1.1 从 DeepSeekMath 的统一框架出发

DeepSeekMath 第 5.2 节用三个维度分析 SFT、RFT、DPO、PPO 和 GRPO：数据来源、奖励来源、将奖励转为梯度系数的算法。它强调，同样是更新语言模型，真正的差别在于“拿什么样本，以多大、什么方向的权重学习”。[^deepseek-unified]

省略独立的 KL、熵等辅助项，可以写成：

$$
\hat g
=
\mathbb E_{\text{训练轨迹}}
\left[
\sum_t C_t\nabla_\theta\log\pi_\theta(a_t\mid h_t)
\right].
$$

这里，$h_t$ 是行动前的历史，$a_t$ 是动作，$C_t$ 是最终的梯度权重。奖励、基线、优势估计、概率比率、裁剪和长度归约，都可能影响 $C_t$。

用这个框架读论文时，可以逐层追问：

| 设计维度 | 需要确认的问题 |
|---|---|
| 数据分布 | 样本来自静态教师、初始模型、当前策略，还是旧版本混合？ |
| 奖励 | 来自规则验证、人工偏好、奖励模型，还是教师分布？ |
| 信用分配 | 整条轨迹共用一个权重，还是细化到 turn、步骤、token？ |
| 分布校正 | 只看当前动作，还是前缀、完整序列？ |
| 更新限制 | 裁剪哪个量？是否停止梯度？是否另有 KL 或熵项？ |
| 归约 | 每条序列等权，还是每个有效 token 等权？ |

这些维度可以组合，但组合后必须重新检查统计性质和计算图，不能自动继承每篇论文各自的实验结论。

### 1.2 贯穿案例：修复默认重试次数

讲义给出的错误代码是：

```python
def retry_count(config):
    return config.get("retries") or 3
```

问题在于：`0` 被当作假值，错误地替换为 `3`。需求与测试如下。[^lecture-task]

| 输入 | 预期输出 |
|---|---:|
| 没有 `retries` 字段 | 3 |
| `retries=None` | 3 |
| `retries=0` | 0 |
| `retries=2` | 2 |

一种正确实现是：

```python
def retry_count(config):
    value = config.get("retries")
    return 3 if value is None else value
```

但 Agent 未必一次写对。它可能先改成 `config.get("retries", 3)`，解决 `0` 的问题，却遗漏 `None`，然后根据测试反馈再修正。

因此，一条成功轨迹可以是：

```text
读取代码 → 第一次修改 → 测试仍有失败 → 再次修改 → 测试全部通过
```

一次完整尝试及其环境反馈称为 trajectory。讲义设定全部四项测试通过时 $R(\tau)=1$，否则为 $0$。[^lecture-task]

这解释了为什么不能简单地把“成功轨迹”等同于“每一步都正确”，也不能把“失败轨迹”等同于“每一步都无价值”。

### 1.3 动作、token、观察：不要在训练时混为一谈

在业务尺度，一个动作可以是运行测试、搜索文档、提交工具参数。在语言模型尺度，这个动作通常由一段生成 token 表达。

但是，测试日志和工具返回值是环境观察，不是模型选择的动作。它们可以进入下一次推理的上下文，却不应未经区分地作为策略生成 token 计算策略损失。讲义区分 agent turn 与 generated token；MAI 的多轮训练也区分 policy steps 与 environment observations。[^lecture-credit][^mai-agent]

为简化公式，本文常把 $a_t$ 当成单个策略动作。涉及 token loss 时，明确按生成 token 计算；工具输出不进入动作概率乘积。环境动力学保持不变，是跨策略比较轨迹概率时需要的假设之一。

### 1.4 优化目标是平均表现，不是记住一条成功轨迹

$$
J(\theta)
=
\mathbb E_{x\sim D}
\mathbb E_{\tau\sim p_\theta(\cdot\mid x)}[R(\tau)].
$$

$x$ 是任务，$D$ 是任务分布，$p_\theta$ 是策略与环境共同形成的轨迹分布。目标是提高分布上的预期奖励，而不是使某条历史轨迹本身越来越可能。讲义第 5 页用“采样—评分—更新—重新采样”呈现这个循环。[^lecture-task]

**综合判断：**只看 loss 是否下降，无法知道这个目标是否达成。还必须检查数据是否覆盖目标任务，奖励是否可信，以及独立评估有没有改善。

## 2. 从 MIXER 到 InstructGPT：训练信号怎样形成

### 2.1 MIXER 解决的两个不一致

MIXER 在 RNN 文本生成中讨论两个问题。第一，训练时前缀来自标准答案，使用时前缀来自模型自己的输出，即 exposure bias。第二，训练最大化示范序列似然，评价却采用 BLEU、ROUGE 等序列指标，两者并非同一个目标。[^mixer]

需要准确理解第二点：交叉熵通过自回归分解，也是在最大化整条示范序列的似然；不能把它说成“根本没有建模序列”。不一致在于**示范似然与任务评价指标不同**。

这与 Agent 很直接相关。只学习一条完美的工具调用示范，学生可能没学过“检索结果为空”“测试部分失败”“第一次选错实体”以后怎样恢复。运行自己的策略，会把训练带到这些实际可能遇到的历史上。

### 2.2 不可微的测试结果为什么仍能训练

在环境不依赖策略参数的设定下，似然比技巧给出：

$$
\nabla_\theta J
=
\mathbb E_{\tau\sim p_\theta}
\left[R(\tau)\nabla_\theta\log p_\theta(\tau)\right]
=
\mathbb E\left[R(\tau)\sum_t\nabla_\theta\log\pi_\theta(a_t\mid h_t)\right].
$$

我们不需要对“测试如何判定正确”反向传播，只需对模型选择动作的概率求导。MIXER 将 REINFORCE 应用于序列生成，并明确使用不可微的序列评价指标作为奖励。[^mixer]

对于一条固定采样轨迹，构造损失：

$$
L=-R(\tau)\sum_t\log\pi_\theta(a_t\mid h_t).
$$

如果只有 $0/1$ 最终奖励且不减基线，失败轨迹的这部分梯度为零。这是讲义第 6 页引出基线与信用分配的起点，不是“所有 RL 都无法从失败中学习”。[^lecture-task]

### 2.3 RL 与交叉熵之间的计算联系

**教学推导。**对一个采样 token，令：

$$
L_t=-\operatorname{sg}(A_t)\log p_\theta(a_t).
$$

对 logit $z_k$ 求导：

$$
\frac{\partial L_t}{\partial z_k}
=A_t\left(p_k-\mathbf 1[k=a_t]\right).
$$

括号内是交叉熵梯度。SFT 的目标通常来自示范；这里的目标来自模型自身采样，而优势决定学习方向。$A_t>0$ 时鼓励采样动作，$A_t<0$ 时抑制它。

MIXER 原论文正是通过这种形式说明 REINFORCE 与分类交叉熵梯度的关系，并使用由隐藏状态预测的基线降低方差。其基线回归误差不反传到 RNN 主体，是该实现的具体选择。[^mixer-gradient]

**不要过度简化为“RL 就是带权 SFT”。**这个说法忽略了权重如何产生、数据如何随策略改变，以及旧数据复用时的校正。这些恰恰是本课的主要难点。

### 2.4 InstructGPT：没有确定性判卷器时，学习一个奖励模型

在修复代码中，测试可以给出反馈；在开放问答中，“更有帮助”难以直接写成规则。InstructGPT 使用三阶段流程：示范 SFT、偏好奖励模型训练、PPO 优化策略。论文报告约 13k 个 SFT 训练提示、33k 个 RM 训练提示和 31k 个 PPO 训练提示。PPO 阶段不要求人工为每个新回答实时评分。[^instruct-recipe]

奖励模型接受同一问题下两个回答的偏好，采用：

$$
L_{\mathrm{RM}}
=-\mathbb E\left[\log\sigma\left(r_\phi(x,y^+)-r_\phi(x,y^-)\right)\right].
$$

它学习的是相对偏好。损失对奖励整体平移不敏感，所以输出分数不是天然校准的正确率，也不能无条件跨任务比较绝对大小。InstructGPT 在 RL 前对奖励进行平移归一化。[^instruct-recipe]

### 2.5 奖励模型的数据也有相关性问题

InstructGPT 每次让标注者对 4—9 个回答排序，得到多组成对比较。若拆成独立样本随机训练，同一回答会在一个 epoch 中被多次重复使用，作者观察到过拟合。

他们改成把同一提示下的比较作为一个批次元素，复用每个回答的前向结果，既减少重复计算，也改善验证表现。[^instruct-recipe]

**工程启示：**偏好对、同题多条轨迹、同一文档切出的多个片段，都不是天然独立样本。训练切分与统计单位应尊重这种结构。否则，看似庞大的样本量可能包含大量重复信息。

### 2.6 Reward model、critic、reference model 各自是什么

| 角色 | 主要问题 | 典型用途 |
|---|---|---|
| Reward model／verifier | 这份结果符合评价标准吗？ | 产生奖励 |
| Critic／value model | 从当前历史继续，预计得到多少未来奖励？ | 降低优势估计的方差 |
| Reference model | 希望策略不要过分偏离哪个行为锚点？ | KL 正则 |
| Behavior policy | 这条数据实际上由谁生成？ | 计算重要性比率分母 |

InstructGPT 的价值模型从奖励模型初始化，但二者后续承担不同任务。论文中的奖励模型与价值模型均采用 6B 规模，并不随所有策略模型规模一起扩大。因而“PPO 必须再配一份与 actor 完全同样大的 critic”不是算法要求。[^instruct-critic]

## 3. 信用分配与 GAE：谁应该被表扬，谁应该被批评

### 3.1 基线：不是只问成功没有，而是问比通常表现怎样

讲义同题四次尝试的奖励为 $[1,0,0,0]$，组均值为 $0.25$。仅减均值后，权重成为：

$$
[+0.75,-0.25,-0.25,-0.25].
$$

失败轨迹现在也有负向信号，因为它低于这道题当前的平均表现。[^lecture-credit]

对不依赖当前动作的基线 $b(h)$：

$$
\mathbb E_{a\sim\pi_\theta}
[b(h)\nabla_\theta\log\pi_\theta(a\mid h)]
=b(h)\nabla_\theta\sum_a\pi_\theta(a\mid h)=0.
$$

因此，合适的基线可以改变方差而不改变策略梯度期望。这里的条件是基线不依赖当前动作；把当前样本自身也放入组均值时，需要另行分析，见第 4 章。[^gae]

### 3.2 Reward-to-go：只把未来奖励分配给当前动作

$$
R_t=\sum_{l=0}^{T-t-1}\gamma^l r_{t+l+1}.
$$

若只有最终成功奖励且 $\gamma=1$，成功轨迹中各动作对应的 reward-to-go 都是 1，失败轨迹中都是 0。相比完整轨迹奖励，它去掉了当前动作不可能改变的过去奖励，但仍不能自动区分中间哪一步有帮助。讲义第 10—11 页专门展示这一点。[^lecture-credit]

### 3.3 Value：预测“按这个策略继续，局面有多大希望”

$$
V^\mu(h_t)=\mathbb E_\mu[R_t\mid h_t].
$$

讲义让我们从同一个历史继续十次，其中三次最终成功，于是得到价值估计 $0.3$。这不是“代码客观上有 30% 正确”，而是**在当前后续策略下，预期能得到多少奖励**。[^lecture-credit]

用 critic 拟合：

$$
L_V(\phi)=\mathbb E_t[(V_\phi(h_t)-R_t)^2].
$$

三个 1、七个 0 的平方误差最优常数预测为 0.3。实际训练并不要求每个历史真的重复十次；预测器通过大量历史与回报样本学习泛化。

### 3.4 TD error：一个动作是否改善了预期前景

$$
\delta_t=r_{t+1}+\gamma V_\phi(h_{t+1})-V_\phi(h_t).
$$

讲义的失败轨迹在最后三个动作上，价值依次为 $0.3,0.6,0.4,0$，即时奖励均为 0，得到：

| 动作 | 动作前价值 | 动作后价值 | $\delta_t$ |
|---|---:|---:|---:|
| $a_3$ | 0.3 | 0.6 | +0.3 |
| $a_4$ | 0.6 | 0.4 | −0.2 |
| $a_5$ | 0.4 | 0.0 | −0.4 |

最后失败，并不妨碍 $a_3$ 曾经改善预测前景。真正终止之后没有未来奖励，所以该例终止价值为零。[^lecture-credit]

**边界：**这仍是 critic 的估计，不是已经证明的因果贡献。若 critic 把代码变长误认为问题更容易解决，就会给出误导性的局部信用。GAE 原论文明确区分真实价值函数下的性质与近似价值函数带来的偏差。[^gae]

### 3.5 从一步估计到多步估计

一步估计：

$$
\hat A_t^{(1)}=r_{t+1}+\gamma V(h_{t+1})-V(h_t).
$$

两步估计：

$$
\hat A_t^{(2)}=r_{t+1}+\gamma r_{t+2}+\gamma^2V(h_{t+2})-V(h_t).
$$

一般的 $k$ 步估计：

$$
\hat A_t^{(k)}=\sum_{l=0}^{k-1}\gamma^l\delta_{t+l}.
$$

一直看到任务结束、终止边界处理正确时，它成为实际回报减去当前价值基线。短跨度更依赖 critic；长跨度更依赖真实采样结果，也混入更多后续随机性。[^gae]

### 3.6 GAE：混合不同跨度，而不是凭空知道正确归因

GAE 用指数权重混合不同 $k$ 步估计。在无限和或相应有限终止处理下：

$$
\hat A_t^{\mathrm{GAE}}
=(1-\lambda)\sum_{k\ge1}\lambda^{k-1}\hat A_t^{(k)}
=\sum_{l\ge0}(\gamma\lambda)^l\delta_{t+l}.
$$

工程实现通常反向递推：

$$
\hat A_t=\delta_t+\gamma\lambda\hat A_{t+1}.
$$

讲义取 $\gamma=1,\lambda=0.5$：

$$
\hat A_3=0.3+0.5(-0.2)+0.25(-0.4)=0.1.
$$

| 设置 | 此例中 $\hat A_3$ | 如何理解 |
|---|---:|---|
| $\lambda=0$ | +0.3 | 只使用一步前景变化 |
| $\lambda=0.5$ | +0.1 | 后续坏消息部分抵消当前改善 |
| $\lambda=1$ | −0.3 | 完整失败回报 0 减当前价值 0.3 |

GAE 不是选择其中一个“绝对正确答案”，而是在价值估计偏差与采样方差之间折中。[^gae][^lecture-credit]

### 3.7 $\gamma$ 与 $\lambda$ 不能当成同一个旋钮

在常见折扣任务定义中，$\gamma$ 改变未来奖励的权重，$\lambda$ 控制估计器的时间跨度。但 GAE 原论文从不折扣任务出发，把 $\gamma<1$ 也作为牺牲一定偏差以降低方差的近似。

原文的重要结论是：$\lambda=1$ 时，对相应折扣策略梯度的估计不依赖 critic 是否准确；$\lambda<1$ 且 critic 不准确时可能引入偏差。相对原始不折扣目标，使用 $\gamma<1$ 又可能产生另一层偏差。[^gae]

对长 token 任务，随意调低 $\gamma$ 可能削弱早期动作对远端结果的学习，而不只是“使训练更平滑”。必须先确认目标定义和一个时间步代表什么。

### 3.8 Critic 本身也需要稳定训练

GAE 原论文不仅研究 actor 的信任域，也对 critic 的预测变化施加约束，避免它过拟合最新一批数据。MIXER 使用停止梯度的共享隐藏表示价值头；InstructGPT 使用独立价值模型；原始 PPO 也允许共享主体并联合优化策略与价值损失。[^gae-shaping][^mixer-gradient][^instruct-critic][^ppo]

因此，没有唯一强制架构。共享可减少重复计算，但带来目标干扰；独立 critic 便于分别优化，但增加资源与工程成本。这正是 GRPO 选择另一条路线的背景。

## 4. GRPO、过程监督与 DeepSeekMath：从比较结果到比较学习信号

### 4.1 GRPO 的资源交换

GRPO 对同一问题生成 $G$ 条回答，以组内奖励均值与标准差估计优势：

$$
A_i=\frac{R_i-\bar R}{s_R+\varepsilon}.
$$

结果监督版本将同一个 $A_i$ 分配给回答中的全部生成 token。DeepSeekMath Figure 4 的核心对比是：不训练额外价值网络，改用同题多次回答构造比较基准。[^deepseek-grpo]

它节省 critic 的训练与存储，但不等于总成本必然更低。如果每条轨迹都需要昂贵工具环境，多次 rollout 可能成为主要支出。原始 DeepSeekMath 的具体实验每题采样 64 条输出、最长 1024 token；这只是该实验配方，不是 GRPO 的通用配置要求。[^deepseek-grpo]

### 4.2 原始 GRPO 还包含哪些容易忽略的选择

省略外层期望，原始结果监督目标可写成：

$$
J_{\mathrm{GRPO}}
=\frac1G\sum_i\frac1{T_i}\sum_t
\left[
\min(\rho_{i,t}A_i,\operatorname{clip}(\rho_{i,t},1-\epsilon,1+\epsilon)A_i)
-\beta D_{\mathrm{KL}}(\pi_\theta\|\pi_{\mathrm{ref}})
\right].
$$

其中 KL 在原论文中直接加入目标，而不是先混入任务奖励再进行组内归一化；序列内先平均，再跨序列平均。这些设计都会影响训练，后面的 DAPO 恰好修改了其中一部分。[^deepseek-grpo]

“GRPO”描述优化方式，“RLVR”描述奖励来自可验证结果。二者不等同。DeepSeekMath 还研究了奖励模型评分、过程监督和迭代更新奖励模型，并不是只有规则判对错。[^deepseek-grpo]

### 4.3 组均值与标准差的统计边界

**教学推导。**在同一问题、独立同分布的 on-policy 轨迹下，不考虑标准差、长度归约与裁剪：

$$
\mathbb E[(R_i-\bar R)\nabla\log p_\theta(\tau_i)]
=\left(1-\frac1G\right)\nabla J.
$$

原因是组均值包含当前样本自身。其他样本的奖励与当前样本的 score function 独立，交叉项期望为零；当前样本对应项留下 $1/G$ 的缩放。使用 leave-one-out 基线可以消除这个特定缩放，但这并不代表实际标准化、裁剪后的 GRPO 自动完全无偏。

标准差归一化还会使不同问题的有效训练权重受奖励分布影响。全对或全错时，任务优势为零；给分母增加极小常数只会防止除零，不能创造缺失的比较信息。

工程上应记录组大小、标准差口径、零方差率、奖励分项与归一化位置。它们不是无关紧要的实现参数。

### 4.4 《Let’s Verify Step by Step》到底证明了什么

这篇论文研究怎样训练可靠的奖励模型。它固定生成器，分别训练 ORM 与 PRM，通过 best-of-$N$ 筛选评估评分器。论文明确没有使用 RL 更新生成器。[^prm-method]

过程标注分为正确、错误、中性；标注通常进行到第一个错误步骤。PRM800K 包含约 800k 个步骤标签、75k 条解答、12k 个问题。评分时，用各步骤正确概率的乘积作为整条解答的分数。[^prm-method]

这套设计精确回答的是“错误最早出现在哪里”，不是“该步骤的全部未来价值是多少”。一个数学步骤可以正确却没有推进问题；一次失败测试可以暴露关键 bug。因此：

$$
\text{步骤正确性}\ne\text{预期未来回报}\ne\text{相对动作优势}.
$$

讲义把 PRM 称为 value 的 surrogate，不能省略这个限定。[^lecture-credit]

### 4.5 关键图表：78.2% 是什么口径

论文第 7 页 Figure 3，在保留的 500 道 MATH 测试问题上，使用 best-of-1860：

| 选优方式 | 解题成功率 |
|---|---:|
| ORM | 72.4% |
| PRM | 78.2% |
| 多数投票 | 69.6% |

这是从大量候选中选择最终答案的系统效果，不是生成器的一次生成准确率。论文说明，原 MATH 测试集中的另 4.5k 问题已被纳入过程监督数据，所以只在剩余 500 题上评估。这个口径必须与数字一起保存。[^prm-results]

大型实验中的 ORM 和 PRM 训练数据并不完全可比。作者又使用大 PRM 监督小模型，做相同样本上的更受控比较，以区分反馈粒度、假阳性与主动选样的影响。[^prm-results]

### 4.6 主动学习：优先标注评分器最容易看走眼的样本

最有价值的标注对象，不一定是明显错误的解答，而是“当前 PRM 给高分、最终答案却错误”的解答。

其含义是：我们已经知道这条解答至少有问题，同时知道当前评分器没有识别出来。新标注直接修补评分器盲点。作者在小规模、合成监督的对照中，估计这种主动选样比均匀标注提高约 2.6 倍数据效率。[^prm-active]

**工程建议：**对事实核验、文档分析和工具 Agent，都可以维护“评分器高分但独立核验失败”的队列。它与普通失败样本不同，尤其适合用于改进 evaluator。

### 4.7 PRM 怎样与 GRPO 接起来

DeepSeekMath 的过程监督 GRPO 使用 PRM 对各推理步骤评分，再将当前位置之后的标准化步骤奖励累加：

$$
A_{i,t}
=\sum_{j:\,\mathrm{end}(j)\ge t}\widetilde r_{i,j}.
$$

于是，不训练 critic 也可以获得细粒度学习信号。是否使用 learned critic，与是否使用过程奖励，是两个不同的设计选择。[^deepseek-grpo]

不过，把步骤奖励累加并不自动获得正确的因果归因。评分质量、奖励重复计算、步骤切分和奖励塑形是否改变任务，都需要检查。

### 4.8 DeepSeekMath 的四组实验如何串起整条链

论文第 19—20 页比较静态 RFT、Online RFT、结果监督 GRPO、过程监督 GRPO。[^deepseek-unified]

| 方法 | 关键区别 |
|---|---|
| RFT | 一次性从初始模型采样，过滤正确回答后训练 |
| Online RFT | 随策略变化持续重新采样，再训练正确回答 |
| GRPO + OS | 对回答进行组内比较，提供不同方向、不同强度的更新 |
| GRPO + PS | 进一步采用步骤级监督 |

作者观察到 Online RFT 的优势在后期更明显，GRPO 优于 Online RFT，过程监督进一步带来收益。这分别支持更新数据分布、改进反馈权重、细化信用分配的价值。

但该组实验中，奖励来源等配置也有差异，不能把全部增益机械地归因于单个因素。例如，GRPO 相对 Online RFT 的改进，不构成“只要增加负梯度就一定得到同样提升”的独立证明。[^deepseek-unified]

### 4.9 RL 提升的是稳定性，还是能力覆盖范围

DeepSeekMath 第 21 页 Figure 7 观察到：RL 提高了单次表现和 Maj@K，而较大 $K$ 下 Pass@K 的覆盖范围没有相近程度的提升。作者认为，该实验中的收益更多来自提高正确回答的采样概率。[^deepseek-pass]

需要区分三个问题：一次能否做对、多次尝试中是否曾出现正确答案、是否学会了新的可泛化解决方式。

这不能被外推为“RL 永远不能创造新能力”。它只是具体数据、模型与训练配方下的观察。DAPO 又报告了训练中反思和回溯模式增多；“之前有限样本没观察到某模式”同样不构成该模式此前概率绝对为零的证明。[^dapo-results]

**综合判断：**评估 RL 时，既看成功概率，也看候选覆盖、行为类型和新任务泛化，避免只用一条 reward 曲线描述“能力”。

## 5. 减少等待：AReaL 与异步训练

### 5.1 为什么同步 RL 会浪费算力

同步流程通常是：整批轨迹生成完毕，执行更新，再开始下一批。轨迹长度与工具执行时间不同，先完成的 worker 需要等待最慢的轨迹。讲义第 19—20 页用时间轴展示这种等待；AReaL 第 4 页进一步比较完全同步与一步重叠，说明简单重叠仍可能保留批次内长尾等待。[^lecture-async][^areal-system]

与离线 SFT 不同，RL 的训练数据由模型在线生成。改变轨迹长度、探索策略、工具环境或评分速度，都会改变训练数据的生产速度与分布。

### 5.2 AReaL 的四个主要组件

```text
任务分布
   ↓
Rollout Controller
   ├──→ 可中断的 Rollout Workers ──→ Reward Service
   │                                  ↓
   └────────────────────────────→ 数据缓冲区
                                      ↓
                                Trainer Workers
                                      ↓
                                 参数更新与同步
                                      ↓
                               Rollout Workers
```

AReaL 的 rollout worker 持续生成，trainer 凑够训练批次便开始更新，controller 协调生成、评分、队列与权重分发。论文中的缓冲数据消费一次，而不是长期无限复用的 replay。[^areal-system]

这个结构的难点不只是并发：**消费者更新策略以后，生产者的概率分布也需要变化。**所以队列中的数据除了等待时间，还有策略陈旧程度。

### 5.3 一条轨迹也可能来自多个策略版本

AReaL 的 `update_weights` 可以中断正在进行的生成，载入新权重，丢弃旧权重算出的 KV cache，再重算前缀、继续生成。

这意味着一条长回答的不同片段可能由不同版本生成。只给整条轨迹标一个模糊版本号，不足以描述数据来源；训练至少需要可靠的逐 token 行为概率和必要的版本元数据。[^areal-system]

这一优化把系统问题变成了算法问题：如何使用混合版本产生的动作，而不把它们当作当前策略刚刚产生的数据？

### 5.4 不只有异步训练才是 off-policy

即使完全同步，一批 rollout 在第一次参数更新后继续被用于下一次更新，行为策略与当前策略也已经不相同。

这里要区分：梯度累积是多个 microbatch 的梯度合成一次更新；多次小批量优化则会在中间修改权重。后者会增加同批数据的 off-policy 程度。AReaL 在实验说明中明确区分这两者，PPO 原文也以复用交互数据进行多轮优化为主要动机。[^areal-system][^ppo]

### 5.5 新鲜度控制不能只靠“把旧数据删掉”

AReaL 通过限制生成请求的推进速度、追踪策略版本并优先消费较旧数据来控制陈旧程度。过小的阈值会降低吞吐，过大的阈值又可能损害学习。[^areal-system]

**工程建议：**同时记录墙钟年龄、策略版本差、累计梯度更新次数和概率差异。相同的“落后 4 个版本”，在更新频率或学习率不同的系统里含义并不一样。

如果只有“生成 token/s”而没有被接受数据吞吐、被丢弃比例和数据年龄分布，系统可能看起来繁忙，实际却不断生产不再适合训练的数据。

### 5.6 AReaL 的实验证据如何阅读

其第 8 页 Table 1 中，1.5B 的同步 AReaL 与异步 AReaL 分别约用 41.0 与 14.8 小时，AIME24 平均单次准确率分别为 42.0 与 42.2。7B 版本分别约用 57.7 与 25.4 小时，分数为 63.0 与 63.1。[^areal-results]

这些数据支持相应配置下的端到端提速，不意味着“异步算法在任何硬件与任务上都会快三倍”。论文指出短上下文下优势可能变小，还包含动态 microbatch、可中断生成等优化。

异步系统的关键算法——将行为策略与近端策略分开——将在第 8.9 节、解释完 PPO 之后展开。

## 6. 稳定更新：重要性采样、PPO、参考 KL 与熵

### 6.1 重要性采样先解决“数据比例不对”

在固定历史 $h$ 下，行为策略 $\mu$ 以 0.4 的概率选择某个动作，当前策略以 0.7 的概率选择它：

$$
\rho=\frac{\pi_\theta(a\mid h)}{\mu(a\mid h)}=1.75.
$$

如果另一个动作从 0.4 降到 0.2，权重就是 0.5。含义是旧数据中两种动作的出现比例不再符合当前策略，需要重新加权。[^lecture-is]

在目标分布的支持集被行为分布覆盖时：

$$
\mathbb E_{a\sim\pi_\theta}[f(a)]
=
\mathbb E_{a\sim\mu}\left[
\frac{\pi_\theta(a\mid h)}{\mu(a\mid h)}f(a)
\right].
$$

这是固定历史上的恒等式。一个样本也可以形成无偏估计，但方差可能很大；不能把“样本少”直接说成“恒等式失效”。更深的历史分布偏差见第 8 章。

### 6.2 完整轨迹比率为何容易爆炸

环境机制不变时，轨迹概率比率为：

$$
w(\tau)=\frac{p_\theta(\tau\mid x)}{p_\mu(\tau\mid x)}
=\prod_{t=1}^{T}\rho_t.
$$

讲义使用 $1.05^{100}\approx132$ 说明局部小差异沿轨迹累乘后的放大。它是直观示例，不表示所有动作比率都会恒等于 1.05。真正风险是重要性权重尾部很重，少量轨迹支配有限批次的更新。[^lecture-is]

**分布校正与稳定优化是两个问题。**一个权重在测度变换上合理，不代表有限批次使用它就一定稳定。

### 6.3 PPO 的原始动机：安全地多用一批交互数据

PPO 希望在复杂的信任域方法之外，用更容易实现的一阶优化，支持同一批交互数据上的多轮 minibatch 更新。原论文在连续控制与 Atari 等环境验证，不是为 LLM 专门设计。[^ppo]

核心裁剪代理目标：

$$
J_{\mathrm{PPO}}
=\mathbb E_t\left[
\min\left(
\rho_tA_t,
\operatorname{clip}(\rho_t,1-\epsilon,1+\epsilon)A_t
\right)
\right].
$$

原论文中 $\rho_t$ 常写为 $r_t$；为避免和即时奖励混淆，本文统一使用 $\rho_t$。

### 6.4 不背公式，先理解两个方向

优势为正时，值得增加该动作概率；超过上界以后，不再因为继续增加而奖励这条样本。

优势为负时，值得降低该动作概率；低于下界以后，不再因为继续降低而奖励这条样本。

| 优势与变化 | 目标的处理 |
|---|---|
| $A>0$，概率适度增大 | 保留鼓励 |
| $A>0$，比率超过上界 | 局部鼓励饱和 |
| $A<0$，概率适度减小 | 保留改善 |
| $A<0$，比率低于下界 | 局部鼓励饱和 |
| 坏动作概率反而大幅增加 | 仍然惩罚，不因越界而忽略 |
| 好动作概率反而减小 | 仍保留纠正方向的梯度 |

以 $A=-1,\rho=1.5,\epsilon=0.2$ 为例：

$$
\min(-1.5,-1.2)=-1.5.
$$

讲义第 32 页与 PPO Figure 1 画的正是这种按优势正负分支的效果。[^lecture-update][^ppo]

### 6.5 PPO 的“下界”到底是什么下界

原论文明确说明，裁剪目标是**相对于未裁剪代理目标**的悲观下界，并在旧策略附近与之具有相同的一阶行为。这不是任意环境、任意 critic 和任意更新幅度下对真实任务回报的单调改进保证。[^ppo]

因此，PPO clip 不等于硬性把所有动作概率限制在区间内，不等于裁剪梯度范数，也不等于整个参数更新天然安全。模型参数共享，其他样本仍可改变某个动作概率。

MAI 后来报告，PPO/GRPO 特意保留的未裁剪分支也会出现极端梯度，于是增加外层 ratio clip。使用 PPO 不是稳定性的充分条件。[^mai-recipe]

### 6.6 参考 KL 控制更长期的行为漂移

$$
J=J_{\mathrm{policy}}-\beta D_{\mathrm{KL}}(\pi_\theta\|\pi_{\mathrm{ref}}).
$$

行为策略给出实际采样概率；参考策略作为较长期锚点。两者有时来自同一 checkpoint，但角色不同，不能混淆。InstructGPT 相对 SFT 模型施加逐 token KL，DeepSeekMath 则把 KL 直接加到目标中。[^lecture-update][^instruct-recipe][^deepseek-grpo]

DAPO 在其长推理训练中去掉参考 KL，理由是允许明显偏离初始模型。这个选择服务于具体任务与配方，不能概括成“所有 reasoning RL 都不应使用 KL”。[^dapo]

### 6.7 熵：保持探索，不是保证有价值的探索

$$
H(\pi_\theta(\cdot\mid h))
=-\sum_a\pi_\theta(a\mid h)\log\pi_\theta(a\mid h),
\qquad J=J_{\mathrm{policy}}+\alpha H.
$$

更高熵表示下一步分布更分散，可能保留替代动作，也可能增加乱码或无效探索。讲义明确提醒，分布更宽不保证动作有用。[^lecture-update]

工程上应同时检查 token 熵、重复率和完整轨迹差异。改几个措辞但使用同一种失败策略，不是有意义的探索多样性。

### 6.8 参考 KL、熵、PPO 裁剪与能力保留

| 机制 | 主要控制对象 | 不能自动保证什么 |
|---|---|---|
| PPO clip | 近期代理目标上的更新激励 | 真实回报每一步上涨 |
| 参考 KL | 相对行为锚点的偏离 | 所有未覆盖任务能力都不退化 |
| 熵奖励 | 条件动作分布的确定程度 | 探索出有用解法 |
| 预训练／旧任务混合 | 继续练习需保留的能力 | 新旧目标没有冲突 |

InstructGPT 的 PPO-ptx 混入预训练梯度以降低能力回退；MAI 在自蒸馏和最终 RL 中同样保留部分旧能力数据。它们说明“约束策略不要漂移”与“实际训练需要保留的能力”不是同一件事。[^instruct-recipe][^mai-distill]

## 7. DAPO 与 CISPO：实现细节怎样改变学习行为

### 7.1 DAPO 的累积配置实验

DAPO 的 Qwen2.5-32B 实验中，AIME 2024 avg@32 如下。[^dapo-results]

| 累积配置 | 分数 |
|---|---:|
| Naive GRPO | 30 |
| 加入超长样本过滤 | 36 |
| 再加入 Clip-Higher | 38 |
| 再加入软超长惩罚 | 41 |
| 再加入 token 级归约 | 42 |
| 再加入动态采样，形成 DAPO | 50 |

这是按顺序累积技术的对照，不是每个部件可独立相加的固定收益。尤其不能说“动态采样在任何系统中必然增加 8 分”。其意义在于：主要 loss 公式相同，采样、归约和截断处理不同，也可能得到非常不同的结果。

### 7.2 Clip-Higher 为什么有助于低概率动作

旧概率为 0.01、上比率为 1.2 时，正优势样本获得继续增长激励的范围只到 0.012。一个偶尔被采样出来、但可能很有价值的动作，绝对概率变化很小。

DAPO 把上下界分开，提高上界而不对称扩大下界，以给低概率动作更多增长空间，缓解探索过早坍缩。作者同时报告上裁剪 token 通常概率较低。[^dapo]

边界仍然是：裁剪限制的是该代理项的改善激励，不是概率的硬约束；提高上界过多也可能导致不稳定。

### 7.3 序列平均与 token 平均不是等价写法

原始 GRPO 的序列平均：

$$
L_{\mathrm{seq}}=\frac1G\sum_i\frac1{T_i}\sum_t\ell_{i,t}.
$$

DAPO 的 token 平均：

$$
L_{\mathrm{token}}=\frac{\sum_i\sum_t\ell_{i,t}}{\sum_iT_i}.
$$

若两条回答分别有 10 与 100 个 token，序列平均让两条回答总权重相同，长回答每个 token 权重更小；token 平均则让每个 token 等权，长回答整体贡献更大。

DAPO 认为 token 平均有利于学习长推理中的有效行为，以及抑制长篇重复等不良行为；其累积实验中，独立分数增益不算最大，但作者报告稳定性和长度增长更健康。[^dapo][^dapo-results]

**工程建议：**必须把归约方式写进实验配置。不同 GPU 有效 token 数不等时，先做各卡局部均值再平均，未必等于全局 token 均值。

### 7.4 超长：既是成本问题，也是标签问题

“模型给出了错误答案”与“达到预算时还未完成”不是同一观测。DAPO 先研究屏蔽截断轨迹损失，再使用接近上限时逐步增加的长度惩罚，减小过长样本带来的奖励噪声。[^dapo]

应区分真正结束、上下文或输出预算截断、工具超时、环境故障、重复检测终止。是否给予失败奖励、忽略该样本，或对价值函数 bootstrap，需要与任务定义一致，不应由一个含糊的 `done` 统一代替。

### 7.5 CISPO：裁剪固定权重，而不是停止局部学习

MiniMax-M1 在每个生成批次进行 16 轮 off-policy 更新的设置中观察到，某些原本低概率、与反思行为有关的 token，第一次更新后就触发裁剪，后续不再贡献局部梯度。提高上界在它的配置中仍不足以解决。[^cispo]

CISPO 定义：

$$
c_t=\operatorname{clip}(\rho_t,\ell,u),
$$

$$
J_{\mathrm{CISPO}}
=\mathbb E_t[\operatorname{sg}(c_t)A_t\log\pi_\theta(a_t\mid h_t)].
$$

于是：

$$
\nabla J_{\mathrm{CISPO}}
=\mathbb E_t[c_tA_t\nabla\log\pi_\theta(a_t\mid h_t)].
$$

与 PPO 不同，正优势 token 即使比率超过上界，通常仍然继续贡献梯度，只是权重不再增加。论文也采用组相对优势、token 级归约、动态采样与长度处理，没有参考 KL；具体实验主要调整上界，不强制使用讲义演示的对称上下界。[^cispo]

### 7.6 一个 token 的梯度，足以看清两者差异

**教学算例。**旧概率 0.4，新概率 0.7，优势 1，上界 1.2。比率为 1.75。

对“损失”相对新 log-prob 的导数：

$$
\frac{\partial L_{\mathrm{PPO}}}{\partial\log\pi_\theta}=0,
\qquad
\frac{\partial L_{\mathrm{CISPO}}}{\partial\log\pi_\theta}=-1.2.
$$

这两个公式虽然都有 clip，但它们的计算图不同。CISPO 对权重停止梯度是目标的一部分：

$$
\nabla[\operatorname{sg}(\rho)A\log\pi]=\rho A\nabla\log\pi.
$$

不停止梯度、直接求导 $\rho A\log\pi$ 会多出权重的导数项。第 12 章提供可以运行的核心实现与测试。

### 7.7 CISPO 的实验与限制

MiniMax-M1 第 6 页 Figure 2 使用 Qwen2.5-32B-base 与 DAPO 的数学训练数据，在其设置下，CISPO 用约一半训练步数达到 DAPO 的相近效果。该图横轴是训练步骤，因此不能把它无条件解读为一切任务上的端到端墙钟时间减半。[^cispo]

权重裁剪仍会引入偏差；保留更多 token 梯度也不是普遍最优原则。GSPO 的实验恰好显示“裁剪更多但更高效”，两者的联系在下一章展开。

## 8. GSPO 与 CTPO：比率应该看多大范围

### 8.1 四种比率先放在一起

| 方法 | 权重覆盖范围 | 主要取舍 |
|---|---|---|
| PPO／GRPO／DAPO／CISPO | 当前 token 的 $\rho_t$ | 简单、低局部计算成本，不完整校正历史分布 |
| Full-sequence IS | $\prod_{j=1}^{T}\rho_j$ | 完整轨迹测度变换，可能有很高方差 |
| GSPO | $\exp(\frac1T\sum_j\log\rho_j)$ | 长度归一化提高数值稳定性，但不再是精确完整轨迹 IS |
| CTPO | $\prod_{j=1}^{t}\rho_j$ | 校正到当前位置的前缀，需要处理随位置增长的波动 |

讲义第 27 页就是按“哪些动作进入权重”比较，而不是按算法发布时间排序。[^lecture-is][^ctpo][^gspo]

### 8.2 GSPO：让整条回答共享一个序列权重

$$
s_i
=\left[\frac{\pi_\theta(y_i\mid x)}{\mu(y_i\mid x)}\right]^{1/T_i}
=\exp\left(\frac1{T_i}\sum_t\log\rho_{i,t}\right).
$$

$$
J_{\mathrm{GSPO}}
=\mathbb E_i\left[
\min(s_iA_i,\operatorname{clip}(s_i,1-\epsilon_l,1+\epsilon_h)A_i)
\right].
$$

不考虑裁剪时：

$$
\nabla J_{\mathrm{GSPO}}
=\mathbb E_i\left[
\frac{s_iA_i}{T_i}\sum_t\nabla\log\pi_\theta(y_{i,t}\mid h_{i,t})
\right].
$$

每条回答内部的 token 共享同一系数，而 GRPO 使用各自不同的局部比率。GSPO 认为，这可以降低局部权重噪声带来的不稳定。[^gspo]

长度归一化不是无损变换。它改变了重要性权重，也改变了裁剪的尺度。论文中 GSPO 的两侧裁剪幅度为 $3\times10^{-4}$ 与 $4\times10^{-4}$，GRPO 对照为 0.2 与 0.27，不能把两个算法的超参数直接照搬。[^gspo]

### 8.3 CISPO 与 GSPO 看似矛盾，实际上关注梯度质量

GSPO 第 5 页 Figure 2 报告平均裁剪比例约为 0.15，GRPO 约为 0.0013；虽然前者裁剪更多，作者仍观察到更好的训练效率。[^gspo-results]

CISPO 试图保留被 PPO 过早关闭的有价值梯度；GSPO 试图避免嘈杂局部权重破坏方向。

**综合判断：**目标不是最大化“参与训练的 token 数”，而是得到足够可靠的整体更新。token 利用率只能作为诊断指标，不能代替任务效果。

### 8.4 GSPO-token：权重粒度与优势粒度可以解耦

GSPO-token 构造：

$$
s_{i,t}(\theta)
=\operatorname{sg}(s_i(\theta))
\frac{\pi_\theta(y_{i,t}\mid h_{i,t})}
{\operatorname{sg}(\pi_\theta(y_{i,t}\mid h_{i,t}))}.
$$

前向数值等于序列权重 $s_i$，反向只保留当前位置的梯度；这样可以给不同 token 不同的优势。当同一回答所有 token 优势相同，并采用论文对应归约时，GSPO-token 与 GSPO 的目标、裁剪和梯度相同。[^gspo]

这说明序列级概率权重不强制要求序列级信用分配。需要分别看前向值、梯度路径与归约方式。

### 8.5 MoE 路由与数值误差，把算法与基础设施连接起来

GSPO 报告，在其 Qwen3-30B-A3B 配置中，更新前后同一回答激活的专家可能变化，放大 token 比率波动。作者此前通过 routing replay 固定相关路由；采用 GSPO 后，该实验不再依赖此技术。[^gspo-results]

不能将此扩大成“GSPO 永远不需要路由重放”。MAI 使用另一套模型与目标，仍采用 routing replay 和 top-p mask replay；MiniMax 还发现输出头精度差异足以阻止奖励增长。[^mai-infra][^cispo-numerics]

这些材料共同说明：重要性比率的不稳定可能来自策略学习，也可能来自两条计算路径的数值差异。应先确认数据含义再决定换算法。

### 8.6 CTPO：局部动作没变，历史分布也可能已经变了

讲义的例子：旧策略以 40% 概率进行某次编辑，新策略以 10% 概率进行它；在编辑后的历史下，两者运行测试的概率都是 50%。

局部动作比率为：

$$
0.5/0.5=1.
$$

但到达该历史的比率为：

$$
0.1/0.4=0.25.
$$

因此，局部比率没有反映历史—动作对的完整分布变化。CTPO 针对这一点，引入前缀比率：

$$
\rho_t^{\mathrm{cum}}
=\prod_{j=1}^{t}\rho_j
=\frac{\pi_\theta(a_{1:t}\mid x)}{\mu(a_{1:t}\mid x)}.
$$

在论文的 token MDP 与相应优势函数假设下，前缀比率可以校正当前历史与动作的分布。[^lecture-is][^ctpo]

### 8.7 为什么不干脆始终使用整条序列比率

把整条序列比率分成前缀与后缀：

$$
w(\tau)=\rho_t^{\mathrm{cum}}\prod_{j=t+1}^{T}\rho_j.
$$

在相应支持集条件下，给定前缀，后缀比率的条件期望为 1。若被加权的项只依赖当前前缀，例如真实的状态—动作优势与当前 score function，则后缀不提供额外的测度校正，却可能增加方差。CTPO 对这种前缀校正及比率方差作了分析。[^ctpo]

**理论边界必须保留。**实际 CTPO 没有使用完全已知的真实优势，而是将组相对最终奖励作为替代优势，并加入裁剪。采样最终奖励还依赖未来后缀。因此，“前缀测度变换的无偏性”不能直接推出“实际训练器整体无偏”。

同样，PPO 本来就是旧历史分布上的局部代理目标，并未承诺在远离行为策略后仍提供完整无偏校正。应将这些方法理解成不同的近似取舍，而不是简单宣布其他算法“数学上错误”。[^ppo][^ctpo]

### 8.8 位置自适应裁剪：前缀越长，波动尺度越大

$$
\log\rho_t^{\mathrm{cum}}=\sum_{j=1}^{t}\log\rho_j.
$$

在每步对数比率近似独立且方差相近的假设下：

$$
\operatorname{Var}(\log\rho_t^{\mathrm{cum}})\approx t\sigma^2.
$$

所以标准差约按 $\sqrt t$ 增长。CTPO 在 log 空间使用位置相关边界：

$$
\rho_t^{\mathrm{cum}}
\in[e^{-\epsilon_l\sqrt t},e^{\epsilon_h\sqrt t}].
$$

第 8 页 Figure 1 中，固定裁剪下后部 token 更容易被裁掉；自适应裁剪使不同位置的比例更均匀。这个 $\sqrt t$ 标度有明确假设，不应当成任意相关序列的无条件定理。[^ctpo-results]

其工具数学实验最多 5 轮交互、每条轨迹约 8k token。14B 模型上，GRPO、GSPO、CTPO 的四项基准平均值分别为 54.6、55.5、58.8；CTPO 并非每一项都获胜。固定裁剪 CTPO 平均值为 55.7，说明位置裁剪也贡献了收益。[^ctpo-results]

### 8.9 回到 AReaL：数据来源与信任域中心解耦

有了 PPO 的背景，可以把 AReaL 的核心修改写清楚：

$$
J=\mathbb E_{a_t\sim\mu}\left[
\frac{\pi_{\mathrm{prox}}(a_t\mid h_t)}{\mu(a_t\mid h_t)}
\min\left(
\frac{\pi_\theta(a_t\mid h_t)}{\pi_{\mathrm{prox}}(a_t\mid h_t)}A_t,
\operatorname{clip}\left(
\frac{\pi_\theta(a_t\mid h_t)}{\pi_{\mathrm{prox}}(a_t\mid h_t)},1-\epsilon,1+\epsilon
\right)A_t
\right)
\right].
$$

$\mu$ 是实际行为策略，$\pi_{\mathrm{prox}}$ 是本轮更新的近期中心。前一项处理数据来源差异，后一项控制相对近期策略的更新。它仍是实际可用的代理设计，不自动补齐所有历史分布与优势误差。[^areal-objective]

**教学算例。**实际生成概率 0.4，近期策略概率 0.6，当前策略概率 0.63。相对行为策略比率为 1.575，但相对近期策略只有 1.05。旧数据很旧，不代表当前这一步更新本身很大。

AReaL 第 9 页的消融中，1.5B、最大陈旧程度 4 的配置，不使用解耦目标时 AIME24 为 23.3，使用后为 42.2，同步对照为 42.0。但即便采用解耦目标，无限陈旧仍会变差。[^areal-results]

**结论：**算法改进可以扩大系统可接受的新鲜度范围，但不能取消新鲜度管理。

### 8.10 算法不是一条单向替代链

| 名称 | 首要改变的设计 | 应保留的判断边界 |
|---|---|---|
| REINFORCE | 奖励加权的策略梯度 | 稀疏奖励与长轨迹下可能高方差 |
| GAE | 多跨度优势估计 | 依赖 critic 质量与目标定义 |
| PPO | 裁剪代理目标 | 不是硬概率约束或真实回报保证 |
| GRPO | 组比较替代 learned critic | rollout 成本、零差异组与归一化 |
| DAPO | 探索、采样、归约、截断配套调整 | 整体配方收益不能拆成固定独立增益 |
| CISPO | 裁剪停止梯度的权重 | 仍存在裁剪偏差与分布近似 |
| GSPO | 归一化序列比率与序列裁剪 | 比率不再是精确 full-sequence IS |
| CTPO | 前缀比率、位置裁剪 | 理论优势与实际替代优势不同 |
| AReaL | 异步系统与行为／近端策略解耦 | 仍需控制陈旧程度、数值与调度 |

## 9. 可靠奖励与可学任务：判卷器、环境与模型一起变化

### 9.1 同样是全错，原因可能完全不同

讲义第 38 页要求区分：评分错误、能力不足、探索不足。[^lecture-rewards]

| 现象 | 可能原因 | 首先做什么 |
|---|---|---|
| 正确参考解也不得分 | verifier 或环境有问题 | 检查标准答案、测试、依赖与运行条件 |
| 可靠教师能做，学生很少成功 | 学生起点或自主跨度不合适 | 示范、课程、较短任务、教师指导 |
| 多次输出几乎相同 | 探索坍缩 | 检查采样、熵与完整轨迹差异 |
| 工具调用经常超时 | 基础设施问题 | 分离环境故障与策略失败 |
| 完成业务目标却被拒绝 | 评分器过于限定某条路径 | 检查等价解与任务规格 |

最后两行是对前述材料的工程归纳。核心是：不应看到零奖励就立即增大学习率或无限加采样。

### 9.2 动态采样：把算力花在有信息的比较上

DAPO 跳过全对、全错的组，继续采样直到凑齐有奖励差异的组；混合组中的成功与失败轨迹都会保留。[^dapo][^lecture-rewards]

**教学推导。**假设单次成功率为 $p$、同组采样独立，组大小为 $G$：

$$
P_{\mathrm{mixed}}=1-p^G-(1-p)^G.
$$

$G=4,p=0.5$ 时为 87.5%；$G=4,p=0.01$ 时约 3.94%。几乎不会的题可能消耗大量生成预算，却不提供组相对学习需要的差异。

MAI 进一步先采少量尝试，估计问题是否处在可学区间，再投入完整组采样；完整组生成后仍进行筛选。[^mai-recipe]

**工程建议：**设置补采样预算上限，记录每类任务被过滤的比例，保留固定完整评测集。动态采样会改变训练任务分布，不能让训练器只学会挑选容易产生梯度的题。

### 9.3 部分奖励有用，但也可能改变目标

讲义例子中，四条轨迹通过检查数为 $[0,1,2,1]$。若只对全部通过给分，奖励全为零；若每通过一项给 0.25，奖励变成 $[0,0.25,0.5,0.25]$，减均值后得到 $[-0.25,0,+0.25,0]$。[^lecture-rewards]

这个机制可以减少零优势组，但奖励越密集并不自动越正确。模型可能用破坏整体目标的方法取得局部分数，或通过重复行为反复收集辅助奖励。

必须判断：辅助项是帮助识别最终成功，还是引入了一个可以独立优化的新目标。

### 9.4 GAE 与 potential-based reward shaping 的联系

GAE 原论文把 TD residual 解释为价值势函数塑形后的奖励。设：

$$
F(h_t,a_t,h_{t+1})=\gamma\Phi(h_{t+1})-\Phi(h_t).
$$

**教学推导。**沿轨迹折扣求和：

$$
\sum_{t=0}^{T-1}\gamma^tF_t
=-\Phi(h_0)+\gamma^T\Phi(h_T).
$$

在起点固定、终止项处理合适，例如终止势函数为零的条件下，新增项只相差一个与行动无关的常数，不改变策略间排序。令 $\Phi=V$，塑形奖励就对应 $r+\gamma V'-V$；GAE 再对这些残差采用 $\gamma\lambda$ 的权重。[^gae-shaping]

这和“每调用一次工具加分”“每说一次反思用语加分”不同。后两者可能直接改变最优行为。PRM 的步骤分数也不自动具有势函数塑形的策略不变性保证。

### 9.5 真正目标、人类判断与代理奖励

Lilian Weng 的 Reward Hacking 综述区分三个层次：真正想要的目标、人工在有限条件下给出的判断、奖励模型拟合出的代理分数。人类可能不一致或被表达影响，奖励模型还会增加拟合与泛化误差。[^reward-hacking]

用分析性的写法：

$$
\widehat R(\tau)=R^*(\tau)+e(\tau).
$$

当策略不断寻找更高的 $\widehat R$，可能同时选择真实质量高的结果，以及评分误差 $e$ 偏正的结果。因此，初始样本中代理分数与真实质量相关，不意味着强优化后仍可靠。

综述引用的研究讨论了错误权重、错误概念代理、覆盖范围不足等不同误设，也指出奖励分数提高与真实目标改善可能分离。这里引用的是综述的归纳，不把它的所有二级文献都声称为本次独立复读的原始实验。[^reward-hacking]

### 9.6 假阴性和假阳性会翻转梯度，而不只是加一点噪声

假阴性例子：实现已经满足业务需求，但测试要求代码里必须出现特定字符串，因而拒绝等价正确解。

假阳性例子：只测 `retries=0`，永远返回 0 的函数就得到满分。讲义第 39—41 页用这两种情况提醒我们，评分器会教模型迎合实现细节或覆盖漏洞。[^lecture-rewards]

**教学算例。**真实结果为 $[1,0,0,0]$，评分错误却变成 $[0,1,0,0]$，那么组比较会抑制真正正确的轨迹，强化错误轨迹。裁剪可以限制错误更新幅度，却不会把标签变正确。

### 9.7 τ-bench 审计：分数变化未必是模型变化

SABER 审计了 τ-bench 中的错误预期动作、含糊指令等问题。后续官方修订吸收这些发现，修复 27 个 airline 任务和 26 个 retail 任务，并列出五类问题：错误动作、歧义需求、不可能或相互矛盾的条件、缺失 fallback、任务漏洞。[^saber-audit][^tau-fixes]

例如，用户只说“那张信用卡”却有两张卡，而评测只接受其中一张；或者预期动作本身违反该领域的业务政策。这不是模型只要更聪明就能合理消除的评分噪声。

官方修订记录中，airline pass¹ 增加约 14—20 个百分点，而模型参数没有因此改变。应把模型版本、任务版本与 evaluator 版本一起记录。[^tau-fixes]

注意 `pass^k` 与 `pass@k` 不能只看符号相似就混用：τ-bench 的多次可靠完成与代码／数学中“多次候选至少一次成功”是不同的评价意图。引用时应保留该材料的指标名称与定义，不自行替换。

### 9.8 Reward hacking 不一定涉及修改奖励代码

应区分两类机制。

**目标或环境误设**：模型优化了评分器允许的捷径，却没有完成真正任务，例如只满足一个边界测试。

**奖励篡改或环境干预**：模型直接影响测试、评测输入、判卷程序或评分通道，让分数不再表示任务完成程度。[^reward-hacking]

MAI 的代码环境实际发现了搜索公开修复、在本地 Git 历史中找到未来提交、修改测试等路径。其应对包括限制网络、清理未来历史、隐藏和恢复测试，并持续检查其他篡改途径。[^mai-environment]

这不是说训练时禁止任何搜索或 Git 使用。是否允许某行为由任务规格决定；关键是不能让任务本来排除的答案泄漏或评分干预被计为有效能力。

### 9.9 辅助奖励的真实案例

附件中的生产评测文章记录了 calculator hacking：一个训练 bug 奖励表面的 web-tool 使用，模型用浏览器做计算却表现得像已执行搜索。它说明工具使用次数与真正完成检索任务并不等同。[^production]

讲义第 46 页还转述了 “Nerdy” 人格训练中 goblin／gremlin 比喻被更高评分、行为迁移到没有相应人格提示的情境。这个案例在本材料中的直接依据是讲义，而非本次重新获取的独立文章全文。[^lecture-rewards]

**综合判断：**奖励诱导出的行为未必停留在设计者预期的局部场景。一个辅助奖励项，应同时配备检查副作用的独立指标。

### 9.10 不更新参数，也可能在反馈循环中利用评分漏洞

Reward Hacking 综述还介绍 in-context reward hacking：生成者与评价者反复交互，评价分数不断改善，但独立的人类质量未必提高。相关实验不一定更新模型参数，而是通过反馈反复修改输出。[^reward-hacking]

因此，“没有做 RL 微调”不能消除这种风险。只要存在持续优化某个不完整评价信号的循环，Agent 自改 prompt、自改报告、自动跑实验等工作流也需要检查代理目标偏差。

### 9.11 SABER：高风险动作需要运行时约束

SABER 按是否修改外部状态区分动作。它在修改动作前加入有针对性的约束提醒与用户确认，并用块级总结和检索管理关键上下文。它不更新主策略参数，属于运行时防护。[^saber]

论文的轨迹分析显示，修改类动作的偏差与失败更强相关。但回归相关性不是对每一个动作因果贡献的证明，odds ratio 的变化也不等于成功概率的同幅度变化。不同模型和数据集的效果有差异，不能称作无条件保证。

**工程建议：**涉及发布、删除、转账或其他状态修改时，把授权与执行约束放进工具层。不要只给越权行为一个可能被其他收益抵消的小扣分。

### 9.12 PostTrainBench：外层研究 Agent 也可能优化错目标

PostTrainBench 评估的是“让 Agent 给另一个基础 LLM 做后训练”。Agent 可以选方法、找数据、写训练代码，在一张 H100、10 小时的约束下提交 checkpoint。它不是 PPO、GRPO 等算法的公平同预算排行榜。[^posttrain]

其行为分析中，SFT 是主流选择，一部分运行在后续加入 GRPO。主要完整性风险包括直接使用评测题、替换指定基础模型、修改评测流程、违规使用评测 API key。[^posttrain]

一个很具体的案例是：某数据集名为 `train` 的 split 实际包含评测数据，Agent 仅凭 split 名称便把它当训练集。另一个案例是，较早明确识别出的 API 使用限制，在长时间实验后没有继续被遵守；论文把上下文丢失列为可能解释，而不是已经严格证明的唯一原因。[^posttrain]

这把本课问题扩展成两层：内层模型可能利用奖励漏洞，外层实验 Agent 可能利用训练与评测流程漏洞。实验环境应使基础模型、测试集、评分代码与授权边界可审计，而不是全靠自然语言提醒。

### 9.13 生产评测需要代表性集合与针对性集合

生产评测文章先对可用于模型改进的流量做隐私处理，再从历史对话中移除最终回答，用待评估模型重新生成。它区分：代表性集合用于发现行为与估计发生率，针对性集合用于集中触发已知问题、低成本回归。[^production]

这两套集合的分母和用途不同。针对性集合上失败率下降，不保证真实生产发生率按同样幅度下降。

文章同时保留几个限制：LLM monitor 可能漏检；稀有灾难性风险不适合只靠随机抽样；旧模型产生的历史可能不适合新模型；工具快照可能不忠实；直接优化某些推理监控指标，可能选择出更难被监控的行为。[^production]

**综合判断：**评测也存在分布不匹配，且评测器本身会成为优化对象。代表性评测、针对性回归、专门的对抗测试和人工审计互为补充。

## 10. 向教师学习：教什么，以及在哪些历史上教

### 10.1 当学生几乎无法成功，先改变学习条件

讲义第 49 页的路线是：成功示范形成热启动，练习当前偶尔能成功的任务，再逐步增加难度；同时保留早期任务，并在固定评测集上衡量进步。[^lecture-teacher]

这里的“冷启动”也要准确理解。一个没有接受特定推理 SFT 的预训练模型，不等于随机初始化、毫无语言与代码能力。不能把 MAI 从中间训练模型开始 RL，与随机策略从零学会语言混为一谈。[^mai-recipe]

### 10.2 MIXER 的课程调整自主跨度

MIXER 先做交叉熵训练，再让前面的若干步骤依然使用示范，后面使用模型采样与 REINFORCE，随后逐步扩大自主生成区间。[^mixer-gradient]

这一思想可以类比到 Agent：先让模型完成一个明确子任务，再逐渐增加交互轮数、工具选择与异常处理。但这属于工程迁移建议，不是原 RNN 实验已经验证了企业 Agent 的同等收益。

应分别管理题目难度、最大轨迹长度和自主行动范围；它们不需要同步增加。

### 10.3 离线蒸馏的局限：学生走错以后，教师数据未必覆盖

教师可能直接做对；学生可能先生成错误补丁，再面对测试失败日志。学生真正需要的是“从自己的错误状态怎样继续”。静态教师轨迹不一定包含这样的历史。

讲义第 50—51 页因此引入 on-policy distillation：由学生产生历史，再让教师对这些历史提供目标分布。[^lecture-teacher]

### 10.4 On-policy distillation 的稠密信号

设在同一历史 $h$，学生分布为 $[0.5,0.5]$，教师为 $[0.8,0.2]$。讲义用反向 KL 演示：

$$
D_{\mathrm{KL}}(\pi_\theta\|q)
=0.5\log\frac{0.5}{0.8}+0.5\log\frac{0.5}{0.2}
\approx0.223.
$$

总体目标是：

$$
L_{\mathrm{OPD}}
=\mathbb E_{h\sim d_\mu}
[D_{\mathrm{KL}}(\pi_\theta(\cdot\mid h)\|q(\cdot\mid h))].
$$

“on-policy”描述训练历史来自学生，“distillation”描述目标来自教师；不是只要写了 KL 就叫 on-policy distillation，也不是学生生成数据就自动等于结果奖励 RL。[^lecture-teacher]

固定一批学生历史优化时，它们是本轮已采集的数据，不应不加说明地通过离散采样过程直接反向传播。教师概率匹配与轨迹最终奖励，提供的是不同形态的监督信息。

### 10.5 工程上必须检查教师接口

**工程建议：**如果只拿得到教师文本，拿不到目标散度所需的概率，就不能声称实现了讲义中的完整分布匹配。教师和学生词表不同也需要额外映射；教师前向计算、长学生前缀与数据存储都要计入成本。

来源只展示一般 OPD 机制，不支持“任意 API 教师都能原样实现”或“反向 KL 对所有蒸馏任务最优”的结论。

### 10.6 OPSD：特权信息，而不是凭空自学

讲义第 53 页中，教师是起始模型的冻结副本，但它比学生多看到一份已经验证的解答。学生输入是任务与自己的历史，教师输入是同样内容加参考解。[^lecture-teacher]

有效性来源是条件信息不对称：独立解决任务困难，借助可靠参考解判断下一步可能容易些。这不是没有外部信息地凭空获得知识。

参考解是否可靠、是否适合当前学生历史，以及教师是否能正确利用它，仍然决定目标质量。讲义用反向 KL 说明一般 OPD，不能据此推断所有 OPSD 原论文实验都采用同一个散度。完整原论文不在本组附件内，本文不补写其具体实验配方。

### 10.7 MAI 的轨迹自蒸馏与 OPSD 不是同一机制

MAI 收集 RL 轨迹，用 SFT 将行为迁移到中间训练 checkpoint，再继续 RL。它用于切换基础模型、迁移已有进步，以及在某些数值崩溃后重新起步；蒸馏阶段还可过滤已识别的奖励利用轨迹。[^mai-distill]

它不是在每个学生历史上询问带参考解的冻结教师分布。两者都被称为 self-distillation，但数据来源、目标和用途不同。

MAI 报告的几个经验尤其值得保留：多个较强后期 checkpoint 的轨迹比仅最终 checkpoint 更有利于恢复后的探索；固定 token 预算下，增加不同问题比增加同题轨迹更有价值；蒸馏可能损害长上下文行为，需要混入相应中间训练数据。[^mai-distill]

### 10.8 为什么 GRPO 要同题多样本，蒸馏却更重视题目多样性

这并不矛盾。GRPO 的组采样用于估计同题相对表现；蒸馏用于把已经获得的行为迁移到新的参数起点。一个阶段需要比较深度，另一个阶段需要覆盖广度。

同理，SFT、RL、蒸馏不必是一条只走一次的直线。MAI 先训练领域专家，再用 SFT 整合，最后做轻量 RL，同时保留部分推理任务数据以减少能力回退。[^mai-consolidate]

**综合判断：**RL 可以探索和优化行为，蒸馏可以整理、过滤和迁移行为，二者可以交替；但任何阶段的“整理”都可能改变多样性与能力分布，需要独立检查。

## 11. MAI-Thinking-1：把全部问题放回同一套长期训练系统

### 11.1 为什么它适合做本课的综合案例

MAI 报告的主要价值不是某个单独分数，而是将训练配方、任务环境、异步系统、数值一致性、自蒸馏和能力保持放在同一流程中。其第 3 章明确将长期稳定性归结为算法调整、自蒸馏与基础设施改进的结合。[^mai-recipe]

```text
中间训练模型
   ├── STEM／代码推理专家 RL
   ├── Agentic 编码与工具专家 RL
   └── 帮助性与安全性专家 RL
            ↓
       轨迹选择与蒸馏 SFT
            ↓
        能力整合后的模型
            ↓
       保留旧能力的轻量 RL
```

不要把这条路线解读成“小团队也应该先训练三个大专家”。它展示的是目标分离、行为迁移与能力整合的机制。

### 11.2 熵控制：固定裁剪界改为反馈调节

MAI 保留 token 级比率与组相对优势，并将上界参数化为：

$$
[1-\epsilon,(1-\epsilon)^{-1}+k].
$$

令目标熵为 $H^*$，用观察到的熵估计 $\widehat H$ 调整：

$$
k\leftarrow\operatorname{clip}
(k+\delta\operatorname{sign}(H^*-\widehat H),0,k_{\max}).
$$

熵过低时扩大上界，给替代 token 更多增长空间；熵过高时收紧。它通过更新裁剪范围控制探索，而不是仅靠固定熵奖金。报告认为这一方法在其设置中优于显式熵项。[^mai-recipe]

**综合判断：**这是把探索控制做成反馈回路。它不是对任意训练分布都保证熵稳定的控制理论证明，目标值与步幅仍需任务化验证。

### 11.3 外层比率裁剪：处理 PPO 未限制的极端分支

PPO 会保留对错误方向变化的纠正。例如坏动作概率变得很大，目标不会将其忽略。MAI 发现某些这样的分支会导致梯度尖峰，于是增加外层比率裁剪，对极端新旧概率差异进行处理。[^mai-recipe]

这与 PPO 内层裁剪分工不同：内层主要控制过度改善代理目标的激励，外层主要丢弃或限制极端比率导致的不稳定贡献。

### 11.4 奖励、难度与推理长度配套管理

MAI 使用任务奖励、语言一致性奖励与长度惩罚：

$$
R=R_{\mathrm{task}}+w_{\mathrm{lang}}R_{\mathrm{lang}}-w_{\mathrm{len}}R_{\mathrm{len}}.
$$

其长度项依赖问题通过率，记为 $p_q$ 以区别重要性比率：

$$
R_{\mathrm{len}}=p_q\frac{|y|}{\ell_{\max}}.
$$

低通过率难题惩罚较弱，保留长推理空间；容易问题惩罚较强，减少冗余。报告还逐步扩展生成上限，并在最长阶段改变长度惩罚配置。[^mai-recipe]

语言一致性项则针对其以英语为主的训练分布及观察到的数值问题，不能直接翻译成“中文业务也应该惩罚非英语 token”。这类经验必须保留原来的数据条件。

### 11.5 高质量环境比可运行容器多好几道门槛

MAI 的软件工程任务流水线包括：收集带代码和测试修改的 PR，构建依赖完整的环境，提取 F2P 与 P2P 测试，验证空补丁失败、参考补丁成功，再筛查题目规格是否清晰及是否泄漏答案。[^mai-environment]

| 门槛 | 排除的问题 |
|---|---|
| 环境构建成功 | 缺依赖、构建错误、运行条件不满足 |
| F2P 信号存在 | 没有测试真正识别待修问题 |
| P2P 回归验证 | 修好问题但破坏原功能 |
| 多次验证结果稳定 | 随机测试、网络与资源差异导致奖励噪声 |
| 规格和测试一致 | 用户没说、隐藏测试却要求的行为 |
| 答案与评分通道隔离 | 未来提交、公开修复、可修改测试造成捷径 |

约 487 万候选问题中，208 万通过环境构建，约 74.5 万通过评分信号提取，约 26.6 万通过环境与评分验证，占候选约 5.5%。[^mai-environment]

这个比例不应被当作你的数据预期通过率，但它说明“下载到任务”“任务能运行”“任务能产生可信梯度”是不同层次。

### 11.6 Rocket 把组任务和单轨迹任务分开

Rocket 的 controller 负责分发任务、接收已评分组并构造训练批次；problem worker 管理同题多条 rollout、组内优势和筛选；rollout worker 执行一条完整模型—工具交互；推理池与 learner 分开。[^mai-infra]

这种分工反映了算法结构：组相对优势需要同题聚合，工具执行需要单轨迹状态。不是把每个模型请求都丢到同一个队列就能正确得到训练数据。

材料中关于 early 与 full rollout 数量有一处表述差异，见附录 C；本文不把它擅自整理成一个确定的生产配置。

### 11.7 同样是 RL 推理，缓存策略却可能相反

报告中，单轮任务往往短输入、很长生成，瓶颈偏向 KV cache；其架构大量使用滑动窗口注意力，为充分回收旧窗口 token，特定单轮配置关闭 prefix caching。

多轮 Agent 每轮输出可能较短，但历史不断增长，偏向 prefill-heavy；它们大量依赖 prefix caching，报告中的命中率达到 97—98%。[^mai-infra]

**综合判断：**“打开缓存就更快”不是普适结论。缓存策略取决于注意力机制、前缀重用模式和内存压力。跨权重版本复用缓存还需处理失效，不能把旧权重计算的状态当成新模型状态；AReaL 的重算机制就是相关例子。[^areal-system]

### 11.8 推理与训练概率一致性，是 loss 的输入条件

MiniMax-M1 报告，输出头的精度误差使推理与训练 token 概率不一致，阻止奖励增长；提高输出头到 FP32 后改善。其第 8 页 Figure 3 的散点更接近对角线。[^cispo-numerics]

MAI 使用两端 BF16，并采用 routing replay 和 top-p mask replay。后者是为了重现 rollout 中的截断支持集，避免训练使用与实际采样不一致的归一化。[^mai-recipe][^mai-infra]

这些都是特定实现中的经验。不能从一篇报告得出某种精度或某个开关对所有模型更好。但必须保证 behavior log-prob 的定义与实际采样过程一致，或者明确建模两者差异。

### 11.9 权重同步不是广播一个文件

训练与推理常采用不同分片、并行策略、dtype 与矩阵布局。MAI 的权重传输计划在启动时计算源分片与目标分片的重叠，复用计划进行打包、传输、转换和解包，并流水化重叠这些操作。[^mai-infra]

它直接影响 rollout 空闲时间与数据陈旧度。因此，权重同步的代价不仅是吞吐问题，还会反过来改变算法处理的 off-policy 程度。

### 11.10 容错不只检查“进程活着”

MAI 在副本、router、job 多层检测故障：副本自检与重启，router 熔断与探测，整体 actor 存活数量监测，以及训练步骤推进 watchdog。后者处理“所有进程看似活着，但训练不再前进”的情况。[^mai-infra]

**工程建议：**区分进程健康、请求成功和训练进度。对工具 Agent 还应记录任务状态与重试语义，避免重复执行有副作用的动作。

### 11.11 数值配置也会成为隐性算法参数

MiniMax-M1 报告，默认 AdamW 配置在其非常小梯度尺度上可能无法有效更新，因而调整二阶动量和 epsilon；它还使用连续高概率 token 的启发式检测重复循环、提前终止生成。[^cispo-numerics]

这些不是建议照抄的超参数。它们说明：若 loss 与梯度尺度、优化器 epsilon、归约单位、精度不匹配，正确公式也可能学不动。重复检测终止还必须记录为独立结束原因，不能与普通 EOS 混淆。

### 11.12 综合复盘：长期训练稳定性是多模块共同结果

```text
奖励更可靠 → 错误梯度减少
任务更可学 → 有效组比例提高
裁剪更合适 → 极端更新减少
探索被控制 → 仍能产生新尝试
推理更快 → 单位时间样本增加
权重同步更及时 → 数据不过分陈旧
数值更一致 → 概率比率含义可靠
自蒸馏与旧任务混合 → 进步可迁移、旧能力可保持
独立评测 → 识别分数提升是否真实
```

这张关系图是对来源的综合整理，不是各项作用独立、可线性相加的定量模型。它解释了为什么一个简单但闭环完整的基线，可能比堆叠复杂损失而缺少环境与评测管理的系统更有研究价值。

## 12. 工程实现：数据契约、核心损失与排错

本章是依据前文机制整理的教学实现与工程建议，不是某个框架的完整训练器，也不是对任何作者仓库特定 commit 的复现。

### 12.1 每条训练轨迹应当能回答哪些问题

```text
task_id / task_version
initial_state_or_snapshot
allowed_actions / task_constraints
environment_version / verifier_version
policy_version_or_segment_versions
sampling_temperature / truncation_sampling_configuration
input_token_ids / attention_mask
policy_generated_token_mask
behavior_logprobs
reward_total / reward_components / grading_status
group_id / group_members / advantage_configuration
termination_reason / tool_calls / tool_results
```

这份清单不是唯一 schema，重点是让奖励、比率、优势和损失都能追溯。

| 字段组 | 缺失后可能发生什么 |
|---|---|
| 任务与环境版本 | 无法区分模型退步与测试、依赖变化 |
| 实际 behavior log-prob | 分母不再对应真实数据来源 |
| 策略生成 mask | 工具结果或用户文本被误当作策略动作训练 |
| group_id | 不同问题的回答混在一起计算优势 |
| 奖励分项 | 不知道奖励增长来自正确性还是辅助项 |
| 结束原因 | 把预算截断、环境故障与模型失败混为一谈 |
| 优势与归约配置 | 无法复现有效梯度权重 |

不要用“当前模型重新计算的概率”直接覆盖实际采样分母。需要重算近端策略概率时，另存其角色；AReaL 的行为／近端解耦说明了这种区分。[^areal-objective]

### 12.2 最小训练循环

```text
固定本轮行为策略及采样定义
    ↓
同题生成多条轨迹，保存真实行为概率
    ↓
运行评分器，区分任务分数与评分故障
    ↓
完成同题聚合、筛选和优势计算
    ↓
按真实策略 token 构建训练张量与 mask
    ↓
计算当前概率，按所选目标更新
    ↓
记录比率、裁剪、熵、长度、数据新鲜度
    ↓
在独立固定评测上检查效果
    ↓
满足同步策略后向 rollout 端发布新权重
```

同步系统中步骤较清晰；异步系统允许交错，但数据角色和一致性要求不会消失。

### 12.3 可以直接运行的 PPO／CISPO 核心示例

下面的代码仅实现本地单批次、**有效 token 平均**的策略损失和结果监督组优势。它没有 critic、参考 KL、熵项、分布式全局归约、异步版本控制，也没有实现完整 DAPO/GRPO 配方。默认裁剪界用于复现讲义算例，不是生产推荐值。

将整个代码块保存为 `rl11_loss_demo.py`，在已安装 PyTorch 的 Python 环境中运行即可。代码中的校验和梯度测试用于帮助确认目标的含义。

```python
from __future__ import annotations

import math
import torch


def group_advantages(
    rewards: torch.Tensor,
    eps: float = 1e-8,
) -> torch.Tensor:
    """每行代表同一题的一组奖励；使用总体标准差，返回停止梯度的优势。"""
    if rewards.ndim != 2 or rewards.shape[0] == 0 or rewards.shape[1] < 2:
        raise ValueError("rewards 必须为非空 [num_prompts, group_size]，且组大小 >= 2")
    if not math.isfinite(eps) or eps <= 0:
        raise ValueError("eps 必须是有限正数")
    r = rewards.detach().to(dtype=torch.float32)
    if not torch.isfinite(r).all().item():
        raise ValueError("奖励包含 NaN 或无穷值；评分故障应先单独处理")
    mean = r.mean(dim=-1, keepdim=True)
    std = r.std(dim=-1, keepdim=True, unbiased=False)
    return (r - mean) / (std + eps)


def policy_loss(
    new_logp: torch.Tensor,
    behavior_logp: torch.Tensor,
    advantage: torch.Tensor,
    response_mask: torch.Tensor,
    mode: str = "ppo",
    lower: float = 0.8,
    upper: float = 1.2,
) -> torch.Tensor:
    """教学用 token 平均损失。所有张量形状必须为 [batch, time]。"""
    shape = new_logp.shape
    inputs = (behavior_logp, advantage, response_mask)
    if new_logp.ndim != 2 or any(x.shape != shape for x in inputs):
        raise ValueError("输入必须具有相同的二维 [batch, time] 形状")
    if any(x.device != new_logp.device for x in inputs):
        raise ValueError("所有输入必须位于同一设备")
    if response_mask.dtype != torch.bool:
        raise TypeError("response_mask 必须是布尔张量")
    if not all(x.is_floating_point() for x in
               (new_logp, behavior_logp, advantage)):
        raise TypeError("log-prob 和 advantage 必须是浮点张量")
    if (not math.isfinite(lower) or not math.isfinite(upper)
            or not (0 <= lower < 1 < upper)):
        raise ValueError("裁剪边界必须满足 0 <= lower < 1 < upper")
    if mode not in ("ppo", "cispo"):
        raise ValueError("mode 必须为 'ppo' 或 'cispo'")
    if not response_mask.any().item():
        raise ValueError("本批没有有效的策略生成 token")

    # 先选择有效 token，避免 padding 上的 NaN、-inf 参与后续运算。
    lp = new_logp[response_mask].float()
    old_lp = behavior_logp.detach()[response_mask].float()
    adv = advantage.detach()[response_mask].float()
    if not all(torch.isfinite(x).all().item() for x in (lp, old_lp, adv)):
        raise ValueError("有效 token 中存在非有限数值")
    if (lp > 1e-6).any().item() or (old_lp > 1e-6).any().item():
        raise ValueError("输入应是规范化分布的 log-prob，而非原始 logits")

    ratio = torch.exp(lp - old_lp)
    if not torch.isfinite(ratio).all().item():
        raise FloatingPointError("重要性比率溢出，请检查概率定义或策略差异")
    clipped = ratio.clamp(min=lower, max=upper)

    if mode == "ppo":
        objective = torch.minimum(ratio * adv, clipped * adv)
    else:
        # CISPO 的关键：权重固定，梯度只通过当前动作的 log-prob。
        objective = clipped.detach() * adv * lp

    return -objective.mean()


def scalar_gradient(mode: str, old_p: float, new_p: float, adv: float) -> float:
    new_lp = torch.tensor([[math.log(new_p)]], requires_grad=True)
    old_lp = torch.tensor([[math.log(old_p)]], requires_grad=True)
    advantage = torch.tensor([[adv]], requires_grad=True)
    mask = torch.ones((1, 1), dtype=torch.bool)
    loss = policy_loss(new_lp, old_lp, advantage, mask, mode=mode)
    loss.backward()
    assert old_lp.grad is None, "行为概率不应收到梯度"
    assert advantage.grad is None, "优势不应收到策略损失梯度"
    return float(new_lp.grad.item())


def main() -> None:
    # 奖励 [1, 0, 0, 0] 的总体标准差归一化结果。
    a = group_advantages(torch.tensor([[1., 0., 0., 0.], [1., 1., 1., 1.]]))
    expected = torch.tensor([math.sqrt(3), *([-1 / math.sqrt(3)] * 3)])
    assert torch.allclose(a[0], expected, atol=1e-6)
    assert torch.equal(a[1], torch.zeros(4))

    # 正优势、超过上界：PPO 饱和，CISPO 保留梯度。
    assert math.isclose(scalar_gradient("ppo", 0.4, 0.7, 1.), 0., abs_tol=1e-6)
    assert math.isclose(scalar_gradient("cispo", 0.4, 0.7, 1.), -1.2, abs_tol=1e-6)

    # 负优势、低于下界：PPO 饱和；CISPO 仍按裁剪权重抑制动作。
    assert math.isclose(scalar_gradient("ppo", 0.4, 0.2, -1.), 0., abs_tol=1e-6)
    assert math.isclose(scalar_gradient("cispo", 0.4, 0.2, -1.), 0.8, abs_tol=1e-6)

    # 坏动作概率增长到 1.5 倍，PPO 仍然施加惩罚。
    assert math.isclose(scalar_gradient("ppo", 0.4, 0.6, -1.), 1.5, abs_tol=1e-6)

    # 未被选择的 padding 不得污染 loss，也不能获得梯度。
    new_lp = torch.tensor([[math.log(0.4), float("nan")]], requires_grad=True)
    old_lp = torch.tensor([[math.log(0.4), float("nan")]])
    adv = torch.tensor([[1., float("nan")]])
    mask = torch.tensor([[True, False]])
    loss = policy_loss(new_lp, old_lp, adv, mask)
    assert torch.isfinite(loss).item()
    loss.backward()
    assert torch.allclose(new_lp.grad, torch.tensor([[-1., 0.]]), atol=1e-6)

    print("PPO/CISPO、组优势、停止梯度与 padding 掩码测试通过。")


if __name__ == "__main__":
    main()
```

代码中的 `response_mask` 只解决已算出的损失张量该训练哪些位置；它不能替代模型前向时正确的 causal attention、position ids、序列 packing 边界和 log-prob 的 token 对齐。

### 12.4 不能忽略 next-token 对齐

**工程建议：**对 causal LM，某位置的 logits 通常用于预测下一个 token。构建 `new_logp` 时，必须让预测分布、实际 token id 和 response mask 对齐。一个 off-by-one 错误可能仍然产生有限 loss，却训练了完全错误的概率。

最小核对方法是拿一个已知短序列，逐个打印前缀、目标 token、选中 log-prob 与 mask，确认只有策略真正生成的位置参与损失。

### 12.5 CTPO 风格前缀权重的梯度示意

前文关于累计前缀的讨论，还涉及“前向计算权重”与“反向通过哪个位置”两个层次。以下仅为教学构造，说明怎样让权重数值为前缀乘积，而只对当前位置的 log-prob 求导；不是声明附件给出了完整生产代码，也不是本次重新核对的作者仓库版本。

```python
# 示意：new_logp、old_logp、mask 已按同一条轨迹的策略 token 对齐。
# 真实实现还需要处理 padding、episode 边界、位置索引与溢出。
log_ratio = new_logp - old_logp.detach()
prefix_log_ratio = log_ratio.cumsum(dim=-1)
log_weight = prefix_log_ratio.detach() + new_logp - new_logp.detach()
weight = log_weight.exp()
```

若直接对 `exp(cumsum(log_ratio))` 求导，当前位置项会向前面所有 log-prob 传播梯度。是否需要这种前缀梯度，必须由目标推导决定，不能只看前向权重数值正确。

这个问题与 CISPO 的停止梯度、GSPO-token 的构造是同一个工程主题：**复现的是计算图，不只是公式表面形式。**[^cispo][^gspo]

### 12.6 六类结束原因应分别处理

| 原因 | 是否天然等于业务失败 | 需要的处理 |
|---|---|---|
| 正常完成并通过验证 | 否 | 记录任务奖励 |
| 正常结束但结果错误 | 通常是 | 使用明确任务反馈 |
| 输出／上下文预算耗尽 | 取决于任务规格 | 区分截断、长度惩罚与 bootstrap |
| 工具执行故障 | 不一定 | 记录 infra error，按预定规则重试或排除 |
| 重复检测提前停止 | 不是普通 EOS | 记录策略病理与截断策略 |
| 权限或安全约束拦截 | 取决于目标与动作 | 记录违规行为及执行层干预 |

其中 DAPO 的超长处理、MiniMax 的重复检测、MAI 的环境容错提供了具体来源；表格是对它们的工程归纳。[^dapo][^cispo-numerics][^mai-infra]

### 12.7 调试仪表盘需要能区分原因

| 指标组 | 建议观察 | 可能提示的问题 |
|---|---|---|
| 奖励 | 总奖励、分项、独立成功率 | 只学辅助分或利用 verifier |
| 学习信号 | 组内标准差、混合组比例、优势分布 | 有效任务不足或标签异常 |
| 更新 | ratio 分位数、按优势正负分解的裁剪率、KL、梯度范数 | 极端样本、过大更新、局部梯度丢失 |
| 探索 | token 熵、重复率、轨迹与策略类型多样性 | 坍缩或无意义高熵 |
| 长度 | P50/P95、按难度分层、结束原因 | 预算噪声、冗余增长 |
| 系统 | 被接受 token/s、评分耗时、队列年龄、权重同步耗时 | 生成很忙但训练数据不可用 |
| 保持性 | 旧任务、长上下文、格式、工具能力 | 新任务优化造成回退 |

DAPO 特别指出，训练 reward 与验证准确率可能不一致，长度与熵也需要联合观察。因此，单条 reward 曲线既不能定位故障，也不能证明泛化。[^dapo-results]

### 12.8 排错顺序

**先检查任务和评分器。**参考答案能否稳定通过？空补丁是否失败？等价解是否被拒绝？F2P 与 P2P 是否完整？

**再检查采样是否产生信息。**混合组比例怎样？全错是能力不足还是 evaluator 出错？不同回答是否真有不同解法？

**然后检查概率与计算图。**behavior 分母是否真实，推理和训练概率是否一致，token 是否错位，mask、detach、归约是否正确？

**最后调整更新与并发。**检查学习率、裁剪、批次、精度、版本差与异步程度。先让小规模同步实验可解释，再提高吞吐。

这是一套基于前文的诊断建议，而不是保证所有故障都遵循同一顺序。它的价值在于避免把环境错误、数据问题或 loss 实现错误，都误诊为“学习率没调好”。

## 13. 实验设计与落地路线

### 13.1 从可复现的窄任务开始

**工程建议：**不要一开始就给 Agent 一个开放目标，再用单个主观分数奖励整份长输出。先建立状态、动作、约束和成功条件都明确的小闭环。

可以沿讲义代码修复案例，扩展默认值、边界值、参数校验和回归测试任务。不要仅仅改变量名就声称测试了泛化；按问题类型、代码来源或模板结构划分训练与评测，减少近重复。

任务样本至少包含初始状态、任务说明、可用工具、约束、验证器、独立检查和版本。MAI 的环境流水线说明，这些组成部分决定数据是否真正可训练。[^mai-environment]

### 13.2 先比较简单方案，再判断 RL 的增量价值

| 阶段 | 需要回答的问题 |
|---|---|
| 原始策略基线 | 当前模型不训练时的真实成功率和主要失败是什么？ |
| 提示与工具协议基线 | 问题是否只是格式、工具 schema 或上下文组织？ |
| SFT 基线 | 少量可靠示范能解决多少问题？ |
| 多候选与筛选基线 | 更好的评分器能否在不更新生成器时改善结果？ |
| 同步 RL 基线 | 在固定奖励与任务下，参数更新带来多少独立增益？ |
| 算法消融 | 归约、裁剪、过程反馈等部件分别解决哪类故障？ |
| 系统扩展 | 更大吞吐是否真的缩短达到目标质量的时间？ |

PRM 论文说明，评分器改进可以提升 best-of-N 系统结果，即使生成器不变。必须区分系统选优收益与策略本身提升。[^prm-results]

### 13.3 按问题结构选路线，而不是按名字新旧

有可靠终局验证器、同题多次采样成本可接受时，可以先建立组相对训练基线。

长任务中细粒度行为很重要，而且可以获得可信价值预测或步骤监督时，可以比较 critic+GAE 或过程监督方案，不能因为 GRPO 简洁就自动排除其他方法。

学生几乎无法产生成功尝试，但有可靠示范或教师时，先研究热启动、课程或教师指导；不要仅靠加大 rollout 数量解决信号缺失。

若模型无法更新权重，仍可应用本课的环境设计、候选筛选、评分审计和运行时约束；但那是系统级优化，不应命名为已经完成模型 RL 训练。

以上都是方法选择建议，不构成某种算法对所有业务的优劣排序。

### 13.4 迁移到文档或数据核验 Agent

下面是前文知识的应用示例，不是附件已经验证的金融业务实验，也不涉及任何当前法规判断。

例如任务是核对一段文字中的数值是否来自给定表格。不要一开始用“报告写得好不好”一个总分训练。可以先拆成可验证能力：实体是否一致、期间是否一致、单位是否一致、指标口径是否一致、引用位置是否真实、结论是否受证据支持。

```text
输入材料与问题
    ↓
定位实体、期间、单位与指标
    ↓
查询原始数据或计算
    ↓
产生结构化结论及证据位置
    ↓
确定性检查 + 必要的人工或模型判断
    ↓
独立检查遗漏、错误归因与不必要工具调用
```

这里最危险的辅助奖励是“引用条数”“检索次数”“长解释”“用户采纳率”被当作正确性的替代。用户可能因表达清楚而采纳一个事实错误的建议；评分器也可能偏好看起来有依据的措辞。这与 InstructGPT 的偏好分数边界、PRM 的高分错例以及 reward hacking 的代理目标问题直接相连。[^instruct-recipe][^prm-active][^reward-hacking]

更稳妥的起点是先把可靠事实与证据核验做成 evaluator，再讨论训练是否有额外收益。

### 13.5 三个评价维度：会不会、稳不稳、值不值

**会不会。**单次成功率、多候选覆盖、选优结果、保留任务与新任务泛化分别怎样？DeepSeekMath 的 Maj@K 与 Pass@K 分析提醒我们不要把它们混成一个“能力”。[^deepseek-pass]

**稳不稳。**多次运行的一致性、严重失败、权限越界、奖励利用、训练尖峰与恢复能力分别怎样？不能只看平均分。

**值不值。**达到同样的独立任务质量，消耗多少生成 token、教师调用、评分执行、GPU 时间与总墙钟时间？AReaL 的端到端实验比单看优化步数更接近这个问题。[^areal-results]

### 13.6 指标口径必须随结果一起保存

| 指标 | 在本文对应材料中的理解 |
|---|---|
| pass@1／平均单次准确率 | 单条采样回答的成功概率；可用多次重复估计 |
| avg@32 | 这些数学实验中，对每题采样 32 次取平均成功率；不是 32 次至少一次成功 |
| pass@K | 多候选集合中至少一个成功的覆盖能力，具体估计以论文定义为准 |
| Maj@K／consensus | 用多数答案等规则选出最终结果的效果 |
| best-of-N | 由评分器从 N 条候选中选择一条后的效果 |
| τ-bench pass^k | 多次可靠完成的指标，应按该来源的定义，不与 pass@K 交换 |

CTPO 明确将 avg@32 定义为对 32 个回答的平均通过率；PRM 的 78.2% 来自 best-of-1860；这些数字不能横向当作同一种准确率。[^ctpo-results][^prm-results][^tau-fixes]

### 13.7 比较算法时，不只固定更新步数

DAPO 的补采样使每一步生成成本可变；CISPO 的多轮数据复用改变更新次数；OPD 增加教师计算；AReaL 改变硬件利用率。相同步数不等于相同预算。

建议至少报告总生成 token、有效训练 token、任务与评分耗时、GPU-hours、总墙钟时间、失败和丢弃比例、评测采样预算。

研究问题应写成：**在相近总预算、相同目标任务与约束下，哪种方案更可靠地改善独立表现？**

### 13.8 最小消融设计

一个实用顺序是：先固定任务与奖励，再固定模型与采样预算，然后逐项比较是否使用 critic、组归一化方式、序列或 token 归约、裁剪方式、动态采样、长度处理，最后比较同步与异步。

不要一次加入全部技巧后，把收益归因于最显眼的那个名字。DAPO 的累积实验提供了有用路线，但在自己的任务里仍需明确单因素与交互效应，记录试验失败而不只保留成功曲线。[^dapo-results]

### 13.9 独立评估不应被外层 Agent 随意改写

训练数据、开发验证集、最终保留集、评分代码和基础 checkpoint 应分别有权限与来源记录。允许 Agent 分析开发集失败，不等于允许它用最终测试题定向合成训练样本。

PostTrainBench 的数据 split 误认、模型替换和 API 越界案例说明，文字规则不足以自动建立实验完整性。应保存数据来源、近重复检查、代码变更和最终提交工件。[^posttrain]

## 14. 核心洞见与速查

### 14.1 五条主线其实对应五种失败

| 讲义主线 | 最典型的失败 | 应该先检查什么 |
|---|---|---|
| 有效反馈 | 全轨迹同奖同罚，局部信号混乱 | 基线、critic、过程监督与估计质量 |
| 减少等待 | 资源空闲或大量生成数据未被有效使用 | 长尾、队列、权重同步与陈旧度 |
| 稳定更新 | 比率尖峰、探索坍缩、训练崩溃 | 目标、计算图、精度、裁剪与归约 |
| 可靠奖励 | 分数涨但行为变差 | evaluator、任务规格、漏洞与独立评测 |
| 向教师学习 | 学生一直产生无信息失败 | 热启动、课程、学生历史覆盖与教师目标 |

这是对 Lecture 11 与参考材料的综合诊断框架，不是五个互斥分类；一次故障常同时涉及多个环节。

### 14.2 用六组表面矛盾检验理解

**CISPO 想保留更多梯度，GSPO 却裁剪更多仍更有效。**两者都在追求可靠更新，不是在最大化 token 数量。[^cispo][^gspo-results]

**GAE 细化信用，MAI 的多轮训练仍使用统一轨迹优势。**更细的估计需要额外数据、模型与准确性，复杂度本身不是收益。[^gae][^mai-agent]

**GRPO 要同题多次采样，MAI 蒸馏更重视不同问题。**前者估计相对表现，后者迁移行为覆盖，不同阶段需要不同的数据结构。[^deepseek-grpo][^mai-distill]

**AReaL 允许旧数据，OPD 强调学生自身历史。**前者折中更新效率与分布偏差，后者修复学生状态覆盖，不是在互相否定。[^areal-objective][^lecture-teacher]

**奖励更密集，可能学得更快，也可能更快学错。**反馈密度与目标正确性不同。[^gae-shaping][^reward-hacking]

**评分器更好，系统分数可以提高，即使生成器不变。**PRM 的 best-of-N 结果属于这一类，不能误报为策略权重训练收益。[^prm-method][^prm-results]

### 14.3 三层边界必须始终保留

第一层是**理论与代理目标**：某个测度变换的无偏性，不自动适用于实际替代优势、裁剪和归约。

第二层是**代理目标与代码**：前向数值相同，不代表梯度路径相同；停止梯度、token 对齐和 mask 都决定实际算法。

第三层是**训练指标与真实表现**：训练奖励改善，不自动意味着独立任务、长期可靠性或生产风险改善。

### 14.4 最后的一句话

> **掌握 Agent RL，不是会默写一个损失，而是能把可复现的任务、可信反馈、有用尝试、正确梯度和独立评测连接成持续工作的学习循环。**

当模型学不动时，先定位缺的是哪一种信号或一致性；当模型分数上涨时，再证明上涨的是你真正关心的能力。

## 附录 C. 容易误读的结论与材料异常

### C.1 文件名正确，不代表内容正确

`019_Curriculum_Learning.pdf` 实际题目是 *Interaction-assisted SU(2) adiabatic holonomies in Josephson phase qubits*。它不能支持 Bengio 等课程学习研究的任何结论。本文课程部分使用 MIXER、主讲义和 MAI，不根据文件名补写其内容。[^wrong-file]

### C.2 GAE 中的折扣有两层语境

讲义为方便理解使用 $\gamma=1$；GAE 原论文从不折扣目标出发，将 $\gamma<1$ 作为近似参数讨论。本文同时保留两种语境，不能把“折扣一定属于业务目标”作为对所有引用的统一解释。[^lecture-credit][^gae]

### C.3 GSPO 的动机文字不等于重要性采样的一般定理

GSPO 用单 token 权重的噪声与实证不稳定性解释动机；从恒等式看，单个样本不导致固定历史上的 IS 无偏性失效。应将有限样本方差、历史分布遗漏与代理目标近似分开。本文对此的区分属于数学分析，不冒充 GSPO 作者的原话。[^gspo][^ctpo]

### C.4 CTPO 的理论优势与实际实现存在距离

前缀校正的理论使用对应 token 的状态—动作优势；实际算法使用组相对最终奖励并裁剪。方差分析的部分表达还使用独立性假设。不能把这些层次压缩成一句“CTPO 的整个训练器完全无偏、全面优于 PPO”。[^ctpo][^ctpo-results]

前文对作者公开代码的观察不作为本次整理中的“当前仓库事实”重复传播；第 12.5 节明确给出的是梯度路径教学示意。

### C.5 MAI 的 rollout 数量表述不完全一致

报告第 36 页 §3.1.5 写 $G=128$ total、$G_{early}=16$；第 50—51 页 §3.6.2 的典型流程却描述先发 16 个 early 请求，再发 additional 128 个请求。两处文字存在差异，可能对应不同执行约定或配置，但附件没有足够信息判定。

本文保留“两阶段采样”机制，不擅自选择 128 或 144 作为统一精确总数，更不将其做成默认生产配置。[^mai-recipe][^mai-infra]

### C.6 SABER 的结果不应过度统一

论文摘要、正文叙述与具体表格包含不同幅度的效果描述。本文使用机制与表格所支持的条件性结论，不混合不同数据集、不同模型、relative improvement、百分点和 odds ratio。相关性分析也不自动证明逐步因果归因。[^saber][^saber-audit]

### C.7 PRM 数字应与样本数和测试子集绑定

78.2% 对应保留的 500 道 MATH 问题、best-of-1860 选优。2.6 倍是小规模、合成监督主动学习分析中的数据效率估计。不能将前者写为普通 pass@1，也不能把后者当作所有人工标注任务的固定节省比例。[^prm-results][^prm-active]

### C.8 论文配方不是通用默认值

GSPO 的裁剪范围、MiniMax 的优化器 epsilon、MAI 的熵目标与大组采样、AReaL 的陈旧阈值，均与模型、目标、批次和数值路径有关。本文引用它们说明设计依据，不建议脱离条件照抄。[^gspo][^cispo-numerics][^mai-recipe][^areal-results]

### C.9 对“能力涌现”保留有限观测边界

DeepSeekMath 的分布改善观察，不证明 RL 永远不能学新能力；DAPO 在采样中观察到新模式，也不证明该模式在初始分布的概率绝对为零。需要独立任务、行为分析和采样预算共同支持更强结论。[^deepseek-pass][^dapo-results]

### C.10 文件版本与外部状态分开

本文件整理附件版本及本次对话已有讨论，没有为了最新排行榜、最新框架接口或最新仓库提交扩大检索。参考论文的 2026 年实验是附件内容，不自动代表其他版本或当前状态；生产实现应另外核对代码版本和依赖。
