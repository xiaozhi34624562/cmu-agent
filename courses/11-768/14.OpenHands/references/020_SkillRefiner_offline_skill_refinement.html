SkillRefiner: Offline Skill Refinement from Historical Agent Traces

OpenHandsUT AustinNYU
CMU
Anirudh KhatryCalvin SmithGreg DurrettIsil DilligGraham Neubig
+1 moreShow less

Abstract

Skills capture procedural knowledge that helps agents solve complex tasks. Existing skill-refinement methods improve these instructions by generating new rollouts with candidate skills, which can be costly or impractical when environments are not replayable or supervision arrives only after deployment. We introduce SKILLREFINER, an offline method that refines deployed agent skills from historical execution traces and observed outcomes. SKILLREFINER summarizes long trajectories, clusters recurring behaviors and failure modes, and derives targeted edits from each cluster. Successful clusters reinforce effective behavior, while failure clusters produce guardrails and procedural corrections that are checked against supporting evidence. We evaluate SKILLREFINER on spreadsheet manipulation, mathematical reasoning, and production pull-request review. SkillRefiner improves over both the LLM and human authored skills across all settings while using 1.4–42× fewer refinement tokens than competing refinement methods.

AI Overview

SKILLREFINER treats an agent's past runs as supervision for improving its instructions, even when the work cannot readily be replayed or its outcome arrives late. Production code review shows the problem. An agent writes its review now, but quality is revealed only later, when developers revise the code and it becomes clear which suggestions matched issues they addressed, typically days to weeks later. Replay-based refinement assumes tasks can be replayed and evaluated quickly, and that assumption can fail for deployed tasks with delayed human feedback. SKILLREFINER learns from records of prior work instead of repeatedly asking the agent to redo tasks with candidate instructions. The authors report gains across their evaluation settings, including this delayed-feedback setting.

Turning traces into reusable instructions

A skill is reusable natural-language procedural guidance for an agent. SKILLREFINER takes historical traces, their outcomes, and any available evaluator feedback. It summarizes each trace's context, strategy, and salient actions, then embeds the summaries. Successful runs and failed runs are clustered separately, and the method proposes one edit per cluster. Edits derived from failures are checked against the evidence. Supported failure edits and success-derived reinforcements are then merged into the initial skill. No new agent executions are generated during refinement. Singleton clusters are treated as noise and do not independently generate edits.

The two kinds of cluster work differently. A success cluster supplies repeated behavior to reinforce. A failure cluster points to a recurring problem, and the LLM supplies a proposed remedy from its pretrained knowledge. That remedy is a hypothesis, and the traces do not prove it correct. The evidence gate checks whether the targeted behavior occurred and is plausibly connected to failure. The gate does not revise the proposal or replay the task. When positive and negative guidance conflict, the merge is instructed to restrict a behavior only in the context where failure was observed, so useful behavior is kept elsewhere.

What the comparisons establish

The closest prior work, Trace2Skill, also turns historical traces into a skill. It does so by proposing patches from individual runs and consolidating them. GEPA takes a different approach: it generates new executions to evaluate candidates, using a budget of five candidate revisions.

The first comparison uses held-out SpreadsheetBench tasks, where accuracy means the output workbook passes the benchmark's evaluator. With an LLM-authored initial skill and GPT-5.4-mini, SkillRefiner reaches 84.0% accuracy, compared with 79.0% for Trace2Skill and 78.5% for GEPA. The result is significant against both baselines by paired bootstrap (p < 0.05, N = 10,000). In the same setting, refinement used 2.78 million tokens, versus 6.87 million for Trace2Skill and 117.22 million for GEPA. These counts cover refinement tokens only. They exclude the cost of collecting the historical rollouts and do not establish lower wall-clock time or total compute.

The second comparison is a component ablation, which tests the mechanism directly. With SpreadsheetBench, an LLM-authored initial skill, and MiniMax-M2.7, each component was removed in turn:

  • Removing failure-cluster proposals reduces performance by 8.0 points.
  • Removing success-cluster proposals produces a 0.0-point change.
  • Removing evidence gating reduces performance by 5.0 points.

Across settings, removing failure-derived proposals hurts more than removing success-derived ones in seven of eight cases. The authors also note that successful executions provide useful signals in some cases. These results support the pipeline's components, but they do not establish that any individual repair is correct.

History as feedback

In PR Review, developer revisions serve as delayed supervision. An LLM judge matches agent suggestions to developer-addressed issues to compute F1, which is a proxy for review usefulness. GEPA cannot be applied in this setting because immediate replay with automated feedback is unavailable. The paper's contribution is an offline method that refines skills from prior executions without repeatedly generating new rollouts. Its distinctive step is compiling repeated, outcome-separated patterns into conditional, evidence-checked guidance, rather than treating every trace as an isolated lesson. Its main boundary is that failure-derived fixes remain LLM hypotheses that are checked against evidence but never replayed.
