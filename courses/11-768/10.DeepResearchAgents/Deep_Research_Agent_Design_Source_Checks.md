# Deep Research Agent 通用设计：一手来源核查

初次核查：2026-10-07；本地来源与独立阅读复核：2026-10-26。本文为通用设计提供补充来源核查；课程资料入口为 [SOURCES.md](SOURCES.md)，已有综合归纳见[课程笔记第四、九、十一、十四章](Deep_Research_Lecture10_Integrated_Notes.md)。下文分别标记原文事实、工程推导与结论边界，不把不同系统的实验数字合并比较。

## 1. OpenScholar：证据缺口驱动修订，引用单独验收

**已核实的原文机制。** 系统先生成绑定检索段落的带引用初稿，再产生反馈；缺失信息类反馈会触发新检索，然后修订、核验引用。其合成数据过滤会比较初稿与最终稿，修订并非必然更好。引用评价分别检查需要支持的陈述是否获得支持，以及每条引用的相关性与必要性。[Methods：Inference: self-reflective iterative RAG](https://www.nature.com/articles/s41586-025-10072-4#Sec28)、[Data filtering](https://www.nature.com/articles/s41586-025-10072-4#FPar10)、[Citation accuracy](https://www.nature.com/articles/s41586-025-10072-4#Sec44)。

**工程推导。** 将反馈结构化为“缺失主张—需要哪类证据—下一动作”；只有缺证据时才补检索。保留稿件版本，按具体质量要求比较修改前后；交付前逐条建立 claim → passage → source 关系。

**边界。** 这些材料支持闭环工作流，不证明反思次数越多越好，也不证明引用支持等同于来源真实。结构化反馈、版本回滚和证据账本是这里的实现建议，并非论文逐项验证过的固定架构。

**访问说明。** 2026-10-07的核查记录记载 Nature 在线访问遇到身份/cookie 跳转；上述机制通过仓库保存的[原文 HTML](readings/001_OpenScholar.html)核对，保留原文章节锚点用于复核。2026-10-26复核仍依据本地HTML，不把历史访问失败或本地读取改写成已成功读取当前官网全文。

## 2. AgentIR：传递本轮信息需求，避免无选择地堆叠历史

**已核实的原文机制与分析。** AgentIR 联合编码当前轮 reasoning 与 query，并用 DR-Synth 构造局部查询训练监督；输入方式与训练贡献有分离消融。历史输入比较未优于当前轮方案；含历史文档的设置受长度限制，实际截取了最近若干轮。作者讨论了旧假设、冗余与噪声传播。[AgentIR v3，§3.2–3.3](https://arxiv.org/html/2603.04384v3#S3.SS2)、[§5.1–5.3](https://arxiv.org/html/2603.04384v3#S5)。

**工程推导。** 检索接口显式传递“当前子问题、已确认约束、尚缺证据、搜索词”；已否定假设不应再次作为事实注入。保留完整轨迹用于复核，但检索与写作只加载相关状态。这是受论文启发的实现，不要求取得或暴露模型私有思维链。

**边界。** 不能把有截断的历史实验说成对任意长度完整历史的普遍否定；不能将特定基准的检索收益当作开放式长报告的质量收益。普通搜索 API 是否接受意图文本、embedding 是否需要训练，都应在自己的任务上比较。[论文评测设置 §4.2](https://arxiv.org/html/2603.04384v3#S4.SS2)、[本地 PDF](readings/AgentIR_Reasoning-Aware_Retrieval_for_Deep_Research_Agents.pdf)。

## 3. Anthropic：并行有适用条件，长期执行需要持久状态

**已核实的官方工程经验。** [本地归档](../../2680/readings/web/How_we_built_our_multi-agent_research_system.html)中的2025-06-13文章描述 lead/worker 研究系统：明确子任务目标、输出、工具来源与边界；协调者综合后决定是否继续，引用组件定位来源。文章认为可独立展开的广度任务更适合并行，而高度共享上下文、依赖密集的任务较难获益；同时指出额外 token 成本，以及持久执行、重试、checkpoint 和恢复的重要性。[How we built our multi-agent research system：Benefits / Architecture / Prompt engineering / Production reliability](https://www.anthropic.com/engineering/multi-agent-research-system)。

**工程推导。** 先实现可靠的单协调者循环，只有可独立验收的子问题才并行。子任务返回结构化证据包与原文定位，不只交付摘要；主协调者负责统一口径、合并冲突和全局停止决策。执行层记录任务、工具结果、预算及已完成阶段，故障后从检查点继续。

**边界。** 这是特定产品的官方经验，不是隔离所有变量的跨平台对照实验。文中的性能、时间和成本数字不作为通用容量规划依据。并行研究的路径独立也不等于证据来源独立；多个 Agent 引用同一上游材料不能增加独立证据数，这是本笔记的证据治理推导。

## 4. 可直接用于设计评审的判断

以下是综合上述来源的工程建议，尚需在目标任务上验证：

| 设计问题 | 建议 | 对应依据与边界 |
|---|---|---|
| 下一步做什么？ | 让尚未满足的证据需求决定搜索、读取、计算或修订。 | OpenScholar 的缺口反馈；不把固定搜索轮数当完成标准。 |
| 系统主要记住什么？ | 保存主张、条件、证据定位、矛盾和待办；按任务筛选上下文。 | AgentIR 的当前检索信号与噪声分析；账本结构是工程设计。 |
| 什么时候并行？ | 子任务可独立开展与验收、预算允许时。 | Anthropic 的适用经验；并行数不是质量指标。 |
| 怎样交付？ | 分开核验内容覆盖、陈述支持和引用必要性，明确未解决问题。 | OpenScholar 的评价维度；引用核验不替代来源可信度判断。 |
| 怎样防止长任务失败？ | 持久化产物和检查点，记录工具失败，支持继续执行。 | Anthropic 的生产实践；恢复策略需匹配实际工具副作用。 |

据此，通用架构应围绕**任务要求 → 证据需求 → 工具行动 → 证据状态更新 → 综合与核验**形成循环；多 Agent、专用检索训练与更大模型都是可按瓶颈增加的能力，而非定义 Deep Research 的前置条件。


## 5. 复核材料版本与实现验收边界

2026-10-26按仓库实际正文复核：AgentIR为arXiv:2603.04384v3（2026-03-09，22页），§3.2与§5分别提供机制及输入比较；OpenScholar使用本地Nature HTML的Inference、Data filtering与Citation accuracy小节；Anthropic文章使用仓库HTML归档。在线链接用于来源追溯，本地文件用于固定本篇实际依据。

OpenScholar的生成式citation verification是提出检查与补引，不是形式证明；其训练数据过滤明确发现初稿有时优于修订稿，因而系统不能把“执行了核验/反思”当作自动通过。这里建议的实现验收应另测：无支持的主张能否被识别、引用是否只支持更窄范围、原文更新后旧结论是否失效。

AgentIR当前轮输入的检索优势，也不等于长期状态可以删除：完整轨迹可供审计，相关状态可供本轮决策，两者承担不同职责。Anthropic的可恢复执行经验同样不是通用幂等保证；重试前仍须知道外部动作是否已经发生。上述验收条目是工程推导，未在本地运行模型或系统实验。
