Claude Code: setup and what you submit

Claude Code

Assignment 1 is done with Claude Code (the CLI, the desktop app, or the VS Code extension, whichever you prefer), and its submission includes your session files. Every later assignment uses it too, and each submission includes the session files for that assignment's work. This page is how you get set up and what you hand in. It is one of four environments under computing setup, alongside model API access, the HPC, and AWS.

Getting your account

Harvard FAS provides this, so do not buy a subscription. Claude Code is included in the Harvard Claude license, alongside Claude chat and the desktop app, and you sign in with HarvardKey. The request form for FAS, GSAS and SEAS is on HUIT's Claude page.

Do this in week one, not the night before Assignment 1 is due. A license request is a ticket that a human approves, so it does not clear instantly.

Two things worth knowing before you start. The free Claude plan does not include Claude Code at all, so a free account will not get you through Assignment 1. Claude Code requires a Pro, Max, Team, Enterprise or Console account, and the Harvard license is how you get one. If you already pay for Claude personally, you can keep using that account provided you have the quota for it.

Installing it

Three interfaces, one tool and one account behind all of them. Pick whichever you will actually use; you can switch, and you can run more than one. Claude Code needs macOS 13+, Windows 10 1809+, or a current Linux, with 4 GB of RAM.

Terminal (CLI)

The reference interface, and the one this page's commands assume. On macOS, Linux or WSL:

curl -fsSL https://claude.ai/install.sh | bash

On Windows PowerShell:

irm https://claude.ai/install.ps1 | iex

Homebrew (brew install --cask claude-code) and npm (npm install -g @anthropic-ai/claude-code, needs Node 22+) also work; the native installer is the one that auto-updates. Then check it:

claude --version
claude doctor

claude doctor prints installation and settings diagnostics without starting a session, and is the first thing to run when something is wrong, and the first thing to paste when you ask for help.

Desktop app

A graphical interface, no terminal required. Download it for macOS, Windows or Linux from the desktop quickstart.

VS Code extension

Open the Extensions view (Cmd+Shift+X on Mac, Ctrl+Shift+X otherwise), search for “Claude Code”, and install. It needs VS Code 1.94 or later, and it also installs in VS Code forks including Cursor. See the extension docs.

One thing to know if you go this route: the export commands below are CLI commands. The extension can open a terminal session for you, or you can install the CLI alongside it and run them there. Both read the same session history on your machine.

Logging in

Run claude in a terminal. It opens a browser for you to sign in; use your Harvard account. If the browser does not open, press c to copy the login URL and paste it in yourself. If the browser shows you a code instead of returning to the terminal (common over SSH, in WSL, and in containers), paste that code back at the prompt. On success the terminal says Login successful.

Check what you are actually signed in as with /status, which shows the login method and the account. /login re-runs the flow and /logout signs you out.

What to submit with each assignment

Assignment 1 takes three artifacts: your code, the write-up, and your Claude Code session files.

We collect these to understand how the class works with an agent (where people get stuck, which habits pay, what the tool is doing badly), so that we can provide feedback and adjust the course while it is running. They may also be used in grading, as the evidence behind the process claims in your write-up.

Claude Code already keeps every session on disk, so rather than exporting conversations one at a time, package the directory it keeps them in. Sessions are stored per working directory, under a name that is your project's path with every non-alphanumeric character replaced by a hyphen, so /home/you/cs2680/assignment2 becomes -home-you-cs2680-assignment2. From your project directory, this prints the right path:

echo ~/.claude/projects/$(pwd | sed 's/[^a-zA-Z0-9]/-/g')

Or just look at what is there and pick yours out with ls ~/.claude/projects/. Then archive it, from inside projects/ so the paths in the archive stay tidy:

cd ~/.claude/projects
tar -czf ~/cs2680/assignment2/a2-sessions.tar.gz ./-home-you-cs2680-assignment2

Use your own project directory and repository path in place of the examples. On Windows PowerShell, Compress-Archive -Path $env:USERPROFILE\.claude\projects\<dir> -DestinationPath $env:USERPROFILE\cs2680\assignment2\a2-sessions.zip does the same job. Commit the archive under the corresponding assignmentN/ directory in your shared private course repository, for example assignment2/a2-sessions.tar.gz.

That leading hyphen will bite you. A project directory for an absolute path starts with -, which tar, zip, grep and du all read as the start of a command-line flag, so tar -czf out.tar.gz -home-you-cs2680-assignment2 fails with an unhelpful error. Prefix the name with ./, as above, and everything works.

Include a directory for each place you did assignment work; if you worked in two repositories, that is two directories. Inside, you will find one .jsonl file per session, a folder of overflow tool-results for the larger ones, and a memory/ folder of notes the agent kept for itself. Leave all three in. The transcripts reference the tool results, and the memory notes are some of the most interesting material in the archive. Expect tens of megabytes per assignment, compressing to roughly a third of that.

Your session history expires after 30 days by default. Claude Code deletes session data older than cleanupPeriodDays at startup, and the final project runs for over five weeks, so the sessions from the week you started can be gone by the week you submit. Either export as you go, or raise the retention now by putting { "cleanupPeriodDays": 180 } in ~/.claude/settings.json.

Keep secrets and private information out of your sessions

You are handing these sessions to us, so treat a Claude Code session as something you will publish to an audience of one. And note what the archive actually contains: not just what you typed, but every file the agent read, every command it ran, and everything those commands printed. If Claude ever opened your .env, that file's contents are in the transcript. This is a wider surface than a conversation you can skim, which is why the scan below matters.

Before you start work, and again before you submit:

  • No credentials. No passwords, API keys, tokens, SSH keys, HPC credentials or connection strings pasted into the chat. Keep them in environment variables or a .env file that is in your .gitignore, and let your code read them, which is what you should be doing anyway, and is the habit Assignment 2 will test.
  • No personal information. Not yours (HUID, address, health or financial details), and in particular not anyone else's. If an Assignment 1 example task is the obvious candidate for this, because it touches your own real data, use synthetic or scrubbed records instead.
  • Nothing confidential that is not yours to share. Unpublished work from a lab, another course's solutions, an NDA'd dataset.

Scan before you archive. From ~/.claude/projects, against your own project directory, noting the ./ again:

grep -rlE 'sk-[A-Za-z0-9_-]{20,}|ghp_[A-Za-z0-9]{36}|AKIA[0-9A-Z]{16}|BEGIN [A-Z ]*PRIVATE KEY' ./-home-you-cs2680-a2

That catches the common shapes (OpenAI and Anthropic-style keys, GitHub tokens, AWS access keys, PEM private keys) and prints the files containing them. It is a smoke test, not a guarantee: it knows nothing about your database password or your lab's internal hostnames. Silence means the obvious things are absent, not that you can skip thinking. The memory/ folder is the one part short enough to read properly, so read it.
