## 1．模型接口背后：下一 token 预测并不等于任务验证

语言模型把文本转换为 token 序列，对给定上下文 $x$ 生成输出 $y=(y_1,\ldots,y_m)$。自回归分解是：

$$
p_\theta(y\mid x)=\prod_{t=1}^{m}p_\theta(y_t\mid x,y_{<t}).
$$

$\theta$ 是模型权重，$y_{<t}$ 是已经生成的前缀。模型每一步只生成下一个 token，但训练让它能在这个接口上表现出问答、编码和任务分解能力。乘积描述的是这条文字序列的生成概率，不是它符合事实的概率，也不是整项工作完成的概率。[A，§3，PDF pp.2–5；公式按自回归定义作教学展开]

例如，模型给“公司利润增长 20%”较高概率，可能因为它在上下文中读到了这一数字，也可能因为这样的表述符合语言模式。除非系统核对来源和口径，单靠 token 概率不能区分两者。工具调用也仍然是模型生成的结构化文本；执行框架必须解析、校验并实际执行，模型自己写出“已查询数据库”不构成查询记录。

输入 token 也不是汉字数、字符数或字节数。一个证券代码、英文缩写、路径或中文词可能被切成不同数量的 token。预算应使用实际模型的 tokenizer 或供应商返回用量，而不能把“每个汉字一个 token”当成普遍规律。这里不绑定某个当前模型或 SDK 的具体行为。

## 2．解码是在已有分布上作选择

模型最后一层给出每个候选 token 的分数 $z_i$，称为 logits。对正温度 $T$：

$$
p_i(T)=\frac{\exp(z_i/T)}{\sum_j\exp(z_j/T)}.
$$

**讲义表述校正**：第 20 页写“把全部概率除以温度，再重新归一化”，按字面计算会得到 $\frac{p_i/T}{\sum_jp_j/T}=p_i$，根本不改变分布。常用机制是上式对 logits 除以 $T$；若从已有概率出发，等价写法是 $p_i^{1/T}/\sum_j p_j^{1/T}$。这里按数学关系校正措辞，保留原讲义不改写。[L，p.20]

温度改变候选分布的尖锐程度。$T$ 较小，较高分的 token 相对更占优势；$T$ 较大，分布更平。温度没有向系统增加最新公告、计算器或业务权限，所以不能把降温当作事实核验。

用两个 logits 的教学例子理解：$z=[2,1]$。$T=1$ 时第一项概率约为 0.731；$T=0.5$ 时约为 0.881。只是同一组候选的相对采样倾向改变了。温度为 0 的行为通常实现为贪心选择等特殊分支，不能把 0 直接代入上面的除法式。

常见解码策略的作用不同：

| 策略 | 主要做什么 | Agent 场景的注意点 |
|---|---|---|
| Greedy | 每步取当前最高分 token | 局部最可能不保证整段任务最优 |
| Temperature sampling | 调整分布后采样 | 多样性可帮助搜索，也可能增加无效动作 |
| Top-k | 只保留概率最高的若干候选 | 候选数固定，不适应分布尖锐程度 |
| Top-p | 保留累计概率达到阈值的候选集合 | 阈值控制采样集合，不是答案置信度 |
| Beam search | 同时保留多条高分序列前缀 | 优化生成概率，与事实或业务奖励仍有距离 |

这里是机制解释，不是建议所有服务同时设置这些参数；具体接口如何组合参数，需查对应版本文档。原始 Transformer 论文使用 beam search 完成翻译任务，其训练与解码设置不能直接解释成现代工具 Agent 的最佳参数。[A，§6.1，PDF p.8]

### 同样输入、低温，为什么仍可能不同

应先排查是否真的“同样”：系统提示、工具 schema、检索结果顺序、时间、模型版本和服务配置都可能变化。即使接口名相同，底层服务也可能更新。并行数值计算和实现细节还可能影响接近的候选排序。因此，可复现记录要保存输入与系统版本；需要严格一致的业务计算，适合交给确定性代码。

内部助手的事实提取可先采用较保守的生成策略；探索补查路径则可允许受控多样性。两者都应通过任务级结果评测选择，不能只凭“温度低更可靠”的口号。

## 3．注意力：模型怎样从当前输入中选择信息

把一层输入表示记为 $X\in\mathbb R^{n\times d}$，$n$ 是位置数，$d$ 是表示维度。通过学习到的投影得到：

$$
Q=XW_Q,\qquad K=XW_K,\qquad V=XW_V.
$$

原始 Transformer 的 scaled dot-product attention 为：

$$
\operatorname{Attention}(Q,K,V)=\operatorname{softmax}\!\left(\frac{QK^\top}{\sqrt{d_k}}+M\right)V.
$$

$Q$ 是当前位置提出的“查询”，$K$ 让不同位置与查询比较，$V$ 是被加权混合的信息，$d_k$ 是 key/query 的维度，$M$ 是屏蔽不允许连接的位置的 mask。这里的 query/key/value 是神经网络内部表示，与 RAG 中用户查询、文档向量不是同一层对象，名称相似不表示数据结构相同。[A，§3.2，PDF pp.3–5]

为何除以 $\sqrt{d_k}$？若向量分量近似独立、均值为 0、方差为 1，点积方差随 $d_k$ 增长。过大的分数容易让 softmax 过于尖锐，影响训练梯度；缩放用于缓和这一现象。这是原论文解释所用的简化假设，不代表真实训练后每个向量都严格满足这些条件。[A，§3.2.1 与脚注 4，PDF p.4]

一个位置不是查找唯一“正确句子”，而是对多处信息作加权混合。多头注意力使用不同投影，在不同表示子空间里完成这种混合。注意力权重也不能简单当作可靠的因果解释或事实证据；晨会报告的来源仍应链接到外部原文，而不是展示某个头的热力图。

## 4．因果 mask、位置与 Transformer 的版本边界

自回归生成不能偷看未来输出。以 decoder-only 的常见索引约定为例，输入位置 $t$ 已放入 token $x_t$，其隐藏状态可注意到 $x_{\leq t}$，用于预测标签 $x_{t+1}$；mask 屏蔽的是 $j>t$ 的输入位置，并不屏蔽当前位置。若写成“预测 $y_t$”，可见前缀则是 $y_{<t}$，两种写法只是标签移位。训练时真实序列已知，可用移位标签与因果 mask 并行计算所有位置的损失；推理时未来 token 尚未产生，仍要逐步生成。没有标签移位或 mask，模型可能读取目标答案而造成训练泄漏。[L，pp.37–40、60；A，§3.1、§3.2.3，PDF pp.3–5]

在整个 block 中，attention 负责在位置之间混合信息，feed-forward network 对每个位置作非线性特征变换；残差连接保留直接的信息与梯度路径，归一化用于调节各层的表示尺度。讲义 pp.49–60 把这些 block 堆叠，再通过 LM head 与 softmax 得到词表分布。注意力不是模型的全部计算，也不是所有知识的唯一存放位置。[L，pp.49–60]

原论文是 encoder-decoder 架构：encoder 编码输入，decoder 自回归输出，并通过交叉注意力访问 encoder 表示。今天很多对话模型使用 decoder-only 结构。两者都可借助注意力工作，但不要把原论文的层数、head 数、归一化顺序或全部结构当作所有当前模型的规格。[A，图 1 与 §3]

注意力本身对输入排列缺少足够的位置约束，因此模型需要位置信息。原论文讨论正弦、余弦位置编码，也比较学习到的位置表示；现代模型可能使用其他机制。对工程师最直接的启示是：上下文长度、位置外推与长距离检索能力，不能只根据“支持多少 token”推断，应在实际位置和资料密度下测试。[A，§3.5，PDF p.6；工程含义为推导]

对于公告任务，可以把关键约束分别放在开头、中间和末尾，改变文档顺序、加入相似干扰段，检查实体、日期和证据是否仍保持一致。这比只测一份短报告更能暴露长上下文问题。

## 5．长上下文的成本：先分清 prefill 和 decode

对稠密全注意力，处理长度为 $n$ 的输入时，注意力分数涉及 $n\times n$ 的关系。原论文复杂度表给出 self-attention 每层 $O(n^2d)$ 的形式。但实际运行还包括投影、前馈层、内存搬运和调度，不能直接把复杂度式当作端到端延迟预测。[A，§4、表 1，PDF p.6]

**Prefill** 处理已知输入前缀，可以对多个位置并行计算。**Decode** 一次生成一个新 token；若缓存此前位置的 key/value，就不必每步重新计算整个前缀的 K/V。对采用普通全注意力和 KV cache 的单个解码步，当前 query 仍需读取已缓存的历史 K/V，相关工作随上下文长度增长。生成很多步的总工作会继续累积。

一个用于容量估算的 KV cache 教学式为：

$$
M_{\mathrm{KV}}\approx 2\,L\,B\,n\,H_{\mathrm{KV}}\,d_h\,b.
$$

$L$ 是层数，$B$ 是同时缓存的序列数，$n$ 是各序列长度的简化共同值，$H_{\mathrm{KV}}$ 是 KV 头数，$d_h$ 是每头维度，$b$ 是每元素字节数，因子 2 对应 K 和 V。真实批次应按各序列长度求和。这个式子只估 KV 数据，不含模型权重、激活、内存池、碎片及其他运行开销；不同注意力结构也未必适用。

假设教学模型有 32 层、8 个 KV 头、每头 128 维、缓存长度 32768、单序列、每元素 2 字节，则 K/V 理论数据量为 4 GiB。这不是某个真实模型的显存需求，更不表示 4 GiB 可以部署整个模型。

这也解释了为什么“把全部邮件和公告每轮都带上”不仅贵，还可能降低并发。对高频助手，稳定前缀复用、按需读取和更短工具返回，往往先于更换注意力架构成为可控优化点。是否获益必须实测，尤其要防止删除信息后引入遗漏。

## 6．线性注意力：改变计算对象，而不只是改实现

指定阅读《Transformers are RNNs》给出一种核特征形式的注意力。一般加权输出可写为：

$$
y_i=\frac{\sum_j\operatorname{sim}(q_i,k_j)v_j}{\sum_j\operatorname{sim}(q_i,k_j)}.
$$

若相似度写为非负特征映射的内积 $\operatorname{sim}(q,k)=\phi(q)^\top\phi(k)$，则可利用结合律：

$$
y_i=\frac{\phi(q_i)^\top\left(\sum_j\phi(k_j)v_j^\top\right)}{\phi(q_i)^\top\left(\sum_j\phi(k_j)\right)}.
$$

原来每个 query 都逐一比较全部 key；现在先把 key/value 汇总成共享状态，再让 query 读取。设特征维度为 $c$、value 维度为 $d_v$，汇总状态大小主要由 $c\times d_v$ 决定，而不是显式保存 $n\times n$ 分数矩阵。[B，§3.2，式 3–6，PDF p.3]

对因果序列，只累计截至当前位置（含当前位置）的信息：

$$
S_t=S_{t-1}+\phi(k_t)v_t^\top,\qquad z_t=z_{t-1}+\phi(k_t),
$$

$$
y_t=\frac{\phi(q_t)^\top S_t}{\phi(q_t)^\top z_t}.
$$

这就得到递归状态，解释论文标题中“RNNs”的含义。在固定维度下，每步更新可以不随已处理 token 数线性增大；数学分母要求有效正值，数值实现还需稳定性处理。[B，§§3.3–3.4，PDF pp.4–5]

### 为什么不能把普通 softmax 随手搬到括号外

矩阵乘法满足结合律，softmax 不是可任意交换的线性操作。原文明确讨论，精确指数核对应无限维特征映射；他们的实用选择包含 $\phi(x)=\operatorname{elu}(x)+1$，对应不同的相似度机制。不能据此声称“把现有模型换个算子，就能完全等价地省掉所有 KV cache”。[B，§3.2.1、式 7，PDF pp.3–4]

### 对 Agent 的选择含义

全注意力保留可逐位置访问的历史表示；递归汇总把历史压入固定维状态。对于精确查找稀有编号、引用原句或多处相似细节，二者的实际表现需要专项测试。混合结构试图组合不同机制，但某个模型的具体结构与能力，仍应核查其报告，不能由这篇 2020 年论文推断。

讲义 pp.66–67 的“Drop Softmax”用于直观展示结合律，不能理解为对既有 checkpoint 做无损替换；pp.83–90 再展示速度、长上下文和混合架构。固定维状态的“常数内存”限定于状态随序列长度的增长，不包含模型权重，也不意味着不同状态维度都同样便宜。[L，pp.66–90]

论文摘要中的极高加速数字来自其特定实验和序列设置，不能直接转换为“当前 Agent 服务可加速几千倍”。阅读时应分别看渐近复杂度、实际硬件吞吐、任务质量及比较对象。[B，摘要、§4；本文未复现其速度实验]

## 7．预训练、SFT、RL：哪一个对象正在改变

| 阶段或方法 | 主要信号 | 通常改变的对象 | 内部助手能从中得到什么 |
|---|---|---|---|
| 预训练 | 大规模序列上的预测任务 | 模型权重 | 通用语言、知识和模式能力 |
| 监督微调 SFT | 输入与期望输出示范 | 模型权重 | 输出形式、工具习惯、领域任务模式 |
| 基于反馈的优化/RL | 行动结果或偏好评分 | 模型策略/权重等 | 增强在奖励定义下的行为倾向 |
| Prompt / few-shot | 请求中的指令与示例 | 当前上下文 | 无训练地调整本次行为 |
| RAG / 工具 | 外部证据与执行结果 | 当前观察和系统状态 | 最新事实、精确计算和实际动作 |

### 7.1 数据流程与中期训练为何影响应用

讲义 pp.102–107 讨论从 HTML 到文本提取、去重、语言识别、规则与质量过滤，再到数据混合。它提醒我们：模型不是把所有网页等量背下来，资料的覆盖、重复与质量会影响能力。第 108–111 页引入 midtraining，主要通过调整数据分布，让训练更关注目标领域；它位于大规模通用预训练与更明确任务/交互对齐之间，边界依具体训练方案而定。它仍更新权重，不是把领域 PDF 放进检索库。[L，pp.102–111]

对企业助手，预训练是否覆盖金融语言，后训练是否学会遵循工具契约，和当前检索是否取得最新公告，是三种不同条件。不能从“模型做过金融微调”推断它掌握当日持仓，也不能从一次检索成功推断它具备多步工具策略。

### 7.2 损失、后训练和 Agent 轨迹

监督训练的一般负对数似然目标可写成：

$$
\mathcal L_{\mathrm{SFT}}=-\sum_{(x,y)}\sum_t\log p_\theta(y_t\mid x,y_{<t}).
$$

**对数底数校正**：讲义第 99 页写 $-\log(0.0124)=1.907$，该数值对应以 10 为底的对数；通常用自然对数表示交叉熵时，$-\ln(0.0124)\approx4.39006$。改变底数会按常数因子缩放损失，比较不同实现的数值前须明确约定。本文公式按自然对数解释；两个算例已用本地 Python 复算。[L，pp.99–100]

它让示范输出更可能出现，但示范必须包含系统真正希望形成的行为。例如，若所有示范都在证据不足时强行给出结论，模型可能更熟练地输出无根据结论。RL 则利用结果评分来引导尝试，评分若只奖励“报告写得完整”，可能惩罚诚实的缺口披露。这些是一般训练目标的教学说明，不是说本课每个算法都采用同一损失或同一奖励实现。

内部助手最容易混淆的三个情形是：把今天的公告放进输入属于上下文更新；把历史错误写入外部经验库属于系统记忆更新；用示范做梯度训练才属于参数更新。三者都可能改善行为，但版本管理、删除方式、成本与验证方法不同。

讲义 pp.113–118 将 instruction tuning、偏好反馈、可验证奖励和 Agent 专用轨迹放在一起。偏好标注存在不一致及激励偏差；RLVR 则把单元测试、精确匹配或环境状态作为可验证信号，但验证器本身必须防止漏洞。对代码 Agent，训练对象还包含在真实环境里读取、修改、测试的交互，而不只是最后答案。本文在此讲信号与行为的关系，不把讲义引用的 SWE-smith 或 RLVR 研究当作本地已复现实验。[L，pp.113–118]

如果问题是“没有拿到最新正文”，优先修数据和检索；如果问题是“不遵循稳定输出规范”，先查提示与结构约束，再评估 SFT；如果问题是“需要在多步行动中优化结果”，才考虑与该行为相匹配的轨迹和反馈。选型应由失败归因驱动，而非按技术热度升级。

## 8．推理性能与 Test-time scaling：多花预算，如何知道值得

### 8.1 Roofline、服务指标与推测解码

讲义 pp.121–135 用 GPU 和 Roofline 区分算力上限与内存带宽上限。教学形式是 $P\leq\min(P_{\mathrm{peak}},B_{\mathrm{mem}}I)$：$P$ 是每秒计算量，$P_{\mathrm{peak}}$ 是算力上限，$B_{\mathrm{mem}}$ 是每秒搬运字节数，$I$ 是每字节数据对应的计算量。批量处理较多输入位置时可能提高数据复用，使 prefill 更接近算力限制；逐 token decode 往往更受带宽与状态读取影响。实际瓶颈仍随批次、长度、结构和硬件变化，第 134 页是典型示意，不是所有请求的定律。[L，pp.121–135]

服务指标也要分开：首 token 时间包含排队、输入处理等开销；随后每 token 时间描述连续生成节奏；整体时延还依赖输出长度；系统吞吐描述并发总产出。Agent 还会串联工具等待与多次模型调用，因此单看模型 tokens/s 无法推断整项工作的交付时间。

第 136–137 页引入 speculative decoding：较便宜的 draft model 提议一段 token，target model 以并行验证等机制接受一部分并处理不一致，再继续。收益依赖草稿接受率、验证代价、候选长度与调度，不是给任意任务多加一个小模型就一定更快。是否保持目标分布取决于具体算法中的接受与校正规则；本文只按讲义解释 draft/target 分工，不声称实现或复现了某一种精确采样算法。[L，pp.136–137]

### 8.2 增加推理预算改变了什么

推理时增加预算可表现为更长生成、多候选、检索补查、工具验证或多次尝试。它们消耗的是不同资源，也解决不同问题。多候选让系统探索更多答案；可靠验证器帮助选择；新增检索改变可见证据；单纯延长解释则未必引入信息。

对于晨会助手，可以分别做三项对照：保持资料不变，增加候选数；保持候选数不变，增加正文补查；保持两者不变，加入事实验证。记录任务成功率、证据覆盖、成本和延迟，才能区分预算效应与机制效应。

若每次尝试独立、成功概率固定为 $p$，至少一次成功的理想化概率是 $1-(1-p)^k$。真实 Agent 的失败经常相关：它们共享错误数据、提示或假设，独立性不成立。而且系统必须有办法识别哪次真的成功，否则“采样里存在正确答案”不等于可交付正确答案。这个式子是帮助理解预算边界的教学模型，不是实际 Agent 成功率预测器。

讲义 pp.139–148 还区分单条轨迹的推理预算与多条轨迹的聚合。提高某模型的 reasoning effort、增加候选数、增加工具补查次数，是三个独立的控制变量；更长推理不能替代缺失证据。对于晨报任务，可以先在相同总预算下比较“单条深入核查”和“多条候选加验证”，再比较最佳方案的预算曲线。模型专用的 effort 参数与训练实现以各自版本为准，本课展示的产品图不能转换为通用 SDK 配置。[L，pp.139–148；实验设计为工程建议]

## 9．结构化 I/O：语法约束能挡住哪类错误

讲义 pp.153–158 连续展示受限解码、DSPy Signatures 和分类器，三者都能组织接口，但保证不同：Signatures 声明输入输出契约，具体 adapter 可以把它转成提示并解析结果；仅有类型声明不证明生成过程受到硬约束。受限解码在采样时排除不合法延续；分类器则直接在有限标签集合上决策，无需先生成任意长文本。固定邮件意图分类可以评估分类器基线，开放式论证仍需要生成；不能把所有结构化输出都当成同一种技术。[L，pp.153–158]

假设要求输出：

```json
{"company_id":"C001","period":"2026Q3","change_pct":20.0,"evidence_ids":["doc-17:p8"]}
```

JSON Schema 或受限解码可减少漏括号、错误字段类型、非法枚举等形式问题。其机制可以抽象为：在当前输出前缀下，只允许符合语法或 schema 的下一 token，再在允许集合内选择。具体供应商是否支持完整 schema、如何处理拒绝、截断和工具调用，属于版本相关能力，应查实际接口文档。

即使结构完全合法，`company_id` 仍可能指错公司，`change_pct` 仍可能口径错误，`evidence_ids` 仍可能不存在。系统需要分层验证：

1. 字节与语法层：能否解析，是否被截断。
2. Schema 层：字段、类型、范围和枚举是否满足契约。
3. 参照完整性层：公司、文档和页码是否存在且可访问。
4. 语义层：原文是否支持论断，时间、币种和合并范围是否一致。
5. 业务层：输出是否满足任务目标、授权和接受标准。

例如，模型输出利润增长 20%，程序应保存用于计算的本期、基期、单位及公式；证据定位检查与算术检查分别执行。让模型再输出一句“我已核实”，不能代替这些层次。

## 10．上下文工程：控制本轮模型实际看见什么

指定阅读《Effective context engineering for AI agents》把上下文工程从“写好系统提示”扩展为运行时信息的持续选择：系统规则、工具说明、检索内容、消息历史和外部状态，都占用同一个有限输入空间。[C，Context engineering vs. prompt engineering、Why context engineering is important]

对企业助手，应把输入分成几种不同生命周期：任务目标与权限约束比较稳定；持仓与日期属于本次任务配置；公告原文按需读取；工具观察随行动追加；已经完成的步骤可以压缩为结构化进度。静态规则、实时事实和未验证推断混在一大段文字中，会让系统难以判断可信度和更新顺序。

### 按需读取如何改变信息流

先传入文档 ID、标题、日期、类型和小段摘要，模型选择值得阅读的正文；遇到疑点再读原页或补查历史。这样可以降低无关 token，但增加交互延迟，也依赖检索和工具设计。不能把“少放上下文”当成目的：如果删除了证券代码、基期、单位和来源，就可能让输出变短而更不可靠。[C，Context retrieval and agentic search]

### 长流程的三种状态管理方式

| 方式 | 保留什么 | 主要风险 |
|---|---|---|
| Compaction | 对此前交互作摘要后继续 | 丢掉后来才变重要的细节或限制 |
| 结构化笔记 | 目标、决策、证据 ID、未解事项等外部状态 | 笔记过时、把假设写成事实 |
| 子 Agent 隔离 | 让局部探索留在独立上下文，回传结果 | 摘要丢证据、协调成本、重复工作 |

这三种方式可以组合。第 168–169 页还提醒尽量保留稳定前缀并顺序追加：在前面插入或改写 token，会改变后续位置及其因果输入，使原来的后缀 KV 不能直接复用。这里说的是模型计算前缀；供应商是否提供跨请求缓存、缓存命中条件和计费，另属接口行为，不能由这两页推断。[L，pp.168–169]

第 172–173 页的 Recursive LMs 给出另一种组织方式：把长输入保存在外部代码环境中，模型通过程序读取片段、拆子问题，并递归调用模型处理局部内容。它把“如何访问资料”变成程序与子调用的控制问题，仍需验证切分、聚合、预算和结果完整性；不等于模型单次上下文真的无限大。本文根据讲义图解释信息流，未通读该外链论文或复现其分数。[L，pp.172–173]

压缩任务状态时要保留原始证据位置，不能只保留模型总结；子 Agent 回传“已确认”时也应带来源和核验范围。[C，Context engineering for long-horizon tasks]

## 11．把机制变成一套选型流程

先建立失败基线：模型是缺知识、漏证据、算错、格式错误，还是无法正确使用工具？对同一组任务保存当前完整输入、输出和环境快照。

然后按最接近原因的对象干预：缺知识改检索；数字错误改解析和计算工具；工具混淆改接口契约；无关历史干扰改上下文；稳定行为模式缺失才评估训练数据与微调。每次只改变少量变量，保留回归任务。

例如，若公告表格的“万元”在解析时被丢掉，换更强模型可能偶尔猜对，却掩盖数据问题。若正文已正确输入，但相似公司名称反复混淆，可增加实体标识、结构化证据和专门评测；不能直接跳到“模型记忆不行”。

最后同时评估任务质量与资源。更短上下文若遗漏关键事实，不算优化；更高准确率若来自十倍预算，需要明确其成本和上线场景。对内网模型，尤其要把数据入口、工具、验证与模型能力分开测试，避免把所有失败都归因于模型规模。

## 12．故障诊断表

| 现象 | 机制层可能原因 | 最小验证方法 | 优先处理 |
|---|---|---|---|
| 输出每次都不同 | 采样、上下文或服务版本变化 | 固定真实输入快照并重复运行 | 先建立运行版本记录 |
| 长输入漏掉中间证据 | 信息干扰、位置和检索能力 | 移动关键片段，加入受控干扰 | 减少无关信息、分段读取 |
| 显存随并发和长度增长 | KV、激活与调度开销 | 分别改变并发、输入长度和输出长度 | 根据实际结构估容量并实测 |
| JSON 正确但数字错误 | 语义与口径未验证 | 对照原文和确定性计算 | 增加参照与业务检查 |
| 反思越来越长但无进展 | 没有新观察或验证信号 | 检查每轮是否新增证据 | 改工具反馈与停止条件 |
| 换线性模型后精确检索下降 | 状态压缩与任务特性不匹配 | 同资料同预算测稀有事实定位 | 按真实工作负载选模型 |
| 微调后仍不知道最新公告 | 参数更新和数据时效混淆 | 检查当前上下文是否有新正文 | 修实时资料链路 |

## 13．自测与答案

**题 1：生成概率高，是否说明结论事实可信？**  
答案：不说明。它描述在给定输入下文字出现的倾向，事实需要外部证据或任务验证。

**题 2：训练能并行处理所有输出位置，为什么推理不能一次确定整段？**  
答案：训练时目标前缀已知，通过因果 mask 并行计算各位置损失；自回归推理时后续 token 依赖刚生成的前缀，未来内容未知。

**题 3：KV cache 是长期业务记忆吗？**  
答案：不是。它缓存当前序列各层的神经表示以节省重复计算；业务长期记忆需要可管理的存储、读取、更新和权限机制。

**题 4：线性注意力为什么能变成递归计算？**  
答案：相似度采用可分解的特征内积后，历史 key/value 的贡献可累计成 $S_t,z_t$，当前 query 读取这些汇总状态。其机制一般不等于精确 softmax。

**题 5：受限解码能否阻止模型引用不存在的文件？**  
答案：仅当可选文件被纳入实际约束时，才能限制某些非法标识；一般 JSON 语法约束做不到。仍需要在程序中检查对象存在、权限和证据支持。

**题 6：三次尝试中有一次正确，就一定能交付正确答案吗？**  
答案：还需要可靠选择或验证机制；没有它，可能挑中错误候选。尝试之间的错误也可能高度相关。

**题 7：同一段历史压缩到十分之一，成本降低，是否已经优化成功？**  
答案：需要检查任务成功率、约束遵循和证据保留。只节省 token 而丢失关键事实，不能算整体改善。

**题 8：一个表格数字在 PDF 中有单位，解析后没有，应微调还是修解析？**  
答案：先修解析与结构化数据契约；否则训练只会学习猜测缺失信息。
