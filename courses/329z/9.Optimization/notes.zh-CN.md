# 第 9 课｜Optimization：把 Agent 的改进变成有预算、有证据的搜索

> **课程**：Stanford CS329Z，Engineering AI Agents，Fall 2026。  
> **日期与编号**：2026-10-21，Week 5；本地第 9 次课。  
> **主讲义**：[lecture09.pdf](slides/lecture09.pdf)，125 页。  
> **来源入口**：[SOURCES.md](SOURCES.md)。

一个 Agent 在十个案例上反复失败，你可以改提示、挑示例、修改工具、换模型、微调权重，也可以让另一个 Agent 自动提出修改。真正困难的不是列出这些手段，而是判断：**哪一个变量导致失败，什么反馈能指导修改，怎样在有限预算内选出可泛化的新版本，以及凭什么允许它替换旧版本。**

本课从上下文优化进入权重优化，再讨论 Agent 作为优化器。本文用一个“企业公告取证与摘要助手”贯穿：输入公司和期间，检索公告，抽取有来源的事实，比较变化，生成摘要。系统的检索提示、抽取提示和汇总提示可以分别改变，但整体交付是否正确需要端到端验证。本文没有调用外部模型、训练权重或复现论文分数；教学算例与拟议实验均另行说明。

## 1. 优化之前，先把可改变的对象写清楚

把一个系统表示为：

$$
y=F(x;\Pi,\Theta,C,R),
$$

$x$ 是任务输入，$\Pi$ 是各模块提示与示例，$\Theta$ 是模型权重，$C$ 是控制流与工具代码，$R$ 是检索索引、记忆和其他持久资源。一次修改可能只改变其中一项，也可能改变多项。若同时换模型、加检索、改提示并提高预算，即使结果变好，也无法把收益归给某个具体算法。

GEPA 原文将 compound AI system 写成含模块、控制流和输入输出 schema 的结构，并把每个模块的提示和权重分别列为参数。它自身固定权重、优化提示；与 GRPO 的比较则跨越了不同参数空间。[GEPA，§2，PDF p.4](readings/GEPA_Reflective_Prompt_Evolution_Can_Outperform_Reinforcement_Learning.pdf#page=4)

**工程建议**：一次实验保存系统配置、代码提交、提示与示例哈希、模型标识、数据版本、工具版本、评测器版本和预算。不要只保存最后一段“最佳 prompt”。同一 prompt 在不同检索结果或工具反馈格式下，可能对应完全不同的系统行为。

对当前企业助手，可以先拆出四类故障：检索没有找到正确公告；抽取丢失单位和期间；汇总超出了证据；工具或权限错误。前两类也许适合提示和示例优化；检索库根本没有原文时，继续改汇总提示不能创造证据；接口签名错误需要修复代码或契约。优化器的搜索空间应包含能够影响真正故障的变量。讲义 pp.8–11 将数据、系统和评测列为共同前提；模型的通用能力升级不取消这种 last-mile 适配，因为业务约束、输出口径和环境仍有具体差异。[L9，pp.8–11](slides/lecture09.pdf#page=8)

## 2. 目标函数必须包含业务成功条件

设 $z$ 表示候选系统配置，$\tau=\operatorname{Run}(x;z)$ 是一次完整轨迹，$\mu(\tau,m)$ 是依据验收元数据 $m$ 计算的分数。优化希望在任务分布 $\mathcal T$ 上提高期望表现：

$$
z^*=\arg\max_z\mathbb E_{(x,m)\sim\mathcal T}[\mu(\operatorname{Run}(x;z),m)].
$$

我们不能直接观察未来全部任务，只能用有限样本估计。若一次 rollout 需要检索、模型、工具和评测，搜索还受预算 $B$ 限制。GEPA 以 rollout 数量表述其样本效率问题；生产中还需统计反思模型、训练、验证、时间和金钱成本。[GEPA，§2，式 1–2，PDF p.4](readings/GEPA_Reflective_Prompt_Evolution_Can_Outperform_Reinforcement_Learning.pdf#page=4)

企业摘要不能只用“文字像标准答案”评分。可以分别检查：事实字段是否正确，来源是否实际支持陈述，单位期间是否一致，缺失时是否如实说明，是否满足输出结构和权限约束。对于不可妥协的条件，适合设置硬门槛；其余维度再按业务目标比较。

例如，一个候选提高摘要可读性，却开始补造未披露数字，不应靠平均分抵消这个退化。可以采用约束优化：先要求未经证据支持的关键数字率低于允许阈值，并满足权限边界，再比较任务成功率、费用和延迟。阈值需要由具体业务验收定义，本文不替业务规定一个通用值。

### 2.1 评分错误会成为优化方向

若 judge 奖励回答更长，优化器会不断增加内容；若只看引用格式，系统可能学会生成漂亮但无支持作用的引用。优化器没有义务发现你忘记写进指标的目标。评测器应先与人工审查或可执行验证对齐，并保存原始判定依据，便于识别 reward hacking。

把指标叫作 reward、score 或 loss，不会改变这个问题。高质量反馈应指出哪条要求违反、依据是什么、如何区分实际错误与表述差异。自然语言批评也可能错误，不能因为它比一个分数更详细，就直接当作真实因果解释。

## 3. 从手工 few-shot 到 Bootstrap：示例为何能改变行为

Few-shot 把少量输入输出示范放入提示，告诉模型哪些约束和处理模式重要。它改变的是上下文条件，不是权重。对抽取模块，示例可以展示“单位在表头、期间在标题、缺失值要返回 null”；这些条件有时比一句“认真核对”更容易操作。

Bootstrapping 的思路是先用现有系统或较强教师处理训练输入，保留达到成功标准的轨迹，再将各模块的输入输出作为示例候选。多阶段系统不一定有每个中间模块的人工标签；只要最终结果通过评测，就可以提出中间示例候选。MIPRO 原文将这种策略作为优化起点。[MIPRO，§3.1、§4.1，PDF pp.3–5](readings/Optimizing_Instructions_and_Demonstrations_for_Multi-Stage_Language_Model_Programs.pdf#page=3)

这里的“候选”非常重要：最终答案正确，可能是错误相互抵消或模型绕过了中间输出。因此成功轨迹不自动证明每一步都正确。涉及原始数字、引用和权限时，应该对示例做额外过滤，至少确认它没有依赖泄漏标签、私有答案或不可重复的环境状态。

示例选择还要考虑覆盖和成本。十条几乎相同的正常案例，未必比三条覆盖单位、缺失与修订的案例有效。示例增加输入 token、延迟和缓存条件；找到更短而有区分力的组合，有时比无限堆示例更值得。

### 3.1 讲义中的示例排序：同一批样本，顺序也会影响结果

pp.14–18 用 prompt ordering 说明，示例集合相同并不表示条件分布相同。讲义展示两种统计：global entropy 看一批探测输入的预测标签分布是否塌缩到单一类；local entropy 看每个探测输入上类别分布的不确定性，再在探测集求平均。对离散分布 $p$，熵为 $H(p)=-\sum_k p_k\log p_k$，它衡量分布分散程度，不是正确率。[L9，pp.14–18](slides/lecture09.pdf#page=14)

没有使用探测集真值，可以降低某些标注需求，却不能使熵自动成为可靠业务指标。一个预测总是自信但错误的模型可以具有低局部熵；一个类别分布平衡的系统也可能逐例全错。这里用排序启发式理解候选筛选，最终仍回到独立准确性与业务约束。讲义 pp.15、18 的图片链接指向其他背景材料，本文不据此宣称已经核实排序原论文的完整实验。

pp.19–22 再从“人工示例缺少中间推理”转向 STaR 和 DSPy 的拒绝采样。前者的整体研究包含训练环节，后者的这段课堂例子强调也可以只把成功轨迹用作上下文。相同的轨迹采集步骤，后续可以进入不同更新空间，不能仅凭使用了 reasoning traces 就判断发生了微调。[L9，pp.19–22](slides/lecture09.pdf#page=19)

## 4. MIPRO：把“写哪些提示”与“选哪种组合”分开

本课课表使用 MIPROv2 名称；指定的 2024 论文介绍 MIPRO 及其变体。这里用原论文解释算法思想，不把 2024 PDF 当作当前 DSPy 类的完整 API 文档。原文是 arXiv:2406.11695v2，2024-10-06，共 28 页。

多模块优化存在两个问题：**proposal** 是怎样提出有希望的指令和示例；**credit assignment** 是怎样根据系统最终分数推断哪些模块组合值得继续探索。逐模块贪心修改虽然容易理解，但模块之间可能互相依赖，一个局部改进在其他模块不变时看不出收益。[MIPRO，§1、§3，PDF pp.2–4](readings/Optimizing_Instructions_and_Demonstrations_for_Multi-Stage_Language_Model_Programs.pdf#page=2)

MIPRO 的基本流程可以分成三步。

1. **生成示例候选**：运行并筛选成功轨迹，形成各模块的 demonstration 候选集。
2. **生成指令候选**：给 proposer LM 数据摘要、程序控制流、示例等上下文，提出更贴近任务的指令。
3. **搜索组合**：用 Bayesian optimization 的代理模型，在各模块指令与示例的离散组合中寻找较优配置，并用真实端到端评测更新搜索。

论文采用 Tree-structured Parzen Estimator；使用小批量评测降低每次探索成本，定期对有希望配置做更完整评测。代理模型是对“配置与得分关系”的统计近似，不是优化目标真正的梯度，也不是语言模型本身的权重。[MIPRO，§4.3，图 4，PDF pp.5–6](readings/Optimizing_Instructions_and_Demonstrations_for_Multi-Stage_Language_Model_Programs.pdf#page=5)

### 4.1 在公告助手里怎样发生作用

设检索模块有三条候选指令，抽取模块有三组示例，汇总模块有两条指令，那么已有 $3\times3\times2=18$ 个组合。模块和候选数增加后，穷举很快变贵。搜索算法通过历史评测把预算集中到有希望的组合，但最终质量仍须由真实系统运行检验。

好的组合可能要求检索模块返回公告版本、抽取模块保留单位、汇总模块仅使用结构化事实。仅优化汇总模块的语言风格，可能无法弥补前两步丢失的信息。这也是多阶段优化需要端到端目标的原因。

原论文在多个任务上比较指令、示例和联合优化，并发现它们的贡献随任务变化。不能把“示例总比指令重要”或“指令优化一定胜出”当作固定结论。[MIPRO，§5–6](readings/Optimizing_Instructions_and_Demonstrations_for_Multi-Stage_Language_Model_Programs.pdf#page=7)

### 4.2 跟着讲义的 Iris 动画走完一次优化

pp.27–34 先运行分类程序，按 species 指标保留或丢弃轨迹；pp.35–47 将程序摘要、数据摘要、成功轨迹和一条提示建议送给 proposer；pp.48–62 把指令和示例集合视为离散槽位，按代理模型信念采样组合，在小批量评分后更新信念，并周期性完整评估；p.63 才展示被选中的整个模块提示。[L9，pp.27–63](slides/lecture09.pdf#page=27)

这段动画中的“大灾难/拯救物种”措辞是候选，不是被证明普遍有效的提示法则。p.43 的生成式 rationale 也不能因最终类别得分较高就当作可信生物学解释：它对品种特征的描述与前面的数据展示并不一致。这个课堂例子恰好说明最终标签指标不会自动验证中间文字解释，训练或重用前仍需检查。

## 5. OPRO 与 TextGrad：反馈怎样转成修改

### 5.1 OPRO：让模型从候选—分数历史中继续提案

OPRO 把优化问题、约束、历史候选和分数写入 meta-prompt，让 LLM 生成下一批候选，再通过实际评测取得分数。改进来自迭代提案与筛选，而不是仅让模型给自己的 prompt 打分。[OPRO，§2，图 2，PDF pp.3–4](references/Large_Language_Models_as_Optimizers.pdf#page=3)

它易于接入仅提供 API 的模型，也适用于其他可以描述和评测的候选空间。不过，历史分数可能噪声很大，模型也可能偏向已经见到的表达模式。若只有整条流水线的一个分数，proposer 还需面对多模块信用分配问题。MIPRO 原文专门讨论把 OPRO 扩展到多阶段时的这些假设。[MIPRO，§4.2、§4.5，PDF pp.5–6](readings/Optimizing_Instructions_and_Demonstrations_for_Multi-Stage_Language_Model_Programs.pdf#page=5)

讲义 p.3 的投票和 pp.24–25 的 OPRO 案例应读成“在某个 scorer 和任务上搜索过的表达”，而不是让所有请求加一句深呼吸。OPRO Table 1 把用于评测的 scorer 与用于提案的 optimizer model 分列；讲义开头的模型标题是简写，解释具体百分比时要回到原表的角色与设置。[OPRO，Table 1，PDF p.1](references/Large_Language_Models_as_Optimizers.pdf#page=1)；[L9，pp.3、24–25](slides/lecture09.pdf#page=24)

### 5.2 TextGrad：用自然语言批评沿计算图传递修改建议

TextGrad 把输入、输出、提示或其他产物视为计算图中的变量，通过 LLM 提供的自然语言反馈，说明这些变量怎样修改可能改善整体目标。论文明确把 differentiation 和 gradient 作为类比；这不是对字符串求出数学导数，也不自动具有数值梯度的局部最优性质。[TextGrad，§1–2，PDF pp.2–4](references/TextGrad_Automatic_Differentiation_via_Text.pdf#page=2)

对公告助手，最终反馈“结论没有区分单季与累计”可以沿图回查：抽取字段是否缺少期间；汇总是否忽略字段；检索是否取得错误版本。语言反馈提供更丰富的诊断材料，但错误归因仍需回查中间产物和对照实验。

这些方法都依赖反馈质量。优化器若收到的批评是“请更专业”，只能猜测；若收到“字段 period 应为前三季度，源文件第 3 页标题说明累计期间”，修改方向就更明确。后者把诊断绑定到可检查证据，减少错误反思被固化的机会。

## 6. GEPA：从失败轨迹提炼规则，保留互补候选

GEPA 固定底座权重，迭代修改一个或多个语言模块的提示。它结合反思性变异、基于实例的候选选择，以及可选的 system-aware merge。关键输入包括系统、训练任务、评分函数、文本反馈函数与总 rollout 预算。[GEPA，§3、Algorithm 1，PDF pp.4–7](readings/GEPA_Reflective_Prompt_Evolution_Can_Outperform_Reinforcement_Learning.pdf#page=6)

一次反思性变异可以按下面理解：选一个候选系统；选待修改模块；在训练小批量上运行；收集输入输出、工具结果、分数和评测文本；让反思模型提出新提示；在同一小批量比较父子；有收益再进入更完整的候选评测。每一步都需要运行结果，不能仅凭反思模型认为“写得更好”就激活候选。

### 6.1 为什么文本反馈比 0 分多提供了一些信息

假设一次工具任务失败，标量奖励只有 0。环境原本还给出了“必填字段缺失”“单位不匹配”“引用文件版本不符”等信息。GEPA 主张保留这些 evaluation traces，与系统 execution traces 一起指导修改。执行轨迹说明系统做了什么；评测轨迹说明验证过程观察到了什么。[GEPA，§3，PDF pp.5–7](readings/GEPA_Reflective_Prompt_Evolution_Can_Outperform_Reinforcement_Learning.pdf#page=5)

这些信息可以支持更有针对性的候选，比如在检索阶段保留版本，而不是笼统让汇总模块“更严谨”。但“反思归因”仍是启发式，不能自动证明某模块对失败负全责。最好通过固定其他模块、替换该模块并在独立数据上测试，检查推断是否成立。

### 6.2 这里的 Pareto 不是只保留平均分最高的 prompt

设候选 A 在两类任务的得分为 $(1,0.5)$，B 为 $(0.6,1)$，C 为 $(0.4,0.4)$。A 与 B 各有擅长的实例；C 则被较好候选支配。保留互补候选，可能帮助后续搜索发现不同解决策略，而非始终围绕一个平均分赢家微调。

GEPA 的实例级选择先找出在至少一个实例上达到当前最好分数的候选，再进行过滤并按它们在实例最优集合中的出现频率采样。这个具体过程比通常泛称的“质量—成本二维 Pareto 前沿”更具体；论文这里主要利用各实例得分保留多样性。[GEPA，§3.1、Algorithm 2，PDF pp.6–7](readings/GEPA_Reflective_Prompt_Evolution_Can_Outperform_Reinforcement_Learning.pdf#page=6)

System-aware merge 也不等于把两段长 prompt 拼在一起。它利用候选的模块与演化关系，尝试组合互补改进；合并后仍需评测。两个模块分别表现好，组合起来可能产生接口或行为冲突，不能假设收益可加。[GEPA，图 3、附录 D.1](readings/GEPA_Reflective_Prompt_Evolution_Can_Outperform_Reinforcement_Learning.pdf#page=5)

### 6.3 PAPILLON 示例不是两个基线实验的混合

讲义 pp.66–67 使用隐私保护委托任务：一个模块把私有请求转换成外部模型可处理、又不暴露私有信息的请求；另一个模块利用外部回复服务原用户。反思可以发现哪些姓名、代码或细节该抽象，哪些任务条件必须保留。隐私与有用性都需评测，不能靠删掉所有信息取得“零泄漏”却无法完成任务的虚假成功。[L9，pp.66–67](slides/lecture09.pdf#page=66)

p.66 明确说明展示的是 GEPA 论文中的 baseline prompts，并不是原 PAPILLON 论文的 baseline。比较优化前后时，不能把这两个来源的基线和成绩拼接。这里用课堂例子解释反馈怎样变成提示规则，不复现其私有数据处理实验。

## 7. 怎样读“GEPA 可以超过 RL”的实验

本地版本为 arXiv:2507.19457v2，2026-02-14，96 页，包含大量附录。主实验使用六类任务、Qwen3 8B 与 GPT-4.1 Mini 等设置，比较 GEPA、MIPROv2、TextGrad、Trace 与 GRPO。它支持的是这些模型、任务、系统和预算定义下的结果，不是“所有场景 prompt 都比训练好”。[GEPA，§4、Tables 1–2，PDF pp.8–9](readings/GEPA_Reflective_Prompt_Evolution_Can_Outperform_Reinforcement_Learning.pdf#page=8)

读结论至少需要问：反思和执行模型分别是谁；GRPO 的训练配置与停止点是什么；提示方法是否得到额外文本反馈；预算是否只数 rollout，还是包含优化器调用和训练资源；测试集是否隔离；对多次候选选择是否控制过拟合。

论文区分可以查看内容并用于更新的反馈训练数据，与主要用于候选选择的评测数据。大部分 rollout 可能花在候选验证上。较少训练 rollouts 并不自动等于端到端金额、耗时和显存都按同一比例下降。对企业应用尤其应统计反思教师费用和部署时增长的 prompt token。[GEPA，§4，Observation 1，PDF p.9](readings/GEPA_Reflective_Prompt_Evolution_Can_Outperform_Reinforcement_Learning.pdf#page=9)

此外，长 prompt 的知识可以被人工检查、版本化和回滚，这是工程优势；但其长度也可能增加推理成本、与系统规则冲突或过拟合特殊评测器。模型版本更换后，应重新跑回归，而不是因为权重没有训练就认为它是模型无关的永久规则。

## 8. SFT：让模型更像经过筛选的成功行为

监督微调把输入条件和目标输出组成样本，通过负对数似然提高目标 token 的概率。最简教学形式为：

$$
\mathcal L_{SFT}(\theta)=-\mathbb E_{(x,y)\sim D}\sum_t\log p_\theta(y_t\mid x,y_{<t}).
$$

$x$ 可以包含用户请求、工具定义和历史；$y_t$ 是目标的第 $t$ 个 token；$\theta$ 是需要训练的权重。对 Agent 数据，目标可以包含工具调用、结构化抽取和最终回答。实际训练需明确哪些位置计入 loss，不能把工具返回当作模型应生成的动作，也不能把隐藏答案放入输入。

SFT 适合有稳定且可信示范的情况，例如反复违反输出 schema、不会使用特定工具格式、缺少某领域任务流程。它直接模仿给定轨迹，但不自然告诉模型“两个都没见过的动作哪个更好”。成功样本还可能分布很窄，使模型在错误后无法恢复。

因此训练资料应包含真实调用状态、可解释失败与修复，而不只是完美最终答案。要区分来源：人工示范、教师生成、真实用户轨迹和自动修复，它们的可靠性和偏差不同。模型训练成本还包括数据清洗、去重、隔离评测、部署兼容与回归，不只是一次 GPU 任务。

### 8.1 讲义的两个 Agent SFT 案例应归因到什么

pp.74–79 用 OpenThoughts-Agent 与 FireAct 展示“教师在环境中完成任务 → 筛选轨迹 → 学生后训练”的路线。FireAct 例子包含不同推理/行动模式，让模型在推理时选择；它不是只把一篇标准最终答案反复喂给学生。[L9，pp.74–79](slides/lecture09.pdf#page=74)

这些案例支持在各自条件下使用高质量任务轨迹的价值；教师更强、任务更丰富、训练样本更多和具体训练方法都可能贡献收益。本文未取得并重跑这些实验，因此不把讲义中的跨模型条形图改写成对任意小模型的收益保证。

## 9. GRPO：用同一任务的相对结果更新权重

强化学习让当前策略生成动作或回答，取得反馈，再调整权重，让得到较好结果的行为更可能出现。与 SFT 模仿固定答案相比，RL 可以利用结果反馈探索，但需要足够可靠的奖励与大量可运行任务。

DeepSeekMath 引入 GRPO，核心变化是不用单独学习价值模型来估计基线，而对同一个问题采样一组输出，用组内奖励的相对高低估计优势。原文 outcome supervision 下：

$$
\widehat A_i=\frac{r_i-\operatorname{mean}(r_1,\ldots,r_G)}{\operatorname{std}(r_1,\ldots,r_G)}.
$$

$G$ 是同一问题的采样数，$r_i$ 是第 $i$ 个完整输出的奖励。该优势在原文相应设置中赋给输出的各 token；它表示“相对同组其他回答好多少”，不是这个回答绝对正确的概率。[DeepSeekMath，§4.1.2，PDF p.14](readings/DeepSeekMath_Pushing_the_Limits_of_Mathematical_Reasoning_in_Open_Language_Models.pdf#page=14)

教学上，若一组奖励为 $(0,0,1,1)$，均值是 0.5；用总体标准差 0.5，可得优势 $(-1,-1,1,1)$。具体实现还要规定标准差约定、零方差处理、数值稳定项和无效轨迹处理。若全组都相同，无法从组内相对比较得到有效区分，不应机械除以零。

### 9.1 为什么还需要 old policy、clip 和 KL

采样时的旧策略 $\pi_{old}$ 生成这些输出，优化后的 $\pi_\theta$ 可能已经变化。目标使用二者对已采样 token 的概率比，PPO 风格的 clipping 削弱沿有利方向过度改变该概率比的优化激励；KL 正则惩罚当前策略偏离参考模型。旧策略是这批rollout的采样快照，参考策略是偏移约束的基准，两者职责不同，不能随每次梯度更新一起替换。参考策略也不一定永远固定为初始模型：原文的迭代GRPO在外层迭代刷新参考策略，而在内层按采样批次更新old policy；需要记录各自的更新边界。[DeepSeekMath，§4.1.1、式 3–4、Algorithm 1、§4.1.4，PDF pp.13–15](readings/DeepSeekMath_Pushing_the_Limits_of_Mathematical_Reasoning_in_Open_Language_Models.pdf#page=13)

Clipping也不是硬性保证所有概率比始终位于区间内。例如优势为1、$\epsilon=0.2$、概率比已到1.3时，该样本代理项取1.2；但共享参数还受其他样本梯度影响，后续概率比仍可能继续变化。因此要监测实际KL、clip比例、梯度和留出表现，而不是只看到公式有clip就认定更新受控。稳定性机制也不负责判断奖励是否代表真正业务目标。[依据目标函数的教学推导]

去掉 critic 降低一部分训练资源，不代表 RL 无需显存，也不代表 rollout 免费。策略、参考分布、梯度、优化器状态、采样缓存和奖励计算仍然占资源。原文研究的是数学模型，不能把其训练设置直接搬到长工具链 Agent。

特别要保留来源边界：DeepSeekMath 原实验训练并使用奖励模型，并不是仅依赖一个确定性答案验证器；其 RL 从已有 SFT 模型开始，数据、采样和奖励模型都有具体设置。[DeepSeekMath，§4.2，PDF p.15](readings/DeepSeekMath_Pushing_the_Limits_of_Mathematical_Reasoning_in_Open_Language_Models.pdf#page=15)

把 p.93 与 DeepSeekMath 式 3 对照，教学上可简写为：

$$
J(\theta)=\mathbb E\!\left[\frac1G\sum_{i=1}^G\frac1{T_i}\sum_{t=1}^{T_i}
\left(\min\{\rho_{i,t}\widehat A_i,\operatorname{clip}(\rho_{i,t},1-\epsilon,1+\epsilon)\widehat A_i\}-\beta D_{KL,i,t}\right)\right],
$$

其中 $T_i$ 是输出长度，$\rho_{i,t}=\pi_\theta(o_{i,t}\mid q,o_{i,<t})/\pi_{old}(o_{i,t}\mid q,o_{i,<t})$；$\epsilon$ 控制裁剪，$\beta$ 控制参考策略正则，$D_{KL,i,t}$ 表示原文对应的逐 token KL 项或其估计。外层平均涵盖问题与同组采样；这个式子只是原文 outcome-supervised 形式的教学记号，不定义所有 GRPO 变体。[L9，pp.88–93](slides/lecture09.pdf#page=93)；[DeepSeekMath，式 3，PDF p.13](readings/DeepSeekMath_Pushing_the_Limits_of_Mathematical_Reasoning_in_Open_Language_Models.pdf#page=13)

因此要限定讲义 p.91 的“Only KL is per token”简写：奖励与该 outcome advantage 可在序列级给出，但目标中的策略概率比、裁剪、对数概率与梯度仍涉及 token。PPO 图中的“四模型”和 GRPO 图中的“三模型”也是逻辑角色说明，不应直接当成某部署必须常驻几份独立完整权重的显存公式。[L9，pp.83–93](slides/lecture09.pdf#page=83)

### 9.2 工具型 Agent 的奖励比数学答案更难

对于代码任务，测试可以提供部分可执行反馈；对于公告摘要，“引用正确、口径正确、没有遗漏重要变化”需要多维验证；对于开放研究，正确答案可能没有唯一文本。最终一句用户满意，也无法说明检索、计算和权限全部正确。

因此应先完善环境、终止条件和评分器，再决定 RL。若奖励存在漏洞，更多训练可能让系统更善于利用漏洞。对于包含外部副作用的任务，训练环境还需要可重置、可隔离、可重复评测，不能让探索动作直接作用于生产账户。

迁移到多轮工具轨迹还要检查两件事。首先，记录assistant生成的动作token与环境返回的观察token，后者作为后续决策的输入，却不作为策略采样动作计算policy loss；KL应在相应的模型动作位置计算。另行明确长度归一化使用动作token数还是整段长度，以及截断怎样处理未完成动作，避免无意中让工具返回长度改变样本权重；不同归一化是不同目标选择，不能只改mask却不检查分母。其次，记录组内奖励方差与全成功/全失败组比例：若大量任务全失败，仅扩大采样未必能提供区分信号，可能需要调整任务难度、初始化策略或反馈；零优势时KL等其他目标仍可能产生更新。这些是训练实现与诊断建议，不是声称原始数学实验已经包含这种Agent环境。[承接 L9，pp.81–93；第3课Search-R1提供观察token屏蔽的具体例子]

## 10. On-policy distillation：在学生真正会走到的状态上教学

普通蒸馏可以让小模型学习教师的输出或概率分布，但学生在实际生成时会走到自己的前缀。若训练只看教师的完美轨迹，学生犯错后进入的状态可能没有得到教学，这就是训练与推理的分布不匹配。

GKD 的 on-policy 思路是：由学生生成序列，让教师在这些学生前缀上提供 token 分布反馈，再训练学生。它修正的是“在哪些状态上学”，不等于让学生无验证地把自己的回答当作真值。[On-Policy Distillation，§3.1、Algorithm 1，PDF pp.3–4](references/On-Policy_Distillation_of_Language_Models_Learning_from_Self-Generated_Mistakes.pdf#page=3)

教师分布与学生分布的散度用于定义训练信号。完整概率蒸馏通常需要可获得的教师分布信息；一个只返回最终文字的 API，不能被直接当作同样的训练接口。把教师生成文本做 SFT 也是一种实用方式，但机制与论文的 token-level 分布蒸馏不同。

对 Agent，可类比在学生实际会选错工具或遗漏条件的状态上，取得可靠教师建议或验证反馈。是否有效仍需评测；涉及真实环境时，状态重放、工具版本和副作用隔离会成为数据基础设施问题。这里是工程推导，不声称 GKD 原文已经完成通用企业 Agent 的全部训练。

### 10.1 本讲反向 KL 与 GKD 的关系

讲义 pp.97–100 的核心比喻是“在自己下过的棋局上获得指导”。p.100 展示学生采样下的 log-prob 差；对一个完整序列分布，可以写成反向 KL：

$$
D_{KL}(\pi_\theta\Vert\pi_T)=\mathbb E_{y\sim\pi_\theta}\!\left[\log\pi_\theta(y\mid x)-\log\pi_T(y\mid x)\right].
$$

自回归分解把序列对数概率差展开为各 token 的和。它解释了为什么教师在学生实际到达的前缀上评分；却不等于“对随机采样所得的一个标量按普通确定性函数求导即可得到完整训练算法”，采样分布与梯度估计仍需相应实现。[L9，pp.97–100](slides/lecture09.pdf#page=100)

补充的 GKD 原文允许前向 KL、反向 KL、JSD 以及固定数据与学生采样的混合，提供更一般的分布不匹配视角。讲义 p.103 的结果截图标注来自 Qwen3 技术报告，经博客引用，不是 GKD 的原始 T5 实验。这里保留这种来源差异，不把“on-policy 优于 RL”提升为所有任务、模型和训练预算上的定理。[GKD，§3.1，PDF pp.3–4](references/On-Policy_Distillation_of_Language_Models_Learning_from_Self-Generated_Mistakes.pdf#page=4)；[L9，pp.101–103](slides/lecture09.pdf#page=103)

## 11. Agent 作为优化器：什么时候算系统在自我改进

前面的 OPRO、MIPRO 和 GEPA 把模型用于提出提示修改；进一步可以让 Agent 修改代码、运行实验、检查结果、归档候选并继续搜索。关键是区分**运行中的任务求解**与**跨任务被保留的系统更新**。

在一次任务里反复改答案，说明进行了测试时搜索；把经验证的提示或工具代码发布为后续任务使用的版本，才改变了系统持久能力。是否可以叫 self-improvement，还需说清被修改对象、更新者、验证方法和泛化范围。是否构成严格意义的递归自我改进，更不能仅凭“有一个反思循环”判断。

DGM 保存不同的编码 Agent 版本，采样候选、修改自身代码并用编码基准经验验证。其开放式归档允许保留暂时不是当前最优、但可能成为后续改进踏脚石的版本。它修改运行框架代码，不等于自动训练底座模型，也不是为每次修改给出数学正确性证明。原文对自修改组件的定义明确排除了外层开放探索过程；因此不能从该实验推出系统已经能够任意重写全部优化与验收机制。[DGM，§2–3](references/Darwin_G%C3%B6del_Machine_Open-Ended_Evolution_of_Self-Improving_Agents.pdf#page=3)

对于 autoresearch 一类自动实验循环，应逐项检查实际对象：修改的是训练超参数、模型代码、实验脚本，还是优化器自己的决策逻辑？预算由谁控制，实验结果由什么测量，失败版本是否可回滚？这些问题比一个“自进化”标签更有工程意义。

讲义 pp.110–111 还介绍 Meta-Harness：由一个 meta agent 查看历史经验，再决定下一次修改哪些 harness 组件。它与 DGM 的差别要看改进者本身是否随候选一起改变、外层控制是否固定，不能统称为相同递归机制。随后 pp.113–116 的 autoresearch 把读上下文、提案、实验、保留/回退、日志连接成循环；是否真改进取决于指标与环境的防作弊边界。[L9，pp.105–116](slides/lecture09.pdf#page=105)

### 11.1 自动修改不意味着自动上线

可以让优化器在隔离环境中自由提出候选，再通过独立门槛决定采纳。生产运行和候选搜索应拥有不同权限：优化器不应通过改写评测器、删除失败测试或读入测试答案获得高分。评测数据、验收器和部署审批应处于被优化对象之外的保护边界。

每次采纳至少保存父版本、修改范围、数据与评测版本、预算、训练或搜索日志、独立测试结果和回滚入口。若新增提示只在优化用案例上涨分、在时间更晚的数据上退化，应保留为失败实验，而不是删去不利结果。

## 12. 一个可以落地的优化实验流程

以公告助手为例，先把历史请求按公司、时间和重复模板分组去重，防止同一事件的改写同时进入训练与测试。准备训练反馈集、候选选择集和最终测试集；特别重视按时间划分，以检验对新公告和口径修订的泛化。

然后冻结源公告快照与检索索引，记录一个可重放的基线。为每个失败保留请求、检索结果、模块输入输出、工具错误、最终产物和验证原因。先修复确定性的接口或数据缺失，再决定在哪些提示模块上做搜索。

可以从 Bootstrap/random search 开始，再比较 MIPRO 或 GEPA。给各方法可比的总费用和执行限制，记录反思模型与全部验证成本。先用较小任务集发现明显失败，候选通过后在完整选择集运行；最终测试集只用于最后报告，不能持续把它的逐例反馈交回优化器。

如果准备训练，使用经过验证的数据并建立训练前后回归。把新模型与旧模型放在相同工具和输入版本下比较，同时检查准确性、拒答、结构、长任务恢复和预算。模型更小或单次推理更快，不保证每成功任务成本更低：如果需要更多重试，整体费用可能上升。

最终发布候选时先在低风险流量或影子模式观察，确认真实数据分布与离线评测相近。线上发现新失败后，加入下一轮训练或反馈数据；不要反复污染已作为最终测试的样本集。保留稳定回归集和滚动新分布集，可以同时观察遗忘和新任务适应。

## 13. 选择方法：先看故障与资源，再看算法名称

| 观察到的问题 | 优先尝试 | 需要警惕 |
|---|---|---|
| 格式和条件经常误解 | 明确契约、少量高质量示例、上下文优化 | 评分器只检查表面格式 |
| 多模块提示组合难调 | Bootstrap、MIPRO 类联合搜索 | 成功最终答案隐藏中间错误 |
| 有丰富工具错误和逐项评语 | GEPA、TextGrad 类反馈驱动修改 | 自然语言归因不一定正确 |
| 稳定任务量大且有可信示范 | SFT、蒸馏 | 数据偏差、部署成本与回归 |
| 有可重置环境和可靠结果奖励 | 评估 RL 可行性 | 奖励漏洞、探索成本、长轨迹信用分配 |
| 工具或框架本身限制能力 | 代码级候选搜索与实验 | 候选修改评测器或越权上线 |
| 根本缺少原始证据或数据 | 补数据、修检索与来源管理 | 把数据问题错当提示问题 |

这些是工程选型建议，不是论文证明的严格排序。方法可以组合：先优化提示收集高质量轨迹，再蒸馏到较小模型，再在实际学生状态上补充反馈。但每新增一个阶段，都要单独检查其增益、成本与信息泄漏风险。

### 13.1 BetterTogether：更新次序也属于搜索空间

讲义 p.118 展示先优化提示、再优化权重、再调整提示的一种组合。逻辑上，提示改变会改变可采集的训练轨迹；权重改变又会改变哪个提示有效。因此各阶段不是固定可加的收益。可以把“prompt → weights → prompt”作为候选流程，与只做其中一步、相同总预算的流程比较，不能把它当作永远最优顺序。[L9，pp.118–122](slides/lecture09.pdf#page=118)

当仅有 API、需要频繁适配、环境交互昂贵时，上下文优化往往更容易开始；当较小模型难以遵循长指令、已有可信教师且流量足够大，或者 prompt 膨胀成为瓶颈时，权重优化更值得评估。它们是讲义的选型条件，最终仍由你的独立测试、维护能力与总成本决定。

## 14. 自测与参考答案

**1．模型权重没变，GEPA 为什么仍可以叫优化？**  
它搜索并保留提示参数，使整个系统的条件行为改变；优化对象可以是程序配置而非权重。是否变好由独立任务验证。

**2．一个成功轨迹的每个中间步骤一定都正确吗？**  
不一定，可能出现错误抵消、绕过或答案泄漏。Bootstrap 产生候选示例，还需按任务风险验证来源与步骤。

**3．MIPRO 与 GEPA 的关键差别是什么？**  
MIPRO 原文主要生成指令与示例候选，再用代理模型搜索组合；GEPA 反复利用轨迹和文本反馈生成新提示，并保留实例级互补候选。两者都需要真实评测。

**4．TextGrad 是否对文本求出数学梯度？**  
不是。它以计算图和反馈传播组织自然语言修改建议，gradient 是类比，不能套用真实导数的保证。

**5．GEPA 的 Pareto 是否主要指准确率和费用两个轴？**  
本论文核心选择按各实例得分维护有互补优势的候选，不应泛化成只有准确率—费用的二维权衡。

**6．全组 GRPO 奖励相同会怎样？**  
组内无法区分相对优劣，标准化还面临零方差；实现需规定处理方法。增加同样失败的样本并不能凭空提供有效奖励信号。

**7．GRPO 不需要 critic，是否意味着不需要奖励模型？**  
不是。critic 与奖励来源不同；原始 DeepSeekMath 实验使用奖励模型。其他系统可以使用可执行验证器，但不能把它们混为同一个设置。

**8．学生生成自己的训练序列，是否等于自说自话地学习？**  
在 on-policy distillation 中，序列来自学生，监督来自教师在这些前缀上的概率反馈；不是直接把学生全部输出视为正确。

**9．为什么不把最终测试集每次失败都喂给优化器？**  
这样它已经成为优化反馈集，最终成绩不再是独立泛化证据。需另留未参与更新与选择的数据。

**10．什么证据才能支持自动更新确实有收益？**  
固定输入、工具、验收和预算，对照父版本，在未参与提案的数据上取得可重复改进，同时检查回归、成本和权限；保存最终候选与全部版本证据。

## 15. 本课的工程落点

优化不是让模型不断改写一段话，而是定义一个可变化系统、取得可信反馈、提出候选、用受控预算筛选、在独立分布验证并持久化采纳。上下文、权重、代码与数据各有适用故障和成本。把更新对象、反馈来源和发布边界分别讲清楚，才能知道下一次实验究竟在改善什么。
