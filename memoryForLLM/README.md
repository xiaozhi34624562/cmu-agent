## 1. 先判断论文类型和真正贡献

这是一篇以模型架构为中心的综述，不是一篇提出单个新模型并通过统一实验验证它的研究论文。

它试图解决一个概念问题：注意力的 KV cache、Mamba 的循环状态、Titans 的动态参数、Engram 的查找表以及 MoE 的专家，都被不同研究群体称为“记忆”。如果没有共同语言，人们容易把长上下文、低显存、在线学习、跨会话保存混为一谈。

作者提出三个分类轴：表示形式（隐式/显式）、更新时机（离线/在线）、持续时间（短期/长期），并进一步整理写入、路由、状态转换、淘汰与整合机制。它的价值主要是设计空间的组织，而不是给出已经成立的统一记忆理论。

阅读这篇论文的目标应当是：拿到任何一个新架构，都能回答“信息存在哪里、怎样写、怎样读、何时遗忘、代价在哪里、什么实验能验证它”。

## 2. 一个统一的数学框架

为便于理解，可以把模型记忆抽象为：

$$
m_t=U_\theta(m_{t-1},x_t),\qquad r_t=R_\theta(m_t,q_t),\qquad y_t=F_\theta(x_t,r_t).
$$

这里的 $m_t$ 可以是 KV 列表、隐藏向量、矩阵、一个小网络的权重，也可以是数据库。$U$ 是更新，$R$ 是读取，$F$ 是利用读出结果进行预测。不同架构的差别不是“有没有记忆”，而是这些变量和操作的结构。

信息以什么形式留下来，决定了它未来可以回答什么问题。一个系统可以保存文本全文却检索失败，也可以只留下一个小状态却保留了完成任务需要的全部信息。应追求的是任务所需信息的充分性，而非机械地最大化存储量。

一个有用的理论连接是充分统计量。如果压缩状态满足：

$$
p(y_{t+1}\mid x_{1:t})=p(y_{t+1}\mid m_t),
$$

那么对这个预测任务而言，压缩没有丢失有用信息。但若以后可以提出任何未知问题，想让同一个小状态对所有问题都充分，就难得多。例如语言风格容易压缩，随机 UUID 的每一位却未必可以压缩。

有限精度下，假定状态只有 B 比特，它至多有 $2^B$ 个不同取值。若需要无损区分的独立历史多于这个数量，必有不同历史映射到同一个状态。这是固定状态模型不能无损记住任意长随机序列的根本原因。它仍能有效建模具有规律的长序列，两者并不矛盾。

## 3. 三个分类轴，以及需要修正的边界

### 3.1 隐式与显式：判断依据是接口

按照本文定义，KV cache 虽然是实际存在的张量，仍属于隐式记忆：写入和读取由前向计算规定。显式记忆强调可以独立操作的存储对象、可寻址性和专门更新策略。

| 机制 | 存储对象 | 更新方式 | 主要保留内容 |
|---|---|---|---|
| 完整注意力 | 每个位置的 K、V | 逐 token 追加 | 可回查的细粒度上下文表征 |
| Mamba/线性注意力 | 有界循环状态 | 状态转移 | 压缩后的历史信息 |
| Titans | 动态神经网络权重 | 联想损失的梯度更新 | 当前序列中的关联信息 |
| TTT-E2E | 部分动态 MLP 权重 | 下一 token 损失更新 | 有助于后续预测的上下文规律 |
| MEMORYLLM | 分层潜在记忆槽 | 前向自更新 | 被吸收的新知识表征 |
| kNN-LM | 上下文向量与目标 token | 构建和维护数据存储 | 可按相似上下文检索的实例 |
| Engram | 哈希索引的 N-gram 嵌入表 | 主要离线学习 | 固定局部模式 |
| MoE | 多个专家子网络 | 通常离线训练 | 条件调用的参数化变换 |

这些边界不是唯一标准。比如系统可以序列化 KV，也可以对它分页、替换与淘汰；某些 fast-weight 更新又可以改写成循环状态更新。因此“隐式/显式”更适合描述干预接口，不宜被理解为两种截然不同的数学实体。

### 3.2 在线更新不等于在线梯度学习

KV cache 在推理期间不断追加，因此属于在线更新；但模型参数可以完全不变。Mamba 的状态在推理时更新也不意味着每个 token 都进行反向传播。只有当指定参数通过学习目标更新时，才涉及这一层意义的测试时训练。

作者的表 II 比简单的二分更实用：

| 更新机制 | 例子 | 核心风险 |
|---|---|---|
| 优化驱动写入 | Titans、TTT-E2E | 目标不匹配、梯度不稳定、漂移 |
| 状态转移 | Mamba、Gated DeltaNet | 压缩损失、相互干扰 |
| 信号控制写入或读取 | surprise/entropy 门控 | 信号校准不准、忽略未来才重要的信息 |
| 准入、淘汰、整合 | 滑动窗口、KV 保留策略 | 被丢弃信息难以恢复 |
| 训练目标或结构塑形 | 离线训练的查找表/模块 | 推理时适应能力有限 |

“什么时候更新”“如何更新”“为什么值得更新”应分开回答。

### 3.3 长期至少包含三件事

应区分：

1. 计算历史可以有多长：系统能否持续处理无限输入流。
2. 有效回忆跨度有多长：经过多少干扰之后，过去信息仍能影响正确答案。
3. 生命周期有多长：换会话、换进程、重启服务之后，状态是否保留。

主论文表 I 把 Mamba 等归为长期记忆，主要强调前两者；不能据此推断模型会自动记住某位用户的上一次会话。Titans 和 TTT 的动态权重也不自动等于持久化用户档案。是否重置、归属于哪个用户、怎样恢复，必须看训练和服务协议。

Nested Learning 原论文还把常见测试时记忆视为上下文内的参数化学习，明确讨论上下文结束后知识可能消失。这个提醒比“权重会更新，所以会终身学习”准确得多。

## 4. 注意力：高分辨率的内容寻址

标准因果注意力可以写成：

$$
r_t=\sum_{i\le t}\frac{\exp(q_t^\top k_i/\sqrt{d_k})}{\sum_{j\le t}\exp(q_t^\top k_j/\sqrt{d_k})}v_i.
$$

K 是检索线索，V 是对应内容，Q 表示当前需要。它保留逐位置表征，在未来问题出现时才决定重点读哪里。相对于提前把历史压进小状态，它推迟了不可逆的信息取舍。

这并不表示 KV 是原始文本的无损数据库。投影、位置编码、精度和检索能力都会影响表现。但在保留细粒度位置索引的意义上，完整注意力适合精确回忆。

必须准确区分复杂度。固定模型宽度与层数，序列长度为 n：

- 全注意力 prefill 的注意力计算约为 $O(n^2)$。
- 缓存已有 K、V 后，生成下一个 token 的注意力计算约为 $O(n)$。
- KV cache 的存储量为 $O(n)$，不是 $O(n^2)$。
- 朴素实现物化完整注意力分数矩阵才会引入二次的中间存储；不能把它与 KV 的大小混淆。

主论文引言把注意力计算和存储一起概括为二次增长，这种表述需要以上限定；论文第 V-B 节对 KV 线性增长的描述更准确。

StreamingLLM 保存少量初始 attention sink tokens 和最近窗口，以维持流式推理稳定。初始 token 被保留不一定因为它包含重要语义，而可能因为模型把多余注意力质量分配给它。它可以在非常长的输入流上稳定运行，但并未因此恢复已被窗口淘汰的所有旧信息。[[15] 原文](https://arxiv.org/abs/2309.17453v1)

工程问题也要区分：少读一部分 KV 可以减少计算；只有真正少存、压缩或共享 KV，才减少对应的存储占用。

## 5. 循环状态与 Delta Rule：压缩为什么会干扰

### 5.1 从线性注意力到关联矩阵

在核特征形式下，线性注意力可以累计：

$$
S_t=S_{t-1}+v_t\phi(k_t)^\top,\qquad z_t=z_{t-1}+\phi(k_t),
$$

$$
r_t=\frac{S_t\phi(q_t)}{z_t^\top\phi(q_t)}.
$$

这依靠乘法结合律先聚合历史，从而避免每次查询访问所有 token。若省略归一化并取恒等特征，则成为最简单的联想记忆：

$$
S_t=S_{t-1}+v_tk_t^\top,\qquad r_t=S_tq_t.
$$

这是教学简化，不是一般 softmax 注意力的精确改写。不同核具有不同表达能力。[[64] 原文](https://arxiv.org/abs/2006.16236)

当查询 $q=k_a$ 时，读出的结果包含目标项以及其他 key 的交叉项：

$$
Sk_a=v_a\|k_a\|^2+\sum_{i\ne a}v_i(k_i^\top k_a).
$$

其他 key 与它不正交，就会产生串扰。把很多条独立信息叠加到一个固定矩阵里，代价在检索时体现出来。

### 5.2 Delta Rule 的推导

对当前关联 $(k_t,v_t)$，定义：

$$
\ell_t(S)=\tfrac12\|Sk_t-v_t\|^2.
$$

一步梯度下降得到：

$$
S_t=S_{t-1}+\beta_t(v_t-S_{t-1}k_t)k_t^\top.
$$

它写入的是预测误差：当前关联已经被记住时，更新小；发生冲突时，修正旧关联。若 key 单位归一化、$\beta_t=1$，这一步会精确修正当前 key 的输出；但非正交的其他 key 仍可能被波及。因此 Delta Rule 改善写入，不会消除有限容量。

Gated DeltaNet 在此基础上引入衰减：

$$
\widetilde S_{t-1}=\alpha_tS_{t-1},\qquad
S_t=\widetilde S_{t-1}+\beta_t(v_t-\widetilde S_{t-1}k_t)k_t^\top.
$$

$\alpha_t$ 控制旧信息遗忘，$\beta_t$ 控制当前关联修正。这也是循环状态、在线线性回归、fast weights 三条文献之间的数学桥梁。[[23] 原文](https://arxiv.org/abs/2412.06464)

### 5.3 Mamba 的关键是输入依赖的选择

Mamba 的离散状态模型可抽象为：

$$
h_t=\overline A_t h_{t-1}+\overline B_t x_t,\qquad y_t=C_t h_t.
$$

其选择机制使部分状态空间参数依赖当前输入，让不同 token 有不同的保留、写入与读出方式。它的贡献同时包含建模与实现：选择性压缩加上硬件友好的 scan、融合与重计算。[[4] 原文](https://arxiv.org/abs/2312.00752)

学术上，要比较状态转移能表达什么；工程上，要检查扫描与矩阵运算是否能充分使用设备。仅有 $O(n)$ 的复杂度，并不足以保证真实延迟更低。

Kimi Linear 的 KDA 把部分遗忘控制细化到通道，并采用 KDA 与完整注意力交替的混合结构。论文使用 3:1 的层比例，体现了固定状态与细粒度读取的互补。但只要还保留固定比例的全注意力层，最坏情况下的长序列注意力计算仍有二次项；减少层数降低常数，不等于消除这一阶复杂度。[[26] 原文](https://arxiv.org/abs/2510.26692)

## 6. 测试时学习：记忆可以是一组动态权重

### 6.1 Titans：学习如何写入

Titans 用一个神经网络作为动态记忆，学习 key 到 value 的关联。简化记法为：

$$
\ell_t(\phi)=\|M_\phi(k_t)-v_t\|^2,
$$

$$
u_t=\mu_tu_{t-1}-\eta_t\nabla_\phi\ell_t(\phi_{t-1}),\qquad
\phi_t=(1-\alpha_t)\phi_{t-1}+u_t.
$$

梯度形成当前写入方向，动量携带近期更新信息，衰减提供遗忘。外层训练则让整套表示与写入过程对最终任务有用。这里梯度相对于记忆参数计算；它不是“对输入文本随便求个梯度”。[[8] 原文](https://arxiv.org/abs/2501.00663)

Titans 还区分动态 long-term neural memory 与输入无关、训练得到的 persistent memory tokens。两者都使用“memory”一词，却承担不同职责；不要把它们都解释成跨会话积累的个人经历。

surprise 的直觉有吸引力，但必须审视代理目标：梯度大可能来自噪声、罕见乱码或分布变化。惊讶不自动代表真实、重要或未来有用。论文的机制需要通过下游任务评价，而不能依赖人类认知类比来证明。

### 6.2 TTT-E2E：局部重建目标与最终任务目标的差别

TTT-E2E 在测试时优化最终下一 token 预测损失，并在训练阶段优化“经过这种更新后”的表现。教学性简式为：

$$
W_t=W_{t-1}-\eta\nabla\ell_t(W_{t-1}),
\qquad
\min_{W_0}\mathbb E_X\sum_t\ell_t(W_{t-1}(W_0)).
$$

外层目标依赖整条更新轨迹，而不是把 $W_0$ 当作永远静止的权重。它训练的是一个善于在上下文中适应的起点。

原文为稳定性和效率采用分块更新、滑动窗口，仅更新靠后的一部分 MLP，并保留静态 MLP 分支。它并不是把任意现成聊天模型在每一步随意微调。原文 128K 设置使用 8K 滑动窗口和 1K 更新批次；窗口覆盖当前尚未写入权重的批次内容。[[9] 原文](https://arxiv.org/abs/2512.23675)

最有教育意义的是原文表 2。作者在其 3B 模型、128K 测试条件下报告：

| 方法 | 单 passkey | haystack 中数字 | haystack 中 UUID |
|---|---:|---:|---:|
| 完整注意力 | 99% | 86% | 64% |
| TTT-E2E | 6% | 5% | 3% |

这与它良好的长文本语言建模结果可以同时成立。自然文本的规律能被压缩为有助于预测的参数变化；一个与上下文无关、只出现一次的随机标识符却可能被压缩目标忽略。

上述找针结果来自特定模型、训练目标和评测配置，支持“预测效果与精确回忆可以分离”，不能证明所有测试时学习方法都无法精确回忆。它应与语言建模收益、训练成本和消融结果一起解读。

作者报告的 128K 下约 2.7 倍加速，测量对象是 **prefill latency**。原文 §3.7 使用约 3B 模型、单张 H100，每批总 token 数固定为 128K：128K 上下文时是一条序列，8K 上下文时是 16 条序列。这不是整体服务加速或独立的 decode 延迟测量；作者没有另行报告 TTT-E2E 的独立 decode 延迟数据。

生成过程中的更新也有成本：尚未填满测试时更新批次时执行滑动窗口解码，填满后还要进行一次 TTT 更新。因此平均吞吐与交互时的延迟峰值需要分别评估。

训练成本同样不能省略。原文 §3.7 在 H200 上按相同总 token 批量测量，报告其当时实现的训练速度在 128K 上下文下约为完整注意力的 1.2 倍，但在 8K 下慢 3.4 倍。作者将二阶自动微分与时间维度的梯度检查点开销列为限制。这些数据都是论文特定实现的结果，不是普遍性能保证。证据位置：所核读 TTT-E2E v2 的 §3.7，第 16–17 页。

### 6.3 对“TTT 其实是线性注意力”的正确理解

参考 72 对 KV-binding TTT 分析发现，多类内循环可以改写成学习到的线性注意力形式。这说明“使用梯度更新”和“使用循环状态”不一定是两个互斥范式。

需要三项限定：其主要对象是 KV-binding，而不是所有 end-to-end TTT；能写成线性注意力形式不代表一切实现都能相同地并行；动态特征变换和每步权重归一化等会阻碍简单的并行归约，作者在附录 I 中专门分析。

该论文还报告梯度上升变体不一定更差，但这是把改变后的内循环贯穿训练与推理、重新训练后的实验，不能解释成“把已经训练好的模型的梯度符号反过来就没有影响”。[[72] 原文](https://arxiv.org/abs/2602.21204)

## 7. 可寻址存储：实例、局部模式与专家不能混为一谈

### 7.1 kNN-LM：在概率分布中利用实例记忆

kNN-LM 的 datastore 保存上下文表示与实际下一个 token。查询近邻后得到 $p_{kNN}$，再与模型分布插值：

$$
p(y\mid x)=(1-\lambda)p_{LM}(y\mid x)+\lambda p_{kNN}(y\mid x).
$$

它不是先检索几篇文档，再拼进 prompt；检索结果直接影响下一 token 分布。因此主论文把它纳入模型级记忆，而把一般应用层 RAG 排除在主要范围外。[[40] 原文](https://arxiv.org/abs/1911.00172)

它也揭示一个工程代价：如果每个 token 都查询大索引，延迟、索引容量、表示版本与数据更新都成为系统问题。外部存储并不等于免费存储。

### 7.2 MEMORYLLM：专门的槽不一定要靠梯度写入

MEMORYLLM 在 Transformer 各层维护固定大小的潜在记忆池。读取新材料后，通过前向过程生成新记忆 token，替换一部分旧槽位。它把“知识写入”设计成专用计算路径，说明显式在线记忆不必等于反向传播。[[44] 原文](https://arxiv.org/abs/2402.04624)

不过随机替换槽位的生存概率，只能直接刻画槽位保留；不能直接当作语义知识或回答准确率的精确遗忘曲线。压缩后一个知识点可能分布在多个槽位，后续更新也可能继续传播它。

### 7.3 Engram：固定知识查表

Engram 基于局部 N-gram 进行规范化和多头哈希，查出嵌入，再由当前隐藏状态控制融合强度。

必须区分寻址和融合：寻址主要由 token IDs 确定，隐藏状态用于对查出的内容进行门控。主论文对“基于隐藏状态查询”的高层描述，容易掩盖这个对于工程至关重要的区别。[[10] 原文](https://arxiv.org/abs/2601.07372)

因为地址能提前知道，主机端可以预取嵌入，并用前面网络层的计算隐藏传输延迟。这是一种明确的算法与系统协同设计。

原文的离线表主要存储学习到的局部模式，不是在线把每次用户对话追加进事实库。表项可寻址也不表示每个表项对应一个可读事实；哈希冲突和分布式表征仍存在。

其表 4 用 Dense-4B/8B 骨干、H800、512 条长度在 100–1024 之间的序列，测量 100B 参数表完全放在主机内存时的吞吐变化，最坏约 2.8%。这一结果证明该测量设置下预取有效，不证明任何并发、硬件、超长输入或 MoE 部署的 P99 延迟都只增加这么多。

### 7.4 MoE：可以从记忆角度看，但不要把类比当作事实

MoE 计算：

$$
y=\sum_{i\in\operatorname{TopK}(g(h))}g_i(h)E_i(h).
$$

作者把专家看作可条件访问的参数记忆，这是一个有用视角。但专家被选择以后执行的是变换，不是读取一个事实记录。MoE 也不会因为启用了路由，就在推理时自动写入新经验。

更具体地说，主论文第 IV-C 节关于领域分工的概括过强。Mixtral 原文第 5 节表示，没有观察到按主题分配专家的明显模式，观察到的更接近语法结构和相邻 token 的局部性。因此不能未经验证就设想“某个专家专门记住数学，另一个专家专门记住医学”。[[13] 原文](https://arxiv.org/abs/2401.04088)

## 8. 多时间尺度与混合记忆

Nested Learning 关注不同模块以不同频率更新，以及知识如何在层级之间传递。更新频率不同，意味着稳定性和适应性不同；但仅把频率分层并不能自动保证重要知识永不遗忘。[[11] 原文](https://arxiv.org/abs/2512.24695)

例如当前任务临时变量需要快速变化，稳定的语言能力不应因为一次输入立即被重写。在工程中可以借鉴这种分工，但数据库缓存层级与神经网络内多层优化并不是同一个算法。

混合架构进一步回答：让什么信息由什么载体保存？固定混合安排某些层做全注意力、另一些层做循环压缩；自适应混合则对每个 token 决定是否值得额外保留。

HAM 让循环路径处理全部输入，把难以由循环状态预测的关联写入稀疏 KV，再融合两个路径。论文的一个路由方式比较状态对 value 的预测误差，具体可以用余弦距离，而不必等同于语言模型输出分布的熵。[[39] 原文](https://arxiv.org/abs/2603.22325)

但难预测程度只是未来价值的代理。一个现在平凡的信息可能在很久之后变得关键；一个异常字符串也可能永远没用。因此应专门测“延迟相关性”。

复杂度也需要准确。如果平均保留比例 $\rho$ 是固定非零常数，KV 占用仍为 $O(\rho n)$，扫描保留历史的总注意力计算仍可能是 $O(\rho n^2)$。自适应保留降低实际代价，但若没有固定预算或次线性的保留数量保证，就不能宣布无限输入下恒定内存。

## 9. 工程实践：把抽象主张换成预算

### 9.1 显存要按请求计算

若各层维度相同、K 与 V 维度相同，普通缓存大小近似为：

$$
M_{KV}=2BLnH_{kv}d_hb,
$$

其中 B 为并发序列数，L 为层数，n 为缓存 token 数，$H_{kv}$ 为 KV 头数，$d_h$ 为头维度，b 为每个元素字节数。

取教学配置 B=1、L=32、$H_{kv}=8$、$d_h=128$、b=2：128 Ki tokens 约占 16 GiB KV；1 Mi tokens 约占 128 GiB KV。它不包含模型权重、临时激活、分配开销和运行时工作区，也不适用于所有 MLA、量化或混合缓存布局。

PagedAttention 解决逻辑 KV 到物理块的映射、碎片和共享问题，不自动改变模型能记住什么，也不让单个请求的逻辑 token 数消失。[[82] 原文](https://arxiv.org/abs/2309.06180)

### 9.2 固定大小快权重仍可能很大

“对序列长度为 O(1)”不等于“每用户很小”。若一个假设的测试时记忆模块有 1 亿个独立 FP16 动态参数，权重本身就约 200 MB；如另存一份 FP32 动量，再增加约 400 MB。并发用户的动态状态通常不能像静态模型权重一样简单共享，真实成本还可能包括梯度、激活和工作区。

因此需要同时比较：每请求 KV、每请求循环状态、每请求快权重及优化器状态，而不是只比较模型文件大小。

### 9.3 顺序、隔离和缓存正确性

如果两个请求从同一记忆快照并发写入，怎样合并？在非线性更新下，先 A 后 B 与先 B 后 A 往往不同。服务系统必须明确状态归属、更新串行化或合并规则、版本与回滚策略。

对会变化的模型状态，前缀缓存键也要包含会影响结果的参数或状态版本。相同文本前缀在不同快权重状态下未必生成相同激活。不能把普通静态模型服务的缓存假设原封不动搬过来。

这里只是指出在线状态所直接引入的正确性要求，不是说每个方案都需要同样复杂的基础设施。

### 9.4 墙钟时间取决于数据移动

粗略下界可写为：

$$
T\gtrsim\max\left(\frac{\text{FLOPs}}{\text{计算吞吐}},\frac{\text{搬运字节数}}{\text{有效带宽}}\right).
$$

不规则索引、CPU/GPU 同步、跨卡通信、小矩阵启动开销和动态 batch 形状，都可能让理论更省 FLOPs 的算法实际更慢。应测目标并发与长度分布下的 TTFT、TPOT、P95/P99、峰值显存与吞吐。

### 9.5 对 Agent 工程的适用范围

如果只有托管模型 API，通常无法给它插入 Titans、Engram 或 KDA 层。能直接控制的仍是上下文组织、检索、外部持久化和工具执行。

这篇论文提供的可迁移原则是：对必须精确且可验证的信息，保留可回查原始依据；对可概括的经验做压缩；对频繁变化的事实明示版本；用近期上下文承担当前任务状态。它没有证明某种 Agent 向量库产品一定更好。

如果能够训练或修改骨干模型，才可以真正比较这些模型级记忆架构；此时训练目标、数据顺序、更新协议和内核实现同样重要。

## 10. 怎样做可信的记忆评估

RULER 把长上下文评估扩展为检索、多跳追踪、聚合和问答，并强调有效上下文长度与宣称长度不同。其限制章节同样承认合成任务与真实使用的相关性不能想当然。[[59] 原文](https://arxiv.org/abs/2404.06654)

建议分开测以下维度：

| 能力 | 可复现实验 | 指标 |
|---|---|---|
| 精确保留 | 写入随机 ID，插入不同长度干扰后查询 | exact match 随距离变化 |
| 多条独立记忆 | 随机 key-value 数量持续增加 | 准确率随条目数变化 |
| 纠正旧信息 | A=v1，干扰，A=v2，再问当前及历史 | 当前值正确率、旧值保留 |
| 干扰鲁棒性 | 相似 key、冲突陈述、噪声混入 | 串扰率与遗忘曲线 |
| 压缩与归纳 | 反复示例后引入新组合 | 未见问题泛化表现 |
| 延迟相关性 | 早期低显著信息在后期才成为目标 | 未来相关信息漏存率 |
| 跨会话持续性 | 明示重置、保存、恢复和重启条件 | 恢复后准确率和一致性 |
| 工程效率 | 固定设备与服务负载 | TTFT、TPOT、P99、内存、吞吐 |

实验要保证因果顺序：测试时写入只能看到当时已有的输入，不能提前使用后面的问题、正确答案或未来 token。比较不同系统时应明示各自可访问的信息范围；允许外部存储的系统应计入索引和检索成本。

公平性应分成多个受控比较：相同训练 token 和模型规模、相近训练 FLOPs、相同推理内存预算、相同服务延迟约束。它们通常不能全部同时精确匹配，因此应报告多组 Pareto 曲线，而不是选择一个有利条件宣布全面优胜。

一个具体小实验：让模型读“A 的验证码是随机 UUID”，插入 1K/4K/16K 干扰，再查询；另做一组跨整个上下文重复出现的语言模式预测。对比完整注意力、窗口注意力、循环记忆、TTT 与混合记忆，可以直接观察“精确存储”和“规律压缩”的差别。没有实际训练或测量时，应把这视作实验方案，而不是已得到的结果。

## 11. 对主论文的学术评价

最有价值的部分，是把记忆载体、更新机制和系统代价联系起来，并且意识到写入、遗忘和评价不能被上下文长度一个数字代替。表 II 的机制分类对研究设计尤其有用。

主要不足有五点。

第一，长期的定义在序列跨度与跨会话持久性之间移动，需要在每个具体模型上重新落地。

第二，隐式/显式的边界依赖接口和论文视角，并不总是数学不变量。fast-weight 与递归状态之间的等价性正好说明这一点。

第三，排除静态基础参数，却纳入静态 MoE 专家，体现了作者重视模块化寻址，但也使纳入标准需要更严谨的操作定义。

第四，部分原文概括过强。Mixtral 的领域分工、Engram 的寻址路径、注意力的存储复杂度，都应回到原始论文和具体实现进行限定。

第五，综述没有在统一训练预算、推理预算与测试协议下重新实现各方法，因此它的分类表不能作为性能排行榜，也不能证明某个范式全面优于另一个。

一个更可检验的研究方向，是把“是否值得保存”写成未来任务收益减去成本的决策问题，例如教学性的目标：

$$
\max_\pi\ \mathbb E[U_{future}(\pi)]-\lambda C_{storage}(\pi)-\mu C_{read}(\pi)-\nu C_{write}(\pi).
$$

这里的未来效用未知，才导致 surprise、entropy、预测误差等代理信号出现。研究重点可以是这些代理何时失效、怎样校准，以及误删后有没有恢复路径。这是分析提出的研究问题，并非原论文已证明的定理。

读完后应能够区分：完整注意力推迟信息取舍，循环状态提前压缩历史，动态参数通过更新吸收经验，查找表把固定模式外部化，混合架构在多个载体之间分配有限预算。设计目标始终是让未来任务需要的信息，以可承担的成本保持可访问。

### 12.3 需要补强的三条理论联系

**容量与可测量能力。** 有限比特论证只说明“不可能无损保存任意历史”，还不能直接指导模型选型。应进一步明确查询分布、干扰强度、容许错误率，以及在这些条件下可保存的关联数量。容量应是带条件的可测量量。

**遗忘与稳定更新。** 应比较衰减、局部修正、记忆分区、更新约束等机制。主论文 §IV-E 讨论的几何与正交约束也值得继续核读，但限制参数变化不等于保证所有旧知识不遗忘。

**记忆与推理。** 应使用跨段关系、多跳问题和状态追踪，分别诊断：信息被丢弃、信息仍在但读不出、读出正确但组合推理失败。三者不能共用一个“记忆差”的解释。

### 12.4 工程教学的贯穿案例

建议用“持续数天的编程 Agent”连接各节：它需要记住项目约束、代码修改、失败尝试、工具结果和当前任务状态。

这个案例应依次回答：

1. 哪些信息必须精确保存，哪些可以概括？
2. 代码更新推翻旧结论后，怎样保留历史并更新当前事实？
3. 任务结束后，哪些状态清除，哪些允许跨任务保留？
4. 检索、读取和推理分别怎样评价？
5. 只有模型 API 时能实现什么，可修改骨干时又能实现什么？
6. 如何计算请求状态占用、写入成本、读取成本与恢复成本？

后续应给出带状态版本、读取、写入、提交和恢复边界的伪代码，并设计对应实验。目前本文只有实验方案，没有声称完成实现或得到实测结果。
